```
│   └── positions (持仓记录表)
├── new_coin (Schema)
│   ├── coin_monitor (新币监控表)
│   ├── short_signals (做空信号表)
│   └── short_positions (做空持仓表)
├── grid (Schema)
│   ├── grid_config (网格配置表)
```

上传脚本会:

1. **停止旧容器**: 停止所有运行中的策略容器

6. **构建镜像**: 构建所有策略镜像（不使用缓存）
7. **启动容器**: 启动所有策略容器

### BTC/ETH 策略配置 (v6.20+ 新增)

#### market_state 配置节

市场状态识别配置，用于5条件判定当前市场是强趋势（STRONG_TREND）还是震荡（RANGING）：

```yaml
market_state:
  enabled: true                     # 是否启用市场状态识别
  adx_threshold: 25                 # ADX阈值，高于此值为趋势
  bb_width_threshold: 0.05          # 布林带宽度阈值，低于此值为震荡
  price_change_threshold: 0.02      # 价格变化率阈值
  ema21_slope_threshold: 0.001      # EMA21斜率阈值
  kline_confirm_count: 3            # K线确认所需连续K线数
```

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `enabled` | 是否启用市场状态识别 | true |
| `adx_threshold` | ADX判定阈值，ADX > 此值判定为趋势 | 25 |
| `bb_width_threshold` | 布林带宽度阈值，宽度 < 此值判定为震荡 | 0.05 |
| `price_change_threshold` | 价格变化率阈值（辅助判定） | 0.02 |
| `ema21_slope_threshold` | EMA21斜率阈值（辅助判定） | 0.001 |
| `kline_confirm_count` | K线形态确认所需连续K线数 | 3 |

#### ranging_strategy 配置节

震荡市策略配置，在 RANGING 状态下执行低风险、高频次的小额交易：

```yaml
ranging_strategy:
  enabled: true                     # 是否启用震荡策略
  position_ratio: 0.5               # 仓位比例（相对趋势策略）
  take_profit_min: 0.005            # 最小止盈比例
  take_profit_max: 0.01             # 最大止盈比例
  stop_loss_min: 0.003              # 最小止损比例
  stop_loss_max: 0.005              # 最大止损比例
  cooldown_minutes: 30              # 冷却期（分钟）
  max_daily_trades: 10              # 每日最大交易数
  rsi_oversold: 30                  # RSI超卖阈值
  rsi_overbought: 70                # RSI超买阈值
  score_threshold: 60               # 最低评分阈值
```

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `enabled` | 是否启用震荡策略 | true |
| `position_ratio` | 仓位比例（相对趋势策略，0.5=50%） | 0.5 |
| `take_profit_min` | 最小止盈比例 | 0.005 (0.5%) |
| `take_profit_max` | 最大止盈比例 | 0.01 (1.0%) |
| `stop_loss_min` | 最小止损比例 | 0.003 (0.3%) |
| `stop_loss_max` | 最大止损比例 | 0.005 (0.5%) |
| `cooldown_minutes` | 震荡策略冷却期（分钟） | 30 |
| `max_daily_trades` | 每日最大交易笔数 | 10 |
| `rsi_oversold` | RSI超卖阈值（做多信号） | 30 |
| `rsi_overbought` | RSI超买阈值（做空信号） | 70 |
| `score_threshold` | 最低评分阈值，低于此值不交易 | 60 |

#### stop_limit_order 配置节（v6.20.3 新增）

止损限价单偏移配置。止损单从 `STOP_MARKET`（市价止损）改为 `STOP`（限价止损），触发后以限价单成交，降低手续费。

```yaml
stop_limit_order:
  offset_pct: 0.002             # 偏移比例 0.2%
```

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `offset_pct` | 止损限价偏移比例。做多：限价 = 触发价 * (1 - 偏移)，做空：限价 = 触发价 * (1 + 偏移) | 0.002 (0.2%) |

#### tp_limit_order 配置节（v6.20.3 新增）

止盈限价单偏移配置。止盈单从 `TAKE_PROFIT_MARKET`（市价止盈）改为 `TAKE_PROFIT`（限价止盈），触发后以限价单成交。

```yaml
tp_limit_order:
  offset_pct: 0.0015            # 偏移比例 0.15%
```

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `offset_pct` | 止盈限价偏移比例。做多：限价 = 触发价 * (1 - 偏移)，做空：限价 = 触发价 * (1 + 偏移) | 0.0015 (0.15%) |

#### close_limit_order 配置节（v6.20.3 扩展）

平仓限价单配置。v6.20.3 将所有平仓原因统一为限价单，取消市价降级逻辑，改为超时重试机制。

```yaml
close_limit_order:
  enabled: true
  timeout_seconds: 10           # 首次等待成交超时（秒）
  poll_interval_seconds: 2      # 轮询间隔（秒）
  max_retries: 3                # 超时后最大重试次数（v6.20.3 新增）
  retry_interval_seconds: 2     # 重试间隔（秒，v6.20.3 新增）
  applicable_reasons:           # 扩展为所有平仓原因（v6.20.3）
    - TP1
    - TP2
    - CHANDLIER
    - TIME_STOP
    - STOP_LOSS
    - EXTREME
    - LIQUIDATION
    - LIQUIDATION_REDUCE
```

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `enabled` | 是否启用限价平仓 | true |
| `timeout_seconds` | 首次等待成交超时（秒） | 10 |
| `poll_interval_seconds` | 轮询检查间隔（秒） | 2 |
| `max_retries` | 超时后最大重试次数 | 3 |
| `retry_interval_seconds` | 重试间隔（秒） | 2 |
| `applicable_reasons` | 适用限价平仓的平仓原因列表 | 全部 8 种原因 |

## 故障排查

### 问题 1: SSH 连接失败

**症状**: SSH 连接提示 "Permission denied" 或 "Connection refused"

**解决方案**:

```bash
# 1. 检查密钥文件权限
ls -la /Users/yl/vscode/inspection_automation/docs/only.pem
# 应该显示: -rw------- (600)

# 2. 修复权限
chmod 600 /Users/yl/vscode/inspection_automation/docs/only.pem

# 3. 测试连接
ssh -i /Users/yl/vscode/inspection_automation/docs/only.pem \
    -o StrictHostKeyChecking=no \
    root@43.156.242.184 "echo '连接成功'"
```

### 问题 2: 容器启动失败

**症状**: 容器启动后立即退出

**解决方案**:

```bash
# 1. 查看容器日志
ssh -i $SSH_KEY_PATH root@43.156.242.184 "docker logs trading_system-btc_eth"

# 2. 检查环境变量
ssh -i $SSH_KEY_PATH root@43.156.242.184 "cat /root/trading_system/.env"

# 3. 检查数据库连接
ssh -i $SSH_KEY_PATH root@43.156.242.184 << 'EOF'
docker exec postgres-db psql -U trading_user -d trading_platform -c "SELECT 1;"
EOF

# 4. 重启容器
ssh -i $SSH_KEY_PATH root@43.156.242.184 << 'EOF'
cd /root/trading_system
docker-compose restart btc-eth-strategy
EOF
```

### 问题 3: 数据库连接失败

**症状**: 策略容器无法连接到数据库

**解决方案**:

```bash
# 1. 检查 PostgreSQL 容器状态
ssh -i $SSH_KEY_PATH root@43.156.242.184 "docker ps -f name=postgres-db"

# 2. 检查数据库是否就绪
ssh -i $SSH_KEY_PATH root@43.156.242.184 << 'EOF'
docker exec postgres-db pg_isready -U trading_user -d trading_platform
EOF

# 3. 检查网络连接
ssh -i $SSH_KEY_PATH root@43.156.242.184 << 'EOF'
docker network inspect trading-network
EOF

# 4. 重启 PostgreSQL
ssh -i $SSH_KEY_PATH root@43.156.242.184 << 'EOF'
cd /root/trading_system
docker-compose restart postgres
EOF
```

### 问题 4: 镜像未更新

**症状**: 部署后容器运行的还是旧代码

**解决方案**:

```bash
# 1. 检查镜像创建时间
ssh -i $SSH_KEY_PATH root@43.156.242.184 << 'EOF'
docker inspect -f '{{.Created}}' trading_system-btc_eth
docker images | grep btc_eth
EOF

# 2. 强制重新部署
./one_click_deploy.sh

# 3. 如果仍然失败,手动清理并重新部署
ssh -i $SSH_KEY_PATH root@43.156.242.184 << 'EOF'
cd /root/trading_system
docker-compose down
docker rmi trading_system-btc_eth:latest trading_system-new_coin:latest trading_system-grid:latest --force
docker-compose build --no-cache
docker-compose up -d
EOF
```

### 问题 5: 磁盘空间不足

**症状**: 部署失败,提示磁盘空间不足

**解决方案**:

```bash

docker image prune -a -f --filter "until=24h"
docker volume prune -f
EOF

# 3. 清理旧备份
ssh -i $SSH_KEY_PATH root@43.156.242.184 << 'EOF'
find /root/trading_system/database/postgres/backups -name "*.sql.gz" -mtime +7 -delete
```
