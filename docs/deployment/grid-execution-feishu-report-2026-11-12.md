# ETHUSDT 自动网格执行报告：飞书独立推送

日期：2026-11-12（北京时间）。原 V2.5.5 网格信号消息保持原样；同一 `FEISHU_WEBHOOK_GRID` 增加一条执行报告，每笔已确认且归属网格执行器的成交各一条。

## 消息口径

- 交易：执行账本 `fill` 与 PM `/papi/v1/um/userTrades` 同时以交易所订单 ID、成交 ID、方向、数量和价格吻合后才报告。人工验收交易没有写入网格执行账本，不计入网格成绩。
- 持仓：发送时读取 PM `positionRisk` 的 ETHUSDT 单向净仓、入场均价、标记价和未实现盈亏；这是**发送时快照**，不声称它是每笔历史成交瞬间的仓位。
- 当前网格阶段盈亏：当前最新 `grid_epoch` 内本执行器成交的 `realizedPnl` 减 USDT 手续费，加该阶段 ETHUSDT 资金费和当前净仓未实现盈亏。
- 执行器累计盈亏：首个网格阶段以来全部执行器成交的同一口径，加累计 ETHUSDT 资金费与当前净仓未实现盈亏。300 USDT 初始划转与上线前人工验收交易不在该口径内。
- PM 手续费原字段为正数支出，报告中明确扣减。若手续费币种不是 USDT、成交归属或资金费证据不完整，本轮不发送不可信的盈亏数字。该报告不是原信号的预估网格收益。

## 实现与故障行为

- 独立通知进程只读生产 `grid_execution.sqlite3`，自己的投递状态保存在 `grid_notifications.sqlite3`；不修改执行账本 schema，也不参与下单或风控判定。
- 同一 `(order_id, trade_id)` 成功送达后落 `sent_at_ms`，进程重启不会重复发送。HTTP 失败或结果未知时保留待发并至少 30 秒后重试；由于飞书 Webhook 无本项目可用的幂等键，结果未知后可能重复投递，消息中的成交 ID 供人工识别。
- 后续顺序修复 `996bad186d83c0dce7e7c06c24d9c381b5967281` 使未确认的早期消息阻挡后续成交报告，直到重试完成，避免晚成交先到飞书。当前生产镜像为 `grid-notifier:996bad18`，镜像 ID `sha256:4731a08f841f384d662f89adc584f26b8d8e2284bb15be782cff087d10e0cc4c`；发布证据：服务器 `.releases/grid-notifier-ordering-20261112/996bad186d83c0dce7e7c06c24d9c381b5967281/`。
- 当前没有任何真实网格成交时，通知进程不制造“0 盈亏成交报告”；有成交才推送。它不做定时持仓播报，持仓和盈亏随每笔成交报告更新。
