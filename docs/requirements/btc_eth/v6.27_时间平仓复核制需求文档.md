## 二、需求背景与目标

### 2.1 背景

MTPCS 策略目前存在「时间平仓」（time_stop）机制：

- 持仓时长达到 `max_holding_hours` 后，**无条件**按 `close_ratio` 比例部分平仓（平仓原因 `TIME_STOP`）。
- 该机制按信号等级独立配置：`max_holding_hours`（S=96 / A=72 / B=48 / C=24）、`close_ratio`（S/A=0.5、B=0.6、C=0.8）。

**存在的问题：** 时间平仓是纯时间条件，不看行情。当持仓在 `max_holding_hours` 到期时恰好处于行情启动前夜（方向正确、即将启动），无条件平仓会「砍在行情启动前」，丢失后续收益。

**已有的基础：** v6.26 已上线「震荡反转风控三机制」（方向一致性对齐、过热保护、波动熔断），用于**入场前护栏**，可在 `_check_direction_alignment` / `_check_overheat_ban` / `_check_volatility_regime` 三个函数中评估「当前持仓方向是否仍该持有」。

### 2.2 核心思路

将 time_stop 到期后的动作从「无条件平仓」改为「**先复核，判定不该持有才平仓**」：

1. 到期后进入「复核期」，不再无条件平仓。
2. 每个调度周期复用三机制复核当前持仓方向是否仍该持有。
3. 任一机制判定「不该持有」→ 平 `close_ratio` 比例（平仓原因 `TIME_STOP_REVIEW`）。
4. 全部判定「该持有」→ 继续持有，下周期再复核。
5. 设置复核期上限 `max_review_hours`，超时**无条件**平仓，保证资金最终释放。

### 2.3 目标

1. time_stop 到期后，由「无条件平仓」升级为「三机制持仓复核」。
2. 方向正确、行情启动前的持仓可继续持有，避免砍在启动前。
3. 方向已反转、重度过热、波动极端时及时部分平仓，控制风险。
4. 通过 `max_review_hours` 兜底，确保资金最终释放，不无限持有。
5. 全程可配置（`review_enabled` 一键开关），`false` 时完全恢复原无条件到点平仓行为。

### 2.4 非目标（本次不做）

1. 不修改三机制函数的判定逻辑本身（只复用，不重写）。
2. 不修改 `max_holding_hours`、`close_ratio` 的原有取值。
3. 不修改 TP1/TP2、动态止盈、移动止损等止盈逻辑（复核平仓后的剩余仓位仍交由既有机制管理）。
4. 不引入新的指标或外部数据源。
5. 不做「复核期内的分批多次砍仓」（复核期只允许平一次 `close_ratio`，见 5.3 R3）。

### 2.5 成功指标（验收口径）

1. 到达 `max_holding_hours` 且未触发 TP1 的持仓，**不再无条件平仓**，而是进入复核期（详见 8.1 AC-1）。
2. 三机制任一判定「不该持有」时，按 `close_ratio` 平仓，平仓原因为 `TIME_STOP_REVIEW`（详见 8.2 AC-3 ~ AC-5）。
3. 三机制全部判定「该持有」时，继续持有并在后续周期持续复核（详见 8.3 AC-8）。
4. 持仓时长达到 `max_holding_hours + max_review_hours` 时，无条件平仓兜底（详见 8.3 AC-7）。
5. `review_enabled: false` 时，行为与 v6.26 及以前完全一致（详见 8.1 AC-2）。

## 三、术语表

| 术语 | 定义（本文约定） |
|------|------------------|
| 时间平仓（time_stop） | 持仓时长达到 `max_holding_hours` 后按 `close_ratio` 比例部分平仓的既有机制 |
| 复核期 | time_stop 到期后、`max_holding_hours + max_review_hours` 之前的时间窗口；期间不再无条件平仓，改为每周期三机制复核 |
| 复核（review） | 每个调度周期对持仓方向执行三机制判定的动作 |
| 该持有 | 三机制全部放行，允许继续持有 |
| 不该持有 | 三机制任一判定风险过高，触发部分平仓 |
| 调度周期 | 策略主循环执行间隔（当前配置为每小时，见 4.1） |
| 三机制 | v6.26 的震荡反转风控三机制：方向一致性对齐、过热保护、波动熔断 |
| 方向一致性对齐 | 机制①：日线均线排列（`EMA21` vs `EMA55`）与持仓方向的一致性校验 |
| 过热保护 | 机制②：乖离率 / RSI 进入极值区（重度过热）的禁开判定 |
| 波动熔断 | 机制③：ATR 短长比突变放大（极端期）的熔断判定 |
| 量价确认 | v6.26 机制③a：价格穿越布林中轨 + 缩量的入场确认信号（**本次不用于持仓复核**，原因见 5.6 R6） |
| 兜底平仓 | 持仓时长达到 `max_holding_hours + max_review_hours` 时的无条件平仓 |
| EMA21 | 周期为 21 的指数移动平均（v6.26 CP-1 新增字段） |
| EMA55 | 周期为 55 的指数移动平均（现有字段） |
| ATR_short / ATR_long | 短周期 ATR（周期 14，现有 `ATR` 字段）/ 长周期 ATR（周期可配，默认 50，现有 `ATR_long` 字段） |
| 乖离率（bias） | `(close - MA) / MA × 100%`，方向敏感（正=价格在均线上方，负=在下方），不使用 `abs()` |
| 极端期 | `ATR_short / ATR_long > spike_ratio` 触发的熔断窗口（per-symbol，跨调度周期保持） |

### 4.2 time_stop 基线（`_check_time_stop`，strategy.py L3906-3955，v6.27 改造后）

> 本节为 v6.27 **改造前的基线逻辑**，作为需求背景；改造后该逻辑保留为 `review_enabled: false` 分支（见 5.1 R1），行号已同步至改造后位置。

现有逻辑（**本次改造的基座**）：

```
1. 守卫：position.tp1_hit 为 True，或 current_quantity <= 0 → return（不检查）
2. 从 grade_risk['time_stop'] 读取 max_holding_hours、close_ratio
   （grade_risk 由 _get_grade_risk(position.grade) 从 risk.signal_levels.<grade> 获取）
3. holding_hours >= max_holding_hours：
   - close_quantity = position.current_quantity * close_ratio
   - 平仓，close_reason="TIME_STOP"
   - 成功后 position.tp1_hit = True（防重复触发）
4. 平仓失败 → 保持持仓状态
```

**注意（实现要点）：** `update_positions()` 当前内部只有 `current_price`，**没有** `indicators` / `klines`。三机制函数需要 `indicators` 与 `klines`，因此复核期的数据获取是本需求的技术依赖（见 9.1 依赖 D1）。

### 4.3 三机制函数（v6.26 已实现，本次只复用）

| 函数 | 位置 | 签名 | 返回语义（False = 拒绝/风险） |
|------|------|------|-------------------------------|

| `_check_overheat_ban` | strategy.py L1715 | `(direction, indicators, klines, ranging_config)` | 重度过热（乖离率超禁开阈值 或 RSI 极值区）→ `(False, reason)` |

| `_check_volume_confirm` | strategy.py L1741 | `(direction, indicators, klines, ranging_config)` | 量价确认（入场专用，**本次不参与持仓复核**） |

### 4.5 平仓原因（close_reason）说明

`close_reason` 为自由字符串（无枚举校验），用于日志、通知（`action=f"CLOSE_{close_reason}"`）、数据库记录。新增 `TIME_STOP_REVIEW` 为合法值，不影响既有 `TP1` / `TP2` / `TRAILING_STOP` / `STOP_LOSS` / `TIME_STOP` 语义。

## 五、功能范围（详细规则）

### 5.1 R1：触发条件（进入复核期）

**前置守卫（维持现状，与 v6.26 及以前完全一致）：**

- `position.tp1_hit == True` → 不进入任何时间平仓/复核逻辑，直接返回（TP1 已触发即不检查 time_stop，见 R5-1）。
- `position.current_quantity <= 0` → 直接返回（无持仓则不触发，见 R5-3）。

**复核期进入条件（同时满足才进入复核期）：**

1. `holding_hours >= max_holding_hours`（持仓时长达到时间平仓阈值）。
2. 配置 `review_enabled == true`（复核制总开关）。

**开关语义：**

- `review_enabled: false` → 完全恢复现状：`holding_hours >= max_holding_hours` 时无条件平 `close_ratio`，`close_reason="TIME_STOP"`（行为与 v6.26 及以前逐字节一致，作为一键回退开关）。
- `review_enabled: true` → 进入复核期，按 R2/R3/R4 执行。

### 5.2 R2：复核判断（每周期执行）

进入复核期后，**每个调度周期（每小时）执行一次复核**。由新增编排函数 `_should_keep_position` 执行，按以下顺序短路判定（任一判定「不该持有」即返回，触发平仓）：

**步骤 1：数据可用性预检（编排层新增，落实「保守」原则）**

复核所需关键指标存在且非 NaN 是执行三机制的前提。任一以下字段缺失、为 NaN、或对应 K 线为空 → 直接判定「**不该持有**」（无法评估风险，不冒险，与 R5-2 一致）：

- `indicators['1d']['EMA21']`、`indicators['1d']['EMA55']`（方向对齐 + 过热所需）
- `indicators['4h']['RSI']`（过热所需）
- `indicators['4h']['ATR']`、`indicators['4h']['ATR_long']`（波动熔断所需）
- `klines['1d']`、`klines['4h']` 数据存在且非空

> 设计说明：三机制函数内部对缺失数据的 fallback 行为不一致（方向对齐缺失→拒绝；过热/波动缺失→放行）。编排层统一预检，可保证「数据缺失→保守平仓」的规则不依赖各机制内部行为，避免歧义。

**步骤 2：机制① 方向一致性对齐**

复用 `_check_direction_alignment(direction=position.direction, indicators, ranging_config)`：

| 持仓方向 | 日线排列 | 判定 |
|----------|----------|------|
| LONG | `EMA21 > EMA55`（多头排列） | 该持有 |
| LONG | `EMA21 < EMA55`（已转空头） | **不该持有**（方向反转） |
| SHORT | `EMA21 < EMA55`（空头排列） | 该持有 |
| SHORT | `EMA21 > EMA55`（已转多头） | **不该持有**（方向反转） |
| 任意 | 均线粘合（`\|EMA21-EMA55\|/EMA55 ≤ stick_threshold_pct`） | **不该持有**（方向不明，保守） |

**步骤 3：机制② 过热保护**

复用 `_check_overheat_ban(direction=position.direction, indicators, klines, ranging_config)`：

- **LONG 持仓**：重度过热（`bias_fast ≥ bias_fast_ban_pct` 或 `bias_slow ≥ bias_slow_ban_pct`，或 `RSI_4h > rsi_extreme_long`）→ **不该持有**（追高风险）。
- **SHORT 持仓**：对称判定（`bias_fast ≤ -bias_fast_ban_pct` 或 `bias_slow ≤ -bias_slow_ban_pct`，或 `RSI_4h < rsi_extreme_short`）→ **不该持有**（追空风险）。
- 仅轻度过热（降级档区间）→ 该持有（轻度过热只作用于入场降级，持仓复核只认「重度过热」档）。

**步骤 4：机制③ 波动熔断**

复用 `_check_volatility_regime(symbol, indicators, ranging_config)`：

- `ATR_short / ATR_long > spike_ratio` 触发极端期，或该 symbol 已处于极端期暂停窗口 → **不该持有**（波动极端）。

> 已知副作用（设计说明）：复核复用 `_check_volatility_regime` 时，若当前触发极端期，会写入 `self.symbol_extreme_pause_until[symbol]`，同时暂停该 symbol 后续震荡反转入场。该副作用与「极端期既不应持有也不应入场」的语义一致，属预期行为，无需规避。

**编排返回：**

- 步骤 1~4 任一判定「不该持有」→ `_should_keep_position` 返回 `(False, reason)`。
- 步骤 1~4 全部放行 → 返回 `(True, "")`（该持有）。

### 5.3 R3：复核结果行为

**判定「不该持有」：**

1. 计算平仓量：`close_quantity = position.current_quantity * close_ratio`（`close_ratio` 为当前持仓等级的配置值，与既有 `TIME_STOP` 平仓口径一致）。
2. 调用 `_close_position(...)`，`close_reason="TIME_STOP_REVIEW"`。
3. 平仓成功后，**结束该持仓的复核期**：置位「复核已完成」标记，后续周期不再对该持仓执行复核；剩余仓位（`1 - close_ratio`）交由动态止盈 / 移动止损管理，**不再反复砍**（见 R5-4）。
4. 平仓失败 → 保持持仓状态与复核状态，下周期重新复核（幂等，不重复计数、不重复触发）。

**判定「该持有」：**

1. 继续持有。
2. 记录日志：含各机制判定明细（机制名、关键指标当前值 vs 阈值、结论）。
3. 下个调度周期再次执行复核（复核状态持续至兜底或平仓完成）。

### 5.4 R4：兜底（资金最终释放）

- 触发条件：`holding_hours >= max_holding_hours + max_review_hours`。
- 动作：**无条件**平 `close_ratio` 比例，`close_reason="TIME_STOP"`（语义：复核期耗尽，回归原时间平仓的强制释放；与 `review_enabled: false` 路径共用同一 reason，保证「到点强制平仓」语义统一）。
- 优先级最高：即使上一周期刚判定「该持有」，只要达到兜底时间线就强制平仓。
- 平仓成功后同样结束复核期（置位标记）。

### 5.5 R5：边界情况（明确约定）

| 编号 | 场景 | 行为约定 |
|------|------|----------|
| R5-1 | 到期时 TP1 已触发 | 不检查 time_stop / 复核（维持现状，`tp1_hit` 守卫，见 R1） |
| R5-2 | 均线无排列 / 指标数据缺失 | 保守判定「不该持有」，到点即平 `close_ratio`（reason=`TIME_STOP_REVIEW`）。无法评估风险时不冒险（见 R2 步骤 1 预检） |
| R5-3 | 复核期动态止盈已平仓 | 无持仓则不再触发（`current_quantity <= 0` 守卫），与既有机制无冲突 |
| R5-4 | 判定不该持有部分平仓后 | 剩余仓位交给动态止盈 / 移动止损管理，不再反复砍（R3 防重复标记） |

### 5.6 R6：量价确认不用于持仓复核（排除原因）

`_check_volume_confirm`（量价确认）**不参与持仓复核**，理由如下：

1. **语义错位**：量价确认是「入场确认信号」，用于验证「反转信号此刻是否成立」（价格穿越布林中轨 + 缩量），回答的是「现在能不能入场」。
2. **持仓中无意义**：持仓阶段该入场信号已被消费，继续用「入场时点确认」衡量「是否该继续持有」逻辑上不成立。
3. **持仓应评估的是环境风险**：持仓阶段「是否该持有」取决于方向是否反转（机制①）、是否重度过热（机制②）、波动是否极端（机制③），即持仓环境风险，而非入场确认。

因此，持仓复核只复用三机制（方向 / 过热 / 波动），不引入量价确认。

## 七、非功能要求

### 7.1 编码规范（硬性约束，必须满足）

1. **禁止硬编码**：`review_enabled`、`max_review_hours`、`max_holding_hours`、`close_ratio` 必须从 `risk.signal_levels.<grade>.time_stop` 读取；三机制阈值必须从 `risk.ranging_strategy` 读取。禁止在代码中写死固定值。
2. **禁止重复代码**：必须复用 `_check_direction_alignment` / `_check_overheat_ban` / `_check_volatility_regime`，**严禁复制三机制逻辑**；新增编排函数 `_should_keep_position` 只做数据预检与顺序编排。
3. **禁止幽灵参数**：`_should_keep_position`、改造后的 `_check_time_stop` 的所有参数必须在函数体内被引用；回调/兼容参数用 `_` 前缀标记。
4. **单函数 ≤ 50 行**、**单行 ≤ 120 字符**；改造后的 `_check_time_stop` 若超长必须拆分。
5. **中文注释**：新增/修改代码的注释、日志输出一律中文；对外函数/变量名可用英文。
6. **异常兜底**：所有指标读取（`EMA21`/`EMA55`/`RSI`/`ATR`/`ATR_long`）需处理缺失、NaN、长度不足、数据为空等边界，禁止裸 `iloc[-1]` 抛异常导致主循环中断；异常应捕获并保守按「数据缺失」处理（见 R2 步骤 1）。

### 7.2 配置一致性

- 新增配置键命名与现有 `time_stop` 块风格一致（snake_case）。
- 每个新增键必须有「合理的默认值 + 中文注释」。
- 新增配置需与 `tuning_overrides/`（如有）不冲突；部署前校验配置合并结果。

### 7.3 性能

- 复核为 O(n) 的指标读取/比值运算，不允许引入多进程/多线程。
- 单个 symbol 单次复核新增耗时控制在毫秒级。
- **数据获取约束**：仅对「已进入复核期」的持仓获取多周期 K 线与计算指标（避免每周期全量拉取）；指标计算必须复用 `TechnicalIndicators.calculate_all()` 及与生产一致的 `atr_long_period`，保证口径统一（见 9.1 依赖 D1）。

### 7.4 可观测性

- 每次进入复核期必须记录日志（含持仓时长、`max_holding_hours`、等级）。
- 每次复核必须记录日志：各机制判定明细（机制名、关键指标当前值 vs 阈值、结论「该持有/不该持有」）。
- `TIME_STOP_REVIEW` 平仓日志必须包含：触发机制、reason、平仓量。
- 兜底平仓日志必须包含「复核期耗尽」标识，与 `review_enabled: false` 路径在日志上可区分。
- 平仓失败必须记录 error 日志并保持持仓状态。

### 7.5 可维护性

- 复核制通过 `review_enabled` 一键开关，`false` 时完整恢复原行为，便于回退与 A/B 对比。
- 复核编排集中在 `_should_keep_position` 单一函数，便于后续增删复核维度。

## 八、验收标准

### 8.1 触发与开关

- [ ] AC-1 构造「持仓时长 ≥ `max_holding_hours`、未触发 TP1、仍有持仓、`review_enabled: true`」→ 不立即平仓，进入复核期，日志含「复核期」。
- [ ] AC-2 `review_enabled: false` → 持仓时长 ≥ `max_holding_hours` 时无条件平 `close_ratio`，`close_reason="TIME_STOP"`，行为与 v6.26 及以前一致。

### 8.2 三机制复核

- [ ] AC-3 方向对齐：LONG 持仓且 `EMA21 < EMA55`（转空头）→ `TIME_STOP_REVIEW` 平 `close_ratio`；SHORT 持仓且 `EMA21 > EMA55`（转多头）→ 同样平仓；方向一致（多头持仓 + 多头排列）→ 该持有。
- [ ] AC-4 方向对齐：均线粘合（`|EMA21-EMA55|/EMA55 ≤ stick_threshold_pct`）→ 判定不该持有，平 `close_ratio`。
- [ ] AC-5 过热保护：LONG 持仓且重度过热（`bias_fast ≥ bias_fast_ban_pct` 或 `bias_slow ≥ bias_slow_ban_pct` 或 `RSI_4h > rsi_extreme_long`）→ 平 `close_ratio`；SHORT 持仓对称判定。
- [ ] AC-6 波动熔断：`ATR_short / ATR_long > spike_ratio` 或该 symbol 已处于极端期 → 判定不该持有，平 `close_ratio`。
- [ ] AC-7 **量价确认不参与**：复核流程中 `_check_volume_confirm` 不被调用（可用 mock/spy 断言验证）。

### 8.3 持有、兜底与防重复

- [ ] AC-8 三机制全部判定「该持有」→ 继续持有，且后续调度周期仍持续复核（验证复核跨周期保持）。
- [ ] AC-9 兜底：持仓时长 ≥ `max_holding_hours + max_review_hours` → 无条件平 `close_ratio`，`close_reason="TIME_STOP"`，日志含「复核期耗尽」。
- [ ] AC-10 防重复：`TIME_STOP_REVIEW` 平仓成功后，后续周期不再对该持仓复核；剩余仓位交由动态止盈/移动止损管理，不重复平仓。

### 8.4 边界情况

- [ ] AC-11 TP1 已触发 → 不检查 time_stop / 复核（维持现状）。
- [ ] AC-12 指标数据缺失（`EMA21`/`EMA55`/`RSI`/`ATR`/`ATR_long`/对应 K 线任一缺失或 NaN）→ 保守判定不该持有，平 `close_ratio`（reason=`TIME_STOP_REVIEW`），且**不抛异常**、不中断主循环。
- [ ] AC-13 无持仓（`current_quantity <= 0`）→ 复核不触发，无冲突。
- [ ] AC-14 `TIME_STOP_REVIEW` 平仓失败 → 保持持仓状态，下周期重新复核，不重复计数、不重复触发。

### 8.5 非功能验收

- [ ] AC-15 新增/修改代码通过「禁止硬编码」「禁止重复代码」「禁止幽灵参数」「单函数 ≤ 50 行」规范检查。
- [ ] AC-16 新增单元测试覆盖：正常用例、边界（NaN/缺失/空/极值/粘合）、每个条件分支、每个异常兜底路径；三机制判定通过 mock 复用真实函数签名验证（确保复用而非复制）。
- [ ] AC-17 `review_enabled: false` 时行为与原逻辑一致（回归测试）。
- [ ] AC-18 复核日志满足 7.4 可观测性要求（含机制明细与阈值对比）。

## 九、依赖与风险

### 9.1 依赖

| 编号 | 依赖 | 说明 |
|------|------|------|
| D1 | `update_positions()` 需要 `indicators` / `klines` 数据源 | 当前 `update_positions()` 仅获取 `current_price`，无指标数据。复核需为「已进入复核期」的持仓获取多周期 K 线并计算指标（复用 `TechnicalIndicators.calculate_all()` + 与生产一致的 `atr_long_period`），或复用/缓存当轮 `analyze()` 已计算的指标（方案详见 CP-2，需架构设计确认） |
| D2 | `risk.ranging_strategy` 三机制配置 | v6.26 已就绪，复核直接复用，无需新增 |
| D3 | 新增持仓状态标记字段 | 用于 `TIME_STOP_REVIEW` 平仓后防止重复复核（方案详见 CP-3） |
| D4 | `close_reason` 自由字符串 | 新增 `TIME_STOP_REVIEW` 无需枚举改造，但需在日志/统计/文档中同步说明 |

### 9.2 风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| 数据获取成本 | 复核期持仓需每小时拉取多周期 K 线并计算指标，有 API 与性能开销 | 仅对已进入复核期的持仓获取；复用公共指标计算函数；指标计算毫秒级 |
| 与动态止盈交互 | `TIME_STOP_REVIEW` 平仓后剩余仓位由动态止盈接管；若复用 `tp1_hit` 标记防重复，可能触发动态止盈 `also_on_tp1: true` 的「TP1 已触发」语义，造成误激活 | 建议新增独立标记字段（如 `time_stop_review_done`），不复用 `tp1_hit`（CP-3） |
| 极端期副作用 | 复核复用 `_check_volatility_regime` 会写入 `symbol_extreme_pause_until`，同时暂停该 symbol 后续震荡反转入场 | 该行为与「极端期不持有也不入场」语义一致，属预期；在代码注释与文档中明确说明 |
| 兜底 reason 语义 | 兜底与 `review_enabled: false` 路径共用 `TIME_STOP` reason，可能无法仅凭 reason 区分 | 兜底日志含「复核期耗尽」标识；评审确认是否需独立 reason（CP-1） |
| 回测口径不一致 | 回测引擎若不同步实现复核制，会导致回测结果与生产偏差 | 回测引擎同步实现复核逻辑，且指标口径与生产一致（同一 `calculate_all`） |
| 复核过度保守 | 数据缺失一律平仓，可能在某些数据暂时缺失场景提前离场 | 「宁可错过不可做错」主基调；数据缺失通常伴随不可评估风险，属预期取舍 |
