# v6.21 动态利润保护机制 -- 取代吊灯止损

本版本引入**动态利润保护机制（Dynamic Profit Protection）**，替代原有的固定 ATR 倍数吊灯止损（Chandelier Exit），解决"利润跑出 10%，回调 5% 才走"的利润回吐问题。基于浮盈百分比和币种波动特性，动态计算移动止损价位，实现"利润越厚，保护越紧"。

| **设计哲学** | 利润越厚，保护越紧；波动越大，宽容越高 |

## 二、问题背景与动机

### 2.1 吊灯止损的固有缺陷

v6.20 及之前版本使用"吊灯止损"（Chandelier Exit）保护利润，其核心逻辑是：

```
止损价 = 最高价 - 固定 ATR 倍数（如 1.5 × ATR）
```

该机制存在以下问题：

| 问题 | 具体表现 | 影响 |
|------|----------|------|
| **固定回撤幅度** | 无论浮盈多少，始终允许固定 ATR 倍数的回撤 | 浮盈 10% 时允许回撤 5%，浮盈 2% 时也允许回撤 5% |
| **利润回吐严重** | 典型场景：浮盈 10%，回调 5% 才触发止损 | 50% 的利润被回吐，用户体验差 |
| **无视浮盈水平** | 大赚和小赚的保护力度完全一致 | 需要区别对待，大赚时收紧保护 |
| **波动率适应性差** | 高波动币种容易被正常波动扫掉，低波动币种保护不足 | 需要根据币种波动特性动态调整 |

### 2.2 典型场景分析

```
场景：BTCUSDT 做多，开仓价 60000，最高涨到 66000（浮盈 10%）
- 吊灯止损（1.5×ATR，ATR≈1500）：止损价 = 66000 - 2250 = 63750
- 从最高点回撤：66000 → 63750，回撤 2250（3.4%），利润回吐 34%
- 实际利润：63750 / 60000 - 1 = 6.25%，而非 10%

期望行为：
- 浮盈 10% 时，只允许回撤 25% 的利润（2.5%），止损价 ≈ 64350
- 实际利润：64350 / 60000 - 1 = 7.25%，多保住 1% 利润
```

### 2.3 解决思路

**动态利润保护**：基于浮盈百分比和币种波动特性，动态计算允许回撤的比例，实现阶梯式收紧保护。

```
核心逻辑链：
实时监控最高价 → 计算浮盈% → 查阶梯确定回撤比例 → 乘以波动率调节因子 → 计算止损价
```

## 三、核心设计

### 3.1 逻辑链条

```
┌─────────────────────────────────────────────────────────────────┐
│                    动态利润保护逻辑链条                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. 实时监控持仓的最高价（做多）或最低价（做空）                │
│     position.highest_price = max(current_price, highest_price)  │
│     position.lowest_price = min(current_price, lowest_price)    │
│                                                                 │
│  2. 计算最高浮盈百分比                                          │
│     做多：(最高价 - 开仓价) / 开仓价                            │
│     做空：(开仓价 - 最低价) / 开仓价                            │
│                                                                 │
│  3. 根据浮盈高低，查阶梯确定允许回撤比例                        │
│     浮盈 < 1.5% → 保本模式（止损=开仓价）                       │
│     1.5% ~ 4% → 允许回撤 50% 利润                              │
│     4.0% ~ 8% → 允许回撤 35% 利润                              │
│     > 8.0%    → 允许回撤 25% 利润                              │
│                                                                 │
│  4. 计算波动率调节因子（ATR% / 历史ATR%中位数）                  │
│     clamp 到 [0.5, 2.0]，缓存 1 小时                            │
│                                                                 │
│  5. 计算动态止损价                                              │
│     做多：止损价 = 参考价 - 每单位利润 × 回撤比例 × 波动调节   │
│     做空：止损价 = 参考价 + 每单位利润 × 回撤比例 × 波动调节   │
│     参考价 = 做多时取最高价（highest_price），做空时取最低价    │
│     （lowest_price），即峰值价格。用峰值计算允许回撤，才能在    │
│     价格回落时锁住已实现利润                                    │
│                                                                 │
│  6. 与固定硬止损取 MAX/MIN                                      │
│     做多：最终止损价 = MAX(动态止损价, 硬止损价)                │
│     做空：最终止损价 = MIN(动态止损价, 硬止损价)                │
│                                                                 │
│  7. 单向移动保护                                                │
│     做多：止损价只能上移（不能下移）                            │
│     做空：止损价只能下移（不能上移）                            │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 回撤阶梯规则

| 浮盈区间 | 回撤系数 | 设计逻辑 | 示例（浮盈 10%） |
|---------|---------|---------|-----------------|
| < 1.5% | 0.0（保本模式） | 刚脱离成本，先保命，止损 = 开仓价 | - |
| 1.5% ~ 4.0% | 0.5 | 利润尚薄，给市场宽松空间，允许回吐一半利润 | 浮盈 3% 时允许回吐 1.5% |
| 4.0% ~ 8.0% | 0.35 | 利润较厚，开始收紧保护，允许回吐约 1/3 | 浮盈 6% 时允许回吐 2.1% |
| > 8.0% | 0.25 | 大赚阶段，极度收紧，只允许回吐 1/4 | 浮盈 10% 时只允许回吐 2.5% |

**与吊灯止损对比**：

| 场景 | 吊灯止损（1.5×ATR） | 动态利润保护 | 改善 |
|------|---------------------|--------------|------|
| 浮盈 3%，ATR=2% | 从最高点回撤 3% | 允许回吐 1.5% | 多保住 1.5% |
| 浮盈 6%，ATR=2% | 从最高点回撤 3% | 允许回吐 2.1% | 多保住 0.9% |
| 浮盈 10%，ATR=2% | 从最高点回撤 3% | 允许回吐 2.5% | 多保住 0.5% |

### 3.3 波动率调节因子

**公式**：
```
波动率调节因子 = 当前币种 ATR% / 历史日线 ATR% 中位数
```

**说明**：

| 要素 | 值 | 说明 |
|------|-----|------|
| 数据源 | 日线 ATR(14) | 使用日线级别计算波动率，避免短期噪声 |
| 历史窗口 | 30 个交易日 | 计算历史 ATR% 中位数 |
| 调节范围 | [0.5, 2.0] | clamp 到该范围，防止极端值 |
| 缓存 TTL | 3600 秒（1 小时） | 避免频繁计算，降低 API 调用 |
| 缓存键 | `base_atr_pct_{symbol}` | 按币种独立缓存 |

**设计逻辑**：
- 高波动币种（ATR% 高于历史中位数）：调节因子 > 1.0，允许更多回撤，避免被正常波动扫掉
- 低波动币种（ATR% 低于历史中位数）：调节因子 < 1.0，收紧保护，减少利润回吐
- 历史中位数作为基准，反映该币种的"正常波动水平"

### 3.4 最终止损价公式

**做多**：
```
最终止损价 = MAX(动态利润保护价, 固定硬止损价)
```

**做空**：
```
最终止损价 = MIN(动态利润保护价, 固定硬止损价)
```

**设计逻辑**：硬止损（1.5 × ATR）作为兜底防线，动态利润保护价在利润较厚时提供更紧的保护，两者取更保护利润的一方。

### 3.5 单向移动保护

| 方向 | 规则 | 说明 |
|------|------|------|
| 做多 | 止损价只能上移，不能下移 | 价格创新高时保护价上移，价格回落时保护价不跟随下移 |
| 做空 | 止损价只能下移，不能上移 | 价格创新低时保护价下移，价格反弹时保护价不跟随上移 |

**实现方式**：
```python
if position.trailing_stop_price is not None:
    if position.direction == 'LONG' and final_stop <= position.trailing_stop_price:
        final_stop = position.trailing_stop_price
    elif position.direction == 'SHORT' and final_stop >= position.trailing_stop_price:
        final_stop = position.trailing_stop_price
```

### 3.6 激活条件

| 激活方式 | 条件 | 说明 |
|---------|------|------|
| 浮盈激活 | 浮盈 >= 1.5% | 达到最小利润阈值，退出保本模式 |
| TP1 激活 | TP1 部分止盈触发 | 即使浮盈 < 1.5%，TP1 触发也激活保护 |
| 永不退出 | 激活后持续有效 | 即使浮盈回落，激活状态不退出 |

**激活逻辑**：
```
激活状态 = 浮盈 >= 1.5% 或 (TP1 已触发 且 also_on_tp1=true)
激活后永不退出 → position.trailing_activated = True
```

### 3.7 做空场景

做空场景的对称处理：

| 维度 | 做多 | 做空 |
|------|------|------|
| 监控价格 | 最高价（highest_price） | 最低价（lowest_price） |
| 浮盈计算 | (最高价 - 开仓价) / 开仓价 | (开仓价 - 最低价) / 开仓价 |
| 止损价计算 | 参考价（最高价）- 允许回撤 | 参考价（最低价）+ 允许回撤 |
| 硬止损方向 | 开仓价 - 1.5×ATR | 开仓价 + 1.5×ATR |
| 最终止损 | MAX(动态价, 硬止损价) | MIN(动态价, 硬止损价) |
| 单向保护 | 只能上移 | 只能下移 |

## 五、核心方法设计

### 5.1 `_check_dynamic_trailing()` 方法

**功能**：检查并执行动态利润保护止损，同步止损价到交易所条件单

**方法签名**：
```python
async def _check_dynamic_trailing(
    self,
    symbol: str,
    position: PositionState,
    current_price: Decimal
) -> None:
```

**流程**：
1. 检查持仓数量 > 0，否则直接返回
2. 调用 `_calculate_dynamic_trailing_stop()` 计算止损价
3. 如果返回 None，说明未激活，直接返回
4. 检查当前价格是否触发止损：
   - 做多：`current_price <= trailing_stop` → 触发
   - 做空：`current_price >= trailing_stop` → 触发
5. 触发时调用 `_close_position()` 平仓，平仓原因为 `TRAILING_STOP`：
   - 平仓前取消交易所上的移动止损条件单（如果有）
6. 未触发时，检查止损价是否改善：
   - 旧止损价 == 新止损价（无改善）→ 直接返回，无需更新交易所条件单
   - 止损价改善（首次设置或向有利方向移动）→ 调用 `_sync_trailing_stop_order()` 同步到交易所

**调用时机**：每个策略周期（每小时）检查所有持仓

### 5.2 `_calculate_dynamic_trailing_stop()` 方法

**功能**：计算动态利润保护止损价

**方法签名**：
```python
async def _calculate_dynamic_trailing_stop(
    self,
    symbol: str,
    position: PositionState,
    current_price: Decimal
) -> Optional[Decimal]:
```

**详细流程**：

```
1. 读取配置
   ├── dt_config = risk_config['dynamic_trailing']
   ├── activation_config = dt_config['activation']
   └── tiers = dt_config['regression_tiers']

2. 计算浮盈百分比（基于参考价，即峰值价格）
   ├── 做多：参考价 = max(highest_price, current_price if no highest_price)
   ├──     浮盈% = (参考价 - entry_price) / entry_price * 100
   ├── 做空：参考价 = min(lowest_price, current_price if no lowest_price)
   ├──     浮盈% = (entry_price - 参考价) / entry_price * 100
   └── 浮亏时计为 0.0
   └── 更新 position.pending_profit_pct

3. 激活判断
   ├── profit_activated = 浮盈% >= min_profit_pct (1.5%)
   ├── tp1_activated = also_on_tp1 && position.tp1_hit
   └── 未激活 && 未激活过 → 返回 None

4. 标记激活
   └── position.trailing_activated = True

5. 保本模式（浮盈 < 1.5% 且 TP1未触发）
   └── stop_price = position.entry_price

6. 正常模式
   ├── 查 tier 确定 retrace_ratio
   ├── vol_adj = await _get_volatility_adjustment()
   ├── 做多：stop_price = 参考价(最高价) - 利润 × retrace_ratio × vol_adj
   └── 做空：stop_price = 参考价(最低价) + 利润 × retrace_ratio × vol_adj
   └── 设计依据：用峰值计算允许回撤，才能在价格回落时锁住已实现利润

7. 硬止损兜底
   ├── hard_stop = entry_price ± 1.5 × ATR
   └── 做多 MAX，做空 MIN

8. 单向移动保护
   ├── 做多：final_stop <= 上次值 → 保持上次值
   └── 做空：final_stop >= 上次值 → 保持上次值

9. 更新 position.trailing_stop_price
└── 返回 final_stop
```

### 5.3 `_get_volatility_adjustment()` 方法

**功能**：计算波动率调节因子

**方法签名**：
```python
async def _get_volatility_adjustment(
    self,
    symbol: str,
    position: PositionState
) -> float:
```

**流程**：

```
1. 检查缓存（cache_ttl = 3600s）
   ├── 命中 → 直接返回缓存值
   └── 未命中 → 继续计算

2. 获取历史日线数据
   ├── lookback = 30 天 + 14(ATR周期) + 10(缓冲)
   └── 数据不足 → 返回 1.0

3. 计算日线 ATR(14) 和 ATR%
   ├── atr_series = TechnicalIndicators.calculate_atr(df, 14)
   └── atr_pct_series = atr_series / close_price

4. 计算历史 ATR% 中位数
   └── base_atr_pct = atr_pct_series.median()

5. 计算当前 ATR%
   └── current_atr_pct = position.atr / entry_price

6. 计算波动率调节因子
   ├── vol_adj = current_atr_pct / base_atr_pct
   └── vol_adj = clamp(vol_adj, 0.5, 2.0)

7. 写入缓存
└── 返回 vol_adj
```

### 5.4 `_sync_trailing_stop_order()` 方法

**功能**：将动态止损价同步到交易所条件单，实现交易所自动触发止损

**方法签名**：
```python
async def _sync_trailing_stop_order(
    self,
    symbol: str,
    position: PositionState,
    trailing_stop: Decimal
) -> None:
```

**设计动机**：

原动态止损仅在软件层面检查，存在以下问题：
1. 需要时刻监控价格，策略进程重启后止损价丢失
2. 策略进程异常退出时，止损保护完全失效
3. 无法在非交易时段（如策略调度周期外）自动触发

通过将动态止损价下到交易所条件单，实现：
- 交易所自动触发止损，无需时刻监控价格
- 策略进程重启后，条件单仍有效，止损保护不丢失
- 止损价改善时自动更新条件单，保持最新保护水平

**流程**：

```
1. 取消旧移动止损条件单（如果存在）
   ├── 调用 binance.cancel_algo_order(symbol, old_order_id)
   ├── 静默处理 -2022（已成交）和 -2011（不存在）错误码
   └── 成功后 position.trailing_stop_order_id = None

2. 首次激活时，取消原有硬止损单（已被动态止损替代）
   ├── 如果 position.stop_loss_order_id 不为 None
   ├── 调用 binance.cancel_algo_order(symbol, stop_loss_order_id)
   └── position.stop_loss_order_id = None

3. 计算止损限价（触发价向不利方向偏移，确保成交）
   ├── 做多：stop_limit_price = trailing_stop × (1 - offset_pct)
   └── 做空：stop_limit_price = trailing_stop × (1 + offset_pct)
   └── offset_pct = 0.002（0.2%，从 config.yaml 读取）

4. 调整精度
   ├── 获取币种 tick_size、step_size、minQty
   └── 对 stop_price 和 stop_limit_price 进行精度调整

5. 下新止损条件单
   ├── 调用 binance.place_conditional_order()
   ├── 参数：symbol, side(SELL/BUY), stop_price, price, quantity,
   │        order_type="STOP", reduce_only=True
   ├── 获取新订单 ID：algoId 或 orderId
   ├── position.trailing_stop_order_id = new_order_id
   ├── 记录条件单到数据库（condition_orders 表）
   └── 记录日志
```

**调用时机**：
- 动态止损价首次激活时（新建条件单）
- 动态止损价向有利方向改善时（取消旧单，新建新单）
- 触发平仓时（取消条件单，避免冗余操作）

**与硬止损单的关系**：

| 阶段 | 交易所状态 | 说明 |
|------|-----------|------|
| 首次激活前 | 硬止损单有效 | 兜底保护 |

## 七、与现有止损系统的关系

### 7.1 不替代，而是叠加

动态利润保护**不替代**原有的固定硬止损（1.5 × ATR），而是**叠加生效**：

```
最终止损价 = 系统取两者中更保护利润的价位
```

| 止损系统 | 依据 | 特点 |
|---------|------|------|
| 固定硬止损 | 开仓价 × ATR 倍数 | 兜底防线，保护本金 |
| 动态利润保护 | 浮盈% × 阶梯回撤 | 利润保护，减少回吐 |
| 最终止损 | MAX(动态, 硬止损) / MIN(动态, 硬止损) | 取最保护利润的值 |

### 7.2 交互场景

```
场景 1：浮盈 2%，硬止损更紧
  - 动态止损价 = 开仓价（保本模式）
  - 硬止损价 = 开仓价 - 1.5×ATR
  - 最终（MAX）= 开仓价（动态止损更保护利润）

场景 2：浮盈 10%，动态止损更紧
  - 动态止损价 = 最高价 × (1 - 2.5% × 波动调节因子)
  - 硬止损价 = 开仓价 - 1.5×ATR
  - 最终（MAX）= 动态止损价（动态止损更保护利润）
```

### 7.3 平仓原因变更

| 旧版本 | v6.21 |
|--------|-------|
| `CHANDLIER` | `TRAILING_STOP` |
| 其他平仓原因 | 不变 |

`close_limit_order.applicable_reasons` 中的 `CHANDLIER` 改为 `TRAILING_STOP`。

### 10.1 回测指标对比

| 指标 | 吊灯止损（v6.20） | 动态利润保护（v6.21） | 预期变化 |

### 10.2 关键验证场景

1. **单边上涨行情**：动态保护应比吊灯止损保留更多利润
2. **震荡上涨行情**：动态保护应避免被正常回撤扫掉
3. **高波动币种**：波动率调节因子应有效防止误扫
4. **低波动币种**：保护应足够紧，减少利润回吐

| 风险 | 说明 | 应对措施 |
|------|------|----------|

## 十三、交易所条件单同步设计

### 13.1 设计背景

动态利润保护机制在 v6.21 初始版本中仅在软件层面计算和检查止损价，存在以下问题：

| 问题 | 影响 | 严重程度 |
|------|------|---------|
| 需时刻监控价格 | 策略调度周期（1小时）外的价格波动无法捕捉 | 高 |
| 进程重启后止损价丢失 | 策略容器重启后，`trailing_stop_price` 重置为 None | 高 |
| 进程异常退出时保护失效 | 程序崩溃后完全失去止损保护 | 严重 |
| 软件层判断延迟 | 从价格触及止损价到策略下次执行存在时间窗口 | 中 |

### 13.2 解决方案

将动态止损价同步到交易所条件单，利用交易所的自动触发能力：

```
┌──────────────┐     ┌──────────────────┐     ┌──────────────────┐
│ 策略计算      │     │ 同步到交易所      │     │ 交易所自动触发    │
│              │     │                  │     │                  │
│ trailing_stop │────→│ cancel_algo(旧)  │     │ 价格触及止损价    │
│  = 64350     │     │ place_cond(新)   │────→│ → 自动平仓        │
│              │     │                  │     │                  │
│ 止损价改善    │     │ 记录到数据库      │     │ 无需策略参与      │
└──────────────┘     └──────────────────┘     └──────────────────┘
```

### 13.3 核心流程

```
策略周期开始
  │
  ├── 计算动态止损价
  │
  ├── 价格触发止损？
  │   ├── 是 → 取消交易所条件单 → 平仓
  │   └── 否 → 继续
  │
  ├── 止损价改善？
  │   ├── 是 → _sync_trailing_stop_order()
  │   │        ├── 取消旧移动止损条件单
  │   │        ├── 取消硬止损单（首次激活时）
  │   │        ├── 计算止损限价（偏移 0.2%）
  │   │        ├── 下新止损条件单（STOP, reduce_only）
  │   │        └── 记录到 condition_orders 表
  │   └── 否 → 跳过，无需更新
  │
  └── 等待下次调度
```

### 13.4 订单类型

| 要素 | 值 | 说明 |
|------|-----|------|
| 订单类型 | `STOP`（止损限价单） | 触发后以限价单进入市场，非市价单 |
| 触发方向 | 做多 SELL，做空 BUY | 与持仓方向相反 |
| 限价偏移 | 触发价向不利方向偏移 0.2% | 确保触发后限价单能成交 |
| Reduce Only | `True` | 仅减仓，不建立新仓位 |

### 13.5 激活时间线

```
时间线：
├── 开仓后：硬止损单有效（兜底保护）
├── 浮盈 >= 1.5% 或 TP1 触发：动态利润保护激活
│   ├── 取消硬止损单（被动态止损替代）
│   └── 创建移动止损条件单
├── 价格继续有利方向移动：动态止损价改善
│   └── 取消旧条件单，创建新条件单
├── 价格回落触发止损价：交易所自动平仓
│   └── 策略下次周期时取消条件单（避免冗余）
└── 手动平仓或止盈：清理条件单
```

### 13.6 进程重启恢复

策略重启后，`_cleanup_position_orders()` 方法负责清理和恢复条件单：

1. 检查所有持仓的 `trailing_stop_order_id`
2. 如果不为 None，取消该条件单（旧进程残留）
3. 策略主循环下一周期会重新计算动态止损价并重新创建条件单

### 13.7 风险与应对

| 风险 | 说明 | 应对措施 |
|------|------|----------|
| 条件单创建失败 | 交易所 API 异常或网络问题 | 记录错误日志，下次周期重试，硬止损单仍有效 |
| 条件单取消失败 | 旧条件单已成交或不存在 | 静默处理 -2022/-2011 错误码，继续创建新单 |
| 条件单与硬止损单冲突 | 同时存在两个止损单 | 首次激活时主动取消硬止损单，避免重复止损 |
| 孤儿条件单 | 策略崩溃后残留的条件单 | `_cleanup_position_orders()` 清理，孤儿单清理任务兜底 |

## 十五、v6.21 BNBUSDT 参数调整与 TRX 移除

本附录记录 v6.21 版本中对 BNBUSDT 交易对的参数调整和 TRXUSDT 交易对的移除，以及 strategy.py 中新增的 per-symbol 震荡市差异化配置逻辑。

### 15.1 背景

随着系统在多币种上的运行，发现 BNBUSDT 的波动特性与 BTCUSDT/ETHUSDT 存在显著差异，原有统一参数导致 BNBUSDT 信号质量偏低。同时 TRXUSDT 交易量过低，流动性不足，决定移除。

### 15.2 BNBUSDT 参数变更表

| 参数 | 原值 | 新值 | 说明 |
|------|------|------|------|
| `adx_min` | 35 | 28 | 降低 ADX 阈值，增加 BNB 信号捕获机会 |
| `vol_ratio_base.S` | 1.8 | 1.4 | 降低 S 级成交量放大倍数，适配 BNB 较低成交量特性 |
| `atr_abs_min` | 0.006 | 0.004 | 降低最小 ATR 绝对值，适配 BNB 较低价格波动 |
| `s_min_score` | 86 | 82 | 降低 S 级最低评分门槛，增加 BNB 高等级信号机会 |

### 15.3 BNBUSDT 新增参数

针对 BNBUSDT 震荡市场景新增独立配置参数，与趋势市参数形成差异化：

| 参数 | 值 | 说明 |
|------|-----|------|
| `ranging_adx_min` | 32 | 震荡市 ADX 阈值，低于趋势市但高于 BNB 基础 ADX 阈值 |
| `ranging_max_daily_trades` | 1 | 震荡市每日最大交易笔数，限制 BNB 震荡交易频率 |
| `ranging_cooldown_hours` | 48 | 震荡市冷却时间，避免频繁交易 |

### 15.4 TRXUSDT 移除

| 项目 | 内容 |
|------|------|
| **移除原因** | TRXUSDT 交易量过低，流动性不足，信号质量不稳定 |
| **影响范围** | config.yaml 中 TRXUSDT 相关配置项全部移除 |
| **后续处理** | 现有 TRXUSDT 持仓正常平仓后不再开新仓 |

### 15.5 strategy.py 中 v6.21 逻辑实现说明

本版本在 strategy.py 中新增了 3 处 per-symbol 震荡市差异化配置逻辑，实现 BNBUSDT 在震荡市场景下的独立参数控制。

#### 15.5.1 第1处：震荡市 ADX 过滤差异化

**位置**：`_check_ranging_entry()` 方法中 ADX 过滤逻辑

**功能**：震荡市入场时，根据币种读取不同的 `ranging_adx_min` 值，而非使用统一 ADX 阈值。

```python
# 伪代码逻辑
if symbol == 'BNBUSDT':
    ranging_adx_min = config['per_symbol']['BNBUSDT']['ranging_adx_min']
else:
    ranging_adx_min = config['ranging']['adx_min']
```

#### 15.5.2 第2处：震荡市每日交易限制差异化

**位置**：频率控制模块中震荡市每日交易数量检查逻辑

**功能**：BNBUSDT 在震荡市模式下使用独立的 `ranging_max_daily_trades` 限制（1 笔/天），而非全局震荡市限制。

```python
# 伪代码逻辑
if symbol == 'BNBUSDT' and strategy_mode == 'RANGING':
    max_daily = config['per_symbol']['BNBUSDT']['ranging_max_daily_trades']
else:
    max_daily = config['ranging']['max_daily_trades']
```

#### 15.5.3 第3处：震荡市冷却期差异化

**位置**：频率控制模块中冷却期检查逻辑

**功能**：BNBUSDT 在震荡市模式下使用独立的 `ranging_cooldown_hours`（48 小时），避免频繁交易。

```python
# 伪代码逻辑
if symbol == 'BNBUSDT' and strategy_mode == 'RANGING':
    cooldown = config['per_symbol']['BNBUSDT']['ranging_cooldown_hours']
else:
    cooldown = config['ranging']['cooldown_hours']
```

### 15.6 设计原则

1. **最小侵入性**：仅对 BNBUSDT 做差异化配置，不影响 BTCUSDT/ETHUSDT 的现有逻辑
2. **配置驱动**：所有差异化参数通过 `per_symbol` 配置节读取，无硬编码
3. **可扩展性**：未来其他币种需要差异化配置时，仅在 `per_symbol` 中新增即可
