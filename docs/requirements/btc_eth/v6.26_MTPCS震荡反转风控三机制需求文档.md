## 二、需求背景与目标

### 2.1 背景

2026-08-19 起，市场出现极端单边暴涨行情：

| 币种 | 涨幅 |
|------|------|
| BTC | +24% |
| ETH | +31% |
| SOL | +32% |
| XRP | +45% |

在此期间，MTPCS 策略在震荡反转（RANGING）模式下反复逆势做空接刀，近半月净亏损约 **-46.8 USDT**。

### 2.2 归因结论

经过复盘，核心原因是「**市场状态判定滞后 + 方向盲**」：

1. **市场状态判定滞后**：`get_market_state` 依赖 ADX、日线均线斜率、布林带宽度等慢指标，在单边行情启动初期仍被判定为 `RANGING`（震荡市），从而进入震荡反转做空逻辑。
2. **方向盲（abs() 缺陷）**：`market_state.py` 的条件 3（价格变化）与条件 4（日线均线斜率）均使用 `abs()` 取绝对值，丢失了涨跌方向。价格单边暴涨 5%+、斜率向上大幅偏离时，绝对值同样放大，反而被误判为「强趋势」，无法为震荡反转提供方向保护。
3. **震荡反转无方向护栏**：`_check_ranging_entry` 仅依赖布林带触轨、RSI 极值、反转 K 线形态三个「局部反转」信号投票决定方向，从不校验日线级别的均线排列方向。在单边多头排列的行情下，布林上轨、RSI 超买、看跌吞没信号会持续触发，导致逆势做空被反复轧空。
4. **追入风险未量化**：没有乖离率/过热度量，价格极端偏离均线时仍照常开仓。
5. **量价/波动未校验**：反转信号没有「跌破布林中轨 + 缩量」的量价确认，也没有波动突变（ATR 短周期环比放大）的「极端期」熔断。

### 2.3 目标

1. 为震荡反转入场增加**方向一致性**护栏：多头排列禁止做空、空头排列禁止做多。
2. 增加**乖离率/过热保护**：价格偏离均线过远或 RSI 进入极值时，对入场信号**降级或禁开**。
3. 增加**量价确认与波动突变熔断**：反转信号须满足「跌破布林中轨 + 缩量」；ATR 短周期相对长周期突变放大时标记「极端期」并暂停震荡反转交易。

### 2.4 非目标（本次不做）

1. 不修改趋势市（STRONG_TREND）路径的 `_check_trend_filter` 逻辑（该路径已有独立方向护栏）。
2. 不修改评分权重体系（`scoring` 各维度权重不变）。
3. 不修改止盈止损、仓位计算、平仓、条件单清理等非入场相关逻辑。
4. 不改动 `MarketState` 枚举结构（仍为 STRONG_TREND / RANGING 二态）。
5. 不引入机器学习或外部数据源。

### 2.5 成功指标（验收口径）

1. 在「日线多头排列（MA21 > EMA55）」行情下，震荡反转路径**绝不产生 SHORT 信号**（详见 7.1）。
2. 在「价格乖离率超过禁开阈值」或「RSI 进入极值」时，相关方向的反转入场被**禁开或降级**（详见 7.2）。
3. 反转信号在「未跌破布林中轨」或「未缩量」时**不成立**（详见 7.3）。
4. 「极端期」标记生效后，震荡反转交易在暂停窗口内**不产生任何入场**（详见 7.4）。

## 五、功能范围（三大机制规则定义）

### 5.1 机制①：方向一致性对齐（Direction Alignment）

#### 5.1.1 规则

震荡反转路径在下单前，**必须**校验日线级均线排列方向：

| 日线排列 | 允许方向 |
|----------|----------|
| 多头排列（`MA21 > EMA55`） | 仅允许 `LONG`，**禁止 `SHORT`** |
| 空头排列（`MA21 < EMA55`） | 仅允许 `SHORT`，**禁止 `LONG`** |
| 均线粘合/无效（`MA21` 或 `EMA55` 缺失或 NaN，或需引入粘合阈值） | 按 CP-2 处理（默认：不开启方向护栏，退化为现状逻辑，仅记录告警日志） |

#### 5.1.2 校验位置与顺序

- 校验发生在 `_check_ranging_entry` 得到候选 `direction` 之后、返回 `(True, direction)` 之前（即三条件投票出方向后，立即校验）。
- 校验通过 → 维持原方向；校验拒绝 → 返回 `(False, "方向一致性拒绝：多头排列禁止做空")`。

#### 5.1.3 涉及指标

- `indicators['1d']['MA21']`（快线）
- `indicators['1d']['EMA55']`（慢线）
- 若 `1d` 指标缺失 → 视为「数据不足」，按 CP-2 的 fallback 处理。

#### 5.1.4 配置项（新增到 `ranging_strategy` 下）

```yaml
ranging_strategy:
  direction_alignment:
    enabled: true
    fast_ma: "EMA21"          # 快线字段名（按 CP-1 新增真正 EMA21 指标字段）
    slow_ma: "EMA55"         # 慢线字段名
    fallback_on_missing: false  # 均线数据缺失时是否放行（true=放行+告警，false=拒绝；按 CP-2 定为 false 保守拒绝）
```

### 5.2 机制②：乖离率 / 过热保护（Overheat Protection）

#### 5.2.1 规则

当追入风险过高时，对震荡反转信号进行**降级或禁开**。分两档：

| 档位 | 触发条件（满足其一） | 动作 |
|------|----------------------|------|
| 轻度过热（预警） | 乖离率超过「降级阈值」但未超「禁开阈值」；或 RSI 进入预警区但未进入极值区 | **信号等级降一档**（如 S→A、A→B、B→C、C→禁开） |
| 重度过热（禁开） | 乖离率超过「禁开阈值」；或 RSI 进入极值区 | **禁止入场** |

#### 5.2.2 乖离率定义

以收盘价相对日线均线计算（方向敏感，**不使用 abs**）：

```
bias_fast = (close_1d - MA21) / MA21 × 100%
bias_slow = (close_1d - EMA55) / EMA55 × 100%
```

方向敏感性约束（关键，避免方向盲）：

- 做多（LONG）时，仅考察**向上过热**：`bias > 0` 且超过阈值才有追高风险。
- 做空（SHORT）时，仅考察**向下过热**：`bias < 0` 且绝对值超过阈值才有追高风险。

> 背景单边暴涨场景：多头排列下做空本应被机制①直接拒绝；机制②的做空方向乖离率保护作为「做多追高」与「非粘合排列下做空接刀」的兜底。

#### 5.2.3 RSI 极值定义

使用 4h RSI：

| 方向 | RSI 极值区（禁开） | RSI 预警区（降级） |
|------|--------------------|--------------------|
| LONG | RSI > `rsi_extreme_long` | `rsi_warn_long` < RSI ≤ `rsi_extreme_long` |
| SHORT | RSI < `rsi_extreme_short` | `rsi_extreme_short` ≤ RSI < `rsi_warn_short` |

#### 5.2.4 降级与 min_grade 的闭环

- 降级动作在 `_determine_grade` 之后、`min_grade` 过滤（strategy.py L845-853）**之前**执行：`grade = self._apply_overheat_downgrade(grade, indicators, direction)`。
- 降级后的 grade 继续参与 `min_grade` 过滤，从而「降级到低于最低允许等级时自然被拒绝」。
- 重度过热禁开动作在 `_check_ranging_entry` 内提前拦截（返回 `False`），无需走评分。

#### 5.2.5 配置项（新增到 `ranging_strategy` 下）

```yaml
ranging_strategy:
  overheat_protection:
    enabled: true
    bias_fast_downgrade_pct: 4.0   # 快线乖离率降级阈值（%）
    bias_fast_ban_pct: 6.0         # 快线乖离率禁开阈值（%）
    bias_slow_downgrade_pct: 6.0   # 慢线乖离率降级阈值（%）
    bias_slow_ban_pct: 9.0         # 慢线乖离率禁开阈值（%）
    rsi_extreme_long: 85           # RSI 极值区上限（禁开做多）
    rsi_extreme_short: 15          # RSI 极值区下限（禁开做空）
    rsi_warn_long: 75              # RSI 预警区上限（降级做多）
    rsi_warn_short: 25             # RSI 预警区下限（降级做空）
    downgrade_enabled: true        # 是否启用降级（false 则预警区也直接禁开）
```

> 上表阈值为**推荐初值**，需评审确认（见 CP-3）。

### 5.3 机制③：量价确认 + 波动突变（Volume Confirm & Volatility Regime）

#### 5.3.1 量价确认规则（Volume Confirmation）

震荡反转信号成立，**必须同时满足**：

1. **价格方向确认**：
   - 做空反转（SHORT）：当前 4h 收盘价**已跌破**布林中轨（`close_4h < BB_Middle`）。
   - 做多反转（LONG）：当前 4h 收盘价**已站上**布林中轨（`close_4h > BB_Middle`）。
2. **缩量确认**：当前 4h 成交量 < `shrink_ratio × Volume_MA(20)`（`shrink_ratio` 默认 1.0，即成交量低于 20 周期均量）。

- 若仅满足其一或均不满足 → 反转信号不成立，返回 `(False, 量价原因)`。
- 数据缺失（无 `volume`、无 `Volume_MA`、无 `BB_Middle`）→ 视为量价确认失败（保守拒绝），按 CP-2 记录告警。

#### 5.3.2 波动突变规则（Volatility Regime / 极端期）

1. 计算 ATR 短周期与长周期比值：

   ```
   atr_ratio = ATR_short / ATR_long
   ```

   - `ATR_short`：短周期 ATR（默认周期 14，复用现有 `ATR` 字段）。
   - `ATR_long`：长周期 ATR（建议周期默认 50，需新增计算或复用更长回溯均值，见 CP-4）。

2. 当 `atr_ratio > spike_ratio`（默认 2.0）时，标记该 symbol 进入「极端期」。

3. 「极端期」期间，**暂停该 symbol 的震荡反转交易**，持续 `pause_bars` 根 4h K 线（默认 12 根，约 2 天），暂停期间直接返回不入场。

4. 极端期标记需有状态记忆（跨调度周期保持），建议沿 `FrequencyController` 的 symbol 级状态字段存储（`extreme_pause_until` 或等效），并随日志输出。

#### 5.3.3 配置项（新增到 `ranging_strategy` 下）

```yaml
ranging_strategy:
  volume_confirm:
    enabled: true
    shrink_ratio: 1.0            # 缩量判定：成交量 < shrink_ratio × Volume_MA(20)
  volatility_regime:
    enabled: true
    atr_long_period: 50          # 长周期 ATR 周期（待确认指标来源，见 CP-4）
    spike_ratio: 2.0             # ATR_short/ATR_long > 该值触发极端期
    pause_bars: 12               # 极端期暂停震荡反转的 4h K 线数
```

### 5.4 三大机制在流程中的执行顺序（总览）

在 RANGING 入场路径中，按以下顺序执行（均为「拒绝即短路」）：

```
_check_ranging_entry 内：
  (0) 现有三条件投票 → 得到候选 direction
  (1) 机制③-波动突变：若处于「极端期」暂停窗口 → 拒绝
  (2) 机制①-方向一致性：校验日线均线排列与 direction 是否一致 → 不一致则拒绝
  (3) 机制③-量价确认：校验「价格穿越布林中轨 + 缩量」→ 不满足则拒绝
  (4) 机制②-重度过热：乖离率或 RSI 进入极值（禁开档）→ 拒绝

_check_ranging_entry 之外（评分后）：
  (5) 机制②-轻度过热：对 grade 降一档（在 _determine_grade 之后、min_grade 过滤之前）
```

> 顺序约定目的：先做零成本的状态判定（极端期、方向、量价），最后做需要附加计算/降级的过热处理，保证拒绝路径开销最小、日志可读。

### 5.6 生效范围

- 三大机制**均作用于 RANGING（震荡）模式下的反转入场路径**。
- 机制②的降级逻辑若未来需覆盖趋势市，另行提需求（本次非目标）。
- 机制③的「极端期」仅暂停震荡反转交易，不暂停趋势市交易（趋势市路径已有 ATR 过滤器与 trend_filter）。

## 六、非功能要求

### 6.1 编码规范（硬性约束，必须满足）

1. **禁止硬编码**：所有阈值、评分、周期、暂停时长、字段名（`fast_ma`/`slow_ma`）必须从 `config.yaml` 读取，禁止在代码中写死固定值。
2. **中文注释**：新增/修改代码的注释、日志输出一律中文；对外函数/变量名可用英文。
3. **禁止重复代码**：乖离率、均线排列、缩量、ATR 突变等计算必须提取为公共函数，不得复制粘贴。若 `get_market_state` 与 `get_market_state_simple` 的斜率/方向逻辑需修复（CP-5），必须共用同一计算函数。
4. **禁止幽灵参数**：新增函数的所有参数必须在函数体内被引用；回调/兼容参数用 `_` 前缀标记。
5. **单函数 ≤ 50 行**、**单行 ≤ 120 字符**：`_check_ranging_entry` 必须拆分。
6. **异常兜底**：所有新指标读取（`MA21`/`EMA55`/`RSI`/`volume`/`BB`/`ATR`）需处理缺失、NaN、长度不足、数据为空等边界，禁止裸 `iloc[-1]` 抛异常导致主循环中断。

### 6.2 配置一致性

- `config.yaml` 新增配置项需与 `tuning_overrides/`（如有）不冲突。
- 配置键命名与现有 `market_state`、`ranging_strategy` 风格保持一致（snake_case）。
- 每个新增配置项必须有一个「合理的默认值 + 中文注释」。

### 6.3 性能

- 三大机制均为 O(n) 的指标读取/比值运算，不允许引入多进程/多线程，不允许在策略容器内执行回测。
- 单个 symbol 单次分析新增耗时控制在毫秒级，不额外拉取 K 线（复用已计算的 `indicators` 与 `klines`）。

### 6.4 可观测性

- 每次「拒绝入场」必须日志化：明确拒绝机制（①/②/③）、当前值 vs 阈值、方向。
- 「极端期」进入与退出必须上报日志（warning 级），并建议接入通知（可选，非强制）。

### 6.5 可维护性

- 三大机制配置集中、模块化，便于后续调优；默认可通过 `enabled: false` 一键独立开关。

## 八、待澄清的边界问题（CP）—— 评审结论（已确认）

> 以下问题已由需求评审确认，作为技术设计与实现的最终基线。

| 编号 | 问题 | 评审结论 | 影响 |
|------|------|----------|------|
| CP-1 | `MA21` 当前为 SMA21，与 `EMA55`（真实 EMA）口径不一致；需求描述中的「EMA21」是否要落地为真正的 EMA21？ | ✅ **新增真正的 `EMA21` 指标字段**，方向对齐与乖离率统一使用 `EMA21`/`EMA55`，`MA` 与 `EMA` 不再混用 | `shared/indicators.py` 需新增 EMA21 计算，回测与生产同步 |
| CP-2 | 均线粘合（`EMA21` 与 `EMA55` 极接近）或均线/量价数据缺失时，方向护栏与量价确认如何处理？ | ✅ **保守拒绝**：均线缺失/NaN/粘合或量价数据缺失时，相关护栏直接拒绝入场（宁可错过不可做错），并记录告警日志 | `fallback_on_missing` 默认值定为 `false`（拒绝）；粘合需定义粘合阈值，粘合时拒绝 |
| CP-3 | 乖离率/RSI 的降级与禁开阈值初值（4.0/6.0/6.0/9.0%、RSI 75/85/25/15）是否认可？ | ✅ 采用推荐初值，后续纳入调优流水线优化 | 直接决定机制②灵敏度 |
| CP-4 | 长周期 ATR 的来源：新增 50 周期 ATR 字段，还是复用现有指标（如 Volume_MA 或日线 ATR）？ | ✅ 在 `calculate_all` 新增 `ATR_long`（周期可配，默认 50），与 `ATR`（14）并列 | 需修改 `shared/indicators.py`，回测与生产同步 |
| CP-5 | `market_state.py` 条件 3/4 的 `abs()` 方向盲，是否纳入本次修复范围？ | ✅ **纳入修复**：条件 4 的日线均线斜率改为「带符号斜率」，条件 3 价格变化同样去除 `abs()` 按方向判断，避免单边暴涨被误判强趋势 | 修复根因，与机制①协同 |
| CP-6 | 机制②「降级一档」是否足以体现追高风险？是否需要「降级 + 仓位乘数削减」双惩罚？ | ✅ 本次仅「降级一档」，仓位乘数不额外削减（复用现有 `position_ratio_mult`） | 决定惩罚力度与实现复杂度 |
| CP-7 | 「极端期」暂停仅暂停某 symbol 还是全市场？ | ✅ 仅暂停触发该条件的 symbol（per-symbol） | 与现状 per-symbol 冷却机制一致 |

## 九、依赖与风险

### 9.1 依赖

- `shared/indicators.py`：可能需新增 `EMA21`（CP-1）、`ATR_long`（CP-4）字段，需确保回测脚本与生产同步。
- `FrequencyController`：极端期状态需复用/扩展 symbol 级状态存储。
- `config.yaml`：新增三大机制配置块。

### 9.2 风险

| 风险 | 说明 | 缓解 |
|------|------|------|
| 过度收紧导致踏空/零成交 | 三机制叠加后震荡反转信号显著减少 | 三机制均支持独立开关；阈值经调优流水线验证；保留「宁可错过不可做错」的主基调 |
| 与回测口径不一致 | 回测 `get_market_state_simple` 未同步修复方向/字段 | CP-5、CP-1/CP-4 落地时同步回测实现，并共用计算函数 |
| 指标缺失导致服务中断 | 新增字段读取失败抛异常 | 6.1 异常兜底，缺失走 fallback，禁止裸 `iloc` |
| 配置文件与 tuning_overrides 冲突 | 调优覆盖文件覆盖了默认阈值 | 部署前校验配置合并结果 |
