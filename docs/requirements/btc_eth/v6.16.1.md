v6.18 相比 v6.16 明显倒退，核心原因是**过度收紧**：ATR%下限从1.0%提到1.2%，S级门槛从85提到88，加上时间止损从48小时延长到72小时，导致交易数锐减（64→27），且剩余信号质量并未显著提升，最终收益近零。

建议**回归 v6.16 的成功配置**，并在其基础上做如下**最小化、精准的调整**，以实现“日均0.8-1.2笔交易、胜率稳定、夏普提升”的目标。

## 针对 v6.16 暴露的两个问题进行精准优化

v6.16 的主要不足：
1. **交易数仍偏低**（64笔/半年 → 日均0.35笔），需要增加到 100-150 笔。
2. **S 级胜率偏低**（54.17%），低于 A 级（100%）和 B 级（59.38%），说明高评分信号质量被高估。

### 优化一：适当放宽 ATR% 上限，增加高波动机会（不改变下限）

- **原**：ATR% ≤ 7.0%
- **新**：ATR% ≤ **8.5%**（放宽，捕捉更强趋势）
- **理由**：高波动区间（7%-8.5%）的信号往往趋势强劲，盈亏比较高，适度参与可增加交易数且不显著降低胜率。
- **风险**：通过波动率目标仓位机制（风险金额下调至 7-8U）和保持 1.8×ATR 止损，风险可控。

### 优化二：微调 S 级评分规则，而非提高门槛

当前 S 级胜率低，是因为**评分权重不合理**（形态权重已高，但趋势权重低可能让趋势末端的信号也被评为 S 级）。改进方案：

- **在评分不变的前提下，增加 S 级额外过滤条件**：
  - 要求 **4 小时 ADX > 25**（确保处于强趋势，而非震荡或末端）
  - 或者要求 **4 小时 MACD 柱状线连续 3 根放大**（趋势加速）
- 保持 S 级最低分 85 不变，这样不会减少 S 级数量，但提升其质量。

### 优化三：放宽成交量要求，增加 B/C 级信号

- **原**：B/C 级不要求放量（已实施）。
- **新**：将 A 级成交量要求从 1.5 倍降至 **1.3 倍**，S 级从 1.5 倍降至 **1.4 倍**。
- **理由**：当前成交量过滤可能过于严格，导致错过放量不明显但形态良好的信号。

### 优化四：缩短冷却期，提高交易频率（可选）

- **原**：同币种冷却 6 小时。
- **新**：同币种冷却 **4 小时**。
- **风险**：若市场快速反转，可能增加连续亏损；但胜率 59% 时影响不大。

## 一、修改 ATR% 上限（放宽至 8.5%）

**文件**：`real_data_backtest_v6.py` 或 `scoring_engine_v6.py`（取决于前置过滤器位置）

**搜索**：`atr_percent > 0.07` 或 `0.07`

**原代码**：
```python

    return False
```

**修改为**：


> 注：若下限也希望放宽到 0.8%，可改为 `atr_percent < 0.008`，但建议保持 1.0% 不变。

## 二、S 级额外过滤（ADX > 25 或 MACD 柱连续放大）

**文件**：`scoring_engine_v6.py`（评分函数或信号确认函数）

**位置**：在确定信号等级（S/A/B/C）之后，对 S 级增加额外条件。

**新增函数**（可放在评分引擎中）：
```python
def is_s_grade_extra_condition(data_4h):
    """
    data_4h: 包含 adx14 和 macd_histogram 列表的字典
    返回 True 表示通过额外过滤
    """
    # 条件1: 4h ADX > 25
    adx = data_4h.get('adx14', [0])[-1]
    if adx > 25:
        return True
    
    # 条件2: MACD 柱状线连续 3 根放大
    hist = data_4h.get('macd_histogram', [])
    if len(hist) >= 3:
        if hist[-1] > hist[-2] > hist[-3]:
            return True
    
    return False
```

**在评分等级分配处调用**：
```python
# 假设已有 score 和 grade
if grade == 'S':
    if not is_s_grade_extra_condition(indicators_4h):
        grade = 'A'   # 降级为 A，不丢弃信号
        # 或者直接跳过该信号：continue
```

> 建议：不满足额外条件时降级为 A 级，而不是完全丢弃。
