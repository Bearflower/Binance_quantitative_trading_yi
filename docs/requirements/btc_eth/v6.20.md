本版本基于 v6.19 进行重大升级，在保留 v6.19 本金保护能力的基础上，新增震荡市策略模块，解决 v6.19"无交易"困境，实现趋势市和震荡市双模式自适应切换。

## 二、核心目标

### 2.1 问题背景

v6.19 成功实现了本金保护（最大回撤 0.15%），但暴露了严重问题：

- 3 个月仅 10 笔交易，月均 3.3 笔
- 总收益率 +0.01%，几乎为零
- 震荡市占据市场大部分时间（约 70%），完全空仓浪费机会
- 资金利用率极低，策略不可持续

### 2.2 解决思路

**双模式策略切换**：

```
市场状态判定
    ├── STRONG_TREND（强趋势市）→ 趋势策略（v6.19 模式）
    │   - 仅 S 级信号开仓
    │   - 大止损、大止盈
    │   - 低频交易
    │
    └── RANGING（震荡市）→ 震荡市策略（新增）
        - 反转信号入场
        - 快进快出、小止损
        - 中等频率交易
```

### 2.3 预期效果

- 交易频率提升至 60-90 笔/季度
- 收益率转正，目标 +3% ~ +5%/季度
- 保持本金保护能力，最大回撤 < 5%
- 趋势市和震荡市都能产生收益

## 三、策略模式切换

### 3.1 市场状态判定（沿用 v6.19）

沿用 v6.19 的 5 条件强趋势市判定逻辑：

| 条件 | 参数 | 说明 |
|------|------|------|
| ADX 强度 | ADX(14) > 35 | 日线级别 |
| 布林带宽度 | BB 宽度 > 7% | 日线 Bollinger Bands (20,2) |
| 价格变化幅度 | 近 5 日价格变化 > 5% | 绝对值 |
| EMA21 斜率 | 日线 EMA21 斜率 > 0.15% | 最近 5 根日线线性回归 |
| 4h K 线一致性 | 连续 3 根 4h K 线收盘在 EMA21 同侧 | 短期趋势方向一致 |

5 条件全部满足 → STRONG_TREND，否则 → RANGING。

### 3.2 模式切换逻辑

```python
def get_market_state_behavior(market_state: str) -> dict:
    """
    根据市场状态返回对应的策略行为配置
    
    参数:
        market_state: 'STRONG_TREND' 或 'RANGING'
    
    返回:
        策略行为配置字典
    """
    if market_state == 'STRONG_TREND':
        return {
            'mode': 'trend',
            'allowed_signals': ['S'],
            'strategy': 'trend_following',
            'description': '强趋势市：仅 S 级信号开仓，大止损大止盈',
        }
    else:
        return {
            'mode': 'ranging',
            'allowed_signals': ['S', 'A', 'B'],
            'strategy': 'mean_reversion',
            'description': '震荡市：反转信号入场，快进快出',
        }
```

### 3.3 两种模式对比

| 维度 | 趋势策略（STRONG_TREND） | 震荡市策略（RANGING） |
|------|--------------------------|------------------------|
| 入场逻辑 | 趋势跟随，S 级信号 | 均值回归，反转信号 |
| 止损 | 1.5 × ATR | 2.0 × ATR |
| 止盈 | 4.0 × ATR (TP1) / 6.0 × ATR (TP2) | 4.0 × ATR |
| 持仓时间 | 数小时至数天 | 数分钟至数小时 |
| 杠杆 | 5 倍 | 3 倍 |
| 每日最大交易 | 1 笔 | 10 笔 |
| 冷却期 | 72 小时 | 3 小时 |

## 四、震荡市入场条件

### 4.1 入场信号体系（投票制：多数决，v6.22 正式实现）

震荡市策略采用**投票制入场**，三个条件各自投票做多或做空，取多数方向入场：

| 序号 | 条件 | 参数 | 投票方向 |
|------|------|------|----------|
| 1 | 价格触及布林带轨 | 距上/下轨 ≤ 5% | 触及下轨投做多，触及上轨投做空 |
| 2 | RSI 超买超卖 | RSI(14) > 80 做空 / < 20 做多 | RSI 超卖投做多，超买投做空 |
| 3 | 反转 K 线形态 | 吞没形态（Bullish/Bearish Engulfing） | 看涨吞没投做多，看跌吞没投做空 |

**判定规则**：
- `long_votes > short_votes` -> 做多
- `short_votes > long_votes` -> 做空
- `long_votes == short_votes`（含同时为 0）-> 拒绝入场

> 注意：v6.22 实际实现为投票制（多数决），而非 v6.20 设计文档中的"至少满足 2 个条件"。1 个条件也可触发入场（只要方向一致），但多条件同时触发时按多数方向决定。

### 4.2 入场条件判定逻辑（v6.22 实际实现）

```python
def _check_ranging_entry(self, symbol: str, indicators: Dict, klines: Dict) -> Tuple[bool, str]:
    """
    震荡市入场条件检查（v6.22 正式实现）
    
    震荡市使用反转信号入场，三个条件各自投票：
    1. BB触轨：价格触及布林带上轨（做空）或下轨（做多）
    2. RSI极端：RSI超买做空（>80），超卖做多（<20）
    3. 反转K线形态：吞没形态
    
    取多数条件一致的方向入场，若方向不一致则拒绝。
    
    Args:
        symbol: 交易对
        indicators: 技术指标字典
        klines: K线数据字典
    
    Returns:
        (是否通过, 方向或失败原因)
    """
    ranging_config = self.risk_config.get('ranging_strategy', {})
    if not ranging_config.get('enabled', True):
        return False, "震荡市策略未启用"
    
    try:
        entry_conditions = ranging_config.get('entry_conditions', {})
        df_4h = pd.DataFrame(klines['4h'])
        close_4h = float(df_4h['close'].iloc[-1])
        long_votes = 0
        short_votes = 0
        conditions_met = []
        
        # === 条件1: BB触轨 ===
        if entry_conditions.get('bb_touch', True):
            bb_upper = float(indicators['4h']['BB_Upper'].iloc[-1])
            bb_lower = float(indicators['4h']['BB_Lower'].iloc[-1])
            bb_range = bb_upper - bb_lower
            if bb_range > 0:
                threshold = entry_conditions.get('bb_touch_threshold', 0.05)
                dist_to_lower = (close_4h - bb_lower) / bb_range
                dist_to_upper = (bb_upper - close_4h) / bb_range
                
                if dist_to_lower <= threshold:
                    long_votes += 1
                    conditions_met.append(f"BB下轨触轨({dist_to_lower*100:.1f}%)")
                if dist_to_upper <= threshold:
                    short_votes += 1
                    conditions_met.append(f"BB上轨触轨({dist_to_upper*100:.1f}%)")
        
        # === 条件2: RSI极端 ===
        if entry_conditions.get('rsi_extreme', True):
            rsi = float(indicators['4h']['RSI'].iloc[-1])
            if pd.notna(rsi):
                oversold = entry_conditions.get('rsi_oversold', 20)
                overbought = entry_conditions.get('rsi_overbought', 80)
                if rsi < oversold:
                    long_votes += 1
                    conditions_met.append(f"RSI超卖({rsi:.1f}<{oversold})")
                if rsi > overbought:
                    short_votes += 1
                    conditions_met.append(f"RSI超买({rsi:.1f}>{overbought})")
        
        # === 条件3: 反转K线形态 ===
        if entry_conditions.get('reversal_pattern', True):
            if len(df_4h) >= 2:
                prev_open = float(df_4h['open'].iloc[-2])
                prev_close = float(df_4h['close'].iloc[-2])
                curr_open = float(df_4h['open'].iloc[-1])
                curr_close = float(df_4h['close'].iloc[-1])
                
                # 看涨吞没：前阴后阳，后实体包住前实体
                if (prev_close < prev_open and
                    curr_close > curr_open and
                    curr_open <= prev_close and
                    curr_close >= prev_open):
                    long_votes += 1
                    conditions_met.append("看涨吞没")
                
                # 看跌吞没：前阳后阴，后实体包住前实体
                if (prev_close > prev_open and
                    curr_close < curr_open and
                    curr_open >= prev_close and
                    curr_close <= prev_open):
                    short_votes += 1
                    conditions_met.append("看跌吞没")
        
        # === 判定方向（多数决） ===
        if long_votes == 0 and short_votes == 0:
            return False, f"无震荡入场条件满足"
        
        if long_votes > short_votes:
            return True, 'LONG'
        elif short_votes > long_votes:
            return True, 'SHORT'
        else:
            return False, f"方向不一致(long={long_votes}, short={short_votes})"
    except Exception as e:
        return False, f"震荡入场检查异常: {str(e)}"
```

### 4.3 短线趋势过滤（一票否决）

即使震荡市入场条件满足，如果存在强短期趋势，**拒绝反向信号**：

```python
def check_short_term_trend_filter(klines_1h, signal_direction: str) -> bool:
    """
    1h EMA21 斜率检查
    
    如果 1h EMA21 斜率 > 0.8 × ATR，视为强短期趋势
    拒绝与该趋势方向相反的信号
    """
    ema21 = calculate_ema(close_prices, period=21)
    atr = calculate_atr(klines_1h, period=14)
    
    # 最近 5 根 1h K 线的 EMA21 线性回归斜率
    slope = linear_regression_slope(ema21[-5:])
    
    if abs(slope) > 0.8 * atr:
        # 强趋势存在
        if slope > 0 and signal_direction == 'SHORT':
            return False, "1h EMA21 强上升趋势，拒绝做空信号"
        if slope < 0 and signal_direction == 'LONG':
            return False, "1h EMA21 强下降趋势，拒绝做多信号"
    
    return True, ""
```

## 五、震荡市退出条件

### 5.1 退出条件汇总

| 退出条件 | 参数 | 说明 |
|----------|------|------|
| 止损 | 2.0 × ATR(14) | 基于 1h ATR 计算 |
| 止盈 | 4.0 × ATR(14) | 达到止盈目标全平 |
| BB 中轨触及 | 价格回归 BB 中轨 | 均值回归完成，平仓 |
| RSI 回归中性 | 做多 RSI > 55，做空 RSI < 45 | 超买超卖修复 |
| 时间止损 | 24 小时 | 持仓超过 24 小时未达目标自动平仓 |

### 5.2 退出逻辑

```python
def check_ranging_exit(position, current_price, klines_1h) -> tuple[bool, str]:
    """
    震荡市持仓退出检查
    
    返回:
        (是否平仓, 平仓原因)
    """
    atr = calculate_atr(klines_1h, period=14)
    close_prices = [k.close for k in klines_1h]
    
    # 1. 止损检查
    if position.direction == 'LONG':
        stop_price = position.entry_price - 2.0 * atr
        if current_price <= stop_price:
            return True, "止损触发：价格跌破 2.0×ATR 止损线"
    else:
        stop_price = position.entry_price + 2.0 * atr
        if current_price >= stop_price:
            return True, "止损触发：价格突破 2.0×ATR 止损线"
    
    # 2. 止盈检查
    if position.direction == 'LONG':
        tp_price = position.entry_price + 4.0 * atr
        if current_price >= tp_price:
            return True, "止盈触发：达到 4.0×ATR 止盈目标"
    else:
        tp_price = position.entry_price - 4.0 * atr
        if current_price <= tp_price:
            return True, "止盈触发：达到 4.0×ATR 止盈目标"
    
    # 3. BB 中轨触及
    bb_upper, bb_mid, bb_lower = calculate_bollinger_bands(close_prices)
    if position.direction == 'LONG' and current_price >= bb_mid:
        return True, "BB 中轨触及：价格回归中轨，做多平仓"
    if position.direction == 'SHORT' and current_price <= bb_mid:
        return True, "BB 中轨触及：价格回归中轨，做空平仓"
    
    # 4. RSI 回归中性
    rsi = calculate_rsi(close_prices, period=14)
    if position.direction == 'LONG' and rsi > 55:
        return True, "RSI 回归中性：超卖修复完成"
    if position.direction == 'SHORT' and rsi < 45:
        return True, "RSI 回归中性：超买修复完成"
    
    # 5. 时间止损
    hours_held = (datetime.now() - position.entry_time).total_seconds() / 3600
    if hours_held > 24:
        return True, "时间止损：持仓超过 24 小时"
    
    return False, ""
```

## 六、震荡市评分体系

### 6.1 评分维度（3 维度，总分 100，v6.22 正式实现）

震荡市评分与趋势市不同，更侧重形态质量和动量。`_calculate_score()` 方法在 v6.22 中新增 `market_state` 参数，根据市场状态自动选择权重：

| 维度 | 趋势市权重 | 震荡市权重 | 评分方式 |
|------|-----------|-----------|----------|
| 趋势一致性 | 25% | 15% | EMA21 价格位置和方向一致性 |
| 形态质量 | 50% | 60% | 反转形态质量、布林带位置、RSI 极端程度 |
| 动量确认 | 25% | 25% | MACD 柱线方向、成交量确认 |

**方法签名**（v6.22）：
```python
def _calculate_score(self, indicators: Dict, klines: Dict, market_state: str = 'STRONG_TREND') -> float:
```
- `market_state='RANGING'` 时从 `ranging_strategy.scoring_weights` 读取权重
- `market_state='STRONG_TREND'` 时从 `scoring_config.weights` 读取权重

### 6.2 评分映射

| 等级 | 总分要求 | 仓位系数 | 杠杆 |
|------|----------|----------|------|
| S | ≥ 85 | 30% | 3 倍 |
| A | ≥ 75 | 20% | 3 倍 |
| B | ≥ 65 | 10% | 2 倍 |
| C | < 65 | 拒绝 | - |

> 注意：震荡市信号等级独立于趋势市信号等级，两者使用不同的评分体系和阈值。

## 七、频率控制（双轨独立计数）

### 7.1 设计理念

趋势市和震荡市使用**独立的频率计数器**，互不影响。趋势市的高质量信号不应被震荡市的频率限制所阻止，反之亦然。

### 7.2 频率控制参数

| 参数 | 趋势策略 | 震荡市策略 |
|------|----------|------------|
| 每日最大交易数 | 1 笔 | 10 笔 |
| 冷却期 | 72 小时 | 3 小时 |
| 连续亏损暂停 | 3 笔暂停 2 天 | 5 笔暂停 1 天 |
| 每日最大亏损 | 3% 总资金 | 5% 总资金 |

### 7.3 频率控制实现

```python
class DualFrequencyController:
    """双模式频率控制器"""
    
    def __init__(self):
        self.trend_counter = FrequencyCounter(
            max_daily=1,
            cooldown_hours=72,
            max_consecutive_losses=3,
            pause_days=2,
            daily_loss_limit=0.03,
        )
        self.ranging_counter = FrequencyCounter(
            max_daily=10,
            cooldown_hours=3,
            max_consecutive_losses=5,
            pause_days=1,
            daily_loss_limit=0.05,
        )
    
    def _check_ranging_frequency(self, symbol: str) -> tuple[bool, str]:
        """
        检查震荡市频率限制
        
        返回:
            (是否允许交易, 拒绝原因)
        """
        return self.ranging_counter.can_trade(symbol)
```

## 十三、v6.20.3 全量委托单（限价单）改造

### 13.1 版本信息

| 项目 | 内容 |
|------|------|
| **版本号** | v6.20.3 |
| **发布日期** | 2026-06-25 |
| **前置版本** | v6.20（震荡市生存版） |
| **核心目标** | 将所有市价单改为限价单，降低手续费和滑点风险，提升订单执行可控性 |

### 13.2 改造背景

v6.20 及之前版本中，策略中部分订单类型使用了市价单：

- **止损单**：使用 `STOP_MARKET`（止损市价单），触发后以市价成交
- **止盈单**：使用 `TAKE_PROFIT_MARKET`（止盈市价单），触发后以市价成交
- **平仓单**：部分场景使用 `MARKET`（市价单），存在滑点风险

市价单的问题：
1. **手续费高**：taker 费率 0.05%，是 maker 费率 0.02% 的 2.5 倍
2. **滑点不可控**：极端行情下成交价格可能偏离预期
3. **降级逻辑复杂**：之前的限价单超时降级为市价单的逻辑增加了代码复杂度

### 13.3 改造内容

#### 13.3.1 止损单改造：`STOP_MARKET` -> `STOP`

将止损单从止损市价单改为止损限价单：

```python
# 旧：STOP_MARKET，触发后以市价成交
await self.binance.place_conditional_order(
    symbol=symbol,
    side=stop_side,
    stop_price=signal['initial_stop_loss'],
    quantity=signal['quantity'],
    order_type="STOP_MARKET"
)

# 新：STOP，触发后以限价成交
await self.binance.place_conditional_order(
    symbol=symbol,
    side=stop_side,
    stop_price=signal['initial_stop_loss'],
    price=self._calculate_stop_limit_price(  # 新增限价
        signal['direction'], signal['initial_stop_loss']
    ),
    quantity=signal['quantity'],
    order_type="STOP"
)
```

#### 13.3.2 止盈单改造：`TAKE_PROFIT_MARKET` -> `TAKE_PROFIT`

将止盈单从止盈市价单改为止盈限价单：

```python
# 旧：TAKE_PROFIT_MARKET，触发后以市价成交
await self.binance.place_conditional_order(
    symbol=symbol,
    side=stop_side,
    stop_price=signal['tp1_price'],
    quantity=signal['quantity'],
    order_type="TAKE_PROFIT_MARKET"
)

# 新：TAKE_PROFIT，触发后以限价成交
await self.binance.place_conditional_order(
    symbol=symbol,
    side=stop_side,
    stop_price=signal['tp1_price'],
    price=self._calculate_tp_limit_price(  # 新增限价
        signal['direction'], signal['tp1_price']
    ),
    quantity=signal['quantity'],
    order_type="TAKE_PROFIT"
)
```

#### 13.3.3 平仓单改造：全部 `MARKET` -> `LIMIT`

统一所有平仓场景使用限价单，覆盖所有平仓原因：

| 平仓原因 | 旧订单类型 | 新订单类型 |
|----------|-----------|-----------|
| TP1 | 限价单 | 限价单（不变） |
| TP2 | 限价单 | 限价单（不变） |
| CHANDLIER | 市价单 | **限价单** |
| TIME_STOP | 市价单 | **限价单** |
| STOP_LOSS | 市价单 | **限价单** |
| EXTREME | 市价单 | **限价单** |
| LIQUIDATION | 市价单 | **限价单** |
| LIQUIDATION_REDUCE | 限价单 | 限价单（不变） |

#### 13.3.4 取消市价降级逻辑，改为超时重试机制

v6.20.3 之前，限价单超时未成交会自动降级为市价单。此版本完全移除降级逻辑，改为：

1. **轮询等待**：下限价单后，轮询检查订单是否成交（默认 10 秒超时）
2. **重新下限价单**：超时未成交则取消旧单，重新下限价单（最多重试 3 次）
3. **不再降级为市价单**：所有重试均使用限价单

```python
# 轮询等待成交，超时后重试（不再降级为市价单）
timeout = close_limit_config.get('timeout_seconds', 10)
poll_interval = close_limit_config.get('poll_interval_seconds', 2)
max_retries = close_limit_config.get('max_retries', 3)
retry_interval = close_limit_config.get('retry_interval_seconds', 2)

elapsed = 0
filled = False

while elapsed < timeout:
    await asyncio.sleep(poll_interval)
    elapsed += poll_interval
    
    # 检查是否已成交
    open_orders = await self.binance.get_open_orders(symbol)
    order_still_open = any(
        str(o.get('orderId')) == str(order_result['orderId'])
        for o in open_orders
    )
    if not order_still_open:
        filled = True
        break

# 超时未成交，重试（非降级）
if not filled:
    for retry in range(max_retries):
        # 取消旧单，重新下限价单
        ...
```

### 13.4 新增辅助方法

#### 13.4.1 `_calculate_stop_limit_price`

计算止损限价单的限价价格。在止损触发价基础上，向不利方向偏移一定比例，确保止损限价单能够被市场接受。

```python
def _calculate_stop_limit_price(self, direction: str, stop_price: Decimal) -> Decimal:
    """
    计算止损限价（v6.20.3 新增）
    
    做多止损（SELL）：限价 = 触发价 * (1 - 偏移比例)
    做空止损（BUY）：限价 = 触发价 * (1 + 偏移比例)
    """
    config = self.risk_config.get('stop_limit_order', {})
    offset_pct = Decimal(str(config.get('offset_pct', 0.002)))
    if direction == 'LONG':
        return stop_price * (Decimal('1') - offset_pct)
    else:
        return stop_price * (Decimal('1') + offset_pct)
```

#### 13.4.2 `_calculate_tp_limit_price`

计算止盈限价单的限价价格。在止盈触发价基础上，向不利方向偏移一定比例。

```python
def _calculate_tp_limit_price(self, direction: str, tp_price: Decimal) -> Decimal:
    """
    计算止盈限价（v6.20.3 新增）
    
    做多止盈（SELL）：限价 = 触发价 * (1 - 偏移比例)
    做空止盈（BUY）：限价 = 触发价 * (1 + 偏移比例)
    """
    config = self.risk_config.get('tp_limit_order', {})
    offset_pct = Decimal(str(config.get('offset_pct', 0.0015)))
    if direction == 'LONG':
        return tp_price * (Decimal('1') - offset_pct)
    else:
        return tp_price * (Decimal('1') + offset_pct)
```

## 十五、v6.20.4 持仓保护机制

### 15.1 版本信息

| 项目 | 内容 |
|------|------|
| **版本号** | v6.20.4 |
| **发布日期** | 2026-06-29 |
| **前置版本** | v6.20.3（全量委托单限价单改造） |
| **核心目标** | 在策略进程重启后，自动检测并补全缺失的止损止盈保护单 |

### 15.2 问题背景

在 v6.20.3 运行过程中发现以下问题：

1. **进程重启后止损止盈单丢失**：当策略容器重启时，内存中的持仓状态（含条件单 ID）全部丢失，无法追踪现有持仓的保护单状态
2. **Binance API 兼容性**：Binance 已废弃条件单查询 API（返回 404），无法通过查询 API 验证保护单是否存在
3. **手动补单操作复杂**：运维人员需要手动计算止损止盈价格并重新下单，容易出错

典型表现：
- BTCUSDT 止损单已触发并消耗后，策略重启无法自动重新创建止损单
- XRPUSDT、TRXUSDT 为旧版本（v6.20 之前）开仓，从未创建过条件单
- 策略重启后无法感知到现有持仓缺少保护单

### 15.3 解决方案

#### 15.3.1 总体设计

```
策略启动
    ├── 清理孤儿条件单（cleanup_orphan_algo_orders）
    │   └── 扫描并删除非当前持仓条件单（兜底清理）
    │
    ├── 加载持仓保护（_ensure_position_protection）
    │   ├── 获取交易所当前持仓
    │   ├── 过滤非策略管理币种
    │   ├── 检查已有持仓记录的条件单ID完整性
    │   ├── 计算 ATR、止损价、止盈价
    │   └── 对缺少保护单的持仓自动补单
    │
    └── 策略切换正常循环
```

#### 15.3.2 持仓保护流程

```python
async def _ensure_position_protection(self):
    """确保持仓有止损止盈保护单（v6.20.4）"""
    
    # 1. 获取交易所当前持仓
    exchange_positions = await self.binance.get_position()
    
    # 2. 只处理本策略管理的币种
    managed_symbols = set(self.symbols)
    
    for pos in exchange_positions:
        symbol = pos.get('symbol', '')
        direction = 'LONG' if position_amt > 0 else 'SHORT'
        
        # 3. 检查该持仓是否已在 self.positions 中且有关联条件单
        existing_pos = self.positions.get(symbol)
        has_stop = existing_pos and existing_pos.stop_loss_order_id
        has_tp = existing_pos and existing_pos.tp1_order_id
        if has_stop and has_tp:
            # 已有完整保护单，跳过
            continue
        
        # 4. 获取价格和 ATR
        current_price = await self._get_current_price(symbol)
        # 计算 ATR（支持 Series 转标量 + 异常值保护）
        atr = self._calculate_atr(symbol, current_price)
        
        # 5. 下限价止损单 + 下限价止盈单
        stop_loss_order = await self.binance.place_conditional_order(
            ..., order_type="STOP"          # 限价止损单
        )
        tp1_order = await self.binance.place_conditional_order(
            ..., order_type="TAKE_PROFIT"   # 限价止盈单
        )
        
        # 6. 更新持仓状态（创建或更新）
        self.positions[symbol] = updated_position
```

#### 15.3.3 关键设计要点

| 设计要点 | 说明 |
|----------|------|

## 十六、v6.21 双轨频率控制改造

### 16.1 版本信息

| 项目 | 内容 |
|------|------|
| **版本号** | v6.21 |
| **发布日期** | 2026-06-29 |
| **前置版本** | v6.20.4（持仓保护机制） |
| **核心目标** | 废除 v6.20 旧版双类设计，在单 `FrequencyController` 中实现趋势/震荡市独立计数 + 单币种差异化限制 |

### 16.2 问题背景

v6.20 文档设计了 `DualFrequencyController`（双模式频率控制器），实际实现是直接在 `FrequencyController` 基础上改造，但存在以下问题：

1. **原始全局计数未按市场状态区分**：`max_daily_total_trades: 1` 对所有市场状态一视同仁，趋势市和震荡市共享一个计数池
2. **震荡市频率检查独立于主流程**：通过 `_check_ranging_frequency()` 方法单独检查，未统一到 `can_trade()`
3. **单币种差异化配置未生效**：`symbol_config` 中的 `max_daily_trades` 未在 `can_trade()` 中被消费
4. **用户澄清频率限制规则**：确认全市场每日上限 1 笔是全局限制，而非单币种独立

### 16.3 解决方案

#### 16.3.1 设计变更

| 维度 | v6.20（旧设计） | v6.21（新实现） |
|------|-----------------|-----------------|
| 计数器 | 全局单 `daily_trades` 字典 | 双轨 `daily_trades_trend` + `daily_trades_ranging` |
| 全局上限 | `max_daily_total_trades: 1` | 从 `market_state.behaviors` 按状态读取 |
| 单币种上限 | 未消费 | 从 `symbol_config` 读取，优先覆盖全局上限 |
| 冷却期 | 统一 `symbol_cooldown_hours: 72` | 震荡市专用 `ranging_symbol_cooldown_hours: 3h` |
| 入口统一 | `can_trade()` 无 market_state 参数 | `can_trade(symbol, current_time, market_state)` |
| 持久化 | 仅 `daily_trade_count` | 新增 `daily_trade_count_trend` + `daily_trade_count_ranging` |

#### 16.3.3 双轨计数器实现

```python
class FrequencyController:
    """频率控制器 - v6.21 双轨计数器"""
    
    def __init__(self, config, risk_config=None, ...):
        self.config = config                    # frequency_control 子配置
        self.risk_config = risk_config or {}    # 完整风险配置（含 market_state、symbol_config）
        
        self.daily_trades_trend: Dict[str, int] = {}     # 趋势市每日计数
        self.daily_trades_ranging: Dict[str, int] = {}   # 震荡市每日计数
        self.daily_trades: Dict[str, int] = {}           # 向后兼容计数器
        # ... 其余状态不变
    
    def can_trade(self, symbol, current_time, market_state=None):
        """检查是否可以交易（v6.21 双轨）"""
        
        # 1. 根据 market_state 选择计数器
        if market_state == 'STRONG_TREND':
            counter = self.daily_trades_trend
        elif market_state == 'RANGING':
            counter = self.daily_trades_ranging
        else:
            counter = self.daily_trades  # 向后兼容
        
        # 2. 读取全局上限（从 market_state.behaviors）
        state_config = self.risk_config['market_state']['behaviors'][market_state]
        global_limit = state_config['max_daily_trades']
        
        # 3. 单币种差异化覆盖（从 symbol_config）
        symbol_limit = self.risk_config['symbol_config'].get(symbol, {}).get('max_daily_trades')
        daily_limit = symbol_limit if symbol_limit is not None else global_limit
        
        # 4. 检查计数是否已达上限
        if counter[today] >= daily_limit:
            return False, f"{market_state}已达每日上限{daily_limit}笔"
        
        # 5. 检查单品种每日上限
        if self.symbol_daily_trades[symbol][today] >= self.config['max_daily_symbol_trades']:
            return False, f"{symbol}已达每日最大交易数..."
        
        # 6. 冷却期检查（按市场状态区分）
        if market_state == 'RANGING':
            cooldown_hours = state_config['ranging_symbol_cooldown_hours']
        else:
            cooldown_hours = self.config['symbol_cooldown_hours']
        # ... 冷却期比较逻辑
        
        return True, "可以交易"
    
    async def record_trade(self, symbol, current_time, market_state=None, pnl=None):
        """记录交易（v6.21 双轨递增）"""
        
        if market_state == 'STRONG_TREND':
            self.daily_trades_trend[today] += 1
        elif market_state == 'RANGING':
            self.daily_trades_ranging[today] += 1
        else:
            self.daily_trades[today] += 1  # 向后兼容
        
        # ... 品种计数、冷却期、盈亏处理
        await self._save_state(symbol)
```

#### 17.3.2 `_check_ranging_entry()` 方法：投票制入场（约 130 行）

新增完整的震荡市入场条件检查方法，实现三个条件的投票制判定：

| 条件 | 投票逻辑 | 数据源 |
|------|----------|--------|
| BB 触轨 | 距下轨 ≤ 5% 投做多，距上轨 ≤ 5% 投做空 | 4h 布林带 |
| RSI 极端 | RSI < 20 投做多，RSI > 80 投做空 | 4h RSI(14) |

```python
    sl_atr_mult = ranging_risk.get('stop_loss_atr', 2.0)  # 震荡市默认 2.0×ATR
else:
    sl_atr_mult = self.risk_config['stop_loss_atr_multiplier']  # 趋势市默认 1.5×ATR
```

### 17.6 风险与应对

| 风险 | 说明 | 应对措施 |
|------|------|----------|
| 投票制过于宽松 | 1 个条件即可入场，可能产生更多假信号 | 依赖评分体系和频率控制进行二次过滤 |
| 4h 数据延迟 | 4h K 线更新频率低，信号可能滞后 | RSI 和 BB 在 4h 级别更稳定，适合震荡市策略 |
| 权重差异大 | 震荡市形态权重 60%，可能过度依赖单一维度 | 通过回测验证权重配置的合理性 |
