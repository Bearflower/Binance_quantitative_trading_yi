## 1. 背景与目标

### 1.1 背景

项目已是一个多策略量化交易系统（Binance 永续合约），现有四类生产策略：

| 策略 | 策略ID | 核心逻辑 |
|------|--------|---------|
| MTPCS 趋势 | `btc_eth` | BTC/ETH/BNB/SOL/XRP 永续趋势 + 震荡双模式 |
| 网格交易 | `grid` | ETHUSDT 三层预警架构 |
| HRS 混合反转 | `hrs` | 三轨并行信号机制（标准 + EMM + LV-RM） |
| 新币做空 | `new_coin` | 新上线币种做空，按评分分档开仓 |

现有策略本质上都是**方向性（beta 相关）策略**，依赖行情波动方向判断。团队希望探索**与新方向正交的 alpha 来源**，即不依赖价格涨跌方向、而依赖市场结构性价差的策略。

经过多轮回测，逐一证伪了 momentum、全局 regime、alt-season、朴素 z-score 配对等方向后，最终锁定 **L0（做多现货 + 做空等额永续，吃永续正向 funding）** 这一相对价值（CV，Cash-and-Carry）策略。

> 说明：以下所有"回测数据结论"均为**本地回测结果**（依据"禁止服务器回测"硬性约束），数据来自 Binance 公开 API / 从服务器拉取到本地后回测。凡标注【回测】的结论，其口径见 [第 6 节回测方法论](#6-回测方法论)，不得被误读为"已验证的上线结果即必然收益"。

### 1.2 业务目标

1. **提供与现有方向性策略正交的低相关收益来源**，降低组合整体波动。
2. **利用期现价差回归机制（funding 费率的长期结构性来源）获取相对价值收益**，而非价格方向判断。
3. **契合 PM（投资组合保证金）账户风控体系**，双腿（现货 + 永续）可共享保证金效率。
4. **在"小而精"的资金规模下可运行**，给出明确的最低资金门槛。

### 1.3 用户人群与适用场景

- **适用人群**：能承受永续杠杆、接受持仓数周至数月级别的相对价值头寸、资金规模偏小（1000~2000 USDT 起步）的量化投资者。
- **不适用人群**：追求短期高频收益、不能接受连续数月"资金占用但收益偏低"（年化 4~6%）的投资者。

### 1.4 成功指标（可衡量）

| 指标 | 目标（回测口径） | 备注 |
|------|----------------|------|
| 年化收益 | +4% ~ +6%（精选池 + 阈值 gate 后）| 结构上限，非保证收益，见 [第 11 节](#11-风险与诚实标注) |
| 与现有策略相关性 | 显著低于方向性策略互相关 | 需在组合层面验证 |
| 在场月份占比 | ≥ 70%（约 72%）| 回测约 72% 月份在场 |
| 单币到场期年化 | 头部币（SFP/ONE/GTC/DYDX）达 +8%~+10% | 由精选池贡献 |
| 断裂止损 | 单币 / 组合层面均有量化的断裂检测与退出 | 见风控 |

## 2. 策略定义（L0 结构）

### 2.1 策略结构

L0 为**相对价值套利策略**，采用"双腿"结构：

1. **现货腿（做多）**：通过 Binance **现货 API** 买入某币种现货。
2. **永续腿（做空）**：同一币种、同一币对，通过永续 API **做空等额名义价值**的永续合约。

> 名义价值 = 现货数量 × 现货价格（即完全对冲，市场中性，delta ≈ 0）。

### 2.2 收益来源与回归机制

L0 的主要设计收益来自**永续合约的资金费率（Funding Rate）**：

- 当市场情绪偏多时，永续价格对现货溢价，多头向空头**支付**资金费。
- L0 持有永续空头，因此在**正向资金费（多头付费）**时，**持续收取资金费**。
- 同时现货做多的方向与永续做空的对冲，`delta ≈ 0`，价格涨跌被完全对冲，组合不承担方向性风险。

**回归机制（结构性保证，非短期保证）**：
期现价差（基差）在较长周期内受"期现套利资金进出"约束而回归，资金费率是这一回归过程的持续现金流副产物。因此 L0 的收益**不依赖价格方向**，而依赖**资金费率长期为正的持续性**。这是 L0 与所有方向性策略的本质区别。

### 2.3 关键约束（强制）

1. **禁止服务器回测**：所有回测仅本地执行（见硬性约束）。
2. **现货腿必须通过 Binance 现货 API**，不得用其他复杂衍生品替代（不得引入期权、不得引入带方向的合成现货）。
3. **必须契合 PM 账户风控**：双腿在账户层做保证金 / 风险对冲管理。
4. **资金小**：策略必须能在小额资金下运行，给出下限并验证（见 [第 8 节](#8-资金门槛与账户要求)）。

## 3. 相对价值策略族分层（L0-L4）

为说明"L0 为何最优先"，此处给出相对价值策略族的完整分层。**L0-L4 为同一逻辑族，L0 是本需求文档当前锁定的落地对象。**

| 层级 | 名称 | 腿结构 | 信号 / 收益来源 | 复杂度 | 优先级判断 |
|------|------|--------|----------------|--------|-----------|
| **L0** | 基础期现套利（本策略） | 现货 + 等额永续 | 吃永续正向 funding，无需择时依赖强 gate | 低 | **最先落地**：结构简单、风控清晰、资金门槛低 |
| L1 | 期现 + 基差择时 | 现货 + 永续（可调对冲比例）| 在 funding 高时放大、低时减仓 | 中 | L0 跑通后再加，避免一上来引入择时噪音 |
| L2 | 期现 + 展期优化 | 现货 + 轻量调仓 | 用资金费率曲线选择永续到期/移仓时点 | 中 | 依赖永续期限结构数据，需数据管线扩展 |
| L3 | 跨期限基差 | 不同到期合约 | 同币跨到期基差套利 | 中高 | 需结构性市场存在，流动性/费率需验证 |
| L4 | 跨所 / 跨标 | 多市场 | 跨所、跨标的价差 | 高 | 引入交易所对手 / 划转风险，暂不考虑 |

**L0 优先理由（评审时确认）**：
1. 逻辑最简单、最不容易出现"逻辑幻觉"bug。
2. 双腿等额对冲，delta≈0，天然契合 PM 账户的风险对冲。
3. 对资金规模最友好，能在 1000~2000 USDT 起步（见 [第 8 节](#8-资金门槛与账户要求)）。
4. 精选池 + 阈值 gate 后，回测口径有明确的 +4~6% 年化锚点。

## 4. 选品与精选池逻辑

### 4.1 候选池

**前沿数据结论（【回测】口径）**：
- 已从服务器拉取至本地 `data_2y`，覆盖 **357 币 × 2 年**的现货/永续 1h + 8h funding 数据，数据量约 **777MB**。
- 该数据集为 L0 选品与回测的基础数据源。

候选池构建需遵循以下原则（具体币名单与参数见"待决策清单"）：

| 环节 | 规则（建议初值，需回测验证） |
|------|------------------------------|
| 基础币源 | 币安 USDT 永续市场候选币 357 枚 |
| 候选池必要条件 | 1) 币安永续与现货均长期上市；2) 永续日成交量、现货流动性达标；3) 非稳定币 / 非指数类 |
| 历史过滤 | 取至少 12~24 个月有完整 funding 与 K 线数据的币 |

### 4.2 排除规则（建议初值）

以下币种从候选池排除（排除规则需回测验证贡献度，避免误伤）：

1. **流动性极差币**：日成交额低于阈值、买卖价差过宽（影响双腿开平仓滑点）。
2. **刚上线不足一定时长的币**：funding 数据不足，无法做历史筛选（如上市 < 3~6 个月）。
3. **已用稳定币 / 杠杆代币**：不属于常规永续-现货套利标的。
4. **长期负 funding 币**：持续为正资金费的币才有意义（见 4.3 精选标准），历史长期为负需排除。

### 4.3 精选池筛选标准（建议初值，需回测验证）

> 该标准直接决定回测中 +4~6% 年化的来源，必须保留完整可复现的参数，不得伪装成"定论"。

| 维度 | 标准（建议初值） | 说明 |
|------|-----------------|------|
| 长期正费率 | 2 年全期净年化 funding 为正（如 +3~6% 档）| 20 币左右命中 |
| 阈值 gate | 开仓时 funding 达到**阈值 3.1%**才入场（见 [第 5 节](#5-信号与交易规则)）| 崩/震荡段需 gate 过滤 |
| 历史稳定性 | 在场期 funding 分布稳定，尾部塌陷频率低 | 避免只吃到一次性的高费 |

**【回测】精选池表现锚点**（作为"现状/依据"，具体参数见待决策清单）：

- **静态测算**：约 **20 币**长期正费率（SFP / CELR / DYDX / PEOPLE 等全期净年化 +3~6%）。
- **崩段与震荡段均值 funding**：崩段均值 **-12.9%**、震荡段 **-7.7%**——证明"不筛选直接全做"会吃到负费率，必须精选池 + 阈值 gate。
- **全币种等权中位数 funding**：**-1.4%**——再次印证必须精选，不能用全币种等权被动做法。
- **择机型回测原型（精选池 82 币 + 阈值 gate 3.1% + 扣 0.15% 手续费）**：
  - 2 年总净值 **1.120**，折合年化 **+5.6%**；
  - 分段表现：2024 **+11.9%** / 2025 **+4.8%** / 2026 **+3.9%**；
  - 组合约 **72%** 月份在场；
  - 单币到场期年化：SFP / ONE / GTC / DYDX 达 **+8~10%**。
- **持仓窗口时长**：中位数 **2 个月**、均值 **3.2 个月**。
- **2026 高费率机会月占比 44%**，与 2025 年持平，两年稳定。

## 5. 信号与交易规则

> 所有数值参数均标注为"**建议初值，需回测验证**"，不得写死为定论。正式参数经回测调优后写入配置文件（禁止硬编码）。

### 5.1 开仓条件（阈值 gate）

| 项目 | 规则（建议初值） |
|------|-----------------|
| 开仓信号 | 标的处于精选池，且其永续**资金费率≥ 阈值 gate（建议 3.1%）**时才开仓 |
| gate 目的 | 过滤崩段（均值 -12.9%）与震荡段（均值 -7.7%）的负费率；仅在正费率显著时持仓 |
| 开仓双腿 | 现货腿做多 + 永续腿做空**等额名义价值**，同时建仓 |
| 价格执行 | 永续腿可用限价单控制滑点；现货腿按市价/限价，规则见待决策清单 |
| 最小名义价值 | 受 Binance 最小下单量（minNotional）约束，见 [第 8 节](#8-资金门槛与账户要求) |

### 5.2 持仓与平仓条件

| 项目 | 规则（建议初值） |
|------|-----------------|
| 单次持仓上限 | 参考持仓窗口（中位 2 个月、均值 3.2 个月），设**最长持仓月数 T_max（建议初值 6 个月）**，超过强制平仓 |
| 持仓中 gate 复核 | 持仓期内持续跟踪 funding，转为明显负费率达到次数/幅度阈值则提前退出（见风控断裂止损）|
| 平仓条件 | 资金费率回落到正收益性价比以下 / 达到 T_max / 触发断裂止损，任一生效即平仓双腿并结算 |
| 手续费 | 回测中已按**扣 0.15% 手续费**计入；生产代码必须把费率、滑点、资金费率开销统一入账（禁止忽略）|

### 5.3 手续费处理（强制）

- 开平双腿各产生手续费；永续收取 funding。**收益口径 = 累计 funding 收入 − 双腿开平手续费 − 滑点**。
- 回测一律按扣 0.15% 手续费口径（如需更严苛口径，在待决策清单中提出并重测）。
- 生产落地时，将"实际成交费率 / 滑点"作为配置参数，与回测口径对比验证（防幻觉，见 [第 6.4 节](#64-回测防幻觉注意点)）。

## 6. 回测方法论

### 6.1 基本原则

**回测仅在本地执行，严禁在服务器执行（硬性约束）。** 数据来源二选一，均落地到本地后回测：

1. 从 Binance 公开 API 直接拉取到本地；
2. 在服务器端筛选目标数据后下载到本地（或本地代码从服务器获取数据后在本地回测）。

> 禁止：`ssh root@server "python backtest/xxx.py"` 在服务器跑回测。原因：回测消耗大量 CPU/内存，会与生产交易程序抢占资源，可能导致交易延迟或服务中断。

### 6.2 数据口径

| 项目 | 口径 |
|------|------|
| 数据范围 | 357 币 × 2 年，现货/永续 1h K 线 + 8h funding（本地 `data_2y`，约 777MB）|
| 时间区间 | 覆盖 2024 / 2025 / 2026（分段口径见下）|
| 净值模型 | 相对价值净收益率模型：自融资组合净值，扣除手续费与滑点 |
| 复利/单利 | 统一采用**复利净值 1.120** 口径（需在待决策清单中固定，避免口径漂移）|

### 6.3 分段验证（牛 / 崩 / 震荡）

回测结果必须分段呈现，不得只用整体年化掩盖结构差异：

| 段 | 表现（回测锚点） |
|----|-----------------|
| 2024 | +11.9% |
| 2025 | +4.8% |
| 2026 | +3.9% |
| 崩段（如 2025/2026 内深回调窗口）| 单独报告 funding 均值 -12.9%，验证 gate 是否过滤干净 |
| 震荡段 | funding 均值 -7.7%，验证 gate 是否过滤干净 |

**验收要求**：gate 在崩/震荡段应显著减少持仓（空仓或低在场），证明过滤有效，而非靠运气。

### 6.4 回测防幻觉注意点

编写回测代码时必须逐项自查（防"看着对、实则错"）：

```
□ 1. 现货腿使用 Binance 现货 API 语义，永续腿使用永续 API 语义，不得混用接口
□ 2. 名义价值在双腿严格等额（现货价 × 现货量 == 永续价 × 永续张数），误差可量化控制
□ 3. funding 采样：8h funding 按实际收取时点入账，不做粗糙日平均近似而不标明
□ 4. 手续费 / 滑点在双腿均计入，口径与生产配置一致
□ 5. gate 规则在历史数据上完整复现，参数未被未来函数（lookahead）污染
□ 6. 分段（牛/崩/震荡）划分有明确定义，不得手工挑选"漂亮段"
□ 7. 净值口径（复利/单利、是否含资金占用机会成本）全局统一
□ 8. 数据对齐：现货与永续 K 线按时间对齐，跨时区/跨校验无误
□ 9. 无重复代码、无幽灵参数（遵循项目编码规范）
```

## 7. 已证伪方向记录（防重复踩坑）

以下方向**已回测证伪**，作为团队知识沉淀与防重复投入的屏障。任何团队不建议重新投入时间，除非提出全新的、可论证的改进证据。

| 方向 | 回测结论 | 证伪原因 |
|------|---------|---------|
| **多币种动量轮动** | 年化跑不赢等权；空头腿负资产 | 动量 alpha 不足以覆盖轮动成本与空头负贡献 |
| **全局市场状态机（regime）** | 增量≈重复发明 | 各现有策略已内化环境判断，再做全局状态机无增量的可验证价值 |
| **alt-season 过滤器（hrs 用）** | beta≈1.05，山寨跟随 BTC | 山寨整体无独立吸血结构，做 alt 过滤器不构成稳定 alpha |
| **朴素 z-score 配对交易** | 47.7% 盈利对、12% 断裂率、中位单对年化 0~2% | 无稳定 alpha，断裂率高，配对关系不持续 |

> 完整论证过程见 `docs/requirements/discover/配对交易讨论稿091601.md` 与 `docs/requirements/discover/L0_cashcarry_立项评估_2026-09-16.md`。

## 8. 资金门槛与账户要求

### 8.1 资金规模结论

**【回测】前端结论（作为现状/依据）**：
- **本金不决定能否正收益**：L0 为比例收益（各币收益率叠加），收益率为比例化，与本金绝对值无正相关性。
- **建议起步规模：1000~2000 USDT**（兼顾分散与滑点/手续费比例摊薄）。
- **纯技术下限：约 300 USDT**（仅能覆盖极少数大流动性标的；分散度不足、滑点处理受限）。

### 8.2 双腿资金占用与最小下单额

| 项目 | 说明 |
|------|------|
| 现货腿资金 | 需真实 USDT 全额买入现货（非保证金），占用本金 |
| 永续腿资金 | 需保证金支撑做空仓位（PM 账户内可共享，见风控）|
| 最小下单额 | 受币安 `minNotional`（最小名义价值）约束；小额资金下单个标的可用名义受此限制，需在选品时剔除名义值超出手头资金的标的 |
| 资金分配 | 单标的占用名义须小于账户可用资金的建议比例（建议初值，需回测验证），避免单点集中 |

### 8.3 账户要求（强制）

- 需持有 **Binance 现货 + USDT 永续**双向权限。
- **契合 PM（组合保证金）账户**：双腿在同一账户结构下做风险对冲，共享保证金效率，满足项目账户体系。
- 不做现货以外的复杂依赖（期权等），严格遵守"不引入复杂衍生品"约束。

## 9. 风控设计

### 9.1 PM 账户契合

- 双腿 `delta≈0`，在 PM 账户按组合风险进行保证金核算，双腿彼此对冲降低整体保证金占用（需 PM 接口验证并确认实现方式，列入待决策）。
- 所有资金费率、部位都归属同一账户结构，便于统一风控。

### 9.2 核心风控项目（建议初值，需回测验证）

| 风控项 | 规则（建议初值） |
|--------|-----------------|
| **资金费率反转** | 持仓期 funding 转负达到阈值（次数或累计幅度）触发提前平仓（断裂止损）|
| **断裂止损（pair 断裂）** | 塞入价差偏离历史分布的极端值（如超过 N 倍滚动标准差）即平掉双腿退出，不硬扛（参考已证伪方向中断裂风险教训）|
| **流动性 / 滑点** | 日成交额、买卖价差设下限；开平仓以限价单控制滑点；极端市况拒开仓 |
| **保证金** | 永续腿保证金留足压力缓冲（崩段 funding 均值 -12.9% 场景压力测试），防止被强平触发被迫平掉单腿造成裸露 |
| **单所集中度** | 全部标的集中于 Binance；需在整体组合层面对"单所暴露"设上限，避免单所极端事件（交易暂停、币种下架）导致系统性损失 |
| **单币集中度** | 单标的名义价值不超过账户可用资金建议比例，禁止重仓单一币 |
| **展期 / 移仓** | 不主动隔展期，仅按持仓窗口与平仓规则进出 |

### 9.3 压力测试要求

- 必须针对**崩段（funding 均值 -12.9%）**做压力测试，验证 gate 让组合空仓/低在场，避免在负费率时仍持仓吃费。
- 必须验证**币种下架、永续交割、流动性瞬间枯竭**等极端事件的止损路径可执行。

## 11. 风险与诚实标注

### 11.1 收益天花板（必须如实告知）

- **L0 结构性收益上限约 4~6%（年化，回测口径 +5.6%）**，属于"低收益、低波动、近似无方向性"策略。
- 该收益是**条件收益（精选池 + gate 才有的结构上限）**，不是无条件保证，更不是结构保证。
- 崩段 / 极端负费率期可能无收益甚至小亏，组合约 28% 月份不在场（空仓等机会）。

### 11.2 风险清单

| 风险 | 说明 | 缓解 |
|------|------|------|
| 资金费率长期转负 | funding 结构反转，正费率不再持续 | 精选池 + gate + 断裂止损 |
| 单所集中 | 全部多头寸集中于 Binance | 单所集中度上限 |
| 流动性冲击 | 极端行情下单腿滑点 / 无法平仓 | 限价单、日成交额下限、拒开仓 |
| 强平裸露 | 永续腿被强平只剩现货裸露 | 保证金压力缓冲 + 崩段压力测试 |
| 币种下架 / 交割 | 标的退市或永续交割 | 选品排除短后代码 + 止损路径可执行 |
| 回测口径偏差 | 回测收益高于实盘 | Phase 5 实盘对照、费率/滑点配置化 |

### 11.3 信任边界声明

- 本 PRD 中所有【回测】数据，均为**本地回测结果**，仅作为策略可行性依据，**不构成对实盘收益的承诺**。
- 所有参数为"**建议初值，需回测验证**"，禁止在未调优前直接写入生产配置或代码中写死。

## 13. 术语表

| 术语 | 定义 |
|------|------|
| **funding / 资金费率** | 永续合约多空之间周期性支付的费用，8h 周期；正值 = 多头向空头付费 |
| **cash-and-carry（L0）** | 做多现货 + 做空等额永续、赚取正向资金费的相对价值结构 |
| **gate** | 开仓的资金费率阈值过滤器，仅 threshold 达标时入场 |
| **delta** | 组合对底层价格变动的敏感度；L0 双腿等额下 delta≈0 |
| **精选池** | 经长期正费率、流动性、历史稳定性筛选后的可交易币集合 |
| **断裂止损** | 价差/关系偏离历史分布极端值时主动平仓退出的风控动作 |
| **PM 账户** | 币安组合保证金账户（Portfolio Margin），双腿可共享保证金做风险对冲 |
| **minNotional** | 币安最小名义价值下单限制 |
| **相对价值策略族** | 依赖市场结构性价差而非价格方向的策略集合（L0-L4）|
