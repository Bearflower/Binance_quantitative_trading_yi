## 网格交易策略 V2 回测引擎 (2026-05-09)

### 回测引擎 V2 架构 ⭐⭐

**设计理念**: 薄层回测引擎，只负责"时间推进 + 成交模拟"。所有策略逻辑（网格计算、市场状态检测、仓位管理、风控）复用 `strategies/grid/` 业务模块。

**核心改进**:
- ✅ **复用 GridCalculator** 进行动态网格参数计算和层级生成
- ✅ **复用 MarketStateDetector** 的核心算法判断市场状态
- ✅ **集成市场状态切换处理**，解决孤儿仓 BUG
- ✅ **支持移动止盈模拟**
- ✅ **支持 ATR 边界止损**
- ✅ **配置驱动**，所有参数通过 `config.yaml` 管理
- ✅ **消除硬编码**，策略参数、阈值全部从配置文件读取

**架构对比**:

| 特性 | V1 旧引擎 | V2 新引擎 |
|------|---------|---------|
| **策略逻辑** | 回测独立实现 | 复用 strategies/grid/ 业务模块 |
| **网格计算** | 自行实现 | 复用 GridCalculator |
| **市场状态** | 无检测 | 复用 MarketStateDetector |
| **移动止盈** | 无 | TrailingStopSimulator |
| **ATR止损** | 硬编码固定值 | 配置驱动动态值 |
| **配置管理** | 分散在代码中 | 统一 config.yaml |

**新增文件**:
- `backtest/grid/backtest_engine.py` (1709行) - 回测引擎 V2 核心
- `backtest/grid/exchange_simulator.py` (953行) - 回测交易所模拟器

### exchange_simulator.py - 回测交易所模拟器 ⭐

**核心功能**:
- **BinanceClient兼容接口**（同步版本）: 模拟真实交易所的下单、撤单、查余额等操作
- **KLineService兼容接口**（同步版本）: 提供历史K线数据访问，**严格防止未来函数**
- **订单模拟撮合**: 限价单成交判定（当前价格穿越订单价格时自动成交）
- **时间线推进**: `advance_to(index)` 推进到指定K线索引，更新当前时间和价格
- **多时间框架支持**: 从 DataLoader 预加载 1h/4h/1d/15m 等多时间框架数据
- **K线截断**: `get_klines()` 只返回 `current_time` 之前的数据，杜绝未来函数泄露

**防未来函数机制**:
```python
# 只返回 <= current_time 的K线数据
if k.get("timestamp", "") > current_ts:
    cutoff_index = i
    break
available_klines = all_klines[:cutoff_index]
```

### trailing_stop_simulator.py - 移动止盈模拟器 ⭐

**核心功能**:
- **三步状态机**: 启动 -> 更新峰值 -> 触发止盈 / 自动重置
- **配置驱动**: `profit_trigger`（如15%）启动追踪，`trailing_percent`（如5%）回撤触发
- **所有金额使用 Decimal**，确保计算精度
- **独立组件**: 纯模拟，不直接操作仓位或订单

**状态机流程**:
```
未激活 --(盈亏>=触发阈值)--> 已激活（记录峰值和止盈价）
已激活 --(价格创新高)--> 更新峰值和止盈价
已激活 --(跌破止盈价)--> 触发止盈，自动重置
```

## 飞书 Webhook 多项目分离配置 (2026-05-09) ⭐

**核心改进**: 将原来单一的飞书 Webhook 拆分为按项目独立配置，每个策略使用独立的 Webhook URL。

**环境变量配置**:
```bash
# 各项目独立飞书 Webhook
FEISHU_WEBHOOK_GRID="https://open.feishu.cn/..."        # 网格交易策略
FEISHU_WEBHOOK_BTC_ETH="https://open.feishu.cn/..."      # BTC/ETH策略
FEISHU_WEBHOOK_NEW_COIN="https://open.feishu.cn/..."     # 新币做空策略

# 默认 Webhook（兜底配置）
FEISHU_WEBHOOK="https://open.feishu.cn/..."
```

**NotificationClient 实现** (`shared/notification.py`):
- ✅ `_load_webhook_mapping()` 方法从环境变量自动加载项目->Webhook映射
- ✅ `use_direct_webhook` 模式：直接根据项目名选择对应 Webhook URL 发送
- ✅ `_send_to_feishu_webhook()` 方法：直接调用飞书 Webhook API
- ✅ 策略调用时指定 `project` 参数: `notification_client.send(message="...", project="grid")`

**代码示例**:
```python
# 网格策略发送通知到专属飞书群
await notification_client.send(
    message="【网格信号灯】ETHUSDT 震荡市场...",
    level="info",
    project="grid"  # 自动路由到 FEISHU_WEBHOOK_GRID
)
```

**修改文件**:
- `shared/notification.py` - NotificationClient 增加多项目Webhook映射逻辑
- `strategies/grid/signal_bot.py` - 网格信号发送使用 `project="grid"`

**适用场景**:
- ✅ **多项目管理**: 不同策略的消息发送到不同的飞书群
- ✅ **通知隔离**: 避免交易信号、告警信息混杂
- ✅ **灵活扩展**: 新增策略只需添加对应的环境变量

## 网格交易策略 V2.1 升级 (2026-06-03) ⭐

### V2.1 核心改进

**设计理念**: 从 V2.0 的被动价格止损升级为**主动的状态止损**，通过双重时间框架确认和波动率异常检测，在趋势形成时主动暂停网格，避免逆势亏损。

### 市场状态从4种升级为5种

| 状态 | 判定逻辑 | 操作建议 |
|------|---------|----------|
| **震荡** | 1h ADX < 25 且 4h ADX < 25 | 正常运行中性网格 |
| **弱趋势** | 25 ≤ 1h ADX < 30 且 4h ADX < 25 | 谨慎运行：减少网格数量、放宽区间 |
| **普通强趋势** | 1h ADX ≥ 30 且 4h ADX ≥ 25 且方向一致 | 建议终止网格 |
| **极端强趋势** | 1h ADX ≥ 35（无论4h如何） | 必须立即终止网格 |
| **波动率异常** | 平滑 ATR 连续2次巡检上升超过 50% | 暂停挂单，保留持仓 |

### MarketStateDetector 构造函数参数变更

从 V2.0 的简单参数升级为 V2.1 的全面可配置参数：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `adx_extreme_strong` | 35 | 极端强趋势阈值（最高优先级） |
| `adx_normal_strong` | 30 | 普通强趋势 1h ADX 阈值 |
| `adx_normal_strong_4h` | 25 | 普通强趋势 4h 确认阈值 |
| `weak_trend_adx_lower` | 25 | 弱趋势 ADX 下限 |
| `weak_trend_adx_upper` | 30 | 弱趋势 ADX 上限 |
| `volatility_ratio_threshold` | 1.5 | ATR 飙升比率阈值 |
| `volatility_consecutive_count` | 2 | 连续异常次数阈值 |
| `volatility_recovery_ratio` | 1.3 | 波动率恢复比率阈值 |
| `recovery_adx_1h` | 25 | 恢复条件 1h ADX |
| `recovery_adx_4h` | 30 | 恢复条件 4h ADX |
| `trend_strength_divisor` | 30 | 趋势强度归一化除数 |
| `atr_history_size` | 3 | ATR 历史窗口大小 |

- 弱趋势使用不同 ATR 倍数：`atr_multipliers.weak_trend`（默认 2.4）

- **从波动率异常恢复**: ATR 回落到峰值的 30% 以内，且 ADX < 30

## 网格交易策略 V2.2 升级 (2026-06-03) ⭐

### V2.2 核心改进

**设计理念**: 在 V2.1 双重时间框架 + 波动率异常检测的基础上，进一步收紧极端趋势判定条件、优化网格参数和波动率检测灵敏度，降低逆势亏损风险，提升震荡市收益效率。

### 极端强趋势阈值升级（双重确认）

| 项目 | V2.1 | V2.2 | 变更说明 |
|------|------|------|----------|
| 极端强趋势判定 | 1h ADX ≥ 35（无论4h如何） | 1h ADX ≥ 40 **且** 4h ADX ≥ 30 | 从单时间框架升级为双重确认，避免误判 |

**影响**: 极端强趋势判定更加严格，需要 1h 和 4h 两个时间框架同时确认，减少因短期波动导致的误触发。

### 波动率异常检测灵敏度提升

| 参数 | V2.1 | V2.2 | 变更说明 |
|------|------|------|----------|
| `volatility_ratio_threshold` | 1.5 | **1.3** | 飙升比率阈值降低，更早检测到异常 |
| `volatility_recovery_ratio` | 1.3 | **1.2** | 恢复比率降低，恢复判定更宽松 |
| `atr_history_size` | 3 | **5** | ATR 历史窗口扩大，基准更稳定 |

**影响**: 波动率异常检测更灵敏（1.5→1.3），能更早捕捉到市场波动率飙升；恢复条件更宽松（1.3→1.2），避免在波动率回落过程中过早恢复；ATR 历史窗口从 3 扩展到 5，使基准 ATR 计算更稳定。

### 网格参数大幅优化

| 参数 | V2.1 | V2.2 | 变更说明 |
|------|------|------|----------|
| 震荡基准网格数 | 30 | **8** | 大幅减少，避免过密网格 |
| 震荡网格数范围 | [20, 50] | **[5, 12]** | 范围收窄，网格更稀疏 |
| 弱趋势基准网格数 | 30 × 0.7 = 21 | **6** | 独立计算，不再依赖震荡基准 |
| 弱趋势网格数范围 | [15, 40] | **[4, 10]** | 范围收窄，弱趋势网格更少 |

**影响**: 网格数量大幅减少，单格利润空间增大，减少频繁小额交易的手续费损耗。震荡市基准从 30 降至 8，弱趋势从 21 降至 6，均改为独立配置。

### ATR 倍数调整

| 参数 | V2.1 | V2.2 | 变更说明 |
|------|------|------|----------|
| `atr_multipliers.oscillation` | 2.0 | **5.0** | 震荡市价格区间大幅放宽 |
| `atr_multipliers.weak_trend` | 2.4 | **6.0** | 弱趋势价格区间大幅放宽 |

**影响**: ATR 倍数大幅提升（震荡 2.0→5.0，弱趋势 2.4→6.0），配合网格数减少，每格覆盖的价格范围更宽，单格利润更高。

### 推送冷却时间延长

| 参数 | V2.1 | V2.2 | 变更说明 |
|------|------|------|----------|
| `push_cooldown_hours` | 4 | **6** | 冷却时间延长 50% |

**影响**: 减少重复推送频率，避免在市场状态未实质变化时频繁打扰。

### 弱趋势止损缓冲新增

| 参数 | V2.1 | V2.2 | 变更说明 |
|------|------|------|----------|
| 弱趋势止损缓冲 | 无独立配置（与震荡相同 2.0×ATR） | **2.4×ATR** | 弱趋势给予更大止损缓冲 |

**影响**: 弱趋势状态下止损缓冲从 2.0×ATR 提升至 2.4×ATR，给予更多价格波动容忍度，避免因正常回调触发止损。

## 网格交易策略 V2.3 升级 (2026-06-24) ⭐

### V2.3 核心改进

**设计理念**: 在 V2.2 双重时间框架 + 波动率异常检测基础上，增加**无条件紧急极端趋势**（1h ADX ≥ 50）和**趋势加速检测**（2h 内 ADX 上升 > 20），市场状态从 5 种升级为 7 种，三档冷却时间（alert=1h / normal=6h / tradable=2h），分状态恢复机制。

### 市场状态从 5 种升级为 7 种

| 优先级 | 状态 | 判定条件 | 冷却时间 |
|--------|------|----------|----------|
| 1 | 紧急极端趋势 | 1h ADX ≥ 50（无条件） | 1h |
| 2 | 趋势急剧增强 | 2h 内 1h ADX 上升 > 20 | 1h |
| 3 | 极端强趋势 | 1h ADX ≥ 40 且 4h ADX ≥ 30 且方向一致 | 1h |
| 4 | 普通强趋势 | 1h ADX ≥ 30 且 4h ADX ≥ 25 且方向一致 | 6h |
| 5 | 波动率异常 | 连续两次巡检 ATR 上升 > 30% | 6h |
| 6 | 弱趋势 | 25 ≤ 1h ADX < 30 且 4h ADX < 25 | 2h |
| 7 | 震荡 | 1h ADX < 25 且 4h ADX < 25 | 2h |

### 新增 MarketState 枚举

- `EMERGENCY_EXTREME_TREND`: 紧急极端趋势（无条件，最高优先级）
- `TREND_ACCELERATING`: 趋势急剧增强

### 配置参数变更

| 参数 | V2.2 | V2.3 | 说明 |
|------|------|------|------|
| `emergency_adx_threshold` | — | **50** | 新增：紧急极端趋势 1h ADX 阈值 |
| `trend_acceleration_threshold` | — | **20** | 新增：趋势加速 ADX 上升点数 |
| `volatility_ratio_threshold` | 1.3 | 1.3 | 保持 |
| `push_cooldown_hours` | 6 | 三档 | 拆分为 alert(1h) / normal(6h) / tradable(2h) |
| `adx_history_size` | — | 3 | 新增：ADX 历史窗口 |

### 修改文件

- `strategies/grid/market_state.py` - MarketState 枚举新增 EMERGENCY_EXTREME_TREND / TREND_ACCELERATING
- `strategies/grid/signal_bot.py` - 7 状态分发、三档冷却、紧急/加速消息模板
- `strategies/grid/config.yaml` - 新增 market 节参数、三档冷却配置、置信度配置
- `strategies/grid/strategy.py` - 版本号升级至 2.3.0

## 网格交易策略 V2.4 升级 (2026-07-03) ⭐

### V2.4 核心改进

**设计理念**: 引入**三层预警架构**解决 ADX 滞后 8-16 小时的核心问题。第一层（价格行为紧急触发）不依赖技术指标，秒级响应；第二层（15m ADX 早期预警）在趋势萌芽阶段（约提前 1-2 小时）发出预警；第三层（1h ADX(10) 趋势确认）缩短 ADX 周期从 14 到 10，比原 ADX(14) 提前约 4 小时确认趋势。同时将趋势加速阈值从 20 降至 8，波动率检测阈值从 1.3 降至 1.2，全方位提升策略响应速度。

### 市场状态从 7 种升级为 9 种

| 优先级 | 状态 | 判定条件 | 冷却时间 | 说明 |
|--------|------|----------|----------|------|
| 1 | 价格行为紧急触发 | 1h 变动 ≥ 3% 或 15m 变动 ≥ 1.5% | 1h | V2.4 新增：秒级响应 |
| 2 | 15m ADX 早期预警 | 15m ADX ≥ 50 且 1h 变动 ≥ 1% | 1h | V2.4 新增：提前 1-2h 预警 |
| 3 | 1h ADX(10) 趋势确认 | 1h ADX(10) ≥ 55 | 1h | V2.4 新增：ADX 周期缩短 |
| 4 | 趋势急剧增强 | 2h 内 1h ADX 上升 > 8 | 1h | 阈值从 20 降至 8 |
| 5 | 极端强趋势 | 1h ADX ≥ 40 且 4h ADX ≥ 30 且方向一致 | 1h | 不变 |
| 6 | 普通强趋势 | 1h ADX ≥ 30 且 4h ADX ≥ 25 且方向一致 | 6h | 不变 |
| 7 | 波动率异常 | 连续两次巡检 ATR 上升 > 30% | 6h | 阈值从 1.3 降至 1.2 |
| 8 | 弱趋势 | 25 ≤ 1h ADX < 30 且 4h ADX < 25 | 2h | 不变 |
| 9 | 震荡 | 1h ADX < 25 且 4h ADX < 25 | 2h | 不变 |

### 新增 MarketState 枚举

- `PRICE_EMERGENCY`: 价格行为紧急触发（最高优先级，置信度 1.0）
- `EARLY_WARNING_15M`: 15m ADX 早期预警（置信度 0.92）
- `TREND_CONFIRMED_1H`: 1h ADX(10) 趋势确认（置信度 0.95）

### 新增 MarketAnalysis 字段

- `adx_15m`: 15 分钟 ADX 值（用于早期预警）
- `price_change_1h`: 1 小时价格变动百分比（用于价格行为触发和早期预警）
- `price_change_15m`: 15 分钟价格变动百分比（用于价格行为触发）

### 新增方法

- `_calculate_price_change()`: 计算指定周期内的价格变动百分比
- `_generate_price_emergency_message()`: 生成价格行为紧急触发推送消息
- `_generate_early_warning_15m_message()`: 生成 15m ADX 早期预警推送消息
- `_generate_trend_confirmed_1h_message()`: 生成 1h ADX(10) 趋势确认推送消息

### V2.3 -> V2.4 参数变更

| 参数 | V2.3 | V2.4 | 说明 |
|------|------|------|------|
| `emergency_adx_threshold` | 50 | **55** | 上调阈值，配合 ADX 周期缩短 |
| `trend_acceleration_threshold` | 20 | **8** | 大幅降低，更早捕捉趋势加速 |
| `volatility_ratio_threshold` | 1.3 | **1.2** | 提升波动率检测灵敏度 |
| `adx_period` | 14 | **10** | 缩短 ADX 周期，提升反应速度 28% |
| `price_emergency_1h` | — | **0.03** | 新增：1h 价格变动紧急阈值 |
| `price_emergency_15m` | — | **0.015** | 新增：15m 价格变动紧急阈值 |
| `adx_early_warning_15m` | — | **50** | 新增：15m ADX 早期预警阈值 |
| `price_early_warning_1h` | — | **0.01** | 新增：早期预警所需 1h 价格变动 |

## 网格交易策略 V2.5 升级 (2026-08-27) ⭐

### V2.5 核心改进

**设计理念**: 集成新的独立 K 线服务（`services/kline_service/`），解决之前 K 线数据服务不稳定、重启后数据丢失的问题。同时优化执行节点固定为每小时 `:05` 分钟，确保与 K 线收盘时间对齐，避免检测时间漂移。修复冷却时间临界值问题和 AI 调优覆盖层格式错误。

### 关键变更

#### 1. K 线服务对接

- **新 K 线服务**：`services/kline_service/` 独立部署，通过 `shared/kline_service.py` 客户端访问
- **服务地址**：`http://kline-service:8000/api/v1`（Docker Compose 服务名）
- **环境变量**：`KLINE_SERVICE_URL` 控制 K 线服务地址
- **数据获取**：`MarketStateDetector` 通过 `KLineService.get_klines()` 获取多时间框架数据（15m/1h/4h）
- **历史数据**：通过 `scripts/fetch_history_bulk.py` 批量回填 90 天历史数据
- **Docker Compose 依赖**：先添加 `kline-service: condition: service_healthy` 依赖，后移除（避免 K 线服务重启时网格策略跟随重启）

#### 2. 执行节点固定（每小时 `:05` 分钟）

- **背景**：原代码使用 `asyncio.sleep(3600)` 间隔，每次启动时间不同，导致检测时间漂移
- **改动**：新增 `_wait_until_next_run()` 方法，计算到下一个固定分钟节点的等待时间
- **配置参数**：`config.yaml` 新增 `signal_bot.run_at_minute: 5`，与 K 线收盘时间对齐
- **效果**：检测锁定在每小时 `:05` UTC 执行，容器重启后自动对齐到下一个 `:05` 节点

#### 3. 冷却时间临界值修复 (2026-08-28)

- **问题**：冷却比较 `hours_since < cooldown_hours` 因浮点数精度问题，在 `hours_since` 略小于 `cooldown_hours`（如 1.9999h < 2h）时跳过推送
- **修复**：增加 0.01 小时（约 36 秒）宽容度：`hours_since < cooldown_hours - 0.01`
- **效果**：`02:05 → 04:05 → 06:05` 等 `:05` 节点的检测不再因临界值跳过推送

#### 4. AI 调优覆盖层格式修复 (2026-09-01)

- **问题**：AI 调优系统在写入覆盖层 YAML 时，将 `{from: old, to: new}` 格式直接写入，导致 `base_grid_count` 为 dict 而非数字，引发 `TypeError: unsupported operand type(s) for *: 'float' and 'dict'`
- **根因**：`ai_tuner/main.py` 直接将 AI 返回的 `adjustments`（含 `from`/`to` 键）传给 `apply_overrides()`，未提取 `to` 值
- **修复**：新增 `clean_adjustments` 提取逻辑，只传 `to` 值给 `apply_overrides()`
- **文件改动**：`ai_tuner/main.py` 第 750~758 行
- **覆盖层示例**：`tuning_overrides/V20260830.yaml` 从 `{from: 6, to: 7}` 修复为 `7`

### 修改文件

- `strategies/grid/signal_bot.py` - 新增 `_wait_until_next_run()` 方法、冷却临界值修复
- `strategies/grid/grid_calculator.py` - 无改动（修复的是 AI 覆盖层格式）
- `strategies/grid/config.yaml` - 新增 `signal_bot.run_at_minute: 5` 配置
- `strategies/grid/strategy.py` - 无改动
- `shared/kline_service.py` - K 线服务客户端（已有，对接新 K 线服务）
- `ai_tuner/main.py` - 修复 `adjustments` 格式处理
- `docker-compose.yml` - 添加/移除 `kline-service` 依赖
- `services/kline_service/` - 新 K 线服务（独立部署）

### 部署说明

- 网格策略容器不再依赖 `kline-service` 的健康检查，K 线服务短暂不可用时自动重试
- 覆盖层文件 `tuning_overrides/` 目录在容器内通过 volume 挂载，需确保文件格式正确（标量值而非 dict）
