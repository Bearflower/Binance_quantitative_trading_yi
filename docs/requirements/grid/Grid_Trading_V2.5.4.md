# 网格交易系统 V2.5.4 需求文档

**主题**：保留小时巡检，新增面向人工操作的实时风险预警

**版本**：2.5.4（需求版本，不代表策略代码或部署版本已经升级）

**原始日期**：2026-10-07

**修订日期**：2026-10-08

**适用对象**：ETHUSDT USDT 本位永续合约、半自动网格信号灯

**状态**：已根据需求评审修订；研究种子在本次事件中未取得可供人工操作的提前量，待重新研究参数；未实施、未部署

## 1. 背景、目标与范围

### 1.1 用户问题

小时巡检给出的终止最高价、终止最低价继续作为用户在币安 APP 中设置保护的参考。用户认可原有止损机制，希望在清醒、能够操作账户时，于行情快速恶化且尚未到达终止价之前收到有依据的提醒，自行判断是否提前终止网格。

本版本要解决的是人工风险提醒的提前量，不承诺预测趋势、避免滑点或必然降低亏损。行情数据更新快、规则判断快、通知送达快和用户操作及时，是不同环节，必须分别测量。

### 1.2 已确认的产品约束

| 编号 | 需求 |
|---|---|
| FR-01 | 保留现有小时巡检的市场状态、ADX/ATR/EMA、网格参数、保证金引导和推送冷却逻辑。 |
| FR-02 | WebSocket 监控与小时巡检并行，不是完成小时巡检后才临时切换到实时监控。 |
| FR-03 | 系统只提供建议与告警；用户在币安 APP 手动操作。实时组件不调用下单、撤单、改单、保证金或杠杆调整接口。 |
| FR-04 | 默认用户采用最新一条成功推送的数值建议，不要求二次确认，也不读取账户来核对是否采用。 |
| FR-05 | 每小时巡检不等于每小时推送。冷却跳过、计算失败、发送失败时，不更新实时组件的建议边界。 |
| FR-06 | 消息统一使用“最新建议区间／最新建议终止价”，展示建议时间，不称为账户实际设置。 |
| FR-07 | 价格区间内检测普通异动，并允许严重风险直接升级；网格区间外、终止价以内的同向缓冲区仍可满足普通异动；达到缓冲紧急条件时升级，触及终止价直接报告事实。 |
| FR-08 | 紧急和越界提醒不依赖先触发普通预警，也不强制等待 3m、5m 或 15m K 线收盘。 |
| FR-09 | 固定小时策略，单独验证实时预警增量效果；计入误退出、通知和人工操作延迟。 |
| FR-10 | 不展示缺乏仓位依据的预计亏损、节省金额或“手动一定避免滑点”等表述。 |

### 1.3 本次新增与不包含的工作

新增：建议快照交接、实时行情接入、滚动窗口特征、分级事件、去重恢复、监控降级、离线事件回放与验收记录。

不包含：自动交易、订单状态同步、用户采用确认、自动识别用户是否清醒、强制变更原有止损、重做保证金模型、BTC 实时确认、成交量因子、全策略参数优化。原小时策略中的 BTC 和保证金逻辑仍按原实现运行。

本文第 2 节为实测证据；第 3～11 节是首版研发规格；第 9 节数值是明确标注的研究配置，不能误认为用户已经确认的最优阈值或线上参数。

## 3. 与现有小时策略的关系

### 3.1 保留原有业务逻辑

现有接入点为 `strategies/grid/main.py`、`signal_bot.py`、`market_state.py`、`grid_calculator.py`、`margin_advisor.py` 和 `config.yaml`。主入口通过 `shared.config_loader.load_strategy_config()` 加载基础配置与生效覆盖层。

小时模块继续按现有调度运行（当前基础配置为每小时 `:05`），保留市场状态判断、参数计算和现有推送冷却。新增功能围绕原推送增加交接状态，只有明确发送成功才激活同一次计算产生的结构化建议快照，并增加独立实时组件。

禁止用本文重写既有市场参数。2026-10-08 本地基础配置可见：`emergency_adx_threshold=55`、`trend_acceleration_threshold=8`、`volatility_ratio_threshold=1.2`、`adx_period=10`、震荡 `base_grid_count=6`、震荡半区间 ATR 倍数 6.0。这些只是本地基础值，实际运行以当时合并配置为准。原稿中 50／20／1.3／8 格／10×ATR 等旧值不再复制成新配置。

### 3.2 并行流程

```text
原小时巡检 → 原状态判断及参数计算 → 原推送决策 → 原通知渠道
                                             ↓ 发送成功且含完整边界
                                      发布持久化建议快照
                                             ↓
ETH 实时行情 → 数据有效性检查 → 滚动特征与边界判断 → 分级、去重 → 飞书提醒
                                             ↓
                                       事件与回放日志
```

实时组件采用独立进程，不能与小时模块的同步 pandas 指标计算共用事件循环线程。现有代码确有同步计算，但其阻塞时长尚未实测；不能把“几秒”当作测量结论。实时故障不能停止小时巡检；两进程仍共享机器和通知渠道资源，需测量峰值竞争。

### 3.3 工程落点（均为待实现）

- 新增 `strategies/grid/realtime/`：`main.py` 独立入口、`feed.py` 行情连接及补齐、`features.py` 窗口、`rules.py` 纯规则、`state.py` 去重恢复、`reference_store.py` 快照、`delivery.py` 通知调度、`replay.py` 回放。规则层只接受快照、配置、行情和明确时钟输入，不导入 pandas、小时检测器或网络服务。规则及特征层不得直接调用 `time.time()`、`datetime.now()` 等系统时钟；事件时间、决策时间、采样对齐与超时均由外部 Clock 注入。
- 已核查的共享 Binance 客户端、K 线客户端及 grid 模块没有可直接复用的 aggTrades WebSocket 实现；这是新增工作。优先使用已声明的 aiohttp，通过 WS 接入，不假设已有重连、补齐或队列能力。首版单 ETHUSDT 聚合成交流、单行情连接；feed 自行实现退避重连，不能假定客户端自动重连。多品种连接规划不在本版范围。
- `signal_bot.run_loop` 捕获 `_send_notification` 的返回值：明确 True 且 `grid_params` 非空才激活数值快照。保留现有 `last_signals` 即使发送失败仍前移的冷却行为；快照不依赖这个内存字段。修复原冷却行为属于另一项变更。
- 为配置加载器增加兼容入口 `load_strategy_config_with_metadata`，原入口继续返回 dict。基础版本取 `strategy.version`，覆盖版本取同一次实际读取的 active version（无覆盖则明确记 null），配置哈希基于确定性序列化的有效业务配置；不包含密钥，也不记录 webhook。新增入口返回 `(config: dict, metadata: dict)`；旧入口委托同一加载路径但仍只返回 config。metadata 区分 requested_overrides_version、实际 applied_overrides_version 与加载错误，覆盖失败回退基础配置时不可标为已应用覆盖。哈希使用 UTF-8、递归排序键、固定分隔符及规范化数值的 JSON（拒绝 NaN/Infinity），针对排除秘密后的业务配置计算 SHA-256。按“读版本→读配置内容→复读版本及内容指纹”核对，变化时有界重试；仍不一致则元数据不可用、禁止激活新参考，不改变原小时回退语义。
- 新增本地 SQLite 持久化存储，小时出口与实时进程共享本机持久卷，保存快照交接、事件、通知 outbox；不能放临时目录或网络文件系统。它是新实时功能的依赖，不把可选 PostgreSQL 强制升级为原小时策略的依赖。多机器部署不在首版范围。

### 3.4 存储与部署约定

容器默认 `storage.path=/app/data/grid_realtime.sqlite3`，对应现有 grid 服务挂载 `./data/grid:/app/data`。新增实时服务必须挂载**同一个宿主目录**至 `/app/data`，而非创建另一个同名但内容不同的卷。数据库、WAL、SHM 文件都在该持久目录内；容器重建与备份恢复须验收。非容器运行显式配置绝对路径，禁止按 cwd 猜测；部署变更清单必须包含实时入口、同卷挂载、写权限及启动顺序，本次不改 compose。

SQLite 使用 WAL、短事务、有限 busy_timeout；WAL 不消除单写者竞争。阻塞数据库操作不得放行情事件循环；超时回滚并进入相应降级，禁止无限锁等待。新增一次性迁移命令持有迁移锁、在两业务进程启动前执行；业务进程只校验 schema_version，不并发迁移。小时出口独占建议及会话表写入，实时进程负责事件/outbox；两者各自连接同一数据库，不跨进程共享连接。

### 3.5 会话确认与心跳

新增常驻心跳线程，与小时调度等待解耦，通过线程安全的不可变状态快照发布 session_id、递增序号、当前确认参考、未决发送状态和更新时间；不在心跳线程计算指标。小时 `await asyncio.sleep()` 会让出事件循环，本身不会阻塞心跳；使用线程是为了减少同步指标计算对心跳的影响，仍须测量 CPU/GIL/存储竞争。

心跳不是“边界肯定正确”的凭证。出口必须先把发送状态置为未决，再调用外部通知；心跳只转发该状态，不替它判定成功。检测到会话变化、未决版本或心跳超时均暂停操作建议。心跳周期和失联阈值见第 9 节，阈值只界定发现故障的最坏等待，不保证实时无漂移；通知出队前再次核对会话与序号。现有架构尚未实现这些能力，不能宣称部署后已有保障。

## 4. 建议快照与生命周期

### 4.1 数据契约

每份 `ReferenceSnapshot` 至少包含：

| 字段 | 含义 |
|---|---|
| `reference_id`、`symbol` | 唯一版本和品种；同一消息重试不生成新版本。 |
| `calculated_at`、`effective_at` | 计算时间、通知服务确认成功的时间；后者为实时参考生效时刻。 |
| `grid_lower`、`grid_upper` | 最新成功推送的建议区间。 |
| `stop_lower`、`stop_upper` | 同一份消息中的建议终止价。 |
| `stop_move_up_price`、`stop_move_down_price` | 可空，仅保留原建议溯源；不是终止价，不参与风险分区，不据此推断 APP 实际移动区间。 |
| `market_state`、`atr`、`adx_1h`、`adx_4h` | 当次背景值；指标可为空，边界不可缺失。 |
| `config_version`、`overrides_version`、`config_hash` | 对应的实际合并配置身份，支持追溯。 |
| `message_id`、`source` | 通知回执标识（渠道不返回则记空）和来源。 |

价格使用 Decimal 或等价定点数。校验 `0 < stop_lower < grid_lower < grid_upper < stop_upper`，同时校验品种、时间及有限数值。运行时直接导出计算对象，不解析中文消息文本，也不重新独立计算一套边界。

### 4.2 更新规则

1. 每次数值发送有唯一 `reference_id`、递增序号和出口进程会话 ID。发送前记录 PREPARED/SENDING；实时组件一旦看到未决的更新，暂停旧参考下的操作建议。发送成功意味着通知服务接收成功，不等于用户已阅读。
2. 明确成功后以发送确认时间为 `effective_at`，整体激活四边界并记录 SENT。先更新内存权威版本，再重试持久化及进程交接；若持久化或交接失败，进入 SYNC_UNCERTAIN，暂停操作建议，**不得回退旧版继续正常预警**。旧边界仅作历史记录。
3. 明确失败记录 FAILED 后可以恢复旧有效参考；发送结果未知记录 UNKNOWN，不能假定失败或成功。冷却跳过和计算失败不创建更新。每次发送前后及实时通知出队前均校验权威版本；Webhook 发送与本地提交无法组成原子事务，必须记录这个边界，不承诺端到端恰好一次。
4. 发送前持久化不可用不能阻止原小时推送：使实时交接失效并暂停操作建议。实时进程必须取得小时出口的当前会话/未决状态确认才进入 VALID；失联即 SYNC_UNCERTAIN。不能单凭磁盘旧 SENT 自动恢复。出口重启后若不能证明最后发送状态，等待下一次明确成功数值建议，不索要用户确认，也不额外绕过小时冷却。
5. 只有风险警报而无新边界时保留旧数值参考，记录背景状态；不能推断用户已平仓。新成功消息边界非法时进入 INVALID，不退回旧建议假装有效。
6. 整体切换边界，保留行情窗口，清除旧参考候选和持续计时，保留 episode 的必要去重信息。新参考已越界时写“新建议参考已越界”，不能写价格刚刚穿越。
7. 幂等约束覆盖 reference_id、事件 ID 和本地提交；渠道未知结果仍可能重复投递，消息附事件 ID。存储使用事务及唯一键，故障记录不得伪造 SENT。重启只恢复已确认发送、无更高未决版本且经当前出口会话确认的快照。

### 4.3 缺失与过期

`reference_status` 分为 `VALID`、`STALE`、`MISSING`、`INVALID`、`SYNC_UNCERTAIN`。年龄从 `effective_at` 计算，超过配置 `reference.max_age_seconds` 为 STALE；不得每小时自动延长年龄。

- VALID：允许正常分级。
- STALE：停止提前终止建议；新鲜价格触及旧建议终止价仍生成事实事件，明确写“参考已过期，已触及旧建议终止价，请核实 APP”，不能称最新有效建议。
- MISSING／INVALID／SYNC_UNCERTAIN：不生成当前有效边界距离或操作建议。若持有此前已确认发送且校验合法的历史快照，只对最新一份这样的快照记录 `HISTORICAL_REFERENCE_CROSSED`：明确参考版本、发送时间、同步不确定原因，不称当前建议或账户实际终止价。未确认发送的 PREPARED/SENDING/UNKNOWN 边界及非法快照不能作为该事件依据；连历史边界也没有时只报告监控降级，不能捏造穿越。
- 历史参考事实不进入当前风险状态升级链；按方向及历史 reference_id 独立去重，每次故障期间每方向只记录一次，重复通知只受投递重试约束。新的已确认参考可以建立新的去重键。行情必须新鲜；无新行情不生成事件。
- 新有效快照到来后恢复，不需要用户确认。

### 4.4 降级对用户的可见性

alert 模式首次进入同步不确定、参考缺失或非法、行情中断、存储/投递故障时，生成独立健康事件，不受普通预警冷却阻挡；同原因持续故障按 health 间隔去重，实质恢复后发送一次恢复事件。正常发送期间的未决状态也按此规则处理，后续可优化通知合并，但不能隐瞒操作建议暂停的时间。shadow 模式只记录，研究参考级提醒为受控例外（见 §9.3）。

降级模板：“实时预警已降级：{原因}。从{时间}起暂停基于最新建议的提前退出提示。{有历史快照：仅记录参考版本X的价格穿越／无历史快照：无法判断建议终止价穿越}。系统未修改币安APP设置，请自行核实。”恢复模板写恢复时间、确认参考及剩余预热状态；参考恢复但行情尚未预热，不能称全部预警已恢复。

健康事件也可能受同一通知渠道故障影响；本地健康状态及日志必须可查，不能承诺用户一定及时获知。明确成功的新参考即使只在出口内存已知，未被实时层可靠取得前也不能伪造对应事实。

## 5. 实时行情与特征口径

### 5.1 初版数据选择

初版研究与回放采用 **ETHUSDT 永续成交价**，在线对应聚合成交流；通知必须标注“成交价口径”。这与当前已取得的事件数据一致，是研发选择，不是对用户 APP 止损触发口径的推断。

币安行情来源参考：

- [USDⓈ-M WebSocket Market Streams](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/ws-streams/market)
- [USDⓈ-M REST Market Data](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)

历史 `/fapi/v1/aggTrades` 支持聚合成交回放。端点地址、连接要求和历史可用范围在实施时按官方文档核对，不把某个历史 REST 保存期限当作长期存储保证。

不把成交价聚合 K 线和标记价格 K 线混用。将来若选择标记价格预警，应建立同口径的数据与独立验证；不得用本次成交价的 3.406 秒作为标记价格系统实测结果。不会因需要统一价格口径而增加自动交易或账户读取。

### 5.2 时间与处理

同时保存 `event_time`、`received_at`、本地决策时间和通知各时间戳。交易所事件时间用于窗口，单调时钟用于本地超时。日志使用 UTC 毫秒，面向用户显示北京时间。

每条新有效成交都进行边界和终止价检查。常规特征与持续性计时固定按每秒一个事件时间采样点计算；不能把“实时”实现为每 3 分钟唤醒一次，也不能因批量处理只保留最后价而丢失中途越界。

持续性从首个满足**完整分支条件**的整秒采样点 t0 起算；在后续每个整秒点都成立且 `t-t0 >= hold_seconds` 时触发。例如 10:01:15 起成立、hold=3，则最早 10:01:18 满足，不回推至逐笔进入缓冲区的 10:01:14.591。漏掉采样、条件中断、参考切换均清零计时，不用“累计3个样本”代替3秒。极近边界和穿越事实逐笔判断，不采用该计时。补验为事件时间理想回放；线上延迟仍另计。

### 5.3 滚动特征

记 `p(t)` 为最新有效成交价，`p(t-w)` 为不晚于 `t-w` 的最后一笔成交。参考笔与目标时刻距离不能超过 `features.max_anchor_gap_seconds`；没有完整有效窗口时该特征为不可用，不填零。

```text
有符号滚动涨跌幅 r_w(t) = p(t) / p(t-w) - 1
向下不利变动 a_w_down = -r_w
向上不利变动 a_w_up   =  r_w
w ∈ {60, 180, 300} 秒
```

百分比配置使用比例值，例如 `0.005` 表示 0.5%。3 分钟和 5 分钟窗口共享数据，OR 组合用于覆盖不同速度变化，不是两个独立确认信号。窗口集合固定为 60/180/300 秒，采样固定为 1 秒；配置中的对应字段只能取这两个常量，修改即拒绝加载。

持续单边程度采用同一窗口内整秒采样价格序列 `q`：每个整秒采样点只取不晚于该时刻的最后一笔成交，不提前读取该秒后续成交。参考笔的时间距离同样受 `max_anchor_gap_seconds` 限制。

```text
方向效率 E_w = |q_last - q_first| / Σ|q_i - q_(i-1)|
分母为 0 时 E_w = 0；采样缺口超限时特征不可用。
```

研发方案用 `E_300` 区分单边推进与往返震荡；其阈值必须验证。实时不重算未收盘小时 ADX 来冒充已确认状态。小时 ATR 可作为日志背景和后续归一化对照，初版基础规则不依赖 ATR，也不直接把小时 ATR 当作 3 分钟标准差。

5m／15m 已收盘确认作为回放对照组保留，不是实时告警的必经步骤。“从小时高点回撤”的原规则不进入首版，避免自然小时重置及只覆盖下跌的问题。

## 6. 区域、方向和事件分级

### 6.1 对称区域定义

记最新建议为 `SL < L < U < SU`：

| 位置 | 区域 |
|---|---|
| `p <= SL` | 下方已触及／越过建议终止价 |
| `SL < p <= L` | 下方缓冲区，含触及网格下边界 |
| `L < p < U` | 网格区间内 |
| `U <= p < SU` | 上方缓冲区，含触及网格上边界 |
| `p >= SU` | 上方已触及／越过建议终止价 |

跌向下侧和涨向上侧独立检测，规则对称。价格越过终止价的判定优先于距离和涨跌幅条件，不取绝对值把越界误当作安全。

```text
下方缓冲消耗 u_down = (L - p) / (L - SL)
上方缓冲消耗 u_up   = (p - U) / (SU - U)
区间内相对边界距离 g_down = (p - L) / (U - L)
区间内相对边界距离 g_up   = (U - p) / (U - L)
```

`u < 0` 表示尚未进入该方向缓冲区（是否在网格内仍按区域表判断），`0 <= u < 1` 表示缓冲消耗，`u >= 1` 表示终止价越界。缓冲消耗不是亏损比例，也不是触及止损概率。

`g` 只在严格区间内定义，边界点归缓冲区，不以负 g 判断位置。每一方向仅绑定同方向的 a、g、u：下行取 `a_w_down=-r_w`，上行取 `a_w_up=r_w`。

### 6.2 普通异动：提前让用户关注

对每个方向，在 VALID 参考、健康行情和完整特征条件下：

```text
变化成立 = a_180 >= normal.return_3m OR a_300 >= normal.return_5m
方向持续 = E_300 >= normal.min_efficiency
位置相关 = 相应方向处于缓冲区 OR（严格区间内 AND g_direction <= normal.near_grid_fraction）
普通候选 = 变化成立 AND 方向持续 AND 位置相关
```

候选在每秒采样上连续成立满 `normal.hold_seconds` 后，生成普通异动事件；任一条件不成立、数据不可用或参考改变则取消并重新计时。未满持续时间只记录，不发提醒。满持续时间只产生一次事件，不每秒重复推送。

信息语义为“持续向某方向运动，请提前关注并准备操作”，不是“保证继续单边”或“必须立即止损”。没有新边界的小时风险警报可附作上下文，但不作为额外强制门槛。

### 6.3 紧急风险：区间内、外都可直接进入

紧急规则与普通规则并行，不要求普通候选先成立。符合下列任一分支可生成紧急事件：

| 分支 | 条件 | 确认方式 |
|---|---|---|
| 区间内快速恶化 | 在区间内且 `g <= urgent.near_grid_fraction`；`a_180 >= urgent.return_3m OR a_300 >= urgent.return_5m`；`E_300 >= urgent.min_efficiency` | 连续成立满 `urgent.hold_seconds`，不等 K 线收盘 |
| 缓冲区继续恶化 | `0 <= u < 1`，且 `a_60 >= urgent.buffer_return_1m` | 同上；缓冲内的运动仍需方向对应 |
| 极度接近终止价 | `urgent.critical_buffer_fraction <= u < 1`，且处于相应方向缓冲区 | 新有效成交直接判断，不强制持续时间、涨跌幅或特征预热 |

前两分支的计时分别维护，不能交替拼接满足持续时间。第三分支允许缓慢逼近时提醒，避免所有分支都依赖快速涨跌而漏掉慢速单边。

紧急语义为“请立即查看，评估是否提前手动终止”。不承诺尚有几秒可执行；不以当前速度线性外推“必将在某秒止损”。

### 6.4 终止价触及事件

参考为 VALID 或 STALE 且新鲜有效价格满足 `p <= SL` 或 `p >= SU` 时，直接生成 `BOUNDARY_REACHED`。不受普通持续性、紧急持续性、窗口预热或低级别冷却阻挡；若断线恢复后才发现越界，应写“恢复后发现价格已越界”，不补造穿越时刻。

通知要求用户核实 APP 中的网格与止损状态，不宣称已平仓、已成交或仍可提前退出。同一次判断同时满足多个风险级别时，仅生成最高级别风险通知；历史已锁存事实不能因此删除。单笔直接跳过缓冲区的事件单独标记 gap_crossing；仍检查此前是否已有预警，不据此直接认定无法提前预警。

## 7. 去重、恢复与状态管理

### 7.1 状态模型

每个方向维护 `IDLE → CANDIDATE → NOTICE → URGENT → BOUNDARY_REACHED`，允许任意低级别直接跳到更高级别；反向检测独立，不能被另一方向的普通冷却压制。数据健康和参考状态为独立维度，不用一次“恢复行情”清除已发送记录。

事件包含 `episode_id`、`reference_id`、方向、当前成立级别、历史最高级别、首次满足时间、最近发送时间、规则配置哈希及条件快照。当前级别可随条件解除而下降，历史最高级别用于去重，不等同于当前风险。行情中断或参考不确定时当前风险为 UNKNOWN，不延续旧风险标签冒充实时状态。

各方向每次评估按下表从上到下选取当前状态（参考/行情失效单独覆盖）：

| 条件 | 当前状态 | 历史最高状态与通知 |
|---|---|---|
| 价格在同方向终止价外 | BOUNDARY_REACHED | 升级立即建事实事件 |
| 任一紧急分支完整成立 | URGENT | 升级立即建事件 |
| 普通条件已满持续时间 | NOTICE | 按去重建事件 |
| 仅普通或紧急持续候选未满 | CANDIDATE | 不发风险消息 |
| 均不成立，但未满足整体恢复 | IDLE，episode 保留 | 不重复发送历史最高级别 |
| 完整恢复成立 | IDLE，关闭 episode | 下一次同向风险创建新 episode，可立即提醒 |
| 数据缺口/预热/参考失效 | 当前风险 UNKNOWN | 清计时，保留历史，不视为恢复；新鲜价格可判定的事实按第 8 节处理 |

因此紧急解除但普通仍满足时降为 NOTICE；均解除时降为 IDLE，不能一直显示“当前紧急”。历史最高级别只用于审计和去重。瞬时边界事实另行锁存，不因当前状态下降被抹去。

### 7.2 去重规则

- 普通、紧急、终止价触及各有自己的重复提醒间隔。
- `NOTICE → URGENT`、任意状态到 `BOUNDARY_REACHED` 必须绕过低级别冷却。
- 普通条件不再成立时，停止普通重复提醒；紧急事件仅在紧急条件仍成立时按其间隔重复；仅由极近边界分支支撑时，每 episode 只提醒一次，不按间隔重复。后来出现持续恶化分支可追加一次原因升级提醒，之后遵守紧急间隔；触及终止价始终直接升级。不得拿未恢复的历史最高级别持续发送不再符合现状的警报。
- 同一波动过程中的来回抖动不建立新 episode，也不绕过同级去重。
- 建议快照变化后重新评估，但不单凭 `reference_id` 改变就重复刷屏。同一方向已有提醒且未恢复时，除级别升级、原重复间隔到期或新参考已越界外，不立即重复。
- 两个方向同一调度批次均有事件时可合并，必须分别写清方向和参考线，不能混合计算距离。

### 7.3 恢复和重新布防

对某一方向，价格回到区间内且 `g >= recovery.inside_fraction`，并且该方向的普通／紧急条件均不成立，持续满 `recovery.hold_seconds` 后关闭 episode，重新布防。恢复只表示预警条件解除，不表示用户可以重新开网格。

若窗口尚未预热，不能凭“特征不可用”判定恢复。跨数据缺口不累计恢复或触发持续时间。新快照替换按第 4 节重置候选，但保留必要的发送去重记录。

## 8. 数据可靠性、降级与通知

### 8.1 行情健康

校验品种、正价格、时间戳、唯一 ID；重复记录丢弃，在线迟到记录只用于审计、补齐及未来窗口连续性，不修改已经作出的候选、计时或通知；不能把旧成交当最新价格发送提醒。相同毫秒的多笔记录按聚合成交 ID 排序。

检测 ID 缺口、超过配置的接收停顿或数据时延后进入 DEGRADED：暂停依赖完整滚动窗口的普通／前两类紧急规则，清除持续计时。最新价格新鲜时，VALID 允许终止价事实与极近边界分支，STALE 仅允许标注过期的终止价事实；其他参考状态不新建当前建议边界事件，但可按第 4.3 节生成独立的历史参考穿越事实。均标明窗口缺口。

断线时不使用最后价格制造新事件。后台按上次 ID 尝试限速补齐，重连后先去重、核对连续性并恢复完整窗口。历史补齐用于日志与重建，不补发已经失效的旧预警；只对恢复后的最新状态进行判断。

所有数据流均应具备心跳、自动重连、退避、启动预热、重启恢复和处理积压监控。不承诺零延迟或无限可靠，维护峰值负载下的决策延迟分布。

### 8.2 通知投递

复用现有 grid 通知渠道，小时消息与实时消息使用独立事件去重，实时发送采用异步队列，不阻塞行情与小时巡检。高优先级可淘汰尚未发送且已过时的低优先级事件；小时原有通知规则不因此被取消。

发送失败记录原因并退避重试。普通／紧急建议每次首次发送和重试前核对有效参考、当前数据新鲜度和条件是否仍成立；超过 `delivery.event_ttl_seconds` 的事件仅留档。

`BOUNDARY_REACHED` 与 `HISTORICAL_REFERENCE_CROSSED` 都是指定参考下已发生的价格事实（后者不具有当前建议语义），首次检测后锁存：不适用普通／紧急的 30 秒 TTL，不能因反弹或排队超时静默删除；持久化 outbox 保留待投递事实。若发送时已反弹，必须写“曾于某时触及，当前价格已回到某位置”；参考已切换则写明旧参考版本，只提示核实该次事件。锁存不会使后续重复提醒永久有效，重复仍要求最新价格处于对应越界区域。超过 30 秒首次送达时标题改为“历史触及事件补报”，展示事件时间和延迟，不冒充当前紧急操作建议。可合并积压事实摘要，但必须分别写清各事件方向、参考线、事件时间及参考版本，底层独立记录不合并删除；不保证渠道故障期间送达。

渠道结果不明确时保留未知状态，不宣称用户已收到。记录发送确认时间而非用户阅读时间，不能用事件生成时间冒充通知成功时间。

通知队列与 worker 均为新增能力：默认复用 grid webhook，共享限流风险需要实测，不假定独立队列就消除渠道竞争。实时 worker 使用新增单次发送适配，重试由调度器安排，不直接调用会内部长时间退避的旧发送路径；小时调用接口保持兼容。优先处理触及事实，其次紧急、普通、健康消息；容量超限先淘汰过时普通消息，事实保留持久化 outbox。磁盘失败时报告投递降级并保留可用内存记录，不能保证进程崩溃后仍不丢失。

持久化容量与清理：已送达 outbox 记录按 `storage.sent_retention_days` 清理，事件审计按 `storage.audit_retention_days` 清理；未送达或结果未知的事实不因年龄删除。后台定期 checkpoint，并统计 DB、WAL、SHM 合计大小及可用磁盘空间；`storage.max_bytes` 是写入准入水位，不是文件系统硬上限，须预留事务/WAL空间。达到水位时先清理到期的已送达记录、暂停非必要逐秒持久化，仍不足则标记 STORAGE_DEGRADED，报告积压数量与最老时间。不能悄悄删除未送达事实来满足容量限制；内存保留和故障恢复后的补写只能尽力，磁盘故障加进程崩溃可能丢数据，明确记录缺口。归档未送达记录必须保留可恢复投递索引，不能视为发送成功。

### 8.3 用户消息字段与模板

以下模板适用于正常有效参考；历史参考事实必须改用“历史建议时间／历史参考线”，健康消息按第 4.4 节，不套用当前操作建议模板。

每条实时风险消息至少包含：级别、方向、检测时间、当前价格及口径、最新建议时间、建议区间、相关终止价、所在区域、触发原因。窗口涨跌幅只在有效时展示；缓冲消耗只在相应缓冲区时展示。

普通异动模板：

```text
⚠️ 【实时预警】下行异动持续，请提前关注
检测时间：{北京时间}
当前成交价：{price}
最新建议：{reference_time}，区间 {L}～{U}
建议终止最低价：{SL}
当前位置：网格区间内
最近3分钟／5分钟变化：{有效窗口值}
触发原因：持续单边下行，正在接近建议下边界
建议提前打开币安APP关注；是否终止由您判断。
参考按最新成功推送建议更新，未核对账户实际设置。
```

紧急模板标题为“🚨 【实时预警】风险升级，请立即查看”，正文列出对应的区间内快速恶化、缓冲区继续恶化或极近边界原因，建议“评估是否提前手动终止网格”。上涨采用完全对称的文案。

越界模板标题为“🚨 【实时预警】已触及／越过建议终止价”，正文为“请核实币安APP中的网格与止损状态；系统未核实实际执行结果”。参考过期、同步故障、行情缺口必须明确标注，不能伪装成正常建议。

## 9. 配置、候选参数与运行模式

### 9.1 配置组织

在现有策略配置中新增独立 `realtime_alert` 节，继续通过现有配置加载器读取。旧 `market`、`grid`、`margin_guide`、`signal_bot` 不迁移、不改名，不另建一份容易与线上漂移的全策略参数文件。

回放读取同一规则 schema，研究覆盖文件只覆盖 `realtime_alert`。每次实验保存完整合并参数、版本和哈希；修改阈值后产生新的实验版本。AI 调优在首版不得自动激活实时预警参数。

运行模式：

- `enabled: false`：新组件不运行，原小时逻辑照常工作。
- `mode: shadow`：计算并记录候选通知；除 §9.3「研究参考级提醒」这一受控例外，所有新增实时／故障消息均不发到用户；小时消息不受影响。shadow 模式允许研究 profile 使用 `features.e_resample_seconds` 研究字段参与实验（默认 1），alert 模式对未声明字段拒绝加载（§5.3 固定窗口／采样仍强制校验，不受影响）。
- `mode: alert`：发送实时提醒；要求该配置具备第 10～11 节验证记录。不得仅靠将示例开关改为 true 就称已通过上线验收。

### 9.2 研究种子配置

以下数值仅用于启动回放和影子对照，**不是当前线上值、不是推荐交易参数，也不是已验证最优值**。基础规则已定义，生产阈值由实验结果形成版本化配置。技术时限同样需负载和故障注入验证。

    notice_seconds: 1800

    max_silence_seconds: 5

    path: /app/data/grid_realtime.sqlite3

校验要求：所有秒数为正；涨跌幅门槛为正比例；效率和缓冲比例位于 `(0,1]`；区间内接近比例位于 `(0,0.5)`；`urgent.near_grid_fraction <= normal.near_grid_fraction < recovery.inside_fraction < 0.5`；紧急效率与涨跌幅门槛不低于普通门槛；`urgent.hold_seconds <= normal.hold_seconds`；`repeat.boundary_seconds <= repeat.urgent_seconds`；重试/重连最大间隔不小于初始值；队列容量、存储容量和保留天数为正整数；`reference_sync.max_silence_seconds >= 3 * reference_sync.heartbeat_seconds`；`storage.busy_timeout_ms / 1000 < reference_sync.max_silence_seconds`；固定窗口及采样值不得修改。存储路径必须是已挂持久卷的绝对路径；busy_timeout、保留期和容量水位分别用于锁等待、后台清理与写入准入；transport 管行情心跳、重连及补齐限速，reference_sync 管独立心跳周期和会话确认超时（本例1秒/5秒为待压力验证研究值，不靠任意放宽到30～60秒掩盖故障），delivery 管队列容量与单次发送失败后的退避。缺少必填字段时拒绝启用该 profile，不静默使用硬编码回退。

只选少量有解释性的候选：滚动 3m／5m 跌涨幅、持续时间、方向效率、接近位置、缓冲紧急比例和恢复滞回。固定小时策略；不同时优化 ADX、ATR、网格数量、杠杆和保证金。每轮比较必须保留旧 profile 作为基线。

### 9.3 研究参考级提醒（shadow 受控例外）

shadow 模式默认不向用户发送操作建议；唯一例外是「研究参考级提醒」，用于 30 天统计验证期间让用户在真实运行中观测候选事件、反馈误报／漏报。它是研究反馈通道，不是操作建议，也不构成实盘预警已验收的凭证，受三重护栏约束：

- **文案边界**：每条以「【研究参考】」开头，明确标注「未经样本外验证、可能误报或漏报、不构成操作建议」，不套用第 8.3 节操作建议模板，不含“立即操作／建议终止”等指令语义；紧急／越界事实可以即时发出一次，但必须沿用研究参考标注。
- **频率护栏**：使用独立频率上限 `shadow_research.notice_interval_seconds`（研究种子默认 1800，须不小于 `repeat.urgent_seconds`），同一 episode 内不重复；频率上限是配置项，不硬编码。
- **可关闭开关**：`shadow_research.enabled`（默认 `false`）。关闭后 shadow 严格只记录、不发任何新增消息。开关须人工显式开启，不因切换 profile 或研究参数而自动打开。

`shadow_research` 为可选配置节，缺失时按默认（`enabled=false`）处理，不因此拒绝加载 profile。

## 10. 验证设计与指标

### 10.1 三阶段验证

1. **事件复现**：用当前两份文件及原始 09:05 建议验证数据处理与穿越时间。只检验实现正确性，不能证明长期有效。
2. **独立历史样本**：加入多日正常震荡、慢速单边、快速单边和上涨事件。按时间划分开发段与未参与选参的验证段；2026-10-07 已参与设计，不能再称样本外。
3. **线上影子运行**：不发送新增操作建议，记录真实接收延迟、候选事件、失败和重复情况。报告形成后才决定是否开启 alert 模式。

首次历史对照至少覆盖 30 个完整自然日，单独列出不足的行情类型；这是研究样本最低范围，不是充分有效性的证明。行情不足或任一类型缺失时维持影子模式，继续采样。极近边界分支分别评估慢速逼近、临界附近横盘及快速跳越；本事件的0.746秒不能外推为慢速逼近场景效果。预注册各行情类型的事件数与置信区间宽度目标；覆盖率等二项比例报告样本数及 Wilson 95% 区间，同日/同趋势聚集事件另用按日聚类重采样评估，不能视为独立样本。零事件记不可评估，30 天不替代事件数量要求。

### 10.2 对照组

| 组别 | 目的 |
|---|---|
| 原小时策略 | 衡量新增提醒相对原有风险通知的增量，不改变原有止损设置逻辑。 |
| 原文档 3m 收盘 1.5% → 15m 收盘 2% | 保留被替代方案作为对照。 |
| 仅出区间／缓冲区升级 | 检验其提前量是否满足人工操作需要。 |
| 实时滚动异动 + 区间内升级 + 缓冲区升级 | 本需求的研发候选。 |
| 普通异动增加 5m 或 15m 收盘确认 | 量化过滤噪音与丢失提前量的交换，不预设更长确认一定更好。 |

### 10.3 防止未来数据与比较口径

- 建议从实际成功发送时刻起生效。历史缺少原文的记录必须标为重建；缺失边界的时段不凭空补齐。
- 新消息没有边界时保留最后数值参考，并遵守参考有效期；不能把每小时计算值当作已推送值。
- 已收盘指标只能在对应收盘后使用。事件回放严格按时间／ID 顺序，不能利用一根分钟 K 线尚未发生的最高最低价。
- 分钟数据只支持分钟级探索；秒级提前量必须用同口径细粒度数据。窗口预热数据与评估数据分开标记。
- 滚动窗口重叠触发合并为 episode，不能把它们当独立样本夸大命中次数。
- 参考切换本身引起的越界单独归类，不混入行情穿越事件。

回放区分两种模式：event_time 理想回放按事件时间/ID排序，仅衡量行情信号；arrival_time 在线等价回放按记录的接收顺序、决策时钟和丢包处理。原始文件没有 received_at，因此只能完成前者，不能证明线上等价。AC-18 要求同一模式重复一致，不要求两种模式结果相同。整秒采样有 0～1 秒调度等待，并非固定锁存 1 秒；记录采样、接收、决策及发送延迟，逐笔边界检查不等整秒。

### 10.4 必须输出的指标

| 指标 | 定义或要求 |
|---|---|
| 终止价事件覆盖率 | 有效参考期内首次行情穿越事件中，提前产生有效预警决策的占比；在线另报渠道发送成功的覆盖率，不能冒充用户已读；缺数据事件另列。 |
| 提前量分布 | `首次同方向穿越时间 − 预警决策时间`，报告中位数、分位数和负值；同时报告相对原小时风险通知的增量。 |
| 可操作覆盖率 | 从提前量扣除通知延迟和人工反应时间后仍为正的占比；人工延迟至少比较 30／60／120 秒，作为假设场景。 |
| 告警负担 | 每日普通／紧急／越界事件数、重复次数、最高密度，不以固定每日次数当盈利目标。 |
| 误报代理 | 分级报告：普通提醒后未进入同向缓冲区也未升级且已恢复；紧急提醒后未触及同方向终止价且已恢复。各用预注册的 15／30／60 分钟观察窗；被数据结束、缺口、参考替换截断的样本另列，不记成功或误报。越界事实不按预测误报计。 |
| 误退出成本 | 有完整网格成交模拟或实际记录时比较提前退出与继续运行；没有时只报告价格路径，不能用误报代理直接冒充资金损失。 |
| 数据与服务质量 | 缺口、乱序、积压、接收延迟、决策延迟、发送失败和建议过期占比。 |
| 参数稳定性 | 不同时间段／行情类型和相邻阈值的表现，披露全部比较次数。分别登记唯一 profile 数、数据划分数、回放模式数、有效组合数和实际运行次数（含重复），不能把重复运行算独立证据。另报极近边界震荡 episode、原因追加及重复提醒数量。 |

真正的收益比较必须计入手续费、滑点、人工延迟、提前退出丢失的配对收益及重建成本，并明确小时警报后的用户响应假设。只有行情和建议时，不输出“平均少亏3%”等结果。

### 10.5 上线结论的形成

实验报告必须冻结：选用 profile、数据范围、开发／验证划分、上述全部指标，以及选参前登记的可接受告警负担和可操作覆盖率目标。目标不能看完验证段后反向修改。

本文件不凭单次事件虚构业务通过率。基础数据、功能和可靠性验收可以先完成；没有独立验证结果及目标对照时，只能判为“可影子运行”，不能判为“实盘提醒效果已验收”。

若独立验证始终达不到预注册的人工可操作覆盖率/告警负担目标，不上线“提前退出提醒”。可保留影子研究；另行评估仅提供边界事实和监控健康状态的有限功能，但必须明确它不满足提前退出目标，不能自动换名当作原目标验收成功。
