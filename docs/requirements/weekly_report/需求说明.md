# 交易周报 — 需求说明

**文档版本**: v2.0
**最后更新**: 2026-05-15
**维护者**: 项目团队

---

## 一、功能概述

交易周报是跨策略的每周交易统计与推送模块。每周一北京时间 **09:20** 自动统计过去一周（周一~周日）的交易数据，通过飞书 Webhook 推送到指定群聊。

覆盖策略：MTPCS 策略、新币做空策略、网格交易策略。

---

## 二、推送内容

### 2.1 标题

```
📊 交易周报 — MM/DD~MM/DD
```

### 2.2 策略概况（每个策略一个摘要）

```
📈 MTPCS策略
   活跃天数：X 天    日均信号：X.X 个
   本周委托：X 笔
   本周成交：X 笔
   本周平仓：X 笔（X盈/X亏，胜率 X.X%）
   已实现盈亏：+X.XX USDT
```

### 2.3 币种明细表格

```
  ┌────────────┬──────┬──────┬──────┬──────────┬──────────┐
  │ 交易对     │ 委托 │ 成交 │ 平仓 │  盈亏    │  胜率    │
  ├────────────┼──────┼──────┼──────┼──────────┼──────────┤
  │ BTCUSDT    │   10 │   10 │    5 │ +X.XXXX USDT │  100.0% │
  │ ETHUSDT    │    8 │    8 │    3 │ +X.XXXX USDT │  100.0% │
  └────────────┴──────┴──────┴──────┴──────────┴──────────┘
```

### 2.4 跨周持仓标注

当某币种存在前周条件单在本周触发成交时，追加标注：
```
    └─ 其中 X 笔为前周条件单成交
```

当平仓数 > 0 但委托数 = 0 时，追加说明：
```
  ℹ️ 本周委托=0但平仓=X：全部为前周开仓本周平仓
```

### 2.5 数据质量告警

当数据源非正常（API 降级等）时：
```
  ⚠️ 数据源：本地缓存（部分数据可能不完整）
```

当勾稽校验不通过时：
```
  🚫 数据异常：成交(X) < 平仓(X)，请联系管理员
```

### 2.6 全策略汇总

```
📊 全策略汇总
   活跃策略：X 个
   总委托：X 笔
   总成交：X 笔
   总平仓：X 笔（X盈/X亏）
   总盈亏：+XX.XXXX USDT
```

## 三、数据采集逻辑

### 3.1 三个核心指标的数据来源（统一数据源架构）

**v2.0 重要变更**：三个指标统一从 Binance API 采集，不再混用数据库和 API 多源数据，保证勾稽关系正确。

| 指标 | 数据源 | API | 过滤条件 |
|------|--------|-----|---------|
| **委托** (order_count) | Binance allOrders | `/papi/v1/um/allOrders` | `order["time"]` 在本周范围内 |
| **成交** (fill_count) | Binance allOrders | `/papi/v1/um/allOrders` | `order["status"]=="FILLED"` AND `order["updateTime"]` 在本周范围内 |
| **平仓** (closed_count) | Binance income | `/papi/v1/um/income` | `incomeType=="REALIZED_PNL"` AND `time` 在本周范围内 |

### 3.2 allOrders 分批查询机制

Binance allOrders API 限制单次时间窗口最大 7 天。为实现 4 周回溯窗口（覆盖跨周条件单），采用分批查询：

```
4周回溯窗口
├─ 第1批: 04/13 - 04/20 (7天)
├─ 第2批: 04/20 - 04/27 (7天)
├─ 第3批: 04/27 - 05/04 (7天)
└─ 第4批: 05/04 - 05/10 (7天)
```

每批一次 API 调用，结果合并后统一过滤统计。

### 3.3 活跃天数与日均信号

从策略专属数据库表统计本周内有信号记录的天数：

| 策略 | 数据源表 |
|------|---------|
| MTPCS 策略 | `btc_eth.trade_signals` |
| 新币做空策略 | `new_coin.short_signals` |
| 网格交易策略 | `grid.grid_signals` |

## 四、勾稽校验规则

### 4.1 硬约束（代码层强制校验，不通过则告警）

| 约束 | 表达式 | 说明 |
|------|--------|------|
| H1 | `fill_count >= closed_count` | 每笔平仓至少需要 1 笔成交（出场单不可凭空产生） |
| H2 | `closed_count == wins + losses` | 平仓数 = 盈 + 亏，天然成立 |

### 4.2 软约束（提示但不阻断）

| 约束 | 表达式 | 说明 |
|------|--------|------|
| S1 | `order_count >= fill_count` | 通常成立，但前周条件单本周触发会打破 |
| S2 | `order_count == 0 AND closed_count > 0` | 全部为前周开仓本周平仓，正常现象 |

### 4.3 降级策略

当 Binance API 不可用时：

| 降级等级 | 处理方式 |
|----------|---------|
| 部分失败 | 单币种失败不中断，标记 `data_quality="degraded"` |
| 全部失败 | 降级到 `trade_records` 本地数据库 |
| 彻底失败 | 返回空结构，报告中标注"采集失败" |

## 五、配置说明

配置文件: `strategies/weekly_report/config.yaml`

```yaml
weekly_report:
  schedule:
    day_of_week: mon   # 每周一
    hour: 9            # 北京时间 09:00
    minute: 20         # 09:20 推送
  feishu_webhook: ""   # 空值时优先 FEISHU_WEEKLY_REPORT_WEBHOOK，其次 FEISHU_DAILY_REPORT_WEBHOOK
  strategies:
    btc_eth:
      name: "MTPCS策略"
      emoji: "📈"
    new_coin:
      name: "新币做空策略"
      emoji: "📉"
    grid:
      name: "网格交易策略"
      emoji: "🔲"
```

**环境变量**:
- `FEISHU_WEEKLY_REPORT_WEBHOOK`: 周报专用飞书 Webhook（优先级最高）
- `FEISHU_DAILY_REPORT_WEBHOOK`: 日报飞书 Webhook（兜底，周报复用）

## 六、调度机制

使用 APScheduler，在容器启动时注册定时任务：
- 每周一北京时间 09:20 执行 `send_weekly_report()`
- 容器启动后立即执行一次（补发可能的遗漏）

---

## 七、数据采集顺序

```
collect_all()
  1. _fetch_unified_orders()    ← allOrders API（分批），产出 order_count + fill_count + cross_week_fills
  2. _fetch_weekly_pnl()        ← income API，产出 wins + losses + total_pnl
  3. _validate_consistency()    ← 勾稽校验
```
