# MTPCS 激进版 —— 需求与实现说明

**版本**: v2.6.0-aggressive-1
**创建日期**: 2026-09-10
**关联原版**: MTPCS 策略（strategies/btc_eth/，v6.21+）

---

## 1. 需求背景

原版 MTPCS 策略已稳定运行，但受限于较严的入场门槛与风控尺度，在特定行情下信号触发偏少、仓位偏保守。为了在不影响生产稳定性的前提下，探索更高风险偏好下的收益空间，需要一套独立的激进参数版策略。

## 2. 核心需求（5 项）

| # | 需求 | 实现方式 |
|---|------|---------|
| 1 | 保持原版 MTPCS 策略不变，另做激进版，**交易代码不变、只调参数** | 复制 `strategies/btc_eth/` → `strategies/btc_eth_aggressive/`，仅改写身份标识（btc_eth→btc_eth_aggressive、MTPCS策略→MTPCS激进策略），参数在 config.yaml 激进化 |
| 2 | 激进版订单与原版订单在数据库中**单独分开** | 独立 schema `btc_eth_aggressive`；共享 `trading.trade_records` 以 `strategy`="MTPCS激进策略"区分；激进版专属表 `btc_eth_aggressive.{trade_signals,positions,trades}` |
| 3 | 激进版与原版**共用 ai-tuner 月度资金计划** | 激进版不参与 `capital_allocation.participating_strategies`；`config_updater` 的 `_SHARED_FUND_MIRROR={"btc_eth":["btc_eth_aggressive"]}` 把原版分配结果镜像写入激进版 config |
| 4 | 新建一套 **ai-tuner 覆盖层 config** 给激进版 | 独立 `strategies/btc_eth_aggressive/tuning_overrides/`（V20260910.yaml + `.active` 指针）；ai_tuner 通过 `load_strategy_config` 合并 |
| 5 | docs 文件夹**单独分开激进版所有项目文件** | 独立 `docs/requirements/btc_eth_aggressive/` 目录 |
| 6 | 激进版 webhook 推送**与原版一致** | `shared/notification.py` 新增 `FEISHU_WEBHOOK_BTC_ETH_AGGRESSIVE` 映射；`.env` 配置指向原版 webhook 地址 |
| 7 | 上线激进版后**原版不停、继续运行** | 激进版独立容器 + 独立 schema + 独立调度，`up -d` 只操作激进版容器，不触原版 |
| 8 | 与原版**错峰调度**（每小时 **15 分**跑） | 激进版 config `strategy.schedule.cron="15 * * * *"`（原版保持 `5 * * * *`） |
| 9 | **只部署激进版**（不影响原版） | 新增 `deploy_aggressive.sh` 激进版定向部署脚本，按需重建机制，不动其他容器 |
| 10 | **分批止盈与原版一致（2026-09-16）** | 与原版 v6.30 同步修复，分批止盈调整为 TP1 止盈 30% + TP2 止盈 40% + 剩余 30% 尾仓交移动止损，硬止损全仓单保留；S/A/B/C 四等级统一生效 |

## 4. 隔离与共享机制细节

### 4.0 调度与通知（需求 6/8）

- **错峰调度**：激进版 `strategy.schedule.cron="15 * * * *"`（每小时 15 分），原版保持 `5 * * * *`（每小时 5 分）。两者错峰，避免同一时刻并发分析竞争 K 线资源。cron 由 [main.py L423](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/btc_eth_aggressive/main.py#L423) 从 config 动态读取，修改即时生效。
- **webhook 一致**：激进版在 [notification.py「_load_webhook_mapping」](file:///Users/yl/vscode/Binance_quantitative_trading/shared/notification.py#L52) 新增 `FEISHU_WEBHOOK_BTC_ETH_AGGRESSIVE` 环境变量映射；`.env` 中该变量指向与原版相同的 webhook 地址（`01d5e59c-...`），因此激进版（`project="btc_eth_aggressive"`）推送**与原版发送到相同的飞书群**。未来如要独立推送，仅需修改 `.env` 中的 `FEISHU_WEBHOOK_BTC_ETH_AGGRESSIVE`。

### 4.1 订单/数据隔离

- **统一交易记录**：激进版与所有策略共用 `trading.trade_records` 表，通过 `strategy` 列="MTPCS激进策略"筛选。**激进版绝不更新原版（strategy="MTPCS策略"）的订单记录**。
- **策略专属表**：独立 schema `btc_eth_aggressive` 下有 trade_signals / positions / trades 三张表，与原版 `btc_eth` 完全隔离。
- **共享状态表**：`condition_orders`、`frequency_control_state`、`strategy_states` 通过 `strategy_name`/`strategy` 参数区分，激进版写入 `btc_eth_aggressive`。激进版通过 `DATABASE_URL?schema=btc_eth_aggressive` 设定 search_path。

关键点：激进版**无硬编码 `btc_eth.` schema 前缀**，所有独有表均落在自身 schema，共享表均带"激进版"标识。

### 4.2 资金共享

- `ai_tuner/config.yaml` 的 `capital_allocation.participating_strategies` 为 `["btc_eth","new_coin","hrs"]`，**不含 btc_eth_aggressive**，激进版不单独参加资金分配。
- `ai_tuner/allocation/config_updater.py`：
  ```python
  _SHARED_FUND_MIRROR = {"btc_eth": ["btc_eth_aggressive"]}
  ```
  当原版(MTPCS)得到月度分配比例后，`_apply_fund_mirror` 将相同 `capital_limits`（monthly_limit / allocated_ratio）与 `position_sizing.total.account_ratio_cap` 原子写入激进版 config.yaml。激进版因此与原版共用同一资金计划。

### 4.3 AI 调优独立

- 独立 adapter：`ai_tuner/adapters/mtpcs_aggressive_adapter.py`（`MTPCSAggressiveAdapter`），独立采集激进版周度表现。
- 独立覆盖层：`strategies/btc_eth_aggressive/tuning_overrides/`，AI 调优结果写入此覆盖层，不影响原版。
- 在 `ai_tuner/config.yaml` 的 `strategies` 列表注册 `btc_eth_aggressive` 条目及红线参数、参数白名单、参数范围。

## 5. 数据库结构变更

### 5.1 schema

```sql
CREATE SCHEMA IF NOT EXISTS btc_eth_aggressive;
GRANT ALL PRIVILEGES ON SCHEMA btc_eth_aggressive TO trading_user;
```

### 5.2 表

位于 `btc_eth_aggressive` schema（结构同 `btc_eth`）：
- `trade_signals` — 交易信号
- `positions` — 持仓记录
- `trades` — 交易记录

共享表（复用，不重复创建）：
- `trading.trade_records` — 统一交易记录（strategy 字段区分）
- `public.strategy_status`（新增 `btc_eth_aggressive` 状态行）
- `public.strategy_states`、共享 `condition_orders`、`frequency_control_state`

| 项目 | 配置 |
|------|------|
| docker-compose service | `btc-eth-aggressive-strategy` |

| .deploy_config | `DEPLOY_BTC_ETH_AGGRESSIVE=true` |
| 部署脚本 | `auto_package.sh`（VERSION 含 `FILE_MD5_AGGRESSIVE`）、`one_click_deploy.sh`、`remote_deploy_btc_eth.sh`、**`deploy_aggressive.sh`（激进版定向部署，推荐，不影响原版）** |

### 部署注意事项（防部署幻觉）

1. 激进版 Docker 镜像使用 `--no-cache` 构建，防止旧代码打包。
2. `VERSION` 文件记录 `FILE_MD5_AGGRESSIVE`（strategies/btc_eth_aggressive/main.py），部署后 `docker exec trading_system-btc_eth_aggressive cat /app/VERSION` 校验 DEPLOY_ID / MD5 一致。
3. **webhook 环境变量需注入容器**：`.env` 不被 auto_package.sh 打进部署包（被 `--exclude='.env'` 排除），故服务器上的 `.env` 需手动确保包含 `FEISHU_WEBHOOK_BTC_ETH_AGGRESSIVE`。若缺失，激进版通知会回退到调用通知服务而失败。手动补充后需 `docker-compose up -d btc-eth-aggressive-strategy`（**不能用 `restart`**，restart 不会重新注入 env_file 变更）重建容器才生效。
4. 首次部署需先初始化数据库（`01-create-schema.sql`、`02-init-tables.sql`），自动建表由策略运行 `ensure_table_exists` 兜底。

- 激进版运行一段时间后，对比激进版与原版的周度胜率/盈亏/回撤，评估激进参数是否有效
