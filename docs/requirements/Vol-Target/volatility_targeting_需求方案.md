# 波动率目标仓位（Vol-Target 30%/30）落地方案

**文档版本**：v1.1（融合版）
**交付日期**：2026-09-18
**课题名称**：波动率目标仓位在多策略体系中的顶层资金分配应用
**交付状态**：正式交付
**适用范围**：作为多策略体系的**顶层总仓位分配器**，叠加在 btc_eth / new_coin / grid / hrs 之上
**核心结论**：推荐 **目标年化波动率 30%、滚动窗口 30 天、最大杠杆 1.5** 的 Vol-Target 方案。该方案不预测方向，只按波动率反向调整总仓位，目标是大幅压缩回撤并提升夏普与 Calmar。

---

## 一、背景与目标

### 1.1 问题

Top30 等权组合年化约 +18.0%，但最大回撤约 66.0%、波动约 79.9%、夏普仅 0.23。收益可观，"收益-风险"比差。

此前试过方向择时（BTC 均线）控回撤，结果：

| 方案 | 年化 | 最大回撤 | 夏普 | 结论 |
|------|------|---------|------|------|
| 纯等权躺平 | +18.0% | 66.0% | 0.23 | 基准 |
| 均线择时空仓(SMA100) | -12.9% | 57.3% | -0.24 | 压回撤有限，收益崩 |
| 分级降仓(SMA100) | -7.1% | 54.5% | -0.13 | 同上 |
| **Vol-Target 30%/30** | **+21.2%** | **29.1%** | **0.66** | **回撤大降 + 夏普提升** |

**核心洞察**：方向择时（猜涨跌）无法在控回撤同时保收益；波动率目标仓位不赌方向，是唯一同时实现"回撤大幅下降、风险调整后收益提升"的方案。

### 1.2 目标

1. 将组合最大回撤从约 66% 压缩到 30% 以内；
2. 将年化波动从约 80% 压缩到 30% 左右；
3. 年化收益尽量保持在 20% 附近，不出现均线择时式崩坏；
4. 夏普和 Calmar 显著优于躺平；
5. 与现有 PM 账户、risk.yaml 风控、飞书推送无缝衔接。

## 二、定义与核心逻辑

### 2.1 一句话定义

**持仓规模反比于当前市场波动。波动大就少拿，波动小就多拿，不判断方向，只维持目标风险。**

### 2.2 核心公式

设目标年化波动率 `σ_target = 30%`、当前预测年化波动率 `σ_forecast`、最大杠杆 `max_leverage = 1.5`：

```
σ_forecast = std(组合日收益[ t-W : t-1 ]) × √365      # W=30 滚动窗
w_raw      = σ_target / σ_forecast
w          = clip( w_raw, 0, max_leverage )
当日组合收益 = w × 基础组合日收益
```

- 波动高 → `w` 自动变小 → 少暴露，躲过大跌段；
- 波动低 → `w` 放大（受 max_leverage 上限约束）→ 在趋势段多赚。

### 2.3 防未来函数（强制）☆☆☆

`w_t` **只能用 `t-1` 及之前的数据**计算：
- 滚动 std 在 `t-1` 时刻取值（对日收益序列 `rolling(W).std().shift(1)`）；
- 严禁使用当日收盘/当日收益，否则构成未来函数，回测与实盘口径不一致。

这是从研究代代码到生产代码迁移时最易被破坏的约束，必须写在实现注释与测试断言里。

### 2.4 参数含义

"Vol-Target 30%/30" = **目标年化波动率 30% + 滚动窗口 30 交易日**。它不是"30% 仓位"，而是"让组合年化波动尽量贴近 30%"。

## 三、参数与计算规则

### 3.1 推荐参数表

| 参数 | 推荐值 | 说明 |
|---|---:|---|
| 目标年化波动率 | 30% | 甜点区，兼顾收益与回撤 |
| 滚动窗口 | 30 天 | 反应速度与稳定性平衡 |
| 年化因子 | √365 | 加密资产 7×24 交易 |
| 最大杠杆 | 1.5 | 防止低波动时过度放大 |
| 最小仓位 | 0 | 极端风险可清仓 |
| 调仓频率 | 每日 | 收盘后计算，次日执行 |
| 执行时点 | T+1 | 避免未来函数 |
| 换手成本假设 | 单边 0.05% | 实际按交易所与滑点调整 |
| 调仓缓冲区 | `|Δw| < 5%` 不调 | 降低换手 |
| 基础组合币池 | 平均成交额前 30、等权、季度再平衡 | 与回测口径一致 |

> 已移除原稿的"EMA 3 日信号平滑"——`|Δw|<5%` 缓冲已足够，再叠 EMA 会延迟对急跌的反应。

### 3.2 每日计算步骤

1. 获取基础组合（前30等权）的日收益序列；
2. 取 `t-1` 及之前最近 30 个交易日日收益；
3. 计算日收益标准差，年化 `σ_forecast = 日标准差 × √365`；
4. 计算原始仓位 `w_raw = 30% / σ_forecast`；
5. 截断 `w = clip(w_raw, 0, 1.5)`；
6. 叠加风控硬约束（见第六章，风控优先级高于 vol-target）；
7. 生成次日执行指令；
8. 推送飞书日报。

## 四、回测依据与预期表现

基于 Top30 等权组合（平均成交额前30、2.7 年 / 999 交易日）：

| 方案 | 年化 | 波动 | 夏普 | 最大回撤 | Calmar |
|---|---:|---:|---:|---:|---:|
| 纯等权躺平 | +18.0% | 79.9% | 0.23 | 65.96% | 0.27 |
| 均线择时 SMA100 | -12.9% | — | -0.24 | 57.3% | -0.23 |
| **Vol-Target 30%/30** | **+21.2%** | **32.2%** | **0.66** | **29.1%** | **0.73** |
| 保守版 Vol-Target 20%/30 | +15.0% | 21.5% | 0.70 | 20.2% | 0.74 |

- 回撤 66% → 29%，降幅约 56%；
- 年化不降反升至 21.2%；
- 夏普 0.23 → 0.66，Calmar 0.27 → 0.73。

**30%/30 是推荐主方案**；风险偏好更低可选 20%/30。

## 五、与 PM 账户的衔接

### 5.1 层级关系

```
策略层 → 基础组合层 → Vol-Target 资金分配层 → 风控层 → PM 执行层
```

- 策略层：现有选币、信号、择时逻辑；
- 基础组合层：前30等权组合；
- Vol-Target 层：输出总仓位系数 `w`；
- 风控层：对 `w` 做硬约束覆盖（优先级最高）；
- PM 执行层：按最终目标仓位调仓。

### 5.2 接口定义

Vol-Target 模块每日输出字段：

- 日期；基础组合名称；30 日年化波动率；目标波动率；
- 原始仓位 `w_raw`；截断后仓位 `w`；风控覆盖后最终仓位 `w_final`；
- 较前日变化 `Δw`；预估换手成本；次日执行指令。

PM 账户接收 `w_final`，换算各币目标权重：

```
单币目标权重 = (1/30) × w_final
```

- `w_final ≤ 1`：总名义仓位 = `w_final × 100%`，剩余为现金/稳定币；
- `w_final > 1`：总名义仓位超 100%，PM 账户需支持杠杆/借币/保证金，且强平线 + 最大杠杆 1.5 兜底。

### 5.3 执行规则

- 每日收盘后计算，次日固定时间执行；
- `|w_final - 昨日 w_final| < 5%` 不调仓；
- 触发风控时优先执行风控指令；
- 每日与 PM 账户对账，确认实际仓位与目标仓位偏差。

## 六、与风控的衔接（两层配置结构）

### 6.1 优先级

**风控硬约束 > Vol-Target 信号 > 基础组合信号**

即：无论 Vol-Target 给出多高仓位，风控都有权强制降档或清仓。

### 6.2 配置结构（ris.yaml 两层，阈值全部配置化，不硬编码）

风控阈值**不写死在代码里**，按两层结构落进 `risk.yaml`：

```yaml
risk:
  # ============ 全局组合级风控，所有策略共用 ============
  global:
    drawdown:
      basis: portfolio_nav_close       # 组合收盘净值
      levels:
        - {id: dd_l1, threshold: 0.10, max_weight: 1.0}
        - {id: dd_l2, threshold: 0.15, max_weight: 0.5}
        - {id: dd_l3, threshold: 0.20, max_weight: 0.0, halt_days: 3, require_review: true}
    consecutive_losses:
      basis: portfolio_daily_return    # 组合日收益
      levels:
        - {id: cl_l1, days: 3, max_weight: 0.5}
        - {id: cl_l2, days: 5, max_weight: 0.0, require_review: true}
  # ============ Vol-Target 专属维度 ============
  vol_target:
    max_leverage: 1.5                  # 杠杆上限（与公式参数一致）
    vol_anomaly:
      forecast_annual_vol_threshold: 0.80   # 30日年化波动 > 80% 触发
      action: reduce_leverage_auto
    single_day_crash:
      threshold: 0.15                  # 单日组合亏损 > 15%
      action: cap_weight               # 上限封顶（不叠加降仓）
```

**关键设计说明**：

1. **两套口径不打架**：全局 `drawdown`/`consecutive_losses` 是现有风险口径的升级，所有策略共用；`vol_target` 只加专属维度，复用全局口径。
2. **单日暴跌"上限封顶"而非"叠加降仓"**：`action: cap_weight` 表示把仓位上限封到低档，**不再乘一次缩仓系数**——否则与 vol-target 自身的波动响应叠加，会对急跌过度反应（过杀）。
3. 回撤三级 `dd_l3` 触发 `halt_days: 3`（暂停）且 `require_review: true`（需人工复核）。

### 6.3 人工复核触发

以下情况需飞书 @风控负责人 与 PM：

- 回撤三级 `dd_l3` 触发；
- 连亏二级 `cl_l2` 触发；
- 波动率异常（年化波动 > 80%）；
- 杠杆触顶且持续 3 日；
- 数据源异常导致信号不可信。

## 七、飞书推送设计

### 7.1 推送类型

| 类型 | 频率 | 接收方 |
|---|---|---|
| 日报 | 每日一次 | PM、风控、研究群 |
| 周报 | 每周一 | 投研群、管理层 |
| 预警 | 实时 | 风控负责人、PM |

### 7.2 日报模板

**标题**：Vol-Target 日报｜{日期}

**字段**：基础组合、30日年化波动、目标波动、原始仓位、最终仓位、较前日变化、当前回撤、风控状态（正常/一级/二级/三级）、次日指令、备注。

**示例**：

> 【Vol-Target 日报】2026-09-18
> 基础组合：Top30 等权
> 30 日年化波动：32.4%
> 目标波动：30.0%
> 原始仓位：0.93
> 最终仓位：0.93（上限 1.5）
> 较前日：-0.07
> 当前回撤：-8.2%
> 风控状态：正常
> 次日指令：总仓位 93%，各币 3.10%

### 7.3 周报模板

字段：本周收益、本周波动、本周最大回撤、平均仓位、调仓次数、换手成本、滚动夏普、滚动 Calmar、风控触发次数、参数健康度、下周建议。

### 7.4 预警模板

字段：预警级别、触发条件、当前值、建议动作、需确认人、时间戳。

### 7.5 推送通道

- 飞书群自定义机器人 Webhook；
- 消息类型建议为交互式卡片；
- 预警消息可 @ 相关负责人；
- 所有推送需留存日志，便于复盘与审计。

## 八、上线与运维流程

### 8.1 灰度上线（分层推进）☆

Vol-Target 是**全局资金分配器**，不宜一步到位全账户。分层灰度：

1. **阶段一**：先在 **btc_eth 单策略**接入 vol-target，paper/小仓验证 `w` 行为、执行、风控交互符合预期（4~8 周）；
2. **阶段二**：验证通过后再扩散到全账户资金分配（含 new_coin / grid / hrs）；
3. **阶段三**：最终作为全局顶层资金分配器常驻，与 AI-tuner 的 account_ratio_caps 共同构成仓位上限体系。

> 理由：vol-target 影响所有策略的名义规模，一上来全账户风险更高；先单策略验证信号与执行链路，再放大。

### 8.2 每日流程

1. 数据更新；
2. 计算基础组合（前30等权）日收益；
3. 计算 30 日滚动波动；
4. 生成 Vol-Target 仓位；
5. 风控硬约束覆盖；
6. 飞书日报推送；
7. PM 账户执行；
8. 收盘后对账。

### 8.3 每周流程

- 汇总周报；
- 检查实际波动与目标波动偏差；
- 检查换手成本；
- 检查风控触发记录；
- 评估参数健康度。

### 8.4 每月/每季度再校准

- 每季度重新评估目标波动率、窗口、最大杠杆；
- 若连续 20 日实际波动 > 目标 1.5 倍或 < 目标 0.5 倍，检查参数；
- 若市场波动中枢显著上移，考虑降低目标波动率或提高窗口；
- 参数变更需走变更记录，避免过度拟合。

## 九、风险与注意事项

1. **历史波动不等于未来波动**：低波动后可能突然闪崩，Vol-Target 反应滞后。
2. **肥尾风险**：必须配合硬止损、回撤熔断、人工复核。
3. **杠杆成本**：`w > 1` 时涉及借币、资金费率、强平风险。
4. **流动性风险**：前30等权仍需检查单币流动性，避免调仓冲击。
5. **相关性上升**：极端行情下分散失效，组合实际波动可能高于预测。
6. **参数过拟合**：30%/30 是回测甜点区，需持续监控，不可一劳永逸。
7. **基础组合口径漂移**：前30名单随成交额变化，需按季度再平衡口径刷新，否则回测与实盘不一致。

## 十、结论与建议

**正式推荐方案：Vol-Target 30%/30 + 最大杠杆 1.5 + 两层风控（risk.yaml 配置化）+ 分层灰度 + 飞书日报/预警。**

预期表现：

- 年化：约 +21%；
- 波动：约 32%；
- 最大回撤：约 29%；
- 夏普：约 0.66；
- Calmar：约 0.73。

若 PM 账户不支持杠杆，设 `max_leverage = 1.0`，方案退化为 0~100% 仓位调节，收益下降但回撤控制仍有效。

若风险偏好更低，用保守版 **20%/30**：年化约 +15%、最大回撤约 20%、夏普约 0.70。

**最终建议**：以 30%/30 主方案上线，先 btc_eth 单策略灰度 4~8 周，确认信号、执行、风控、飞书全链路稳定后，再逐步放大到全账户。
