## 1. 背景与问题

### 1.1 问题现象

2026-09 某交易日，主流币（BTC/ETH/BNB/SOL/XRP 等）整体向上拉升，但系统内的 MTPCS 原版、MTPCS 激进版、HRS 三个策略**几乎全部持有空单**，形成"单边上涨 + 全仓空头"的危险局面。

事后对最近 48 小时真实成交复盘，量化到多次逆势加空的止损亏损，例如：

| 币种 | 止损亏损（示例，U 本位实现盈亏） |
|------|----------------------|
| SOL | -4.69 |
| MARSCOIN | -5.83 |
| SAMSUNG | -2.66 |
| XRP | -4.79 |

### 1.2 根因

现有风控体系是**单币级、慢尺度（4h/1d）、指标导向**的，缺少一个**组合级、快尺度（1h）、纯涨幅导向**的"大盘暴动"熔断器。当整个市场在 1h 内快速拉升时，单币级指标可能尚未同步恶化，导致策略继续按形态/评分逆势开空。

### 1.3 已证实的价值

通过一个"大盘 1h 涨幅超过阈值时暂停新增空单"的保护，上面的 SOL/XRP/MARSCOIN/SAMSUNG 等逆势加空可在开仓前被拦截，直接省下对应的止损亏损。

## 2. 目标与非目标

### 2.1 目标

- 建立一个**组合级、1h 尺度、等权涨跌幅**驱动的"单边暴动熔断"信号，**双向对称**。
- **空头熔断（轧空保护）**：池等权 1h **涨幅**超阈值 → 暂停该策略**新增空单**。
- **多头熔断（轧多保护）**：池等权 1h **跌幅**超阈值 → 暂停该策略**新增多单**。
- 熔断是**否决性拦截**（只拦新开仓），**不砍已有持仓**（多空均如此）。
- 熔断由共享指数供三个策略在"开仓前"读取，实现跨策略一致的防护。

### 2.2 非目标（明确不做）

- **不做全局牛熊择时**（已被证伪，见讨论背景）。
- **不砍已有持仓**（多空均不砍）：已有持仓由各自已有的止损、极端行情保护、移动止损等机制独立处理。
- **不动新币做空策略**：new_coin 是"形态做空 + 新币衰竭"逻辑，与多空探测器无关，不参与本熔断。
- **不做方向择时**：熔断只保护"与开仓方向相反的暴动"（做空防涨、做多防跌），不干预策略自身的方向判断。

## 3. 核心概念：持仓池等权指数

### 3.1 为什么用"持仓池等权"，而非 BTC 单币或全市场指数

要保护的敞口是"**我们的空单被什么轧**"，因此必须用**自己池子里的标的**对齐。当日复盘暴露了关键陷阱：APLD/AMC/SAMSUNG/XAU 等是美股映射/黄金类标的，行情不由 BTC 驱动——若用 BTC 单币指数，这些标的的轧空会被漏判。

因此指数口径定义为**持仓池等权 1h 涨幅**：

```
持仓池等权指数 1h 涨幅 = mean( 池内每个标的的 1h 涨幅 )
                         = mean( (close_t - close_{t-1}) / close_{t-1} )
```

- **等权**：每个标的一票，不做市值加权（市值加权重仓 BTC/ETH，会稀释小币的暴动信号）。
- **1h 涨幅**：取最新已收盘的 1h K 线，`(当前收盘 - 前一根收盘) / 前一根收盘`。
- **带符号**：指数保留正负号（正 = 池上涨，负 = 池下跌），空头熔断用正侧阈值、多头熔断用负侧阈值，双向共用同一指数。

### 3.2 持仓池构成

| 来源 | 池子内容 | 更新频率 |
|------|---------|---------|
| MTPCS 池（固定） | BTCUSDT / ETHUSDT / BNBUSDT / SOLUSDT / XRPUSDT | 固定不动 |
| HRS 池（动态） | HRS 候选池当前活跃做空/做多标的 | **每 24h 更新一次** |

合并去重后做等权平均。**new_coin 策略标的明确排除**。

> 注意：`merge` 后即使 HRS 池为空或本周期尚未扫描完成，MTCPS 固定 5 币仍构成最小指数，熔断始终可用（不会因池空而失效）。

### 3.3 HRS 池更新周期（已确认 24h）

代码核查结论：HRS 候选池重新扫描间隔为 **86400s（24h）**，非 12h。

- [strategies/hrs/config.yaml#L458](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/hrs/config.yaml#L458)：`rescan_interval_seconds: 86400 # 候选池重新扫描间隔（24小时）`
- [strategies/hrs/candidate_pool.py#L973](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/hrs/candidate_pool.py#L973)：`rescan_seconds = cycle_config.get("rescan_interval_seconds", 86400)`

**结论**：持仓池按 24h 刷新一次，指数计算器每次计算时读取 HRS 当前 pool 即可（24h 内 pool 内容稳定，无需每 h 重新拉 HRS 池）。

## 4. 熔断规则

### 4.1 触发条件（分池双指数 + 双向对称，2026-09-21 回测后确认）

熔断采用**分池平权**口径（用户决策），且**双向对称**：

| 策略 | 所属指数池 | 读取时机 |
|------|-----------|---------|
| MTPCS 原版 / 激进版 | **MTPCS 池**（固定 5 币：BTC/ETH/BNB/SOL/XRP）等权指数 | T 时刻 |
| HRS | **HRS 池**（候选池，24h 刷新）等权指数 | T-1 时刻 |

各策略**独立触发**（互不干扰）。指数带符号，按**开仓方向**取对应阈值：

- **空头熔断（轧空保护）**：`所属池等权_1h涨幅 > +trigger_short` → 暂停该策略**新增空单**。
- **多头熔断（轧多保护）**：`所属池等权_1h涨幅 < -trigger_long`（即池跌幅 > trigger_long）→ 暂停该策略**新增多单**。

单币 1h 涨跌幅先做 `cap ±10%` 再取均值，防极端值污染指数。**双向共用同一指数与同一 cap 逻辑**。

### 4.2 解除条件（带滞后，防抖动）

熔断态必须**带回撤滞后**解除，避免在阈值附近反复触发/解除。**空头、多头各自独立滞回**：

- **空头熔断解除**：熔断态中 且 `所属池等权_1h涨幅 < +release_short`（涨幅回落至 1% 以下）→ 解除，恢复新增空单。
- **多头熔断解除**：熔断态中 且 `所属池等权_1h涨幅 > -release_long`（跌幅收窄至 1% 以内）→ 解除，恢复新增多单。

其中 `release_short < trigger_short`、`release_long < trigger_long`（均 2% 触发 / 1% 解除），确保滞回。

### 4.3 阈值配置（回测已确定，2026-09-21）

| 参数 | 确定值 | 说明 |
|------|---------|------|
| `trigger_short` | 2%（0.02） | 池等权 1h 涨幅超此值 → 触发**空头熔断**（拦新空） |
| `release_short` | 1%（0.01） | 池涨幅回落至此下 → 解除空头熔断（滞回） |
| `trigger_long` | 2%（0.02） | 池等权 1h 跌幅超此值（指数 < -0.02）→ 触发**多头熔断**（拦新多） |
| `release_long` | 1%（0.01） | 池跌幅收窄至此上（指数 > -0.01）→ 解除多头熔断（滞回） |
| `single_coin_short` | 3%（0.03） | 双轨单币检查：目标币自身 1h 涨幅超此值拦该币**新空** |
| `single_coin_long` | 3%（0.03） | 双轨单币检查：目标币自身 1h 跌幅超此值拦该币**新多** |
| `single_coin_cooldown_hours` | 4（小时） | 单币熔断触发后的冷却时长（按币记，不分方向，见 4.6） |
| `per_symbol_ret_cap` | 10%（0.10） | 单币 1h 涨跌幅 cap，取均值前截断，防极端值污染指数 |

> **备注**：`trigger_short / release_short / single_coin_short` 由本地回测确定（见第 11 节）；`trigger_long / release_long / single_coin_long` 的初值**继承空单方向回测结论**（多单方向历史样本不足、未独立回测，作为已知风险见第 12 节）。
> 上述数值严禁在代码中硬编码，必须走配置文件（见第 7 节）。

### 4.4 作用范围（否决性拦截 vs 硬砍仓）

| 动作 | 行为 |
|------|------|
| 新增空单（池涨幅 > +trigger_short 时） | **拦截**（跳过本轮开空） |
| 新增多单（池跌幅 > +trigger_long 时） | **拦截**（跳过本轮开多） |
| 已有空单/多单持仓 | **不动**（由已有止损/极端行情保护处理） |
| 已有持仓的补保护单 | **不拦截**（补止损/止盈照常执行） |
| 池涨时的新增多单 / 池跌时的新增空单 | **不拦截**（熔断只保护与开仓方向相反的暴动） |

### 4.5 双轨机制（池指数 + 单币检查，双向对称）

等权池指数会**稀释单币暴动信号**（如 MARSCOIN 事故开仓时池指数仅 -1.25%），因此叠加**单币自身涨跌幅检查**作为第二轨，双向对称：

```
开仓前（目标币 = symbol）：
  方向 == SHORT（开空）：
    ① 所属池等权 1h 涨幅 > trigger_short → 拦该策略全部新空（组合级）
    ② 目标币自身 1h 涨幅 > single_coin_short → 拦该币新空（单币级，进入冷却）
  方向 == LONG（开多）：
    ① 所属池等权 1h 跌幅 > trigger_long（指数 < -trigger_long）→ 拦该策略全部新多（组合级）
    ② 目标币自身 1h 跌幅 > single_coin_long（自身涨幅 < -single_coin_long）→ 拦该币新多（单币级，进入冷却）
```

- 两轨各自独立判定，任一命中即拦。
- 单币检查覆盖 MTPCS 原版/激进版/HRS 的**每个开仓目标**（多空方向均覆盖）。
- 与 HRS 已有单币级 1h 熔断（`is_circuit_breaker_active`）并存，本机制是**组合层**的统一兜底，不冲突。

### 4.6 分情况判定规则（实现/测试唯一依据）

本节是代码实现与测试用例的**唯一判定依据**，所有场景必须与本表一致。

**冷却规则（先于一切方向判定）**：
- 命中单币熔断（下场景 S2/L2）→ 该 `symbol` 冷却截止时间 = `now + single_coin_cooldown_hours`（每次命中都刷新）。
- 冷却期内，该 `symbol` **任何方向**的新开仓均被拦截（冷却不分方向）。
- 冷却到期自动恢复，无需额外解除动作。

**判定真值表（SHORT 方向）**：

| 场景 | 池指数（所属池） | 目标币自身 1h 涨幅 | 判定 | 拦截级别 |
|------|----------------|-------------------|------|---------|
| S1 | > +2%（> +trigger_short） | 任意值 | **拦** | 组合级（该策略本轮全部新空） |
| S2 | ≤ +2%（≤ +trigger_short） | > +3%（> +single_coin_short） | **拦** | 单币级（仅该币，进冷却 4h） |
| S3 | ≤ +2% | ≤ +3% | 放行 | — |

**判定真值表（LONG 方向）**：

| 场景 | 池指数（所属池） | 目标币自身 1h 涨幅 | 判定 | 拦截级别 |
|------|----------------|-------------------|------|---------|
| L1 | < -2%（< -trigger_long） | 任意值 | **拦** | 组合级（该策略本轮全部新多） |
| L2 | ≥ -2%（≥ -trigger_long） | < -3%（< -single_coin_long） | **拦** | 单币级（仅该币，进冷却 4h） |
| L3 | ≥ -2% | ≥ -3% | 放行 | — |

**优先级**：冷却检查 > 组合级 > 单币级。S1/L1 命中时**不再进入单币检查**（组合级直接否决本轮全部同向开仓，节省下游计算）。

**判定伪代码（唯一入口）**：

```
def allow_open(direction, symbol, pool_index, symbol_ret_1h):
    if symbol in cooldown(symbol):            # ① 冷却检查（不分方向）
        return False
    if direction == SHORT:
        if pool_index > trigger_short:        # ② 组合级：轧空保护（S1）
            return False
        if symbol_ret_1h > single_coin_short: # ③ 单币级：该币暴动（S2）
            start_cooldown(symbol)            #    进入冷却 4h
            return False
        return True                           # S3 放行
    else:  # direction == LONG
        if pool_index < -trigger_long:        # ② 组合级：轧多保护（L1）
            return False
        if symbol_ret_1h < -single_coin_long: # ③ 单币级：该币暴跌（L2）
            start_cooldown(symbol)            #    进入冷却 4h
            return False
        return True                           # L3 放行
```

### 4.7 12h 累计维度熔断（二期，与 1h 瞬时并存）

二期在既有 **1h 瞬时**维度之上，新增 **12h 累计**维度。两者判定层级相同（都属于"组合级"），**任一命中即拦**，12h 不进入单币检查（仅组合级）。

**动机（回测依据，2026-09-22 本地回测）**：
- 慢牛单边上涨时，1h 瞬时涨幅通常 <2% 不足以触发轧空保护，但 **12h 累计涨幅持续超 +2%**，策略仍在慢牛中持续逆势加空并在高位止损，吞噬多单利润（7-8月 MTPCS 原版空单净 -69.5U）。12h 累计维度用于捕获这类**跨多小时的温和持续单边**。

**12h 累计指数定义**：
```
池12h累计等权涨幅 = mean( (close_t - close_{t-12h}) / close_{t-12h} )   // 单币先 cap±10%
```
- 与 1h 共用同一分池（mtpcs / hrs）、同一 cap、同一 `index_hour` 整点口径。
- 由指数计算器在每小时 03 分一并计算 1h 与 12h 两个值，写入**同一张表、同一整点、不同列**（`equal_weight` = 1h，`equal_weight_12h` = 12h）。

**触发条件（双向对称，阈值走配置）**：
| 方向 | 触发条件（所属池） | 级别 |
|------|------------------|------|
| 拦空（慢牛防护） | `池12h累计涨幅 > +trigger_short_12h` | 组合级（拦该策略本轮全部新空） |
| 拦多（阴跌防护） | `池12h累计涨幅 < -trigger_long_12h`（即跌幅 > trigger_long_12h） | 组合级（拦该策略本轮全部新多） |

**判定优先级（扩展 4.6，三层不变）**：冷却检查（不分方向）→ 组合级（1h 瞬时 与 12h 累计 任一命中即拦）→ 单币级（仅 1h）。12h 命中不进冷却、不做单币检查，命中 level 记为 `pool_short_12h / pool_long_12h`（供审计日志区分维度）。

**12h 判定伪代码（叠加在 4.6 之上）**：
```
def allow_open(direction, symbol, pool_index, pool_index_12h, symbol_ret_1h):
    if symbol in cooldown(symbol):            # ① 冷却（先于一切）
        return False
    if direction == SHORT:
        # ② 组合级（1h 与 12h 任一命中即拦）：
        if pool_index > trigger_short:              return False   # S1 快尺度
        if pool_index_12h > trigger_short_12h:      return False   # 二期 慢牛累计
        # ③ 单币级（仅 1h）：
        if symbol_ret_1h > single_coin_short:       start_cooldown(symbol); return False
        return True
    else:  # direction == LONG
        if pool_index < -trigger_long:              return False   # L1 快尺度
        if pool_index_12h < -trigger_long_12h:      return False   # 二期 阴跌累计
        if symbol_ret_1h < -single_coin_long:       start_cooldown(symbol); return False
        return True
```

> **已知边界（沿用第 12 节风险 1）**：12h 累计仍按整点小时采样，跨 K 线内的秒级巨幅波动由各策略单币级机制兜底。12h 维度定位为慢变保护，允许与 1h 判定并存但**不改变单币检查逻辑**（单币始终看 1h）。

### 5.1 各策略执行时间（已确认）

### 5.2 指数读取时间线

```
整点00 ─────────── 03分 ─────────── 05分 ─────────── 10分 ─────────── 下一整点00
 HRS执行        指数计算器         MTPCS原版          MTPCS激进版        HRS执行
  │                │                 │                 │                 │
  │ 读T-1指数      │ 算出T指数        │ 读T指数          │ 读T指数          │ 读T-1指数
  │ (上小时03分)    │ (本小时00收盘)   │ (本小时03分)     │ (本小时03分)     │ (本小时03分)
```

- **指数计算器（03 分）**：计算"刚于整点 00 收盘的那根 1h K 线"对应的等权涨幅，记为 `index_hour = 当前整点`，写入 DB。
- **MTPCS 原版（05 分）/ 激进版（10 分）**：读 `index_hour = 当前整点` 的指数（T 时刻，03 分刚算好）。
- **HRS（整点 00 分）**：读 `index_hour = 上一整点` 的指数（T-1 时刻，因为本小时 03 分的指数尚未计算）。

**关于 T-1 顾虑（已解除）**：原版原为 00 分整点执行，与 HRS 一样存在"读不到 T 时刻指数"的顾虑。现已确认原版 cron 本就是 `"5 * * * *"`（05 分），晚于 03 分指数就绪，因此**原版与激进版均读 T 时刻指数**，无需为原版做 T-1 兼容。仅 HRS 因整点执行读 T-1，但 HRS 熔断滞后 1 小时可接受（熔断是慢变保护，1h 滞后不影响其防护价值）。

## 6. 共享存储设计（PGSQL）

### 6.1 选型结论

- 项目**无独立 Redis 服务**（docker-compose 中无 redis 服务；kline_service 仅定义 `REDIS_URL` 字段未实际使用）。
- 共享存储选 **项目级 PostgreSQL**，跨策略读取指数与熔断状态。

### 6.2 表结构建议

```sql
-- 组合级熔断指数快照表（每 h 03 分按池各写一条）
CREATE TABLE public.market_circuit_breaker_index (
    id            BIGSERIAL PRIMARY KEY,
    pool          VARCHAR(20) NOT NULL,          -- 'mtpcs' | 'hrs'（分池双指数）
    index_hour    TIMESTAMPTZ NOT NULL,          -- 对应当前整点（K线收盘时点）
    equal_weight  DOUBLE PRECISION NOT NULL,     -- 池等权 1h 涨幅（小数，单币已 cap±10%）
    equal_weight_12h DOUBLE PRECISION NULL,      -- 池等权 12h 累计涨幅（二期，单币已 cap±10%）
    symbol_count  INT NOT NULL,                  -- 参与 1h 计算的有效标的数
    symbols       JSONB DEFAULT '[]'::jsonb,     -- 参与 1h 计算的标的列表
    symbol_count_12h INT NULL,                   -- 参与 12h 计算的有效标的数（二期）
    symbols_12h    JSONB DEFAULT '[]'::jsonb,    -- 参与 12h 计算的标的列表（二期）
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (pool, index_hour)                    -- 幂等：同池同一整点只保留一条（1h/12h 同整点不同列）
);

-- 熔断状态表（可选，或用指数历史反推）
-- 建议直接由指数值 + 阈值实时判定，避免状态漂移；见 6.3
```

### 6.3 判定方式（推荐：实时判定，不落状态）

熔断态**不单独存布尔状态**，而是由各策略**读取最新指数 + 阈值实时判定**：

- 优点：无状态漂移风险，指数本身就是唯一事实源，回溯/审计清晰。
- 各策略开仓前执行：按方向判定（见 4.6）——`SHORT：equal_weight > +trigger_short → 拦空单`；`LONG：equal_weight < -trigger_long → 拦多单`。
- 滞后解除：读取连续两根指数（T 与 T-1），空头熔断以 `equal_weight < +release_short` 解除、多头熔断以 `equal_weight > -release_long` 解除（简化版：只看最新一根即可，因为等权涨跌幅本身已回落）。

> 若后续需要"熔断持续时间"统计，可另加派生查询，不引入状态表。

## 8. 各策略接入点（否决性拦截位置）

拦截必须发生在**策略分析完成、开仓执行之前**，判定逻辑唯一依据见 4.6。

### 8.1 MTPCS 原版 / 激进版

在原版 [strategy.py](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/btc_eth/strategy.py) 与激进版对应开仓路径中，对每个目标币开仓前插入（池指数 = **MTPCS 池** T 时刻）：

```
开仓前（每个目标币依次判定）：
  ① 冷却检查：目标币在冷却期？→ 是 → 跳过开仓（冷却不分方向，见 4.6）
  ② 方向判定：
     方向 == SHORT（开空）：
       ├─ MTPCS池指数 > +trigger_short → 跳过本轮全部新空（组合级拦截，记日志）
       └─ 否则 目标币自身 1h 涨幅 > +single_coin_short → 跳过该币开空 + 进入冷却
            否则 → 正常开空
     方向 == LONG（开多）：
       ├─ MTPCS池指数 < -trigger_long → 跳过本轮全部新多（组合级拦截，记日志）
       └─ 否则 目标币自身 1h 跌幅 > +single_coin_long → 跳过该币开多 + 进入冷却
            否则 → 正常开多
```

### 8.2 HRS

在 [HRS strategy.py `_execute_cycle`](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/hrs/strategy.py#L752) 中，short/long 信号汇总后、执行开仓前，对所有信号做组合级拦截（池指数 = **HRS 池** T-1 时刻）：

```
信号汇总完成 → ① 读 HRS 池最新等权指数（T-1）：
     方向 == SHORT：
       ├─ 指数 > +trigger_short → 清空/跳过本轮所有 short 开仓（组合级，做多照常）
       └─ 否则 ② 逐币检查自身 1h 涨幅 > +single_coin_short？→ 剔除该币 short（单币级，进冷却）
            否则 → 正常执行 short 开仓
     方向 == LONG：
       ├─ 指数 < -trigger_long → 清空/跳过本轮所有 long 开仓（组合级，做空照常）
       └─ 否则 ② 逐币检查自身 1h 跌幅 > +single_coin_long？→ 剔除该币 long（单币级，进冷却）
            否则 → 正常执行 long 开仓
```

> 注意：HRS 已有**单币级 1h 熔断**（`is_circuit_breaker_active` / `check_price_change`，[strategy.py#L816-L834](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/hrs/strategy.py#L816-L834)），本需求新增的是**组合级**拦截，二者层级不同、并存不冲突（单币看"这只币自己涨跌多少"，组合看"整个池子涨跌多少"）。

### 8.3 接入顺序建议

组合级熔断检查放在**单币级评分之前**（作为最外层闸门），命中时直接跳过本轮全部**同向**信号评分/开仓，节省下游计算。

## 9. 与已有保护机制的互补关系（关键）

| 维度 | 已有机制（MTPCS） | 本熔断（组合级） |
|------|------------------|-----------------|
| 观测对象 | 单币 | 持仓池组合（等权） |
| 时间尺度 | 4h / 1d | 1h |
| 触发依据 | ADX/布林/EMA/RSI/乖离率等指标 | 纯等权涨幅 |
| 作用方式 | 禁开（market_state RANGING）、方向硬约束（trend_filter）、极值禁开（overheat_protection）、持仓后反向平仓（_check_extreme_market） | 开仓前否决性拦反向开仓（多空对称） |
| 防护目标 | 单币形态/趋势失效 | 大盘单边暴动（轧空 + 轧多） |

**结论**：两者互补不冲突。已有机制是"这只币该不该做空/做多"，本熔断是"这个时点整个池子是否在暴动"。即使单币指标全部通过，只要大盘 1h 暴动，也暂停新增同向开仓（池涨拦空、池跌拦多）。

## 11. 回测与验证（本地执行，禁止服务器回测）

### 11.1 阈值回测（本地，已完成 2026-09-21）

按项目规范，回测在本机执行（数据从服务器 PGSQL 导出到本地 `backtest/circuit_breaker/data/`），**严禁在服务器回测**。

**数据范围**：2026-06-16 ~ 2026-09-21（74 天）。固定 5 币 + HRS 当前池 62 标的 1h K 线；三策略全部空单交易记录（261 笔空单仓位，116 笔可评估——HRS 池 K 线 07-16 起，更早仓位无指数无法评估）。

**口径对比结论**（脚本 `backtest/circuit_breaker/compare_variants.py`）：

| 口径 | MTPCS 指数 max | HRS 指数 max | trigger=2% 拦截 |
|------|--------------|-------------|----------------|
| 全池 67 标的等权（无 cap） | 15.20% | 同左 | 1 笔（盈亏 0） |
| 全池 67 标的等权（cap±10%） | 3.54% | 同左 | 1 笔（盈亏 0） |
| **分池平权（用户选定）** | 3.75% | 2.69% | 2 笔（盈亏 0） |
| 分池 + HRS cap±10% | 3.75% | 2.65% | 2 笔（盈亏 0） |

**关键结论**：
1. **cap±10% 几乎不削弱信号**：分池下 HRS 指数 2.69%→2.65%，差异可忽略（62 币平权后单币暴动对指数贡献 <0.2%）。HRS 信号弱源于平权稀释，非 cap 造成。
2. **分池优于全池**：MTPCS 与 HRS 各自保护自己的持仓池，语义清晰，拦截量不劣于全池。
3. **市值加权反而更钝**：HRS 池市值加权会放大币主导、进一步稀释小币暴动，与保护目标相反 → 选**平权**。
4. **拦截量普遍极低（0-2 笔、盈亏≈0）**：历史空单开仓时点几乎不落在"池指数大涨"时段。熔断定位为**尾部保护闸门**，非收益优化器。
5. **15.2% 尖峰溯源**：07-17 早期 HRS 池仅 3 个币有 K 线，单币 +46% 造成的覆盖伪影。cap±10% + MIN_SYMBOLS≥3 可消除。
6. **单币检查（双轨第二轨）**：目标币自身 1h 涨幅 >3% 的档位历史上拦住 2 笔**真实亏损单**（合计 -7.12 USDT）；>5% 档 0 触发。故单币阈值定 3%。

**事故日（09-21）复盘**：MARSCOIN 空单 02:55 开仓时，币自身 1h 涨幅仅 +0.92%、HRS 池指数 -1.25%——开仓时完全平静，亏损源于**开仓后 10 小时缓慢阴涨**（12:30 触发止损 -14.67 USDT）。**任何 1h 频率阈值都拦不住此类慢涨事故**，靠已有止损兜底。熔断防的是"开仓时池子/目标币已明显上涨"的轧空场景。

**回测方法（可复现）**：
1. 从服务器导出池内标的 1h K 线 + 三策略交易记录到本地（见 `backtest/circuit_breaker/data/`）。
2. 重放历史：计算每整点池等权 1h 涨跌幅（单币先 cap±10%）。
3. 扫描 trigger 2%/3%/4%/5%/6% × release 1%~3% 对历史空单开仓的拦截量与收益差。
4. 选定：`trigger_short=2% / release_short=1%`（池指数）+ `single_coin_short=3%`（单币检查）。

> **多单方向（轧多）回测说明**：本次回测仅重建了**空单**仓位（261 笔，历史以做空为主），多单方向未独立回测。`trigger_long / release_long / single_coin_long` 初值（2%/1%/3%）**继承空单方向结论**，属于经验初值——上线后需持续观测拦截行为，或后续补做多单方向回测（见第 12 节风险 6）。

### 11.2 验证要点

- 空头熔断触发时是否正确拦截**所有** short 开仓、且 long 不受影响（S1 场景）。
- 多头熔断触发时是否正确拦截**所有** long 开仓、且 short 不受影响（L1 场景）。
- 组合级未触发时，单币级是否正确拦截该币同向开仓并进入冷却（S2/L2 场景）。
- 池上涨时做多放行、池下跌时做空放行（不串扰）。
- 冷却规则：命中单币熔断后 4h 内该币**任何方向**禁开，到期自动恢复。
- 已有持仓的保护单补单不受影响。
- 滞后解除不回抖（阈值附近反复触发/解除）。
- HRS 整点读 T-1 指数的正确性（无空值、无越界）。

## 12. 风险与边界

1. **滞后性**：指数按小时计算，最快 1h 反应。极端秒级暴动（单根 K 线内巨幅拉升后回落）可能漏判——这是可接受的设计取舍，快尺度由各策略单币级机制兜底。
2. **HRS T-1 滞后**：HRS 比 MTPCS 晚 1 小时感知熔断，属可接受（慢变保护）。
3. **池子重叠**：HRS 池与 MTPCS 固定池若有重叠标的，等权时该标的影响会被稀释；需确认合并去重逻辑（`mean` 对去重后集合）。
4. **new_coin 不参与**：新币做空策略不受此熔断保护（其逻辑独立，按形态做空），需在文档/公告中明确预期。
5. **阈值误设风险**：阈值过高则保护失效，过低则频繁误拦错失开仓机会——已经 2026-09-21 本地回测确定空单方向初值（trigger_short 2% / release_short 1% / 单币 3%），并支持运行时调整（走配置文件）。
6. **多单方向（轧多）阈值未独立回测**：`trigger_long / release_long / single_coin_long`（2%/1%/3%）继承空单方向回测结论，但历史回测仅重建空单仓位，多单方向拦截收益未量化。**上线后需观测**：若出现"池跌拦多导致错失多单机会"或"轧多亏损仍发生"，需补做多单方向回测并回调阈值。多空共用同一指数与 cap 逻辑，实现成本已对称。
