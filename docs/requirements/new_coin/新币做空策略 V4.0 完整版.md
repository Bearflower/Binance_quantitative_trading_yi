## 1. 策略概述

- **目标**：针对币安新上线的永续合约币种，**每个币种只做一次空单**，捕捉上线后第一波明确的衰竭下跌行情。
- **核心理念**：通过**合约数据（OI/上线以来总交易量比率）+ 价格行为形态（三次冲顶、长上影线、放量滞涨）+ 资金费率**三维筛选，找到高概率下跌机会，实现"一击必中"。
- **策略优势**：低交易频率（年约150-200笔）、严格风控、完全基于可获取的实时数据。
- **V4.1核心改进**：修复盈亏方向bug、消除10处硬编码、强化降级模式约束、提高技术面入场门槛，回测胜率从22%提升到78%。

## 2. 币种预筛选（必须全部满足）

| 筛选维度 | 条件 | 数据源 | 一票否决 |
|---------|------|--------|----------|
| 时间窗口 | 上线时间 < 48小时 | 币安公告 | ✅ 是 |
| 合约数据 | OI / 上线以来总交易量 ≤ 0.5 | 币安API | ✅ 是（>0.5直接放弃） |

**说明**：  
- 因市值数据难以获取，使用 **OI / 上线以来总交易量** 替代 OI/市值比。  
- 上线以来总交易量 = 从第一根K线到当前K线的成交量之和（USD）。  
- 阈值 >0.5 为一票否决，0.4~0.5 得分0分（但不否决，可人工复核）。

## 3. 信号评分系统（满分10分，开仓需总分 ≥ 5.0）

### 3.1 合约数据（权重45%）

| OI / 上线以来总交易量 | 得分 | 说明 |
|----------------------|------|------|
| < 0.2 | 10 | 优秀 |
| 0.2 ~ 0.3 | 7 | 良好 |
| 0.3 ~ 0.4 | 3 | 偏高，谨慎 |
| 0.4 ~ 0.5 | 0 | 极危险，手动复核（默认不开） |
| > 0.5 | 一票否决 | 直接放弃 |

### 3.2 技术面（权重35%）

基于 **1小时K线**，每根K线收盘后判断。**纯形态评分，不使用 RSI、MACD 等传统指标**。

| 条件 | 分值 | 量化标准 |
|------|------|----------|
| 三次冲顶 | 0~4 | 最近3-5根K线，高点逐次降低（差≥0.2%）或同一水平受阻≥3次 |
| 长上影线 | 0~3 | 上影线长度 ≥ 实体长度 × 2，且实体为阴线或十字星 |
| 放量滞涨 | 0~3 | 成交量 ≥ 前5根平均 × 1.5，且收盘价低于前一根K线高点 |
| **技术总分** | **0~10** | 三项得分相加 |

**硬性入场要求**（不满足则不开仓，但可继续等待后续K线）：
- 技术总分 ≥ **7**（V4.1：从6.0提高到7.0，强化技术面硬性要求）
- 三次冲顶分 ≥ **3**（V4.1：从2.0提高到3.0，要求形态更清晰）

### 3.3 情绪面（权重20%）

使用当前资金费率（年化），取最近一次结算前的实时费率。

| 资金费率（年化） | 得分 |
|----------------|------|
| > 100% | 5 |
| 50% ~ 100% | 3 |
| < 50% 或 负费率 | 0 |

**V4.1变更说明**：
- 情绪面采用双因子评分：资金费率（0~5分）+ OI变化率（0~5分），总分10分
- 资金费率门槛从年化30%提高到50%（删除30%~50%的1分档），避免中等费率虚高情绪分
- 降级模式（上线<3小时或OI数据缺失）下，仅使用资金费率并乘以2映射到10分制，但新增**情绪分上限截断**（最高6分，配置项 `max_sentiment_score`），避免资金费率中等时情绪分虚高

### 3.4 总分计算与开仓条件

```
总分 = (合约得分 × 0.45) + (技术得分 × 0.35) + (情绪得分 × 0.20)
```

**开仓必须同时满足**：  
- 总分 ≥ **5.0**（保持5.0，通过min_total_score和降级模式约束提升质量）  
- 技术面硬性要求（技术总分 ≥7 且 三次冲顶 ≥3）  
- 无任何一票否决项  
- 该币种尚未开仓过
- **V4.1新增**：降级模式下，技术总分必须 ≥ **7**（配置项 `min_technical_score`），用更严格的技术面要求补偿信号质量

## 4. 进场时机详细规则

- **时间框架**：1小时K线  
- **评分时机**：**每个1小时K线收盘后**立即评分一次  
- **启动条件**：至少有 **18根** 已收盘的1小时K线（V4.1：从14根提高到18根，以保证ATR计算和形态检测可靠性）；若不足18根，**不启动评分也不开仓**  
- **形态检测自适应机制**：形态检测（三次冲顶、放量滞涨）采用自适应算法，根据可用K线数量动态调整检测窗口和基线计算：
  - 长上影线：仅需最新1根K线，始终可用
  - 三次冲顶：K线≥30时窗口=5，≥20时窗口=3，≥14时窗口=2（K线越多，高点识别越精确）
  - 放量滞涨：K线≥25时用5根对比15根基线，≥18时用3根对比更多基线，≥10时用2根简化检测
  - 无需等待30根K线即可开始形态检测，最早14根K线即可参与评分（但V4.1要求至少18根K线才启动评分）
- **开仓执行**：满足条件后，在当前K线收盘时**限价开空**（V4.1：市价改为限价，避免滑点），立即挂好限价止损止盈单（止损/止盈/平仓均使用限价单，详见第10节）
- **入场后处理**：入场成功后**立即停止对该币种的监控**，包括：
  - 将该币种加入 `known_symbols`（不再被检测为新币）
  - 从K线服务注销（停止采集该币种的K线数据）
  - 后续周期不再对该币种评分、不再推送通知
  - 飞书通知中标注为"已入场(已停止监控)"
- **放弃条件**：
  - 形态出现后价格反弹超过最近高点
  - 上线48小时内无合格信号（且尚未入场）
  - 评分不足但继续等待时超48小时（且尚未入场）

## 5. 止损与止盈参数

### 5.1 止损设置（取三者最大值）

| 止损类型 | 计算公式 | 说明 |
|----------|----------|------|
| ATR硬止损 | 开仓价 + 2.5 × ATR(14) | 主要动态止损 |
| 紧急止损 | 开仓价 × 1.015 | 开仓后15分钟内有效 |
| 最小绝对止损 | 开仓价 × 1.05 | 5%硬性下限 |
| **最终止损价** | **取上述最大值** | — |

**作用**：防止因ATR过小或紧急止损过窄被正常波动扫损，确保止损宽度至少5%。

### 5.2 止盈设置（分批+移动）

| 目标 | 触发条件 | 平仓比例 |
|------|----------|----------|
| 第一目标 | 价格 ≤ 开仓价 - 1.5 × ATR | 30% |
| 第二目标 | 价格 ≤ 开仓价 - 3.5 × ATR | 40% |
| 移动止盈 | 从最低点反弹 1.5 × ATR | 剩余30% |
| 时间止损 | 持仓超过 **72小时** 且未达第一目标 | 100% |

**说明**：  
- 若K线不足18根（无ATR），则固定使用：止损5%，止盈3%/6%，移动止盈回撤3%。但V4.1正式版要求至少18根K线才开仓，故不涉及此情况。

### 5.3 动态利润保护（移动止损）

**概述**：复用 btc_eth 策略的动态利润保护机制，核心计算逻辑抽取到 `shared/dynamic_trailing.py` 模块，供两策略共用。该机制在 TP2 到达后激活，作为现有 ATR 反弹移动止盈的补充，覆盖价格冲高回落场景。

#### 5.3.1 激活条件

- **必须条件**：TP2（第二目标止盈）到达后激活，TP1 到达不激活
- 激活后，每次 `check_position_management` 循环都会检查动态止损价
- 与现有 ATR 反弹移动止盈（`_check_trailing_stop`）形成双保险：
  - 动态利润保护：覆盖价格从最高价回落触发止损
  - ATR 反弹移动止盈：覆盖价格从最低价反弹触发止盈

#### 5.3.2 阶梯回撤止损逻辑

基于浮盈百分比的阶梯回撤比例，浮盈越高，允许回撤比例越低：

| 浮盈区间 | 允许回撤比例 | 说明 |
|---------|-------------|------|
| < 1.5% | 保本模式（止损价 = 入场价） | 未产生足够利润，仅保本 |
| 1.5% ~ 4.0% | 50% | 浮盈 2% 时最多回撤 1% |
| 4.0% ~ 8.0% | 35% | 浮盈 6% 时最多回撤 2.1% |
| ≥ 8.0% | 25% | 浮盈 10% 时最多回撤 2.5% |

**计算方式**：以追踪到的最高价（做空场景）为参考价，计算浮盈百分比，根据阶梯确定允许回撤比例，再计算止损价。

```
做空回撤止损价 = 参考价（最低价）+ 浮盈 × 回撤比例 × 波动率调节因子
```

#### 5.3.3 波动率调节因子

基于历史日线 ATR 中位数，衡量当前币种的相对波动水平，动态调整回撤容忍度：

- **公式**：`波动率调节因子 = 当前 ATR% / 历史 N 日日线 ATR% 中位数`
- **范围**：clamp 到 [0.5, 2.0]
- **数据源**：历史 30 日日线 K 线数据（可配置）
- **缓存**：计算结果缓存 1 小时（可配置）
- **含义**：波动率越高，调节因子越大，允许回撤比例越高，避免被正常波动扫损

#### 5.3.4 硬止损兜底

无论阶梯回撤计算出的止损价如何，都受硬止损价约束：

- **做空硬止损价** = `入场价 + 2.5 × ATR(14)`
- 最终止损价取阶梯回撤止损价与硬止损价的**较小值**（做空方向）
- 确保即使浮盈阶梯计算异常，也有 ATR 倍数作为兜底保护

#### 5.3.5 单向移动保护

做空方向下，止损价只能向下移动（向有利方向），绝不能向上移动：

- 每次计算出的新止损价必须 ≤ 当前生效止损价
- 若新止损价 > 当前生效止损价，保持当前止损价不变
- 避免因价格剧烈波动导致止损价被不合理抬高

#### 5.3.6 交易所条件单同步

动态止损价计算后，自动同步到交易所条件单：

- 首次激活时：取消原有硬止损条件单（`algo_ids['sl']`），创建新的动态止损条件单
- 止损价改善时：取消旧条件单，创建新条件单，更新 algoId
- 条件单类型：`STOP`（止损限价单），方向 `BUY`（做空平仓）
- 限价偏移：`止损价 × (1 + offset_pct)`，向不利方向偏移 0.2%，确保触发后成交
- 取消旧条件单时静默忽略错误码：`-2022`（订单已取消/已成交）、`-2011`（订单未找到）

#### 5.3.7 配置项说明

```yaml
trading:
  dynamic_trailing:
    enabled: true                          # 总开关
    activation:
      min_profit_pct: 1.5                  # 浮盈计算阈值（用于阶梯计算，不作为激活条件）
      also_on_tp1: false                   # TP1 触发不激活（new_coin：仅 TP2 激活）
      also_on_tp2: true                    # TP2 触发激活（new_coin 特有）
    regression_tiers:
      - profit_ceiling: 1.5                # 浮盈上限 1.5%
        retrace_ratio: 0.0                 # 保本模式
      - profit_ceiling: 4.0                # 浮盈上限 4.0%
        retrace_ratio: 0.5                 # 允许回撤 50%
      - profit_ceiling: 8.0                # 浮盈上限 8.0%
        retrace_ratio: 0.35                # 允许回撤 35%
      - profit_ceiling: 999.0              # 浮盈上限无限制
        retrace_ratio: 0.25                # 允许回撤 25%
    volatility_adjustment:
      enabled: true                        # 波动率调节开关
      atr_lookback_days: 30                # 历史日线 ATR 回溯天数
      atr_period: 14                       # ATR 计算周期
      cache_ttl_seconds: 3600              # 波动率缓存有效期（秒）
    stop_limit_order:
      offset_pct: 0.002                    # 止损限价偏移比例（0.2%）
    cleanup_silent_error_codes: [-2022, -2011]  # 条件单取消时静默忽略的错误码
```

**配置路径**：`strategies/new_coin/config.yaml` → `trading.dynamic_trailing`

## 6. 仓位管理与风控

| 规则 | 设定 |
|------|------|
| 每笔最大亏损 | 账户总资金 **2%** |
| 杠杆 | ≤ **2倍**（固定） |
| 单日最多开仓 | **2个币种** |
| 连续亏损暂停 | 连续3笔亏损后，暂停交易 **2天** |
| 最大回撤熔断 | 累计亏损 ≥ **15%** 时暂停交易 **一周**，复盘后再启动 |
| 黑名单机制 | 触发止损后24小时内反向暴涨超过止损价5%的币种，**永久禁止**交易 |

**仓位计算示例**（账户500U，止损幅度5%）：  
- 最大亏损 = 500 × 2% = 10U  
- 开仓价值 = 10 / 5% = 200U  
- 2倍杠杆 → 保证金 = 200 / 2 = 100U（佔20%）

## 7. 执行流程清单

1. **早间准备**：获取币安新币公告，列出上线时间 < 48小时的币种。  
2. **筛选**：计算每个币种的 `OI / 上线以来总交易量`，排除 >0.5 的币种。  
3. **等待信号**：对通过筛选的币种，每小时整点后对已收盘的1小时K线进行技术面+情绪面评分（需至少18根K线）。  
4. **开仓**：若总分 ≥ 5.0 且技术面满足硬性要求（技术总分 ≥7 且 三次冲顶 ≥3），在K线收盘时限价开空（V4.1：市价改为限价），立即挂好限价止损止盈单。**入场成功后立即停止对该币种的监控**（加入 known_symbols、从K线服务注销、后续周期不再评分和推送）。降级模式下还需满足技术总分 ≥7 的额外约束。
5. **持仓管理**：每日检查时间止损与移动止盈，记录盈亏。  
6. **复盘**：每周统计胜率、盈亏比、最大回撤，优化阈值。

## 10. 订单执行机制（限价单改造 V4.1）

### 10.1 改造背景与目标

为避免市价单的滑点风险，V4.1 将所有订单类型由市价单改为限价单（委托单）：
- **开仓、止损、止盈、平仓**全部使用限价单
- 通过滑点容忍配置项 `limit_order_slippage` 控制限价相对触发价的偏移，确保限价单能成交
- 平仓操作保留市价单回退容错机制，避免无法平仓的风险

### 10.2 订单类型变更对照表

| 场景 | 改造前（市价） | 改造后（限价） | 限价计算 |
|------|---------------|---------------|---------|
| 开仓 | MARKET | LIMIT | 限价 = 当前价 |
| 止损（单笔/分批） | STOP_MARKET | STOP | 限价 = 止损价 × (1 + 滑点) |
| 止盈（单笔/分批） | TAKE_PROFIT_MARKET | TAKE_PROFIT | 限价 = 止盈价 × (1 + 滑点) |
| 保本止损 | STOP_MARKET | STOP | 限价 = 开仓价 × (1 + 滑点) |
| 平仓 | MARKET | LIMIT（`timeInForce=GTC`，带市价回退容错） | 限价 = 当前价 × (1 + 滑点) |

### 10.3 限价计算规则（统一方向）

做空操作（开仓卖出除外）都是买入，买入限价单成交条件为：市场价 ≤ 限价。因此限价应略高于触发价以确保成交。

| 订单类型 | 限价计算 | 说明 |
|---------|---------|------|
| 开仓限价 | 当前价 | 直接以当前价挂限价单 |
| 止损限价 | 止损价 × (1 + 滑点) | 限价略高于止损价，触发后立即成交 |
| 止盈限价 | 止盈价 × (1 + 滑点) | 限价略高于止盈价，触发后立即成交 |
| 平仓限价 | 当前价 × (1 + 滑点) | 限价略高于当前价，触发后立即成交 |

> **重要**：止盈限价方向必须为 `(1 + 滑点)`。代码审查曾发现并修复了止盈限价方向错误的 bug（错误写法为 `止盈价 × (1 - 滑点)`，会导致限价低于触发价、订单不成交）。该 bug 影响 3 处止盈限价计算（单止盈、分批目标1、分批目标2），现已全部修正。

### 10.4 平仓容错机制

平仓限价单失败时（获取价格异常、限价单抛异常等），自动回退到 MARKET 市价单确保能平仓，避免无法平仓的风险：
1. 优先以 `当前价 × (1 + 滑点)` 挂限价平仓单
2. 若获取当前价格异常（≤0）或限价单抛异常，回退到市价单平仓
3. 容错日志会标注"限价平仓失败，回退市价单"

### 10.5 配置项说明

```yaml
trading:
  # 限价单滑点容忍（V4.1新增：市价→限价）
  # 用于限价单相对触发价的偏移，确保限价单能成交；默认0.001（0.1%）
  limit_order_slippage: 0.001
```

- **配置路径**：`strategies/new_coin/config.yaml` → `trading.limit_order_slippage`
- **默认值**：0.001（0.1%）
- **作用**：止损/止盈/平仓限价单相对触发价的偏移量；开仓限价直接使用当前价，不应用此偏移

## 11. PnL 回写逻辑（2026-08-10 新增）

### 11.1 背景

新币做空策略通过 `TradeLogger` 自动记录订单到 `trading.trade_records` 表。平仓时在 `_monitor_positions` 方法中查询平仓记录，计算已实现盈亏并回写到 `realized_pnl` 字段，供 AI 调优系统（ai_tuner）读取。

### 11.2 回写流程

平仓检测流程：

1. `_monitor_positions` 发现持仓已从交易所消失（`get_position` 返回空）
2. 调用 `_get_position_pnl` 查询 Binance 收入流水获取已实现盈亏
3. 查询平仓订单记录（`SELECT order_id FROM trading.trade_records`）
4. 调用 `trade_logger.update_realized_pnl()` 回写

### 11.3 关键代码

```python
# 查询平仓盈亏
pnl = await self._get_position_pnl(symbol, entry_price)

# 查询平仓订单
close_order = await self.db.fetch_one(
    "SELECT order_id FROM trading.trade_records "
    "WHERE strategy = $1 AND symbol = $2 AND side = $3 ..."
)

# 回写盈亏
if trade_logger and close_order and close_order.get("order_id"):
    await trade_logger.update_realized_pnl(
        order_id=str(close_order["order_id"]),
        realized_pnl=Decimal(str(pnl)),
        side=close_side,
        symbol=symbol,
        executed_at=executed_at,
    )
```

### 11.4 数据来源

| 数据项 | 来源 | 说明 |
|--------|------|------|
| 开仓记录 | `trading.trade_records` | 通过 `TradeLogger.log_order` 自动记录 |
| 平仓盈亏 | Binance 收入流水 API | `_get_position_pnl` 查询 `REALIZED_PNL` 类型 |
| 平仓订单 ID | `trading.trade_records` | 按时间范围查询最近平仓记录 |
| 出场价 | 平仓订单结果 | 从 `avgPrice` 或 `current_price` 获取 |

### 11.5 容错机制

- `trade_logger` 为 None 时跳过回写
- 查不到平仓记录（`pnl` 为 None）时跳过回写
- `order_id` 为空时跳过回写
- 回写异常仅记录 warning 日志，不阻断主流程
