# 混合反转策略 HRS V2.0 完整文档
## Hybrid Reversal Strategy (HRS)

## 1. 策略概述

- **目标**：针对币安永续合约中**流动性充足的存量币种**（不限市值），捕捉**暴涨后的做空机会**与**暴跌后的做多机会**。
- **核心理念**：利用“极端情绪 + 衰竭形态 + 拥挤仓位”引发反向波动，通过**多维度量化评分**实现高概率反转交易。
- **交易方向**：双向（做空 / 做多），每币种同时最多持有一个方向，同一币种不可同时持有多空。
- **优势**：高胜率（回测预期 ≥65%），严格风控，低杠杆，完全基于实时公开数据。
- **V2.0 核心变化**：软化技术门槛（技术总分 ≥ 4.0，三次形态 ≥ 1 分），新增极端行情加分（±15% 涨跌幅 +1.5 分），总分门槛降至 6.0，在不显著牺牲胜率的前提下增加交易机会。

## 2. 币种池与预筛选

### 2.1 币种池范围
- **初始池**：币安永续合约中**所有币种**（排除以下类型）。
- **排除币种**：
  - 稳定币（USDT、USDC、BUSD、DAI 等）
  - 杠杆代币（如 ETHBULL、BTCDOWN 等）
  - 币安官方标记“观察”或“风险”的币种
- **流动性门槛（必须同时满足）**：
  - 24h 成交额 ≥ **5000 万 USDT**
  - 当前持仓量 OI ≥ **1000 万 USDT**

> 去除了“市值前200”的硬性要求，任何币种只要满足流动性门槛即可进入候选池，包括新上线但流动性充沛的币种。

### 2.2 每日动态筛选（自动执行）
每天早上 **8:05 (UTC+8)** 扫描一次（避开 8:00 资金费率结算的瞬时波动），更新候选池。

| 条件                     | 做空候选                     | 做多候选                     |
|------------------------|------------------------------|------------------------------|
| 24h 涨跌幅              | ≥ 12%                        | ≤ -10%                       |
| 资金费率（年化）        | ≥ 80%                        | ≤ -20%                       |
| 价格偏离 EMA20（4h）    | ≥ 8%（向上偏离）             | ≤ -6%（向下偏离）             |
| OI / 市值比             | ≥ 0.10（拥挤）               | ≤ 0.05（冷清，或不做要求）    |

> 满足上述任意一方向粗筛的币种进入候选池，再进行 **形态评分**。

### 2.3 新币策略冲突屏蔽（重要）
- **规则**：若某个交易对在过去 **3天内**（72小时）曾由【新币做空策略 V4.0】开仓（包括已平仓或仍在持仓），则该交易对**自动排除**在本策略的候选池之外，期间不做任何反转信号监控与开仓。
- **目的**：避免两个策略在同一币种上产生冲突，尊重新币策略的“一币一单”原则。
- **实现方式**：维护一个全局黑名单表，记录每个币种被新币策略开仓的时间戳（精确到小时），每次动态筛选及评分前检查该表。

### 2.4 4h K线数据管理（用于EMA20预筛选）

- **实现方式**：策略**不单独订阅4h K线**，而是基于已订阅的1h K线实时合成4h K线。
- **合成规则**：每4根连续的1h K线（严格按照UTC时间边界：0-3,4-7,8-11,12-15,16-19,20-23）合并为1根4h K线：
  - 开盘价 = 第一根1h开盘价
  - 最高价 = 4根1h最高价的最大值
  - 最低价 = 4根1h最低价的最小值
  - 收盘价 = 第四根1h收盘价
  - 成交量 = 4根1h成交量之和
- **EMA20计算**：
  - 每日筛选（8:05）时，从本地缓存的1h K线中合成至少 **30根** 4h K线（约5天数据），计算EMA20。
  - 首次启动时若1h K线不足120根（对应30根4h），则通过API拉取历史1h K线补足。
- **优势**：无需额外订阅4h WebSocket，数据源与评分完全对齐，减少API资源占用。

## 4. 进场时机与执行

### 4.1 K线预热机制（候选池新币种）

每日早 **8:05** 筛选出的新候选币种，若本地存储的1小时K线数量不足 **168根**（7天），执行以下操作：

1. **拉取历史数据**：通过币安API获取该币种 **最近7天的1小时K线**（最多168根）。
2. **补足缓存**：将历史K线与现有数据合并去重，按时间排序存储。
3. **合成4h K线**：基于1h K线合成最近 **50根** 4h K线，用于EMA20计算。
4. **激活条件**：若补足后K线总数 ≥ 24根，该币种即可参与下一个整点收盘后的评分；若仍不足24根（如新币上线不足24小时），则暂不评分，等待自然积累满24根后再自动激活。
5. **增量更新**：激活后，通过WebSocket或定时任务订阅实时1小时K线，每完成一根新K线即触发评分，并同步更新4h合成缓存。

> 此机制确保币种一旦满足流动性门槛，无需等待24小时即可开始监控，同时保证技术指标（EMA20、ATR等）计算所需的最小数据量。

### 4.2 评分与开仓触发
- **K线周期**：1小时
- **评分触发**：每个1小时K线**收盘后**立即对候选池内所有币种评分
- **资金费率获取规则（硬编码要求）**：
  - 评分时使用的资金费率必须是该 K 线**收盘时间点**对应的**历史费率快照**（即上一个结算周期的费率），**禁止使用实时费率**。
  - 实现方法：调用币安 API `/fapi/v1/fundingRate` 获取指定时间戳的历史费率，并缓存结算周期的结果。
  - 若因技术原因无法实现历史费率查询，则必须在结算时刻（00:00、08:00、16:00 UTC+8）后的 **5分钟内**（如 8:00-8:05）**主动跳过评分**，等待费率稳定后再继续。但此方法会损失信号，仅作备选。
- **开仓执行**：满足条件后，在当前K线收盘价**市价开仓**，立即挂好止损止盈单
- **方向限制**：同一币种若已持有多单，不可再开空单；反之亦然。可同时持有不同币种的多单和空单。

### 4.3 放弃条件

以下任一情况发生时，放弃当前币种的本次信号（不进行开仓），但币种仍保留在候选池中，等待后续K线重新评分：

1. **形态失效（反向突破极值）**：
   - **做空场景**：在满足三次冲顶等形态条件后，最新市场价格 **大于** 最近 **20根1小时K线**（含当前未收盘K线）的**最高价**。
   - **做多场景**：在满足三次探底等形态条件后，最新市场价格 **小于** 最近 **20根1小时K线**（含当前未收盘K线）的**最低价**。
   - 此检查在每次K线收盘评分前实时执行。
   - *解释：20根K线约等于1天（24小时），能有效过滤短期噪音，同时避免反转失败后继续持仓。*

2. **开仓延迟**：发出市价开仓订单后，**15分钟内** 订单未能**完全成交**（包括未成交、部分成交、交易所拒绝等）。此时必须：
   - 立即取消该订单的未成交部分；
   - 若已有部分成交，立即以市价反向平仓，恢复零敞口；
   - 放弃本次信号（该币种本轮不再开仓）。

3. **流动性降级**：币种的24h成交额或OI在筛选后跌至流动性门槛以下（< 5000万U 或 < 1000万U）。

4. **新币策略冲突**：币种在3天内被新币策略开仓过（见2.3节）。

> 注意：若价格突破极值后再次回到范围内，且重新形成合格形态，可重新进入候选。

### 4.4 双向信号冲突处理

若同一币种、同一根1小时K线收盘后，做空评分与做多评分均 ≥ 6.0（同时满足开仓条件），则按以下顺序决策：

1. **优先选择总分较高的一方**开仓。
2. 若总分相同，选择**技术总分较高**的一方。
3. 若技术总分仍相同，选择**情绪得分较高**的一方。
4. 若上述均相同，**放弃本次信号**，不进行任何开仓，等待下一根K线。

> 禁止在同一币种上同时持有多单和空单。上述规则确保每次最多开仓一个方向。

### 4.5 候选池生命周期与K线服务管理

- **每日筛选（8:05）后**，比较新候选池与当前活跃币种：
  - **活跃币种** = 候选池币种 ∪ 当前持仓币种
- **注册K线服务**：新候选池币种若不在当前活跃币种中，则：
  - 注册1h K线 WebSocket（或定时拉取）
  - 立即拉取最近7天（168根）1h历史K线，补足缓存
  - 合成4h K线（至少50根），用于EMA20预筛选
  - 加入评分循环
- **注销K线服务**：币种同时满足以下条件时注销：
  - 不在新候选池中
  - 无持仓（完全平仓）
  - 不处于黑名单或暂停状态（这些状态不需要K线）
- **持仓保护**：持仓币种即使不在候选池，仍保留K线服务，用于：
  - 实时监控价格，触发止损/止盈/移动止盈
  - 计算ATR（用于移动止盈）
  - 判断时间止损（72小时）
- **平仓后处理**：平仓完成后，若该币种不在候选池中，立即注销K线服务。

> 此策略确保资源高效利用，同时不遗漏任何持仓管理所需的数据。

## 5. 止损与止盈

### 5.1 止损设置

| 方向 | 止损类型 | 计算公式 | 最终取法 |
|------|----------|----------|----------|
| **做空** | ATR硬止损 | 开仓价 + 2.5 × ATR(14) | 取三者**最大值**（最高价格，即最宽止损） |
| | 紧急止损 | 开仓价 × 1.015 | |
| | 最小绝对止损 | 开仓价 × 1.05 | |
| **做多** | ATR硬止损 | 开仓价 - 2.5 × ATR(14) | 取三者**最小值**（最低价格，即最宽止损） |
| | 紧急止损 | 开仓价 × 0.985 | |
| | 最小绝对止损 | 开仓价 × 0.95 | |

> **为什么做多与做空取法不同？**  
> 止损价必须放在“不利方向”。做空时止损在上方，价格越高对空头越不利，应取三者最高价（防止过早触发）；做多时止损在下方，价格越低对多头越不利，应取三者最低价（同样防止过早触发）。本质上都是取 **对仓位最不利的价格中，最宽松（即距离开仓价最远）的那个**。

|--------------|--------------------------------------------|----------|

| 第二目标     | 盈利 ≥ 3.5 × ATR                           | 40%      |
| 移动止盈     | 从最佳价格回撤 1.5 × ATR                   | 剩余30%  |
| 时间止损     | 持仓超过 **72小时** 且未达第一目标         | 100%     |

## 6. 订单管理（重要）

### 6.1 平仓后自动取消未触发订单
- **规则**：当合约**完全平仓**（无论是止损触发、止盈触发、移动止盈、时间止损还是手动干预）后，系统必须**立即自动撤销**该合约下所有与该平仓方向相关的**未触发订单**，包括：
  - 未触发的止盈限价单（第一目标、第二目标）
  - 未触发的移动止盈条件单
  - 未触发的止损单（若止损单已触发则不存在）
- **目的**：防止已平仓后残留订单在后续价格波动中意外成交，导致无持仓下的净敞口或重复开仓。
- **实现方式**：在平仓回调函数中，调用交易所 `cancel_all_orders(symbol)` 接口，或记录每个订单ID逐一撤销。

## 7. 仓位管理与风控

| 规则                   | 设定                                     |
|------------------------|------------------------------------------|
| 每笔最大亏损           | 账户总资金 **2%**                        |
| 杠杆                   | ≤ **2倍**（固定）                        |
| 单日最多开仓（总）     | **3个币种**（含多空）                    |
| 同一方向单日最多开仓   | **2个**                                  |
| 连续亏损暂停           | 连续3笔亏损后，暂停交易 **2天**          |
| 最大回撤熔断           | 累计亏损 ≥ **15%** 时暂停交易 **一周**   |
| 黑名单机制             | 触发止损后24小时内反向波动超过止损价5%，该币种**永久禁止** |

**仓位计算示例**（账户1000U，做空止损幅度5%）：
- 最大亏损 = 1000 × 2% = 20U
- 开仓价值 = 20 / 5% = 400U
- 2倍杠杆 → 保证金 = 400 / 2 = 200U（佔20%）

## 8. 回测建议与方法

### 8.1 回测数据要求
- 时间范围：至少 **6个月**（推荐1年）
- 币种：币安永续合约中满足流动性门槛的币种（动态筛选）
- K线数据：1小时K线（OHLCV），OI历史数据，资金费率历史

### 8.2 回测步骤
1. **复现候选池筛选**：每日动态筛选，需模拟每日8:05的币种状态及流动性门槛。
2. **形态检测算法**：编写自动化脚本，严格按照文档中的量化标准（固定5根K线窗口）判定三次冲顶/探底、影线、放量。
3. **计算总分**：每个1小时K线收盘后对候选池内币种评分，记录符合条件的开仓信号。
4. **模拟交易**：按文档的止盈止损、仓位管理进行逐笔交易，记录盈亏、胜率、最大回撤。
5. **参数优化**：调整评分阈值（如总分从6.0调整到5.5或6.5）、ATR倍数等，观察稳定性。

### 8.3 预期回测指标（参考逻辑）
- **胜率**：65% – 80%（V2.0 软化后略低于 V1.9 的 70%-85%，但机会数增加）
- **盈亏比**：1.5 : 1 至 2.5 : 1
- **年化收益率**：60% – 180%（机会增多，收益上限提升）
- **最大回撤**：≤ 15%

> 建议使用 **前向测试**（Walk‑Forward）验证参数稳健性。

## 9. 实盘注意事项

1. **滑点与流动性**：避免在极端波动或低流动性币种开仓，优先选择24h成交额 > 5000万 USDT 且 OI > 2000万 USDT 的币种。

2. **资金费率结算处理（硬编码要求）**：
   - 资金费率每日 00:00、08:00、16:00 (UTC+8) 结算，结算时刻费率会跳变。
   - **必须**使用 K 线收盘时间点的**历史费率快照**进行情绪评分，**禁止使用实时费率**。
   - 推荐实现：调用币安 API `/fapi/v1/fundingRate?symbol=XXX&startTime=收盘时间&endTime=收盘时间+1` 获取该时间点有效的费率，并按结算周期缓存结果。
   - 若因技术限制无法实现历史费率查询，则作为备选方案：在结算时刻后的 **5分钟内**（如 8:00-8:05）**主动跳过评分**，等待费率稳定后再继续。注意此备选方案会导致每个结算周期丢失一次评分机会（一天最多3次），可能遗漏信号。

3. **多空同时持仓风险提示**：若遇到大盘极端行情，多空仓位可能同时亏损（双杀）。以下为**可选风控模块（非强制）**，可根据自身偏好决定是否启用：
   - **净 Delta 监控**：计算所有持仓的多空净敞口（多单总价值 - 空单总价值）。若净 Delta 的绝对值超过账户总资金的 **30%**，可选择暂停接收新信号，直至净敞口回落。此模块不影响已开仓的止损止盈，仅用于控制整体方向性风险。
   - 若不启用该模块，策略仍按原逻辑独立开仓，多空仓位自然对冲部分风险。

4. **黑名单管理**：建议使用数据库记录永久禁用的币种，避免再次入场。

5. **订单取消机制**：务必在代码中实现平仓后自动取消未触发订单，并定期（如每小时）检查残留订单做二次清理。

6. **定期复盘**：每周统计胜率、盈亏比、实际滑点，动态调整 OI/市值比分档。

## 11. 策略状态持久化与恢复（硬性要求）

### 11.1 需要持久化的状态

| 状态类型 | 存储内容 | 更新时机 |
|----------|----------|----------|
| 当前持仓 | 币种、方向、数量、开仓价、开仓时间 | 开仓/平仓后立即写入 |
| 未触发订单 | 订单ID、类型（止盈/止损/移动止盈）、触发价格、数量、挂单时间 | 挂单/取消时立即写入 |
| 黑名单 | 币种、原因、加入时间 | 加入黑名单时写入 |
| 策略元状态 | 连续亏损次数、熔断标记（是/否）、熔断结束时间、暂停结束时间 | 每次亏损/熔断/暂停时写入 |
| K线缓存 | 每个活跃币种：
  - 1h K线：最近 **168根**（7天）
  - 4h K线：最近 **50根**（由1h合成，约8.3天） | 每收到新1h K线后异步保存，同时触发4h合成与存储 |
| 活跃币种注册表 | 当前已注册K线服务的币种列表 | 每日8:05更新候选池时写入 |

### 11.2 启动恢复流程

策略每次启动（包括程序重启、崩溃重启、手动重启）时，必须按以下顺序恢复：

1. **加载元状态**：从数据库读取连续亏损计数、熔断状态、暂停状态。若仍在熔断或暂停期内，拒绝任何新开仓，并记录日志。
2. **同步交易所持仓**：
   - 调用币安 API `GET /fapi/v2/positionRisk` 获取当前所有实际持仓。
   - 与本地数据库中的持仓对比：以交易所为准，修正本地记录。若发现本地有但交易所无，则清除本地记录并记录异常。
   - 恢复每个持仓对应的止盈止损单：通过交易所订单列表（`GET /fapi/v1/openOrders`）重新关联已挂的止盈止损单（依据订单ID或自定义参数）。
3. **加载黑名单**：恢复永久禁止的币种列表，候选池筛选时自动排除。
4. **恢复K线缓存**：
   - 从数据库加载每个活跃币种（候选池 + 持仓币种）的最近168根1h K线和最近50根4h K线。
   - 若数据库无数据或数量不足，则通过币安API拉取最近7天的1h K线（最多168根），并合成4h K线补充。
   - 确保后续形态检测和指标计算（EMA20、ATR）所需的最小数据量。
5. **恢复K线服务注册状态**：根据数据库中存储的“活跃币种注册表”，重新订阅这些币种的1h K线WebSocket，恢复评分和持仓管理。

### 11.3 实时持久化要求

- 任何状态变更（开仓、平仓、挂单、取消订单、黑名单新增、元状态变化、K线更新、活跃币种变化）必须**同步**写入数据库（或 Redis + 定期落盘到 SQLite/PostgreSQL）。
- 推荐使用 SQLite（轻量，单文件）并启用 WAL 模式保证崩溃安全；生产环境可使用 PostgreSQL。
- 禁止仅依赖内存状态，否则重启后必然导致重复开仓、风控失效、订单丢失等严重问题。
- 启动恢复完成后，应检查是否有遗留的未完全成交订单（如部分成交的市价单）并按照 4.3 节中的“开仓延迟”规则处理。
