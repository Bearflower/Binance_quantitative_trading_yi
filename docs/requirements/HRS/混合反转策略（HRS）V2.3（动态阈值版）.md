# 混合反转策略 HRS V2.3（动态阈值版）完整文档
## Hybrid Reversal Strategy - Dynamic Threshold (HRS-DT)

## 1. 策略概述

- **目标**：针对币安永续合约中**流动性充足的存量币种**，捕捉**暴涨后的做空机会**与**暴跌后的做多机会**。
- **核心理念**：采用 **“双轨并行”** 机制。
  - **轨道 A（标准反转）**：利用“极端情绪 + 衰竭形态（三次探底/冲顶）”入场。
  - **轨道 B（极端市场模块 EMM）**：利用“价格极端偏离 + 费率极端 + 仓位拥挤”三重共振入场，绕过形态检测。
- **V2.3 核心变化**：将固定阈值全面升级为**动态相对阈值**，基于全市场每日分位数自动适配不同市场状态，彻底解决“固定阈值在冷清市场失效”的问题。

### 1.1 为什么需要动态阈值？

| 市场状态 | 固定阈值问题 | 动态阈值解决方案 |
|----------|-------------|-----------------|
| 牛市狂热 | 费率 ≥80% 容易满足，候选过多 | 只取 TOP 20%，保持精选 |
| 熊市冰冷 | 费率 ≥80% 几乎不可能 | 取 TOP 20%，相对极端即可入候选 |
| 震荡市 | 阈值与市场脱节 | 始终适配当前市场结构 |

> **核心原则**：策略要找的不是“绝对极端”，而是“相对极端”——在当前市场中最可能反转的那些币种。


## 2. 币种池与预筛选

### 2.1 币种池范围
- **初始池**：币安永续合约中**所有币种**（排除稳定币、杠杆代币、观察标签币）。
- **流动性门槛（必须同时满足）**：
  - 24h 成交额 ≥ **5000 万 USDT**
  - 当前持仓量 OI ≥ **1000 万 USDT**

### 2.2 每日动态筛选（自动执行）
每天 **08:05 (UTC+8)** 和 **20:05 (UTC+8)** 各执行一次全市场扫描，动态计算当日阈值。
支持多个扫描时间，可通过 `candidate_pool.scan_times` 列表配置（如 `["08:05", "20:05"]`），向后兼容单值 `candidate_pool.scan_time` 配置（如 `"08:05"`）。

#### 步骤 1：采集全市场数据
- 获取所有 USDT 永续合约的以下数据：
  - 涨跌幅（可通过 `candidate_pool.price_change_source` 配置来源：
    - `"daily_kline"`（默认）：使用日K线开盘价计算，公式 `(当前价 - 日K线开盘价) / 日K线开盘价`，更准确反映当日开盘以来的真实涨跌
    - `"ticker"`：使用 24hr 滚动窗口的 `priceChangePercent`，与旧版行为一致
    - 日K线获取失败时自动回退到 24hr ticker 数据）
  - 资金费率（年化）
  - OI / 市值比
  - 价格偏离 EMA20（4h）

#### 步骤 2：计算动态阈值（基于全市场分位数）

| 筛选维度 | 做空候选条件 | 做多候选条件 | 分位数说明 |
|----------|-------------|-------------|-----------|
| **24h 涨跌幅** | ≥ 12%（保持不变） | ≤ -10%（保持不变） | 绝对阈值保留，确保有足够极端性 |
| **资金费率（年化）** | ≥ 市场 **80分位数** | ≤ 市场 **20分位数** | TOP 20% / BOTTOM 20% |
| **OI / 市值比** | ≥ 市场 **80分位数** | ≤ 市场 **20分位数** | TOP 20% / BOTTOM 20% |
| **EMA20(4h)偏离** | ≥ 市场 **70分位数** | ≤ 市场 **30分位数** | TOP 30% / BOTTOM 30% |

**配置常量（可调）**：
```python
CONFIG = {
    "rate_percentile_short": 0.80,   # 做空费率分位数
    "rate_percentile_long": 0.20,    # 做多费率分位数
    "oi_percentile_short": 0.80,     # 做空OI/市值分位数
    "oi_percentile_long": 0.20,      # 做多OI/市值分位数
    "ema_percentile_short": 0.70,    # 做空EMA偏离分位数
    "ema_percentile_long": 0.30,     # 做多EMA偏离分位数
}
```

#### 步骤 3：筛选候选池
- 满足做空方向所有条件的币种 → 做空候选池
- 满足做多方向所有条件的币种 → 做多候选池
- 同一币种可同时进入两个候选池（由评分系统决定方向）

#### 2.3.2 日K线涨跌幅初筛

**配置项：** `candidate_pool.price_change_source`

```yaml
candidate_pool:
  # 价格变化来源：'daily_kline' 使用日K线开盘价计算，'ticker' 使用24hr ticker的 priceChangePercent
  price_change_source: "daily_kline"
```

**说明：**
- 默认值 `"daily_kline"`：使用日K线（1d, limit=1）的开盘价计算涨跌幅，公式为 `(当前价 - 日K线开盘价) / 日K线开盘价`
- 可选值 `"ticker"`：使用币安 24hr ticker 的 `priceChangePercent` 字段（24小时滚动窗口）
- **日K线优势**：以当日开盘价为基准，不受前一日价格波动影响，更准确反映当日开盘以来的真实涨跌幅度
- **回退机制**：当某个币种的日K线获取失败时，自动回退到 24hr ticker 数据，不影响扫描流程
- 实现位于 [candidate_pool.py:312](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/hrs/candidate_pool.py#L312-L357) `_get_daily_klines()`，使用 `Semaphore(20)` 控制并发，避免 API 过载

#### 2.3.3 候选池为空时休眠

**配置项：** `candidate_pool.sleep_on_empty`

```yaml
candidate_pool:
  # 候选池为空时休眠配置
  sleep_on_empty:
    enabled: true                      # 是否启用候选池为空时休眠
```

**说明：**
- 启用后，当候选池（做空 + 做多）为空时，策略进入休眠状态
- **休眠期间的行为：**
  - 不进行评分计算
  - 不发送心跳通知
  - 仅维护持仓监控（`_monitor_positions()`），确保已有持仓的止损止盈正常执行
- **精确休眠到下一次扫描时间：** 候选池为空时，不再使用固定时间间隔（如30分钟），而是通过 `_calculate_sleep_until_next_scan()` 计算距下一次候选池扫描时间的精确秒数，精确休眠到下一次扫描时间点。这样休眠醒来后恰好赶上扫描时间，候选池可能已被更新，减少不必要的等待轮次。
- **公用扫描时间计算：** `_get_next_scan_time()` 作为公用方法，被 `_candidate_scan_timer_loop()` 扫描定时器和 `_calculate_sleep_until_next_scan()` 休眠计算共同复用，确保两者使用完全一致的扫描时间算法，避免因时间计算不一致导致定时器与休眠产生时间偏差。
- **唤醒条件：** 每次休眠醒来后检查候选池是否已通过扫描更新，若已更新（候选池非空）则恢复正常执行
- **不会休眠的场景：**
  - `enabled: false` 时永不休眠
  - 候选池从未扫描过（尚未初始化）时不休眠
  - 候选池非空时不休眠
- 实现：
  - 休眠判断位于 [strategy.py:542](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/hrs/strategy.py#L542-L563) `_is_sleep_on_empty()`
  - 公用扫描时间计算位于 [strategy.py:838](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/hrs/strategy.py#L838-L877) `_get_next_scan_time()`
  - 精确休眠计算位于 [strategy.py:914](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/hrs/strategy.py#L914-L939) `_calculate_sleep_until_next_scan()`
  - 主循环休眠逻辑位于 [strategy.py:466](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/hrs/strategy.py#L466-L473)


## 3. 信号评分系统（双轨并行）

### 3.1 合约数据（权重 25%）—— OI / 市值比
*（评分逻辑不变，但注意：候选池筛选用的是动态阈值，评分用的是绝对值分档表）*

| OI / 市值比 | 做空得分 | 做多得分 | 说明 |
|-------------|----------|----------|------|
| > 0.25 | 10 | 0 | 极度拥挤 |
| 0.20 – 0.25 | 8 | 1 | 拥挤 |
| 0.15 – 0.20 | 6 | 3 | 中等偏拥挤 |
| 0.10 – 0.15 | 4 | 5 | 中性 |
| 0.05 – 0.10 | 2 | 7 | 冷清 |
| < 0.05 | 0 | 10 | 极冷清 |

### 3.2 标准技术面（轨道 A）—— 权重 45%

| 条件 | 分值 | 量化标准 |
|------|------|----------|
| **三次冲顶/探底** | 0–4 | 最近 **5根** K线高点/低点依次降低/抬高（差≥0.2%），或同一水平受阻/支撑≥3次 |
| **长影线** | 0–3 | 上/下影线 ≥ 实体 × 2 |
| **放量滞涨/止跌** | 0–3 | 成交量 ≥ 前5根均量 × 1.5 |
| **极端行情加分** | +1.5 | 做多：跌幅≥15%；做空：涨幅≥15% |
| **标准技术总分** | 0–10 | 三项相加 + 加分，封顶10分 |

**标准模式硬性入场要求**：
- 技术总分 ≥ 4.0
- 三次形态基础分 ≥ 1.0
- 标准总分 ≥ 6.0

### 3.3 情绪面（权重 30%）—— 资金费率

| 年化费率 | 做空得分 | 做多得分 |
|----------|----------|----------|
| > 150% | 10 | 0 |
| 100% – 150% | 8 | 2 |
| 50% – 100% | 6 | 4 |
| 0% – 50% | 3 | 6 |
| -20% – 0% | 1 | 8 |
| < -20% | 0 | 10 |


### 3.4 🚀 极端市场模块 EMM（轨道 B）

#### EMM 做多触发条件（三条件 AND）

| 条件 | 阈值 | 说明 |
|------|------|------|
| **24h 涨跌幅** | ≤ -15% | 固定阈值，确保足够跌幅 |
| **资金费率** | ≤ 市场 **10分位数** | 动态：全市场最冷的 10% |
| **OI / 市值比** | ≥ 市场 **90分位数** | 动态：全市场最拥挤的 10% |

#### EMM 做空触发条件（三条件 AND）

| 条件 | 阈值 | 说明 |
|------|------|------|
| **24h 涨跌幅** | ≥ +15% | 固定阈值，确保足够涨幅 |
| **资金费率** | ≥ 市场 **90分位数** | 动态：全市场最热的 10% |
| **OI / 市值比** | ≥ 市场 **90分位数** | 动态：全市场最拥挤的 10% |

#### EMM 技术得分
- EMM 触发时，技术分固定为 **5.0**

#### EMM 总分计算
```
EMM 总分 = (合约得分 × 0.25) + (5.0 × 0.45) + (情绪得分 × 0.30)
```
- **入场条件**：EMM 总分 ≥ **6.0**


### 3.5 🔶 半 EMM 机制（轨道 B-）

当恰好满足 **2/3** 的 EMM 条件时，触发“半 EMM”模式：

| 场景 | 触发条件 | 处理方式 |
|------|----------|----------|
| **半 EMM 做多** | 跌幅≤-15% + 费率≤10分位 **或** 跌幅≤-15% + OI/市值≥90分位 **或** 费率≤10分位 + OI/市值≥90分位 | 合约分=Max(原始, 3.0)，技术分=5.0，**总分≥5.0 入场** |
| **半 EMM 做空** | 涨幅≥+15% + 费率≥90分位 **或** 涨幅≥+15% + OI/市值≥90分位 **或** 费率≥90分位 + OI/市值≥90分位 | 合约分=Max(原始, 3.0)，技术分=5.0，**总分≥5.0 入场** |


## 4. 进场逻辑与执行（决策流）

在每个 1 小时 K 线收盘后，按以下顺序判断：

```
1. 检查完整 EMM（3/3 条件）
   └── 触发 → 技术分=5.0，总分≥6.0 → 入场 ✅

2. 检查半 EMM（2/3 条件）
   └── 触发 → 合约分=Max(原始,3.0)，技术分=5.0，总分≥5.0 → 入场 ✅

3. 检查标准模式
   └── 技术分=形态分+加分，技术≥4.0，形态≥1.0，总分≥6.0 → 入场 ✅

4. 均不满足 → 放弃 ❌
```

### 4.1 资金费率获取规则
- 必须使用 K 线收盘时间点的**历史费率快照**，禁止使用实时费率。

### 4.2 放弃条件
- 开仓延迟（15 分钟未完全成交）
- 流动性降级
- 新币策略冲突

| | 紧急止损 | 开仓价 × 0.985 | |
| | 最小绝对止损 | 开仓价 × 0.95 | |

### 5.2 止盈设置
- **第一目标**：盈利 ≥ 1.5 × ATR → 平 30%
- **第二目标**：盈利 ≥ 3.5 × ATR → 平 40%
- **移动止盈**：从最佳价格回撤 1.5 × ATR → 平剩余 30%
- **时间止损**：持仓超过 **72小时** → 100% 平仓
