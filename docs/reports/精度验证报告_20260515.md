```python
def _adjust_quantity_precision(
    self,
    quantity: Decimal,
    step_size: str
) -> Decimal:
    """
    调整数量精度（向下取整到stepSize的整数倍）

    注意：数量必须向下取整，避免超出账户余额

    Args:
        quantity: 原始数量
        step_size: 步长（如 '0.001'）

    Returns:
        调整后的数量
    """
    if not step_size or step_size == '0':
        return quantity

    step = Decimal(step_size)
    # 向下取整到stepSize的整数倍
    adjusted = (quantity // step) * step

    return adjusted
```

**验证结果**: ✅ 正确
- 使用向下取整（floor division），确保调整后的数量不大于原始数量
- 避免超出账户余额
- 正确处理Decimal类型，避免浮点数精度问题

```python
def _adjust_price_precision(
    self,
    price: Decimal,
    tick_size: Decimal
) -> Decimal:
    """
    调整价格精度（四舍五入到tickSize的整数倍）

    注意：价格应该四舍五入到最近的tickSize整数倍

    Args:
        price: 原始价格
        tick_size: 价格步长

    Returns:
        调整后的价格
    """
    if not tick_size or tick_size == 0:
        return price

    # 四舍五入到tickSize的整数倍
    # 使用 Decimal 的 quantize 方法进行精确的四舍五入
    adjusted = (price / tick_size).quantize(Decimal('1'), rounding='ROUND_HALF_UP') * tick_size

    return adjusted
```

**验证结果**: ✅ 正确
- 使用四舍五入（ROUND_HALF_UP），符合交易习惯
- 正确处理Decimal类型，避免浮点数精度问题
- 使用quantize方法确保精确计算

```python
    """

    Args:
        symbol: 交易对名称

    Returns:
        包含 quantityPrecision, pricePrecision, stepSize, tickSize 等字段的字典
    """

    for s in exchange_info.get('symbols', []):
        if s.get('symbol') == symbol:
            filters = {}
            for f in s.get('filters', []):
                if f['filterType'] == 'LOT_SIZE':
                    step_size = f.get('stepSize', '0.001')
                    filters['stepSize'] = step_size  # v6.16.6：保存原始stepSize供精度截断
                    if '.' in step_size:
                        filters['quantityPrecision'] = len(step_size.split('.')[1].rstrip('0') or '0')
                    else:
                        filters['quantityPrecision'] = 0
                elif f['filterType'] == 'PRICE_FILTER':
                    tick_size = f.get('tickSize', '0.01')
                    filters['tickSize'] = Decimal(tick_size)
                    if '.' in tick_size:
                        filters['pricePrecision'] = len(tick_size.split('.')[1].rstrip('0') or '0')
                    else:
                        filters['pricePrecision'] = 0
                elif f['filterType'] == 'MIN_NOTIONAL':
                    filters['minNotional'] = f.get('notional', '5')

            # 缓存精度信息
            self._symbol_precision_cache[symbol] = filters
            return filters
```

**验证结果**: ✅ 正确
- 从币安API获取最新的交易规则
- 正确解析LOT_SIZE、PRICE_FILTER、MIN_NOTIONAL过滤器

## 五、潜在问题与建议

### 1. 已解决的问题

#### 问题：TRXUSDT下单失败（已解决）
**原因**: v6.16.6之前，精度调整使用精度位数截断，对于stepSize=1的币种（如TRXUSDT、XRPUSDT），会错误地保留小数位。

**解决方案**: v6.16.6版本修改了`get_symbol_info()`方法，保存原始stepSize供精度截断使用，而不是使用精度位数。

**验证结果**: ✅ TRXUSDT已成功下单，精度调整正确。

### 2. 潜在风险

#### 风险1：最小下单金额检查
**现状**: 当前代码未在API层强制检查最小下单金额（minNotional）。

**建议**:
- 在`place_order()`方法中添加最小下单金额检查
- 如果调整后的数量 × 价格 < minNotional，抛出异常或警告

**优先级**: 中等（策略层已有检查，但API层双重保险更安全）

#### 风险2：精度信息缓存过期
**现状**: 精度信息缓存在客户端实例生命周期内有效，但币安可能更新交易规则。

**建议**:
- 添加缓存过期时间（如24小时）
- 或在每次下单前强制刷新精度信息

**优先级**: 低（币安很少修改交易规则）

### 3. 改进建议

#### 建议1：添加精度调整日志
**现状**: 当前有DEBUG级别日志，但在生产环境可能不开启。

**建议**:
- 在INFO级别记录精度调整前后的值
- 便于排查下单失败问题

**优先级**: 中等

#### 建议2：单元测试覆盖
**现状**: 当前只有手动验证脚本。

**建议**:
- 添加单元测试，覆盖各种边界情况
- 集成到CI/CD流程

**优先级**: 高
