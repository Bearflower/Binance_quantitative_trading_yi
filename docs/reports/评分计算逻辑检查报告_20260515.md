def _calculate_score(self, indicators: Dict, klines: Dict) -> float:
    """计算综合评分（修正后的评分维度）"""
    score = 0.0
    weights = self.scoring_config['weights']

    # 趋势强度评分（40%）
    trend_score = self._calculate_trend_strength_score(indicators)
    score += trend_score * weights['trend_strength']

    # 形态质量评分（35%）
    pattern_score = self._calculate_pattern_quality_score(indicators, klines)
    score += pattern_score * weights['pattern_quality']

    # 动量背离评分（25%）
    momentum_score = self._calculate_momentum_divergence_score(indicators, klines)
    score += momentum_score * weights['momentum_divergence']

    return round(score, 2)
```

**评分维度**:
1. **趋势强度评分** (40%): 基础分50分，根据MA、MACD、ADX调整
2. **形态质量评分** (35%): 基础分50分，根据形态检测调整
3. **动量背离评分** (25%): 基础分60分，根据RSI、MACD调整

async def get_multi_timeframe_data(
    self,
    symbol: str,
    intervals: List[str] = ["1h", "4h", "1d"]
) -> Dict[str, List[Dict]]:
    """获取多时间框架数据"""

    tasks = [
        self.get_klines(symbol, interval, self._get_limit(interval))
        for interval in intervals
    ]

    results = await asyncio.gather(*tasks, return_exceptions=True)

    data = {}
    for interval, result in zip(intervals, results):
        if isinstance(result, Exception):
            logger.error("获取多时间框架数据失败", ...)
        else:
            data[interval] = result

    return data
```

## 三、问题诊断

### 3.1 评分计算逻辑分析

**理论评分范围计算**:

假设各维度评分范围：
- 趋势强度: 40-90分
- 形态质量: 50-100分（基础分50，最多加95分但限制在100）
- 动量背离: 30-100分（基础分60，最多加45分，最少减30分）

**综合评分范围**:
- **最低分**: 40×0.4 + 50×0.35 + 30×0.25 = 16 + 17.5 + 7.5 = **41分**
- **最高分**: 90×0.4 + 100×0.35 + 100×0.25 = 36 + 35 + 25 = **96分**

**用户报告的评分**:
- BTCUSDT: 61.25
- ETHUSDT: 53.25
- BNBUSDT: 63.45
- SOLUSDT: 60.0
- XRPUSDT: 63.2

这些评分都在理论范围内，**但连续多次完全相同确实异常**。

### 3.2 可能的问题点

#### 问题1: K线服务端缓存 ⭐⭐⭐⭐⭐

**可能性**: 极高

**原因**:
- 客户端每次都会请求最新数据
- 但K线服务端可能有缓存机制
- 如果服务端缓存未及时更新，会导致数据不变

**验证方法**:
```bash
# 检查K线服务日志
ssh root@SERVER_IP "docker logs --tail 100 btc_eth_kline_service"

# 检查K线数据更新时间
ssh root@SERVER_IP "docker exec btc_eth_kline_service ls -lh /data/klines/"
```

#### 问题2: 市场数据变化小 ⭐⭐⭐

**可能性**: 中等

**原因**:
- 如果市场在一段时间内波动很小
- 技术指标可能变化不大
- 导致评分相似

**验证方法**:
```python
# 检查K线数据是否变化
# 在analyze方法中添加日志
logger.info(f"{symbol} 最新K线时间: {klines['1h'][-1]['close_time']}")
logger.info(f"{symbol} 最新收盘价: {klines['1h'][-1]['close']}")
```

#### 问题3: 评分基础分过高 ⭐⭐

**可能性**: 低

**原因**:
- 每个维度都有较高的基础分（50-60分）
- 调整幅度有限（-20到+30）
- 导致评分变化范围有限

**影响**:
- 评分变化范围在41-96分之间
- 大部分评分会集中在50-70分之间
- 但不应该完全相同

#### 问题4: 技术指标计算问题 ⭐

**可能性**: 极低

**原因**:
- 技术指标计算基于pandas的rolling、ewm等方法
- 这些方法都是确定性的
- 只要输入数据相同，输出就相同
