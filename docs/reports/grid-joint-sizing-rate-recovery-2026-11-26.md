# 网格实际分配、接口限流与锁定恢复

## 事故证据

2026-11-26 21:05（北京时间），经典网格以实际 5x 杠杆、106 USDT 预算建出 11 单（每单 0.028 ETH），随后出现 -1003。普通 NEW 回报逐条触发全账户对账；稳定网格每 5 秒也重复全量对账，叠加每轮敞口检查和逐单建单验证，消耗共享 IP 请求权重。最终 11 单均撤销、零成交、无仓位，执行器锁定为 `position unavailable while exiting`。

全账户普通挂单和条件挂单查询不带 symbol 时各消耗 40 权重，带 symbol 为 1。为保留跨币种异常订单发现，仍采用全账户查询。依据：[币安限流说明](https://developers.binance.me/en/docs/products/derivatives-trading-usds-futures/general-info)、[币安 USD-M 交易接口](https://developers.binance.me/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade)。

## 修复

- 通过归属、交易 ID、状态、累计成交数量验证的无成交 NEW 回报不再重复 REST 对账；真实成交、撤单、异常归属仍走完整路径。
- 稳定网格完整对账间隔 30 秒；实际移格、成交、补单、重连继续先取新证据。价格终止边界和敞口检查保留每轮执行。
- 网格执行专用客户端按权重限额 1200/滚动 60 秒；共享 IP 权重头达到 1800 暂停一窗，429/-1003 至少退避 60 秒且服从更长 Retry-After，418 至少 120 秒。保留单次 POST、不重试未知下单结果。此限速不能替其他进程限制请求，但会响应共享 IP 头部。
- 当前清理锁仅在连续两次独立检查通过时恢复：风险 ALLOW、用户流就绪、空仓、无普通/条件挂单、所有订单终态与成交历史逐项匹配、账本净仓为零。保留手工/风险锁。原子写入恢复证据与新信号时间门槛，不直接 SQL 解锁。
- 实盘生产者仅产生结构及利润约束，实际分配器统一使用交易所过滤器、实际核验杠杆、账户可用余额、硬上限；不再用 10x 推导的数量限制 5x 实盘。
- 优先在正数建议预算内寻找最大可行格数；如不足，仅将最少允许格数预算补至最低可行金额（向上取分），仍受余额、240 USDT 保证金、2400 USDT 名义敞口和 13 单上限约束。不提高杠杆，不用零/负数/缺失建议回退 500 USDT。
- 所有 N+1 价格层都计入预算，包括暂时等于市价的价格层；数量按 step 向下，最低价层也须满足 minNotional，最低数量按 step 向上求解。
- 原信号保持不变，真实执行格数、预算来源、过滤器、硬上限、全层保证金和最低单金额在首单提交前写入账户绑定 SQLite 账本。移动网格和重启读取实际几何参数；推送读取同一实际计划及真实成交减码记录。

旧 20:05 价格样本：17 USDT 建 10 格不可行；新分配为 4 格、每单 0.013 ETH、预算 22.10 USDT，最低价层金额 20.73565 USDT。10 格所需最低预算 48.62 USDT；49 USDT 可行。286 USDT 是余额上限证据，并不强制全部投入。
