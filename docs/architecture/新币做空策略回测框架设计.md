# 新币做空策略回测框架设计文档

## 1. 概述

### 1.1 目标
为新币做空策略V4.1（信号质量优化版）设计一个完整的回测框架，用于验证策略效果、优化参数、评估风险。

### 1.2 设计原则
- **复用性**：复用现有策略代码（评分引擎、形态识别、交易执行器）
- **真实性**：模拟真实交易环境（手续费、滑点、杠杆）
- **可扩展性**：支持向量化回测和逐笔回测两种模式
- **可追溯性**：详细记录每笔交易和决策过程

### 2.2 核心模块

#### 2.2.1 数据加载器 (DataLoader)
**职责**：
- 从CSV文件加载K线数据
- 从JSON文件加载交易对列表
- 从YAML文件加载策略配置
- 数据预处理和验证

**输入**：
- K线数据路径：`backtest/new_coin/data/klines/`
- 交易对列表：`backtest/new_coin/data/coin_list.json`
- 策略配置：`strategies/new_coin/config.yaml`

**输出**：
- 标准化的K线数据结构
- 交易对信息列表
- 配置参数字典

**CSV解析方式**：
- 使用 `csv.reader` 按固定字段顺序解析（币安API导出的CSV文件无列名行）
- 字段顺序：`open_time, open, high, low, close, volume, close_time, quote_asset_volume, trade_count, taker_buy_volume, taker_buy_quote_volume`

#### 2.2.2 回测引擎 (BacktestEngine)
**职责**：
- 协调各个模块运行
- 管理回测时间线
- 执行回测逻辑
- 记录交易过程

**核心流程**：
```
1. 初始化账户状态
2. 遍历每个交易对
   2.1 加载K线数据
   2.2 获取上线时间，解析UTC格式（容错处理：若onboardDate为毫秒时间戳导致listing_hours<0，回退尝试秒级时间戳）
   2.3 遍历每根K线
       2.3.1 动态计算当前K线对应的上线时长
       2.3.2 检查上线时长是否超过窗口（48小时），若已入场则跳过（入场后立即停止监控）
       2.3.3 检查K线时间是否在回测范围内（end_date包含整天23:59:59）
       2.3.4 计算OI/总交易量比率
       2.3.5 形态识别
       2.3.6 评分计算
       2.3.7 判断是否入场
       2.3.8 模拟开仓（入场成功后立即将该币种加入已入场集合，后续K线不再评分）
       2.3.9 持仓管理（止损止盈）
       2.3.10 模拟平仓
       2.3.11 记录交易
3. 统计分析
4. 生成报告
```

#### 2.2.3 信号检测器 (SignalDetector)
**职责**：
- 复用现有评分引擎
- 复用现有形态识别器
- 判断入场条件

**核心方法**：
- `detect_patterns()`: 形态识别
- `calculate_score()`: 计算评分
- `should_entry()`: 判断是否入场

#### 2.2.4 订单执行器 (OrderExecutor)
**职责**：
- 模拟开仓
- 模拟平仓
- 计算手续费和滑点
- 管理止损止盈

**核心方法**：
- `execute_short()`: 模拟开空仓
- `close_position()`: 模拟平仓
- `calculate_pnl()`: 计算盈亏
- `check_stop_loss()`: 检查止损
- `check_take_profit()`: 检查止盈

> **说明（回测 vs 生产）**：回测框架的订单执行器通过 `slippage_rate`（滑点率）模拟成交价格，不区分订单类型。生产环境 `strategies/new_coin/executor.py` 自 V4.1 起已将所有订单由市价单改为限价单（开仓 LIMIT、止损 STOP、止盈 TAKE_PROFIT、平仓 LIMIT 带市价回退容错），通过 `trading.limit_order_slippage` 配置限价偏移。详见需求文档第 10 节"订单执行机制（限价单改造 V4.1）"。

#### 2.2.5 仓位管理器 (PositionManager)
**职责**：
- 管理持仓状态
- 计算仓位大小
- 跟踪持仓盈亏
- 实现风控机制

**核心功能**：
- 动态仓位计算（基于2%风险）
- 分批止盈管理
- 移动止盈跟踪
- 时间止损检查
- 连续亏损暂停
- 最大回撤熔断

#### 2.2.6 统计分析器 (StatisticsAnalyzer)
**职责**：
- 计算统计指标
- 分析交易结果
- 生成统计数据

**核心指标**：
- 总交易次数
- 胜率
- 平均盈亏
- 盈亏比
- 最大回撤
- 夏普比率
- 总收益率
- 平均持仓时间

#### 2.2.7 报告生成器 (ReportGenerator)
**职责**：
- 生成回测报告
- 创建可视化图表
- 导出交易记录

**输出内容**：
- Markdown报告
- 资金曲线图
- 回撤曲线图
- 交易盈亏分布图
- 交易记录CSV

## 4. 回测参数配置

### 4.1 基础参数
```yaml
backtest:
  initial_balance: 500      # 初始资金（USDT）
  commission_rate: 0.0004   # 手续费率（0.04%）
  slippage_rate: 0.0001     # 滑点率（0.01%）
  leverage: 2               # 杠杆倍数

  # 时间范围
  start_date: "2025-01-01"  # 开始日期（自动补全为 00:00:00）
  end_date: "2025-12-31"    # 结束日期（自动补全为 23:59:59，包含整天）

  # 回测模式
  mode: "bar_by_bar"        # bar_by_bar（逐笔）或 vectorized（向量化）
```

**时间范围处理说明**：
- `start_date`：如果不含时间部分，自动补全为 `00:00:00`
- `end_date`：如果不含时间部分，自动补全为 `23:59:59`，确保结束日期当天的K线数据全部纳入回测

### 4.2 策略参数
复用 `strategies/new_coin/config.yaml` 中的配置

## 5. 实现细节

### 5.1 手续费和滑点计算
```python
# 开仓成本
entry_cost = entry_price * quantity * (1 + commission_rate + slippage_rate)

# 平仓收入
exit_revenue = exit_price * quantity * (1 - commission_rate - slippage_rate)

# 实际盈亏
pnl = (entry_price - exit_price) * quantity - (entry_cost + exit_revenue)
```

### 5.2 仓位计算
```python
# 每笔最大亏损 = 账户总资金 × 2%
max_loss = balance * 0.02

# 开仓价值 = 最大亏损 / 止损幅度
position_value = max_loss / stop_loss_percent

# 保证金 = 开仓价值 / 杠杆倍数
margin = position_value / leverage

# 数量 = 开仓价值 / 当前价格
quantity = position_value / current_price
```

### 5.3 ATR计算
```python
def calculate_atr(klines, period=14):
    """计算ATR（Average True Range）"""
    tr_list = []
    for i in range(1, len(klines)):
        high = klines[i]['high']
        low = klines[i]['low']
        prev_close = klines[i-1]['close']

        # TR = max(High - Low, |High - PrevClose|, |Low - PrevClose|)
        tr = max(high - low, abs(high - prev_close), abs(low - prev_close))
        tr_list.append(tr)

    # ATR = 平均TR
    atr = sum(tr_list[-period:]) / period
    return atr
```

### 5.4 止损止盈逻辑
```python
# 最终止损价 = MAX(ATR止损, 紧急止损, 最小绝对止损)
stop_loss_price = max(
    entry_price + 2.5 * atr,      # ATR止损
    entry_price * 1.015,           # 紧急止损（1.5%）
    entry_price * 1.05             # 最小绝对止损（5%）
)

# 分批止盈
target1_price = entry_price - 1.5 * atr  # 第一目标
target2_price = entry_price - 3.5 * atr  # 第二目标

# 移动止盈
if current_price - lowest_price >= 1.5 * atr:
    # 触发移动止盈，平仓剩余仓位
```

## 9. 注意事项

### 9.1 数据质量
- 确保K线数据完整、准确
- 检查交易对列表的有效性
- 验证配置参数的合理性

### 9.2 回测限制
- 无法完全模拟真实市场环境
- 忽略了市场深度和流动性影响
- 无法模拟极端行情（闪崩、暴涨）

### 9.3 参数优化
- 避免过度拟合
- 使用样本外数据验证
- 考虑参数稳定性

### 9.4 生产环境订单执行机制（V4.1 限价单改造）

回测框架与生产环境在订单执行上的差异：

| 维度 | 回测框架 | 生产环境（V4.1） |
|------|---------|-----------------|
| 成交价格模拟 | `slippage_rate` 滑点率 | `limit_order_slippage` 限价偏移 |
| 订单类型 | 不区分（按滑点模拟成交） | 全部限价单（LIMIT/STOP/TAKE_PROFIT） |
| 平仓容错 | 无需容错（模拟必然成交） | 限价失败回退市价单 |
| 配置位置 | `backtest` 段 | `trading.limit_order_slippage` |

生产环境限价单改造详情见需求文档：`docs/requirements/new_coin/新币做空策略 V4.0 完整版.md` 第 10 节。
