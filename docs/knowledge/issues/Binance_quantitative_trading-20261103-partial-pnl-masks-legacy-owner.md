# 部分止盈写入入场记录 realized_pnl 后，未平旧仓归属查询返回空

## 现象

2026-11-02 21:32 北京时间巡检时，SOLUSDT 交易所仍有激进策略旧多仓 0.47，reduce-only 硬止损覆盖 0.47，但策略状态和看板不再包含 SOL；XRP 上报正常。通用归属查询返回空，使 SOL 旧仓跳过时间退出、额度占用和保护单补查。

## 根因

通用归属查询只看 `realized_pnl IS NULL` 的非终态入场记录。SOL 原始入场订单 `253886663232` 的数据库记录 id=4553 已写入部分已实现盈亏 0.1002，即使其原始 0.47 lot 仍未归零，也被查询过滤。交易所成交链为 BUY 0.47、BUY 0.54、SELL 0.54，净仓一直保留原 0.47。

## 解决

仅对预先审计过首笔成交时间的旧仓，在现行归属查询为空时执行兜底：重新查询现行入场记录以区分无记录与数据库错误；读取自原锚点起的完整交易所成交，确认无中途归零且净额等于当前仓位；再以首笔成交 `orderId` 精确匹配数据库入场记录的策略、方向和订单类型。若有其他策略有效归属，或任何证据缺失、数量不符、查询失败，禁止兜底，阻止开仓/减仓并保留旧快照。额度、保护、到期退出与看板使用同一边界。

## 验证

- 修复提交 `5079d1a7`，合并最新主线后 `568912df`；259 项相关回归通过，1 项预期失败。CI Run #148 于 2026-11-02 22:06 北京时间成功部署。
- 生产容器内 `strategy.py` 和 `main.py` 的 SHA-256 与提交一致；22:06、22:10、23:10 周期均记录了 SOL“以原始成交单恢复旧仓归属”，证明实际归属兜底运行。
- SOL 后于 23:58:22 以 reduce-only SELL 0.47 归零；XRP 于 2026-11-03 01:45:24–25 以 reduce-only SELL 87.5 + 40.7 归零。08:05 独立复核两币净仓和在挂条件单均为零；旧仓对应残余止盈单各 4 张已在归零后精确清理；数据库历史 OPEN 条件单 SOL 16 行、XRP 9 行已在交易所无仓无挂单后标终态，复查两币 OPEN 均为 0。

## 适用范围与修订

仅适用于 `strategies/btc_eth_aggressive/` 内带固定审计锚点的旧仓兜底，不改变其他策略的通用归属 SQL。旧仓已归零；下一笔新仓自然重启的元数据恢复仍需独立观察。

## 教训

AI 归纳，仅供参考：把 `realized_pnl IS NULL` 当作“仓位仍未平”的唯一证据，会漏掉部分减仓后的剩余仓位。净额账户的归属兜底必须由完整成交 lot 与原始入场订单共同证明，且在证据不足时保持拒绝交易。
