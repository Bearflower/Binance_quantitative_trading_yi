# ETHUSDT 子账号订单网格自动执行设计

日期：2026-11-09。状态：待用户审阅。范围是把现有半自动网格信号接入币安 USDT 本位永续合约订单，不重新设计市场状态、网格区间、网格数、保证金建议或预警阈值。

## 1. 基线与目标

仓库 `strategies/grid/config.yaml` 的版本标识仍为 `2.5.0`；实际信号计算已合入 V2.5.5 资本约束，V2.5.4 实时预警仍为 `shadow`。本设计以当前 `GridSignalBot.run_once()` 的结构化结果和 `capital_constraint.enabled=true` 为策略基线。实时预警不直接触发交易；其研究结果不能当作已验收的自动平仓信号。

目标是让独立子账号上的 ETHUSDT 中性网格按现有信号自动建单、配对补单、暂停、终止和平仓，并在恢复为可交易状态后自动重建。飞书只承担报告与告警，通知发送或冷却不能决定交易是否发生。

## 2. 方案选择

采用独立执行器消费 `GridSignal`。不直接开启 `GridStrategy` 的旧自动路径：它调用 `calculate_grid_levels()`，使用另一套价格和数量配置；`OrderManager` 的订单、`PositionManager` 的仓位和 `RiskManager` 的风险状态主要在内存，数据库写入仍被注释。也不接外部机器人，以免执行语义脱离本仓库的市场状态。

执行器与信号计算、订单规划、币安访问、持久账本、对账和通知分离。信号内容以结构化字段为准，禁止解析中文推送文案做交易决策。

### 现有代码逐项对照

| 位置 | 已具备 | 自动执行缺口 |
| --- | --- | --- |
| `signal_bot.py` | `run_once()` 返回市场状态、动态网格参数、资本可行性 | 主循环仅在通知冷却允许时更新 `last_signals`，没有供执行器逐次消费的持久决策出口 |
| `grid_calculator.py` | V2.5.5 区间、格数、模式、每格数量与可行性计算 | 旧 `calculate_grid_levels()` 读取独立的 `spacing/base_quantity`；缺从 `DynamicGridParams` 生成实盘订单计划的适配器 |
| `strategy.py` | 旧自动模式有初始化、轮询、反向挂单入口 | 半自动模式跳过执行；旧自动路径未消费 `GridSignal`，风险停止只撤单，不执行用户要求的终止平仓 |
| `order_manager.py` | 限价下单、撤单、轮询成交的原型 | 订单与成交集合只在内存，数据库写入被注释；无部分成交配对、幂等恢复或交易所账本对账 |
| `position_manager.py`、`risk_manager.py` | 本地仓位与风险计算原型 | 持久化代码未接通；不能作为子账号实盘仓位或已实现盈亏的权威依据 |
| `shared/binance_api.py` | 下单、按客户端单号查单、撤单、查挂单/仓位及条件单接口已有基础封装 | 需核实子账号普通合约模式、订单结果未知和保护单参数；缺本策略专属的用户数据流消费与订单事件账本 |
| `realtime/` | V2.5.4 实时行情与参考快照影子设施 | 当前 `mode: shadow`，不得接实盘平仓动作 |

## 3. 决策与执行契约

| 市场状态 | 执行动作 |
| --- | --- |
| `OSCILLATION`、`WEAK_TREND` | 若资本可行、数据有效且账户已对账，建网格或按新参数重建；暂停后的仓位先核对再恢复 |
| `EARLY_WARNING_15M` | 停止补单，撤销会增加净敞口的普通挂单；已有仓位保留并确保交易所侧保护有效 |
| `TREND_ACCELERATING` | 停止补单，撤销会增加净敞口的普通挂单；已有仓位保留并确保保护有效 |
| `VOLATILITY_ABNORMAL` | 停止补单，撤销全部网格普通挂单；已有仓位保留并确保保护有效 |
| `PRICE_EMERGENCY`、`TREND_CONFIRMED_1H`、`EXTREME_STRONG_TREND`、`NORMAL_STRONG_TREND` | 立即进入终止流程：禁止补单，撤网格单，使用只减仓单平净仓，核对空仓及无遗留网格单 |
| 未知状态、计算失败、资金不可行、输入过期、账户状态不确定 | 禁止新开仓或补单，保留已确认的保护；告警并等待对账。不得把未知状态当成震荡 |

上述“建议终止”也自动平仓，是用户明确选择。市场退出后，后续有效的可交易信号可自动重建；账户级风控熔断和账本不一致则锁定开仓，必须排除原因后显式解除。

早期预警和趋势加速原文允许“取消逆势单、保留顺势单”，但当前策略没有定义可直接用于订单的“逆势”判定，用户也要求暂缓方向显示问题。自动执行采取可核验的保守解释：保留仓位及只减仓保护，取消所有可能增加净敞口的普通单；不根据推送的“上升/下降”字样决定保留开仓单。这不改变状态触发阈值或终止范围。

执行决策基于**每次成功的巡检**，不受 `_should_notify()` 的飞书冷却控制。状态转换必须按时间顺序处理；旧信号不能覆盖新信号。对同一信号重复送达须幂等。

## 4. 网格订单语义

账户只交易 `ETHUSDT`，使用单向持仓 `BOTH`、单资产 USDT 模式。子账号不能同时运行其他 ETHUSDT 策略或人工 ETHUSDT 订单。启动前核验账户模式、杠杆、保证金模式、交易权限和 ETHUSDT 的交易所过滤器；不匹配即拒绝建网格。隔离保证金为目标模式；无法确认其生效即拒绝建网格。

取 `DynamicGridParams` 的上下界、格数、等差/等比模式及 `CapitalFeasibility.qty_per_grid` 生成网格价格，不调用旧 `calculate_grid_levels()`。新网格初始为空仓，现价下方挂买、上方挂卖；现价所在格不挂会立即成交的单。每次实际成交量形成一笔配对义务，按相邻格价挂反向限价单；未配对头寸计入净仓和风险。部分成交只补对应的已成交量，数量经交易所步长取整；不足最小量的残量留在账本，直到可合并或终止。每格同时最多一个有效普通网格单，禁止重试产生重复单。

任何价格、数量先按实时 `exchangeInfo` 的 `PRICE_FILTER`、`LOT_SIZE`、最小名义金额与订单上限校验。若四舍五入使价位重合、利润空间不足或订单不可提交，本轮网格不可执行并告警；不擅自加杠杆、扩大区间或提高投入。网格计划必须满足仓位、保证金与最大可成交订单情景下的风险上限，不能仅按单个订单校验。

## 5. 终止、保护与自动重建

终止采用持久状态 `EXITING`：先禁止所有补单，再撤该执行器所有普通网格单，查询撤单期间的成交与最新净仓，按净仓方向提交 `reduceOnly` 市价平仓单，再查询到空仓及无普通网格挂单才进入 `FLAT`。超时或 API 结果未知时按客户端订单号查单、重新对账，不盲目重复平仓。若交易所确认仍有仓位，继续只减仓处理并告警。退出的每一步在账本中留痕。

只要存在净仓，维持交易所侧 `STOP_MARKET` 全平保护，触发价使用当前网格的 `stop_loss_low` 或 `stop_loss_high`，不以进程在线作为唯一止损保障。保护单建立或更新失败时禁止新开仓；对尚未保护的仓位执行终止。暂停状态保留净仓时同样保持保护。价格边界更新需先完成对账，且不能出现无保护的新开仓窗口。

`FLAT` 后在下一次有效的 `OSCILLATION` 或 `WEAK_TREND` 巡检中自动重建，前提是账户净仓为零、所有旧网格普通单及保护单均已清理、资金可行且独立风险限制未熔断。退出信号仍有效时不得因为定时重试自动重建。

## 6. 账本、对账和风险边界

持久账本保存 `account_id`、`grid_epoch`、信号 ID/计算时间/配置哈希、状态、计划价位、每个订单的 `clientOrderId` 与交易所 `orderId`、累计成交量、配对关系、保护单 ID、每次风险判定及退出阶段。下单意图先落盘，再调用 API；结果未知时按同一 `clientOrderId` 查询，确认未受理后才重试。仅处理本执行器命名前缀的订单；发现外部 ETHUSDT 订单或不明仓位时锁定开仓并告警。

用户数据流的 `ORDER_TRADE_UPDATE` 驱动实时状态，REST 查询作为启动、断线恢复、定期和终止后的权威对账。重启时先读取账本及交易所持仓、普通挂单、条件单和成交，再决定恢复；绝不按内存中的旧计划直接补单。单进程租约防止两个实例同时执行同一子账号。

现有配置的 `trading.margin=500` USDT、`trading.leverage=10` 只作为回放与模拟基线。实盘必须有独立的硬上限：子账号可用资金、允许使用的保证金、总名义敞口、单日损失、最大回撤及最多挂单数同时约束交易；所有限制取更严者。任何实盘硬上限缺失或非正数时启动失败，不能从模拟基线自动填充。API Key 仅授予所需合约交易权限并绑定服务器 IP，不启用提现。实盘开关默认关闭，子账号凭证不进入仓库或日志。

## 7. 实施与验证门槛

1. 建立纯规划器与决策状态机：用 V2.5.5 结构化信号生成目标订单和终止动作；测试每一种市场状态、资本不可行、重复和乱序信号。
2. 建立持久账本和交易所适配：测试部分成交、成交与撤单竞态、超时结果未知、订单过滤器、重启接管、外部订单及仓位。
3. 建立保护与风控：测试有仓无保护、保护单失败、日亏损熔断、终止失败后的持续对账，确保任何异常都不会新开仓。
4. 历史信号回放与模拟盘核对逐单结果，再使用独立子账号的小额资金进行人工监督验证。只有验证通过且用户另行提供子账号权限与实盘风险限额，才可启用实盘开关。

当前隔离工作树基线：`python3 -m pytest -q tests/test_strategies/test_grid_kline.py tests/test_strategies/test_grid_capital_linkage.py tests/integration/test_grid_strategy.py` 得到 105 通过、1 失败。失败的 `TestGridStrategy.test_strategy_analyze` 将 `get_ticker_price()` 模拟为返回价格字典，而真实客户端签名返回 `Decimal`；因此是既有测试替身与真实接口不一致，不能据此断定生产计算错误。实施前修正该替身或将此测试单独标记为既有失败，保持新功能回归证据可判读。独立执行器仍不得复用旧 `calculate_grid_levels()`，因为它不消费 V2.5.5 参数。
