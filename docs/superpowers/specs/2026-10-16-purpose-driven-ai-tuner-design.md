# 目的驱动的全自动 AI Tuner 与策略回测体系设计

## 1. 文档信息

- 日期：2026-10-16
- 状态：待用户书面确认
- 首期候选策略：MTPCS 激进版；若准备度审计不通过则改为 HRS
- 关联模块：`ai_tuner/`、`shared/config_loader.py`、各策略的 `tuning_overrides/`

## 2. 背景与问题

当前 AI Tuner 已开启 `approval.auto_apply.enabled=true`，会每周生成参数建议并写入覆盖层，但现有流程缺少清晰的优化目标、可靠的候选资格考试、覆盖层真实生效确认和可比较的历史版本成绩卡。

审查中已经确认以下问题：

1. MTPCS 与 MTPCS 激进版的 AI Tuner 参数路径和真实配置层级不一致，导致传给 LLM 的可调参数主要剩下被禁止调整的杠杆与仓位参数。
2. 网格调优器会优化 `grid.grid_spacing_atr_multiplier`，但当前建议系统的实盘网格间距并不由该参数直接决定。
3. 提示词声明单次变化不超过 20%，程序实际只按 200% 阈值产生 warning，且无 error 时不会采用范围截断后的值。
4. `from` 值由 LLM 自报，未与真实当前配置核对。
5. 连续多次不调整后，学习模块会强制 LLM 修改参数，与“证据不足时保持当前版本”的原则冲突。
6. 覆盖层写入成功、数据库标记已应用，不代表策略容器已经加载了该覆盖层。
7. 目前只有网格存在简化逐 K 回测，其回测参数含义又与建议系统的真实计算存在偏差；其他策略没有足以支撑自动上线的等价回放器。

这些问题意味着当前系统是“自动写参数”，还不是“有明确目标、有资格考试、有生效证明和失败恢复的全自动调优”。

## 3. 产品目标

建设一个目的明确、范围受控、可自动生效的参数调优闭环：

> LLM 只在现有且实盘使用的参数空间中提出候选覆盖层；确定性程序使用与实盘逻辑一致的回放、硬约束、稳健性测试和历史版本成绩卡决定是否生效，并在失败时自动切换到适合当前市场状态的合格历史覆盖层。

统一最高目标：

> 在最大回撤硬约束内，最大化扣除真实交易成本后的风险调整收益。

其中：

- MTPCS、MTPCS 激进版、新币做空、HRS：调优覆盖层自动生效到自动交易策略。
- 网格：调优覆盖层只自动生效到网格建议系统，不自动替用户开设、调整或停止网格。

## 4. 非目标

首期不包含：

- 让 LLM 新增指标、交易条件或策略代码。
- 让 LLM 修改数据库、订单执行流程、仓位或杠杆红线。
- 自动执行网格交易。
- 用机器学习重新设计策略。
- 同时搜索几十个参数的全局最优解。
- 承诺回测表现可以保证未来收益。
- 第一阶段迁移全部策略到第三方交易框架。

## 5. 核心设计原则

1. **LLM 无批准权**：LLM 只生成候选参数，程序负责验证、评分、选择和生效。
2. **只调现有参数**：候选项必须已存在、实盘读取、允许覆盖，并通过类型、范围和组合约束。
3. **不为调参而调参**：没有显著更优候选时保持当前覆盖层。
4. **同场比较**：当前版本、新版本和历史版本必须在相同数据、成本和执行假设下比较。
5. **稳健优先于峰值**：选择在相邻参数、多个时间窗口和成本压力下仍能成立的稳定平台，不选择尖峰最优值。
6. **覆盖层不可变**：已创建版本不可修改；切换通过 `.active` 指针完成，保留完整审计轨迹。
7. **生效必须可证明**：写入、加载、参数哈希、运行版本四者必须一致，才允许成绩归因。

## 6. LLM 的职责与边界

### 6.1 LLM 可以做什么

- 根据诊断报告识别主要失效模式。
- 从本轮开放的参数组中选择最多 1～3 个参数。
- 给出当前值、目标值、变化幅度、因果理由和适用市场状态。
- 输出对净收益、最大回撤、交易数和单笔期望的方向性预期。
- 在证据不足时输出空调整。

### 6.2 LLM 不可以做什么

- 输出不在参数清单中的路径。
- 修改代码或引入新指标。
- 修改杠杆、仓位及其他红线。
- 调整未启用、shadow-only 或代码未读取的参数。
- 绕过单次变化上限。
- 决定最终生效版本或自行给候选打通过分。

### 6.3 参数清单 `ParameterManifest`

每个策略维护机器可读清单，示例：

```yaml
scoring.entry_threshold:
  enabled: true
  runtime_path: scoring.entry_threshold
  value_type: float
  min_value: 5.0
  max_value: 8.0
  max_change_pct: 0.10
  group: entry_quality
  affects:
    primary: [trade_count, expectancy]
    secondary: [win_rate, max_drawdown]
  invariants: []
  conflicts_with: [scoring.technical.min_total_score]
  live_usage_probe: hrs.scoring.entry_threshold
```

参数状态分为：

- `tunable`：允许 LLM 调整。
- `redline`：禁止调整。
- `shadow`：当前不影响实盘，禁止调整。
- `dead`：配置存在但代码未读取，禁止调整并告警。
- `derived`：由其他参数计算，禁止直接调整。

### 6.4 本轮参数开放方式

诊断器先把问题映射到参数组，再向 LLM 开放小范围参数：

| 诊断问题 | 首选参数组 |
|---|---|
| 低质量交易过多 | 入场评分、候选池过滤 |
| 交易过少但信号质量良好 | 入场评分、冷却参数 |
| 盈亏比差 | 分批止盈、移动止盈 |
| 尾部亏损大 | 入场过滤、现有止损参数中的非红线项 |
| 持仓过久且收益衰减 | 时间止损、移动止盈 |
| 连亏集中 | 冷却、暂停阈值 |
| 网格手续费侵蚀 | 实际影响建议输出的网格数、区间与单格利润参数 |

同一轮最多开放一个主要参数组，最多修改三个参数。

## 7. 市场状态模型

### 7.1 目的

市场状态用于：

- 给覆盖层成绩分组。
- 从历史版本库中寻找适合当前环境的版本。
- 为 LLM 提供上下文。
- 在没有更优候选时判断是否需要安全暂停。

市场状态不直接替代各策略已有的实时风控，尤其不替代网格现有的多层预警状态机。

### 7.2 统一状态分类

使用两个主维度：

- 方向：`uptrend`、`downtrend`、`range`
- 波动：`normal_vol`、`high_vol`

形成六个普通状态：

1. 上涨趋势 × 正常波动
2. 上涨趋势 × 高波动
3. 下跌趋势 × 正常波动
4. 下跌趋势 × 高波动
5. 震荡 × 正常波动
6. 震荡 × 高波动

另设 `STRESS` 安全否决状态，用于极端价格冲击、流动性异常或波动率突变。`STRESS` 不参与普通版本排名。

### 7.3 输入因子

全局状态使用：

- BTC、ETH 7 日与 14 日收益。
- 4h/1d EMA20 与 EMA50 的相对位置及斜率。
- 4h/1d ADX 趋势强度。
- 主要交易标的上涨比例或位于 EMA20 上方的比例。
- ATR/价格及 7 日实现波动率在过去 180 日的百分位。

策略局部状态使用同一套特征，但标的是该策略当期可交易集合。最终匹配以局部状态为主、全局状态为辅。

### 7.4 状态稳定机制

- 采用进入阈值和退出阈值不同的滞回规则。
- 普通状态连续确认 2～3 次后切换。
- 保存分类置信度；低于阈值时不得仅因状态变化切换覆盖层。
- 成绩卡同时保存标签和原始特征向量，版本选择使用相似度而不是只比较字符串标签。

## 8. 覆盖层版本库与成绩卡

### 8.1 版本身份

每个版本保存：

- `strategy_id`
- `overlay_version`
- `overlay_content_hash`
- `base_config_hash`
- `parameter_schema_version`
- `strategy_code_revision`
- `created_at`
- `activated_at`
- `requested_version`
- `loaded_version`
- `effective_params_hash`
- `activation_verified_at`

基础配置、策略代码或参数 Schema 不兼容的历史版本必须标记为 `ineligible`，不得自动恢复。

### 8.2 成绩卡

成绩卡至少包含：

- 生效时市场状态及特征快照。
- 运行期间各市场状态占比。
- 各市场状态下的净收益、最大回撤、风险调整收益、交易笔数和置信度。
- 总净收益、最大回撤、Calmar/Sortino、Profit Factor、单笔期望、尾部亏损。
- 手续费、滑点和资金费率。
- 收益集中度、币种集中度和单笔贡献上限。
- 回测成绩、压力测试成绩和实盘成绩。
- 是否真实加载成功。
- 合格、观察中、不合格、已过期等状态。

### 8.3 自动选择顺序

1. 过滤路径、Schema、代码版本、样本量和硬约束不合格的版本。
2. 优先选择方向与波动均匹配的历史版本。
3. 其次选择方向相同、波动相邻的版本。
4. 再次选择波动相同、方向相邻的版本。
5. 使用特征距离、成绩置信下限和回撤共同排序。
6. 只有候选分数比当前版本高出最小优势门槛时才切换。

## 9. 数据窗口与防过拟合

### 9.1 数据分区

- 诊断区：此前 8 周，向 LLM 提供聚合诊断。
- 盲测区：最近 2 周，具体策略结果不提供给 LLM，用于候选资格考试。
- 历史市况库：更早数据，按市场状态切片，用于稳健性和压力验证。

当前市场状态快照可以提供给 LLM，但盲测区各候选的收益结果不得进入提示词。

### 9.2 历史状态样本范围

- 默认在最近 8 周诊断区与最近 2 周盲测区完成主判断。
- 当前状态样本不足 14 天时，可向前扩展到 16 周寻找相似状态片段。
- 超过 16 周仍无足够相似样本时，返回“证据不足”，不无限追溯旧行情。
- 长期压力测试数据可超过 16 周，但只用于风险否决，不参与近期主分数。

## 10. 回测引擎选型调研

### 10.1 公开 Agent Skill

公开技能可以提供回测方法论，但不能替代运行时引擎。

候选：

1. `nicepkg/ai-workflow@backtest-expert`
   - 约 98～99 次安装，源仓库约 285 stars。
   - skills.sh 显示 Gen Agent Trust Hub、Socket、Snyk 检查通过。
   - 强调摩擦成本、压力测试、偏差防护和“寻找最不容易坏的策略”。
   - 适合作为回测设计与评审清单，但安装量不高，使用前仍需审阅其完整 `SKILL.md` 和引用资料。
2. `omer-metin/skills-for-antigravity@quantitative-research`
   - skills CLI 显示约 2.6K 安装，仓库约 160 stars。
   - 覆盖 walk-forward、样本外验证、交易成本和过拟合防护。
   - 范围较宽、内容带较强角色化表达，适合作为补充研究规范，不应当成为项目事实来源。

结论：可在实施阶段选择性安装并审阅 `backtest-expert`，同时把关键规则固化到本项目测试和文档中；项目正确性不能依赖某个外部 skill 是否被加载。

## 11. 推荐回测架构

采用“共享事件回放底座 + 策略专用回放适配器”。

### 11.1 共享底座

共享底座负责：

- 时间有序的历史事件流。
- 多周期已收盘 K 线对齐。
- 候选池、资金费率、OI、市值和市场状态等带时间戳快照。
- 市价、限价、止损、止盈、移动止损、撤单与超时事件。
- 手续费、滑点、资金费率、价格精度、数量精度和最小名义价值。
- 仓位、现金、保证金和权益曲线。
- 分批止盈与剩余仓位。
- 最大持仓数、冷却、连续亏损暂停和熔断。
- 确定性时钟和随机种子。
- 绩效计算和逐事件审计日志。

### 11.2 策略专用适配器

适配器负责调用现有策略逻辑，而不是复制或重新解释业务规则：

- `MTPCSAggressiveReplayAdapter`
- `MTPCSReplayAdapter`
- `HRSReplayAdapter`
- `NewCoinReplayAdapter`
- `GridAdviceReplayAdapter`

适配器必须提供：

- `build_universe(at_time)`
- `calculate_signal(snapshot, config)`
- `create_orders(signal, portfolio, config)`
- `manage_open_position(snapshot, position, config)`
- `apply_strategy_guards(state, config)`

如果现有策略函数混合了网络、数据库和纯计算，应通过依赖注入或薄包装提取可回放接口；不得改变交易规则本身。

### 11.3 数据完整性

回放所需数据按策略登记：

- MTPCS 系列：多周期 K 线、成交量、ADX/ATR/EMA/MACD/RSI 所需原始数据、实际交易标的集合。
- HRS：历史候选池、OI/市值比、资金费率、技术形态原始 K 线、各模式启用状态。
- 新币做空：历史币种资格、上市时间、成交额、OI、资金费率、候选池及形态数据。
- 网格：1m/更细粒度 K 线或 aggTrades、建议生成时点、网格区间、人工执行事实单独记录。

缺少时点快照的数据不得使用当前值回填历史，否则属于未来数据泄漏。

## 12. 回测准确性与稳健性

### 12.1 实盘一致性验收

回放引擎必须用历史实盘区间做金样对账：

- 信号方向一致率。
- 入场时点与价格偏差。
- 平仓触发顺序。
- 分批止盈数量。
- 平仓原因。
- 手续费和净盈亏偏差。
- 每日权益与最终权益偏差。

未达到策略验收阈值前，该策略不得启用新版全自动调优。

### 12.2 稳定平台测试

对候选参数执行当前值附近的 OAT 扰动：`-10%`、`-5%`、候选值、`+5%`、`+10%`，同时保证取值仍在合法范围内。

候选只有在相邻取值下仍满足回撤硬约束且主要成绩不发生断崖式下降时才通过。首期不引入大规模黑盒 Hyperopt，避免扩大搜索次数和数据挖掘偏差。

### 12.3 成本压力测试

- 基准成本：真实费率、估算滑点和资金费率。
- 压力一：手续费与滑点乘 1.5。
- 压力二：手续费与滑点乘 2.0。
- HRS 与新币策略增加流动性下降和无法按理想价格成交场景。

### 12.4 收益集中度测试

- 单笔交易不得贡献过高比例的总收益。
- 单一币种不得贡献过高比例的总收益。
- 候选不得只在一个两周窗口获胜、其他窗口显著恶化。

### 12.5 最低样本与置信下限

每个策略通过准备度审计后确定最低成交或有效信号数。版本排名使用保守置信下限，不使用平均分的乐观点估计。样本不足版本标记为 `observing`，不能成为自动回退目标。

## 13. 指标筛选方法

### 13.1 指标分类

1. **硬约束指标**：最大回撤、红线修改、配置生效、数据完整性。
2. **主目标指标**：风险调整后收益、扣费后净收益。
3. **诊断指标**：胜率、交易数、平均持仓、信号等级分布。
4. **稳健性指标**：窗口一致性、参数敏感性、成本压力、收益集中度。

胜率和交易数不得单独成为优化目标。

### 13.2 指标筛选流程

1. 建立参数到指标的专家映射，形成初始因果假设。
2. 对每个可调参数执行 OAT 敏感性测试。
3. 计算参数变化与各指标变化的方向、幅度和跨窗口稳定性。
4. 删除没有实际影响、影响方向不稳定或与其他参数高度重复的参数。
5. 对保留参数建立主要指标、次级指标和冲突指标清单。
6. 每次只按当前诊断开放相关参数组。

### 13.3 四个自动策略的建议评分

硬门槛优先，过门槛后计算 0～100 分：

| 指标 | 权重 |
|---|---:|
| 风险调整后收益 | 35% |
| 扣费后净收益 | 25% |
| 最大回撤质量 | 20% |
| 跨窗口稳定性 | 10% |
| 样本可靠性与单笔期望 | 10% |

风险调整指标优先使用 Sortino 与 Calmar，Sharpe 作为辅助，因为加密策略收益通常偏态且包含跳跃。

### 13.4 网格建议系统评分

| 指标 | 权重 |
|---|---:|
| 扣费后的风险调整收益 | 35% |
| 扣费后净收益 | 25% |
| 最大回撤质量 | 20% |
| 手续费侵蚀率 | 10% |
| 可执行性与资金利用率 | 10% |

网格额外硬约束：单格利润覆盖成本、最小下单量、保证金可执行，并确认调优参数确实改变建议输出。

### 13.5 候选通过标准

新覆盖层必须同时满足：

1. 所有参数均为 `tunable`。
2. 参数真实被实盘代码读取。
3. 单轮修改 1～3 个参数。
4. 变化幅度不超过各参数上限。
5. 组合不变量成立。
6. 最大回撤不突破硬限制。
7. 最近两周盲测不劣于当前版本。
8. 历史相似市况下不显著恶化。
9. 多数滚动窗口不劣于当前版本。
10. 相邻参数扰动后仍处于稳定平台。
11. 1.5 倍成本压力下仍合格。
12. 满足最低样本要求。
13. 综合分至少高于当前版本的最小优势门槛，初始建议为 5 分。

具体阈值必须在首个策略准备度审计和基准回放后校准，不能脱离数据直接硬编码。

## 14. 自动决策状态机

### 14.1 周度正常流程

1. 收集数据并验证完整性。
2. 计算当前市场状态。
3. 对当前版本生成 8 周诊断报告。
4. 根据诊断选择本轮参数组。
5. LLM 生成新候选覆盖层或空调整。
6. 执行静态校验、盲测、相似市况回放、敏感性和成本压力测试。
7. 将当前版本、新候选和合格历史版本统一排名。
8. 有显著更优版本时原子切换。
9. 向策略读取端确认已加载版本和参数哈希。
10. 保存成绩卡和审计记录。

### 14.2 没有更优版本

- 当前版本未突破硬约束：继续使用当前版本。
- 当前版本突破硬约束且存在安全历史版本：切换到当前市场状态下回撤更低的合格版本。
- 当前版本突破硬约束且所有版本均不合格：暂停新增开仓，每日重评；已有仓位继续由原风控管理。
- 网格对应行为是输出“当前不建议新开网格”，不自动操作用户仓位。

暂停不采用固定天数。恢复条件是出现通过硬约束和资格考试的版本。

### 14.3 防版本震荡

- 普通情况下同一策略 7 天内最多切换一次。
- 只有回撤硬约束或生效异常允许紧急切换。
- 状态变化需达到置信度和连续确认要求。
- 新版本必须超过最小优势门槛。

## 15. Prompt 与输出协议

统一输出建议：

```json
{
  "decision": "PROPOSE|HOLD|DATA_ERROR",
  "objective": "maximize_risk_adjusted_net_return_under_drawdown_cap",
  "diagnosis": [
    {
      "metric": "expectancy",
      "observation": "...",
      "evidence": "..."
    }
  ],
  "target_metrics": {
    "risk_adjusted_return": "increase",
    "max_drawdown": "not_increase",
    "net_return": "increase"
  },
  "adjustments": {
    "approved.parameter.path": {
      "from": 1.0,
      "to": 1.05,
      "change_pct": 0.05,
      "causal_reason": "..."
    }
  },
  "applicable_market_regimes": ["downtrend_high_vol"],
  "expected_impact": {
    "trade_count": "decrease",
    "expectancy": "increase",
    "max_drawdown": "not_increase"
  },
  "confidence": 0.0
}
```

Prompt 必须明确：

- 优化目标与硬约束。
- 本轮唯一允许调整的参数及范围。
- 当前市场状态。
- 8 周诊断数据，不包含盲测答案。
- 历史调优仅用于避免重复错误，不直接命令“反向调整”。
- 证据不足时必须 `HOLD`。
- 删除“连续多次不变后必须调整”的规则。

## 16. 首期策略选择

首期在 MTPCS 激进版与 HRS 之间执行最近 90 天准备度审计：

- 已平仓交易数与有效信号数。
- 市场状态覆盖度。
- 交易记录字段完整度。
- 覆盖层版本能否与交易记录对应。
- 入场、分批止盈、移动止损和最终平仓能否回放。
- 外部数据时点快照是否齐全。

默认优先 MTPCS 激进版，因为完成后可以复用到 MTPCS 原版；若其样本或字段不足，则首期改为 HRS。

## 17. MVP 端到端验证

### 17.1 MVP 目的

MVP 不是简化版回测工具，而是用最小范围验证以下完整闭环是否合理：

```text
历史数据
→ 策略诊断
→ LLM 提出参数候选
→ 回测资格考试
→ 与当前及历史覆盖层比较
→ 自动选择
→ 写入覆盖层
→ 确认真实加载
→ 记录成绩卡
→ 表现不合格时自动切换
```

只有 MVP 通过，才允许扩展到更多参数组和其他策略。

### 17.2 MVP 范围

- 只接入一个策略：优先 MTPCS 激进版；最近 90 天准备度审计不通过时改为 HRS。
- 只开放“入场质量”一个参数组。
- 参数清单可以包含 3～5 个 `tunable` 参数，但单轮最多修改 1～2 个。
- 单参数变化默认不超过 10%。
- 每次版本比赛只包含当前生效版本、一个 LLM 新候选和最多三个兼容历史覆盖层。
- 市场状态使用已定义的六个普通状态与 `STRESS`，只实现规则分类、特征快照、成绩分组和相同/相邻状态匹配。
- 评分只使用最大回撤硬门槛、扣费后净收益、Calmar/Sortino、单笔期望、跨窗口稳定性和最低样本。
- 不实现账户组合级资金控制、大规模 Hyperopt、Web 管理界面、自动网格执行和多策略并行调优。

首期不开放杠杆、仓位、核心止损红线、shadow 参数、候选池结构性参数和复杂退出参数组。

### 17.3 MVP 第一步：实盘历史复现

选择首期策略已经发生过的多个真实交易区间，加载当时的基础配置和覆盖层，验证回放结果：

- 信号方向。
- 入场时点与入场价格。
- 分批止盈、止损和最终平仓顺序。
- 平仓原因。
- 手续费、净盈亏和权益曲线。

历史实盘不能在约定容差内复现时，MVP 停止在本阶段，不进入自动候选验证。

### 17.4 MVP 第二步：12～16 周时间机器演练

从历史某个周末开始，按真实时间逐周推进。每个历史时点只能读取当时及以前的数据：

```text
历史周末 T
→ 使用 T 以前的诊断区、盲测区和历史状态库
→ 生成候选并执行资格考试
→ 选择当期覆盖层
→ 使用 T 之后一周行情记录后验成绩
→ 推进到下一个历史周末
```

时间机器演练必须统计：

- LLM 每周提出候选、`HOLD` 和 `DATA_ERROR` 的次数。
- 候选资格考试通过率及每项淘汰原因。
- 新覆盖层在下一周真实未见行情中的表现。
- 与始终使用固定基准覆盖层相比的净收益、最大回撤和风险调整收益。
- 市场状态匹配选中历史版本后的后验表现。
- 普通切换、紧急切换、保持当前和暂停的次数。
- 版本来回震荡次数。
- 是否存在任何未来数据访问。

时间机器中的 LLM 请求和所有外部数据必须可缓存、可重放，保证同一实验可以重复验证。为避免模型随机性掩盖系统问题，验收实验使用固定模型版本、固定采样参数和保存的原始响应。

### 17.5 MVP 第三步：单策略真实全自动运行

时间机器演练通过后，只对 MVP 策略启用新版闭环：

- 每周最多生成一个新覆盖层。
- 每轮最多修改两个参数。
- 普通情况下七天内最多切换一次。
- 最大回撤硬约束或生效异常允许紧急切换。
- 写入后必须验证 `requested_version`、`loaded_version` 和 `effective_params_hash` 一致。
- 加载确认失败时恢复原 `.active`，不得按新版本继续归因或交易。
- 其他策略继续原有流程，不受 MVP 调度器影响。

### 17.6 MVP 通过标准

#### 回放能力

- 相同输入重复运行得到相同结果。
- 防未来数据测试通过。
- 历史实盘的信号方向、主要退出原因、费用、盈亏和权益达到约定一致性。

#### 调优质量

- 不出现红线、shadow、dead 或未知参数。
- 不因连续多次 `HOLD` 而强制调整。
- 新候选只有超过最小优势且通过全部硬门槛时才生效。
- 参数相邻扰动不存在断崖式恶化。
- 1.5 倍成本压力下仍合格。

#### 时间机器表现

- 相比固定基准覆盖层，风险调整后收益不恶化。
- 最大回撤不高于固定基准。
- 没有通过未来信息选择版本。
- 版本切换频率不突破设计限制。
- 无合格版本时能正确保持当前或暂停，不会选择不合格版本。

#### 生产链路

- 覆盖层文件、`.active`、策略实际加载版本和参数哈希一致。
- 加载失败可以自动恢复原版本。
- 每个自动决定均保存选择原因和其他版本的淘汰原因。

### 17.7 MVP 结束后的决策

MVP 只允许得出以下三类结论：

1. `GO`：完整闭环合理，扩大参数组并接入第二个策略。
2. `REVISE`：回放可靠，但 LLM 候选、评分或市场状态匹配不足，修正后重新执行时间机器演练。
3. `STOP`：无法可靠复现实盘，或时间机器结果显示系统性恶化；停止扩展，优先修复数据和可回放性。

## 18. 分阶段交付

### 阶段 0：生产安全与事实修复

- 修复所有策略参数路径。
- 修复范围截断、真实 `from` 校验和 20%/参数级变化上限。
- 删除强制调参规则。
- 修复网格调优参数与真实建议逻辑的错位。
- 验证容器挂载、覆盖层加载和运行时刷新方式。
- 在基础安全修复完成前，禁止将不合格候选写入生效指针。

### 阶段 1：准备度审计与参数契约

- 比较 MTPCS 激进版与 HRS 最近 90 天数据质量。
- 为首期策略建立 `ParameterManifest`。
- 建立参数到指标的映射和 OAT 敏感性基线。
- 确定策略级硬回撤、最低样本和成绩阈值。

### 阶段 2：共享回放底座

- 建立事件时钟、行情快照、订单、成交、持仓、费用和权益模块。
- 建立无未来数据保护和逐事件审计。
- 建立统一指标与市场状态模块。

### 阶段 3：首期策略回放器

- 接入准备度审计胜出的策略。
- 完成实盘金样对账。
- 达到一致性门槛后解锁候选资格考试。

### 阶段 4：成绩卡和版本自动选择

- 建立版本元数据、成绩卡和资格状态。
- 建立市场状态匹配和相似度排名。
- 建立当前、新候选、历史覆盖层统一比较。

### 阶段 5：Prompt 和全自动调度集成

- 更新 Prompt 和响应 Schema。
- 接入候选生成、资格考试、自动切换和生效确认。
- 接入每日监控、紧急切换和暂停恢复。

### 阶段 6：逐策略扩展

- MTPCS 激进版完成后优先复用到 MTPCS 原版。
- HRS、新币做空分别补齐历史外部数据和候选池回放。
- 最后重构网格建议回放，使其与真实建议系统参数完全一致。

## 19. 测试与验收

### 19.1 单元测试

- 参数路径、类型、范围、变化率和不变量。
- 市场状态边界、滞回和置信度。
- 手续费、滑点、资金费率、部分成交和精度。
- 订单生命周期、分批止盈和移动止损。
- 指标、置信下限和成绩计算。
- 版本兼容过滤和排名。

### 19.2 属性与防偏差测试

- 使用未来数据时测试必须失败。
- 相同输入产生完全相同输出。
- 增加成本不能提高净收益。
- 放大亏损交易不能改善回撤指标。
- 不兼容覆盖层不能被激活。
- 未确认加载的版本不能获得实盘成绩。

### 19.3 集成测试

- LLM 输出错误路径被拒绝。
- 范围截断后的值才进入覆盖层。
- 写入失败不移动 `.active`。
- 加载确认失败自动恢复原 `.active`。
- 当前版本、新版本和历史版本使用同一数据切片。
- 全部版本不合格时进入暂停而不是选“最不差”的不合格版本。

### 19.4 实盘一致性验收

首期策略选取多个已知交易区间，形成固定金样。具体容差在准备度审计后按策略确定，但必须覆盖信号、订单、持仓、退出和权益，不得只比较最终 PnL。

## 20. 可观测性与审计

每轮记录：

- 数据版本与时间范围。
- LLM 输入摘要、输出和模型版本。
- 候选参数和静态校验结果。
- 回测、盲测、压力测试与敏感性结果。
- 市场状态及置信度。
- 所有参赛版本排名和淘汰原因。
- `.active` 切换前后值。
- 策略实际加载版本与参数哈希。
- 自动暂停、恢复和紧急切换原因。

所有自动决策必须能回答：“当时为什么选这个版本，而不是其他版本？”

## 21. 主要风险与反方审查

1. **回测与实盘不一致**：通过金样对账和加载哈希门禁缓解。
2. **市场状态误分类**：通过特征向量、置信度、滞回和相似度缓解。
3. **版本幸存者偏差**：统一在相同数据与成本假设下重放，不直接比较不同时期绝对收益。
4. **搜索次数导致过拟合**：限制每轮参数组、候选数和变化范围，并使用盲测与稳定平台测试。
5. **旧版本不兼容**：保存代码、配置和 Schema 身份，严格过滤。
6. **新币/HRS 历史外部数据缺失**：缺失时不回填当前值；未补齐前不开放全自动。
7. **暂停错过反弹**：每日重新评估，不使用固定暂停天数。
8. **网格人工执行污染成绩**：网格以统一建议回放为主，人工实盘为辅。
9. **多策略同时选择高风险版本**：首期策略级闭环完成后，再增加账户组合级风险预算；不把组合控制混入首个回放器交付。
10. **第三方框架锁定**：首期使用项目原生接口；事件模型保持清晰，未来可用 NautilusTrader PoC 替换底层而不改变成绩卡和调优协议。

## 22. 验收结果定义

本项目完成时，至少达到：

1. LLM 无法修改未批准参数或策略代码。
2. 首期策略的新候选在自动生效前通过可重复的资格考试。
3. 回放结果与选定历史实盘区间达到约定一致性。
4. 每个覆盖层拥有可比较、可审计且包含市场状态的成绩卡。
5. 当前版本不合格时可自动选择兼容、同状态且合格的历史版本。
6. 没有合格版本时系统暂停新增开仓，而不是盲目回滚。
7. 覆盖层切换后可以证明目标版本和目标参数已被策略加载。
8. 网格调优只影响建议系统，不自动执行交易。
