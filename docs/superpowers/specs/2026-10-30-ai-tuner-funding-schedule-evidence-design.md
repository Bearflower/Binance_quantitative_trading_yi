# AI Tuner 逐币种资金费日程证据设计

日期：2026-10-30。适用策略：`btc_eth_aggressive`、`hrs`。本设计只建设前瞻采集、冻结与资格考试的数据门禁，不改变策略参数、订单、覆盖层或生产自动生效行为。

## 目标与事实边界

`/fapi/v1/fundingRate` 是已发生结算事件，不能用它反推“预期事件”再证明自身完整。`/fapi/v1/premiumIndex` 的 `nextFundingTime` 是采集时可见的未来结算预告；`/fapi/v1/fundingInfo` 是当时可见的间隔辅助信息，不是可回填的历史日程。采集开始之前没有这条独立于结算事件的历史证据，必须保持 `BLOCKED_DATA`。五分钟采样不是交易所签名的绝对证明，短于采样间隔的变化仍是残余风险；本设计把它定义为可审计的资格考试证据标准，不称为历史事实的绝对证明。

## 边界与数据流

1. 独立采集器每五分钟调用只读公开市场接口，覆盖 MTPCS 激进版 BTC/ETH 与该时点 HRS 历史候选池的并集。先落不可变的采集批次（请求起止时间、结果、所选币种响应的规范化 JSON SHA-256、失败原因），再落每币种观测（交易所数据时间、本地接收时间、`nextFundingTime`、当前 `fundingIntervalHours` 若有、来源批次、所选原始字段）。哈希仅证明留存内容未被改写，不是交易所签名或 HTTP 原始字节哈希。批次与观测均只追加；重试只能幂等去重，不得改写既有时点。禁止用当前接口值伪造过去时点。
2. 采集器独立于小时级 HRS 市场快照任务，使用单独的只读行情客户端和仅能写证据表的数据库身份。失败应保留失败批次并告警，不影响交易容器。采集成功不触发回放、调参或覆盖层写入。
3. 本地只读导出批次/观测、历史 universe、`fundingRate` 结算事件和必要配置，冻结到 Git 忽略的快照目录，逐文件 SHA-256 与 manifest 绑定。服务器不跑回测。若导出来源、时间或文件不完整，先返回 `BLOCKED_DATA`，不创建“已验证”身份。
4. 验证器只使用 `as_of` 前已经采集的数据，在每个币种需要覆盖的时段重建“当时最新可见”的预告序列；日程变更可以发生，但必须有变更前后的有效观测。预告与实际结算事件做一对一匹配，匹配容差仅用于认定同一事件；资金费仍在实际事件时刻入账。验证器输出独立证据状态与明确缺口；只有独立证据通过后，真实策略回放入口才可读取该日程。现有 `synthetic_fixture` 通道不得被当成真实资格考试证据。

## 覆盖与阻断规则

- 计划采集间隔为 5 分钟；同币种相邻有效观测间隔 `>7` 分钟，或源时间相对接收时间滞后 `>2` 分钟，该时段不具备日程覆盖。空响应、币种缺失、时间倒序、未来来源时间、重复冲突、哈希不一致均阻断。允许相同批次重试得到完全相同内容，不允许静默覆盖冲突内容。
- MTPCS 激进版 BTC/ETH 须覆盖整个资格考试窗口。HRS 每个币种只要求覆盖其历史候选池成员时段；入池前数据不作为必需证据，出池后亦不要求。入池到首个有效观测之间若没有证据，不算已覆盖；新入池成员可能令 HRS 暂时 `BLOCKED_DATA`，不得以当前候选池回填。历史成员资格必须来自已冻结的历史 scan run。
- 预告结算时间与实际结算时间相差 `<=30` 秒且一对一才可匹配；漏项、额外事件、重复事件、无法解释的预告变化都阻断。跨越边界的开仓/平仓依实际结算时间计算。若窗口内出现采集故障或间隔切换后证据不足，保留缺口，不用统一 8 小时规则补齐。
- 资格考试的资金费证据仅是众多门禁之一；通过它不等于 readiness、回放、金样对账或最终自动生效通过。采集不足 90 天时，报告“已覆盖起止、缺口与剩余窗口”，不得出 `PASS`。

## 组件与接口

- `database/postgres/init-scripts/14-ai-tuner-funding-schedule-evidence.sql`：追加式批次/逐币种观测表、约束、索引；不触碰现有交易表。
- `ai_tuner/funding_schedule/collector.py`：只读 HTTP 获取与标准化、批次结果；不包含回测或资格考试逻辑。
- `ai_tuner/funding_schedule/repository.py`：参数化追加写入和只读查询；冲突 fail-closed。
- `ai_tuner/funding_schedule/cli.py`：`once` 与独立 daemon，按 UTC 五分钟边界运行；失败指标和告警，不修改交易状态。
- `ai_tuner/replay/funding_schedule_evidence.py`：本地离线覆盖、时点、日程变更和一对一验证，返回结构化缺口与日程证据；不得从实际结算事件推导预期时间。
- `ai_tuner/replay/raw_export.py`、`snapshot_sealer.py`、`data_portal.py` 与资格考试入口：只读导出、哈希封存、`as_of` 防前视、证据门禁。真实策略只接受通过验证且与快照 manifest 绑定的日程，不接受调用方提供的裸字典。

## 验收与上线边界

单元测试须覆盖 5 分钟正常采集、超过 7 分钟断档、超过 2 分钟源延迟、HRS 入池/出池、4/8 小时与日程切换、30 秒边界、重复/漏/额外结算、未来数据和哈希篡改。数据库集成测试验证只追加、幂等重试与冲突拒绝。先本地 FakeDB/合成夹具，再只读生产核对，最后单独部署采集器并核验写入的仅是证据表。上线后的真实资格考试继续 `BLOCKED_DATA`，直到所需窗口和其它门禁分别通过；部署不会让调优结果自动生效。
