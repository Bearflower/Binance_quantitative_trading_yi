# QuantView 策略详情页重设计规格

日期：2026-08-21  
页面：`dashboard/frontend/detail.html`  
目标地址：`http://localhost:8099/detail.html?strategy=hrs&type=daily`

## 1. 背景与问题

现有策略详情页能够展示单个策略的基础指标与交易对明细，但信息层级偏弱，页面留白较多，难以同时完成以下两个核心任务：

1. 快速判断当前周期内的运行结果；
2. 在同一页面横向了解全部策略，并进一步分析当前策略的收益与风险。

当前实现还存在若干工程问题：

- 页面样式和业务脚本大量内联，后续维护与测试困难；
- 全策略信息未进入详情页，必须离开页面才能比较策略；
- 日、周、月切换尚未被定义为页面级单一状态，容易出现模块间周期不一致；
- 请求失败时主要区域整体退化，缺少模块级错误与重试能力；
- 页面源码存在重复声明 `commissionEl`、表格错误态列数不匹配等缺陷；
- 使用 emoji 表达策略类型，不符合专业分析工作台的视觉方向；
- 动效和可访问性细节不足，例如 `transition: all`、缺少明确焦点态与状态播报；
- 当前本地地址的策略接口返回 HTML 而不是 JSON，需要在实施阶段确认静态服务和 API 代理配置。

## 2. 已确认的设计方向

采用“现代分析工作台”方向：浅色、克制、数据密度适中、强调清晰的阅读层级。

页面同时支持两类使用意图，但优先级明确：

- 第一优先级：快速了解当前所选周期的运行结果；
- 第二优先级：查看收益趋势、回撤及分策略、分交易对表现。

用户已确认：

- 日、周、月是整个页面的全局筛选器；
- “运行与风险”区域改为全部策略的紧凑列表；
- 不展示“关注”“停用”等主观状态标识；
- 全策略列表只展示可验证的客观数据；
- 切换周期后，页面所有相关模块必须同步更新。

## 3. 目标与非目标

### 3.1 目标

- 建立明确的页面信息层级和一致的视觉语言；
- 在一个页面查看全部策略，并可快速切换当前策略；
- 让日、周、月成为页面唯一的时间范围状态；
- 保证各模块不会混用不同周期的数据；
- 对尚无可靠来源的指标诚实展示为空值，不制造数据；
- 改善加载、空数据、局部失败、重试和可访问性体验；
- 将详情页样式和逻辑拆分为独立文件，尽量不覆盖当前已修改的全局资源。

### 3.2 非目标

- 本次不增加策略启停、关注、排序配置等管理操作；
- 本次不将详情页改造成交易执行界面；
- 本次不虚构最大回撤、利润因子等暂无可靠来源的数据；
- 本次不改变其他看板页面的整体设计系统；
- 本次不包含生产部署。

## 4. 页面结构

页面由以下区域组成：

1. 顶部导航与返回入口；
2. 当前策略标题、说明及页面级日/周/月切换；
3. 当前策略核心指标；
4. 主分析区：
   - 左侧：累计收益与回撤趋势；
   - 右侧：全部策略列表；
5. 当前策略的交易对明细表；
6. 数据更新时间、来源说明与局部错误提示。

### 4.1 当前策略核心指标

首期复用已有可靠数据：

- 净收益；
- 胜率；
- 已平仓数；
- 订单数；
- 手续费。

新增分析指标只有在后端可从真实数据计算时才展示数值：

- 最大回撤；
- 利润因子；
- 手续费占比。

无法计算时统一显示 `—`，并提供简短说明，不显示模拟值或前端估算值。

### 4.2 全部策略列表

全部策略列表用于在当前周期内横向了解所有策略。建议列为：

- 策略名称；
- 净收益；
- 胜率；
- 已平仓数；
- 最大回撤。

交互规则：

- 当前策略用浅蓝背景和左侧强调线标识；
- 不使用“关注”“停用”“正常”等主观或管理型标签；
- 点击一行切换当前策略，同时保留当前周期；
- 不存在的指标显示 `—`；
- 小屏幕下优先保留名称、净收益、胜率，其余指标可横向滚动或折叠显示。

### 4.3 趋势与回撤图

图表以日期为横轴，包含：

- 累计净收益折线；
- 回撤区域或折线；
- 清晰图例和单位；
- 空数据说明；
- 表格或文本摘要作为非视觉信息补充。

不得将全账户趋势误作当前策略趋势。若现有 `/api/trend` 仅返回组合级数据，应新增策略级接口或在策略详情响应中提供真实的策略级时间序列。

## 5. 全局周期状态

页面状态至少包含：

```text
strategyId       当前策略 ID
reportType       daily | weekly | monthly
requestVersion   当前请求批次，用于丢弃过期响应
```

初始化规则：

- 从 URL 读取 `strategy` 与 `type`；
- 缺少或非法的 `type` 回退为 `daily`；
- 缺少策略时使用后端返回的首个可用策略；
- 初始化后将规范化状态写回 URL。

周期切换规则：

- 切换日、周、月时保留当前策略；
- 同步刷新当前策略指标、趋势与回撤、全部策略列表、交易对明细和分析指标；
- URL 同步为 `?strategy=hrs&type=weekly` 等形式；
- 使用 `history.replaceState` 或 `history.pushState`，确保刷新和分享后状态可恢复；
- 每次刷新生成新的 `requestVersion`，旧请求即使晚返回也不得覆盖新周期数据。

策略切换规则：

- 点击全策略列表中的策略时保留 `reportType`；
- 刷新当前策略相关模块，不必重复请求周期内的全策略列表；
- 同步更新 URL 中的 `strategy`。

## 6. 数据与接口契约

首期应优先复用现有接口：

- `GET /api/strategies?type={daily|weekly|monthly}`；
- `GET /api/strategies/{strategyId}?type={daily|weekly|monthly}`；
- `GET /api/strategies/{strategyId}/symbols?type={daily|weekly|monthly}`。

所有接口必须以同一个 `type` 参数请求。全策略列表不得混入其他周期的缓存结果。

如真实数据源支持，应扩展为可空字段：

```json
{
  "max_drawdown": null,
  "profit_factor": null,
  "commission_ratio": null,
  "performance_points": [
    {
      "date": "2026-08-21",
      "cumulative_pnl": 0.0,
      "drawdown": 0.0
    }
  ]
}
```

数据约束：

- `max_drawdown`、`profit_factor`、`commission_ratio` 必须由所选策略、所选周期内的真实成交或收益数据计算；
- 无足够数据时返回 `null`，时间序列返回空数组；
- 金额、比率和计数在后端保持数值类型，格式化由前端负责；
- 后端需明确 `updated_at` 和数据来源；
- 接口错误必须返回 JSON 错误结构，不应由 `/api` 路径回退到 HTML 页面。

## 7. 加载、错误与空状态

每个主要区域独立管理状态：

- 核心指标加载失败，不阻断全策略列表；
- 全策略列表失败，不清除已成功加载的当前策略数据；
- 趋势无数据时显示解释性空状态；
- 交易对明细失败时在表格区域提供重试按钮；
- 周期切换时可以保留旧内容并降低透明度，同时显示局部加载提示，避免整页闪烁；
- 错误信息使用 `aria-live="polite"` 播报；
- 重试操作必须沿用当前 `strategyId` 和 `reportType`。

## 8. 前端实现边界

为减少与现有未提交改动冲突，优先采用以下文件边界：

- 新建 `dashboard/frontend/css/detail.css`，承载详情页专用样式；
- 新建 `dashboard/frontend/js/detail.js`，承载页面状态、数据加载与渲染；
- 修改 `dashboard/frontend/detail.html`，保留语义化骨架，移除大段内联 CSS 和 JS；
- 尽量不改动当前已修改的全局 `css/style.css`、`js/api.js`、`js/config.js`；
- 若必须扩展公共 API 客户端，只做向后兼容的小范围改动。

页面应使用现有依赖和原生 SVG/CSS，不为图标引入新的运行时依赖。

## 9. 视觉与交互规范

- 浅灰页面背景、白色内容面板、克制的蓝色强调色；
- 正收益与负收益采用一致的语义色，并同时提供正负号或文字，不能只依赖颜色；
- 数据使用等宽或具备 tabular numerals 的字体；
- 卡片圆角、边框、阴影保持轻量，避免强玻璃拟态和过度渐变；
- 避免 emoji 作为功能图标；
- 不使用 `transition: all`，只声明具体属性；
- 交互元素必须具备 hover、active 和 `:focus-visible` 状态；
- 遵循 `prefers-reduced-motion`；
- 支持 375、768、1024、1440 像素宽度；
- 表格在小屏幕下可水平滚动，表头与数据对齐；
- 数值按中文区域规则格式化，日期避免歧义。

## 10. 可访问性

- 使用 `header`、`main`、`section`、`table` 等语义结构；
- 提供跳转到主内容的 skip link；
- 周期切换使用按钮或单选组，并提供可访问名称和选中状态；
- 全策略行可通过键盘进入和激活；
- 图表提供文字摘要，关键指标不只通过视觉图形传达；
- 加载、错误、空状态可被辅助技术感知；
- 文本和控件满足合理的颜色对比度与点击区域尺寸。

## 11. 测试与验证

### 11.1 数据与后端

- 验证 daily、weekly、monthly 均被正确传入各接口；
- 验证新增分析指标在有数据时计算正确、无数据时返回 `null`；
- 验证策略级趋势不会混入其他策略数据；
- 验证 `/api` 错误返回 JSON，而不是静态 HTML；
- 保持现有后端测试通过，并补充相关路由、服务和 schema 测试。

### 11.2 前端行为

- 从 URL 正确恢复策略与周期；
- 切换周期后所有区域显示同一周期数据；
- 快速连续切换时旧响应不会覆盖新状态；
- 点击其他策略后周期保持不变；
- 任一模块失败时其他模块仍可使用；
- 空值展示为 `—`，无伪造分析数据；
- 加载、错误与重试状态正确；
- 无重复 ID、重复变量声明和控制台错误。

### 11.3 浏览器与视觉

- 在本地真实接口环境验证 375、768、1024、1440 像素布局；
- 检查键盘导航、焦点态、屏幕阅读器名称和 reduced motion；
- 检查趋势图、全策略列表和交易对表格的对齐与溢出；
- 确认刷新、复制 URL、前进后退不会丢失页面状态。

## 12. 验收标准

以下条件全部满足时视为本次重设计完成：

1. 页面采用已确认的现代浅色分析工作台视觉；
2. 页面内可查看全部策略，且不展示关注、停用等主观状态标签；
3. 日、周、月切换能同步更新全部策略列表和所有当前策略模块；
4. 当前策略切换后保留所选周期，并同步更新 URL；
5. 快速切换不会出现不同周期数据混杂；
6. 趋势和风险指标只使用真实策略数据，缺失时显示 `—`；
7. 页面具备独立加载、错误、空状态和重试能力；
8. 本地 `/api` 路径能够稳定返回 JSON；
9. 页面在目标响应式宽度与键盘操作下可用；
10. 相关自动化测试和浏览器验证通过，且不破坏现有看板功能。

## 13. 实施顺序建议

1. 先修复本地 API 路由或代理问题，建立可验证基线；
2. 拆分详情页 HTML、CSS、JS，并建立统一页面状态；
3. 接入全策略列表与全局周期联动；
4. 完善交易对表格、局部加载、错误和空状态；
5. 核实策略级时间序列来源，再实现趋势与真实风险指标；
6. 完成响应式、可访问性、自动化测试和浏览器视觉验证。

本规格不授权覆盖或丢弃工作区中与本功能无关的现有改动。
