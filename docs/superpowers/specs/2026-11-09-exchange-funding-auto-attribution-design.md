# 交易所收入自动归属与看板部分值展示设计

日期：2026-11-09。适用范围：共享币安 PM 账户的 USDT 永续策略；交易所 `execution_fact_income` 和 `execution_fact_fill` 仍是金额与成交的唯一事实来源。本设计只改变**策略归属和展示**，不下单、不修改交易所事实、不以币种推断策略。

## 问题与已知边界

当前手续费/已实现盈亏可由 `trade_id → fill → order_id → trade_records` 归属，但部分条件单实际订单 ID 没有写入 `trade_records`。资金费没有 `trade_id`，现有经济账一律标为 `funding_owner_unproven`。2026-11-09 的 11 条资金费由用户补表归属后，新增事件又使看板出现未归属；一次未归属便让所有策略的正式净收益留空。`position_claims` 是开仓互斥/预占记录，不是交易所实际持仓；样本中的 11 条资金费只有 9 条在收费时点找到唯一占用旁证，因此不能直接用占用记录自动认领。相邻的 12 条成交收入经过 PM 条件单核对分别属于 MTPCS 原版和激进版各 6 条，证明同币种或白名单归属不成立。

账户总收入始终包括资金费，且不依赖策略归属。分策略**净收益**需要把资金费归给实际持仓策略，或者明确留下未知池。胜率、夏普率、最大回撤另需已核对的完整平仓/净值序列，不在本设计中恢复。

## 选择与取舍

采用“订单来源持久化 + 交易所成交重放持仓区间 + 唯一归属才自动入账”的方案。继续逐批 Excel 人工处理可作为历史疑难项兜底，但不能成为日常路径。按币种、当前持仓或 `position_claims` 直接归属虽简单，却会把原版和激进版的同币种事件混淆，故不采用。

## 数据流与表

1. **订单归属证据。** 在策略获得交易所普通订单 ID 或 PM 条件单 `algoId` 时，写入账户、策略、币种、交易意图、订单/条件单 ID、交易所响应时间和原始响应摘要。条件单触发后，只接受交易所 `algoId → actualOrderId` 的精确映射；同一实际订单出现多个策略、账户不符或映射缺失时保持待核。历史回补只读扫描 PM 条件单历史，并在明确覆盖区间后生成同样的证据。现有 `trade_records` 可提供候选，但缺账户标识的旧行不能单独作为确证。
2. **实际持仓区间。** 以已完整采集的交易所 fill 按 `(trade_time_utc, trade_id)` 顺序重放账户+币种净数量。只从有交易所确认的零仓基点开始；开仓 fill 必须关联唯一策略订单证据，减仓消耗同一持仓区间。若出现未知订单、跨策略同币持仓、净数量对不上交易所可验证的边界、同时间戳先后顺序不明或采集游标缺口，区间标记 `unverified`，不能自动归属资金费。`position_claims` 和策略当前状态只用于告警/交叉核对，不参与最终判定。
3. **收入归属。** 新增 `trading.derived_income_attribution`，主键 `(account_id, income_type, tran_id)`，保存策略、金额、币种、事件时间、算法版本、证据 JSON 与计算时间。成交收入仅在唯一订单证据且金额与 fill 一致时写入；资金费仅在收费时点落在唯一且已验证的实际持仓区间时写入。金额始终直接采用交易所 income，不按费率推算。人工表 `reviewed_income_attribution` 优先于自动表；两个表指向不同策略时产生冲突告警并阻止发布完整策略报告，不静默覆盖。自动归属记录可重新计算并比对，冲突必须人工审查，不能就地改写旧证据。
4. **读模型与看板。** 账户总额继续由交易所收入相加；策略卡片在部分归属时展示 `observed_pnl`，明确标“已归属部分”，同时展示未知笔数、净额和绝对额，不把部分值标为完整净收益。仅当收入/成交游标完整、收入金额守恒、全部事件归属且无冲突时，`strategy_attribution_complete=true` 并显示“已核实净收益”。资金费为零、某策略无事件时显示 0 还是无样本，由事实覆盖情况决定；不得用 0 代替采集缺口。胜率、夏普率、最大回撤维持待核算，直到各自的数据链通过独立验收。

## 运行与异常

在交易所事实采集成功后运行幂等归属任务，按完整游标水位处理新增收入和成交；重跑不得重复写入或改动已人工确认记录。任务失败不影响交易与账户收入采集，看板保留上一版已发布报告并标记滞后。无法唯一证明的事件进入未知池，记录原因（缺订单证据、区间未验证、多策略/多仓冲突、缺采集覆盖等），生成只含异常的人工复核清单。当前数据库一条资金费只能归一个策略；若未来确有多个策略同币并持，先保留未知，另行设计分摊表，不在本方案中按比例猜测。

## 上线与验收

先只读影子重放至少覆盖已补录的 127+12+11 条事件，逐笔对比既有人工结论与 12 条直接条件单证据；任何自动/人工策略冲突都不得进入写入阶段。再部署表和任务，仅对有完整证据的新事件自动写入；保留人工表及回退开关。验收要求：

- 交易所收入行数、三类金额、账户总额和 `已归属 + 未知 = 账户总额` 在上线前后完全一致；重复运行无新增或改写。
- 12 条已核实条件单成交收入归属一致；资金费唯一持仓、无持仓、双策略、缺 fill、延迟到账、同毫秒成交、缺游标等样本分别得到可预期结果。
- 所有自动行可追溯到订单证据、fill 集合、持仓区间和交易所收入键；人工优先级与冲突告警有数据库及 API 测试。
- 看板部分值有醒目标识和未知池，完整值只在所有门槛通过时显示；账户总额保持交易所口径。生产影子期无冲突、无金额守恒失败、无交易路径影响后再启用自动写入。
