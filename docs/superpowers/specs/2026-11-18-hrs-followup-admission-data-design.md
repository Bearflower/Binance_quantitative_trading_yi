# HRS 剩余准入与数据缺口设计

用户已授权连续实施、测试、审查和合格后的实盘部署，无须例行确认。继续使用隔离工作树，原用户工作区不变。

## 选择与边界

采用有正向归属证明的HRS独立仓位计数；继续全账户计数会让其他策略耗尽HRS上限，单纯提高上限或删预留会绕过既有约束，因此不采用。单笔1%、组合3%、HRS最多3仓、全账户保证金额度/ratio_cap/entry_ceiling、禁止加仓和未决预留保守保留均不变。新计数范围是明确的准入行为变更，不能声称与旧规则经济等价。

HRS typed snapshot只保存真实两套GET库存、PM本地状态、实际观测时刻。在同账户风险锁内核对最新权益门禁所指原始parent哈希、完整签名成交/订单归属链、当前claims及两套库存；未知归属或变化拒绝新风险。HRS槽位取已证HRS持仓与HRS未释放预留的并集；其他策略仍计入账户保证金。旧tuple消费者和v1历史回放保持旧口径，新capture显式声明v2 scope并绑定实际证据。回放HRS仓位来自虚拟组合，不能用实盘基线仓位替代反事实持仓。

K线保留连续性/已收盘/原窗口要求。先对实际缺口定位，再用有限真实GET补全；不插值、不悄悄截掉缺口前数据、不回写旧capture。仅完整连续的真实1h构成4h；完整原始缺口、新响应和实际receipt时刻均留证，超界或补取失败继续否决。准入数据修复不改变已有退出/硬止损执行能力。

预期EntryDenied记录独立reason_code和锁内计数上下文，不再以error字段伪装程序异常；未知异常仍报警。外部监控采集实现尚未定位，不声称其历史记录会被自动删除。

## 不能伪造的验收

缺今日午夜权益/单位/持仓/marks/资金流原点时，不改不可变segment或编造净值。只验证真实未来午夜重建路径。8–9月缺历史决策、市场与资金时点时仍BLOCKED_DATA。SL/TP只能在合格事前窗口和样本形成后选择，保留旧登记和参数；24小时及五笔自然闭合不足不能标通过。

## 验证与发布

先红绿测试，真实非管理员PG测试证明第三方不占HRS槽位、真实HRS/未决预留仍占位、并发最后槽位不超限、全账户保证金仍拦截。K线用实际缺口形态和只读真实源复核。独立审查后，使用新不可变CI候选，保留源哈希/冻结配置/当前保护单和回退；只替换需要的HRS服务，发布后核对自然扫描和真实数据。未来事实未形成者逐项保持未通过。
