# 历史证据容缺与经典模式运行恢复

状态：已核查代码并形成设计；尚未修改生产门槛。用户本轮已认可“无法补齐的历史可以容缺”，不重复请求这一原则授权。用户已明确批准 AI 自动资金分配恢复并沿用现有预算上限；代码在独立分支验证，尚未激活生产凭据。

## 目标

取消“历史必须完全恢复才准运行”的永久阻断。历史资料质量与当前实盘风险分开判断；已知经济损失和已触发风控不因容缺清零，当前缺口不继承历史豁免。

## 还值得补什么

| 数据 | 用途 | 处理边界 |
|---|---|---|
| 主账户 PM 尾段及经典段成交导出：账号、交易对、订单号、成交号、成交时间、方向、数量、价格、手续费/币种、已实现盈亏 | 补成交与持仓归属路径，复核已存 450 条收入 | 优先现有本地归档/生产库/可访问接口；没有的字段不能从收入金额猜造；导出不可得时登记容缺，不继续挡当前运行 |
| 主账户及网格子账户划转明细：账号、划转编号、币种、数量、方向、时间、状态 | 区分资金流和利润；防主/子账户重计 | 已有 PDF 双边腿可做辅助，缺原生 ID 不伪造 ID；网格独立核对，不计入主账户风险预算 |
| 已留存的历史权益采样、账户日结、资产分项 | 衔接估值并识别已知回撤 | 使用真实留存；不要求用户再找已确认没有的 PM 平仓后、切换前截图 |
| 经典阶段历史标记价格与已验证成交 | 从经典期初空仓余额重建经典期内权益/回撤，分钟内可采用保守价格边界 | 重建/保守界明确标注，不冒充当时签名权益采样；余额和资金流必须先核对 |

无法精确恢复：没有留存的 PM 转账瞬间前后全资产权益、确切切换前全账户 USD 净值、没有完整仓位/价格证据的历史最低净值。保留“未验证/可估计范围”，不填 0、不补造连续采样。后续新资料可追加修正，不以等待资料作为恢复先决条件。

## 容缺机制

新增明确的历史容缺回执，绑定账号 UID、PM/经典分界、有限时间窗、缺失类别、证据摘要、批准依据及版本。默认无回执时维持严格模式；回执只影响列明的历史缺口，不接受通配“忽略所有错误”。回执及后续修订留审计记录，激活时检查旧状态版本，防覆盖其他维护。

分别输出历史数据状态与运行风险状态，例如历史 `ACCEPTED_GAPS`、当前 `READY/EXCEEDED/BLOCKED_CURRENT_DATA`。不得把原有 `account_coverage_complete=false` 改成 true，也不得补写虚假的 PM 原生游标。

历史分段保留原始 PM 报表、所有已知亏损、已知触发记录和可证实高水位；经典运行优先使用已核对的真实经典期初空仓快照，不把维护当日余额当新起点。PM 与经典计价/资产范围不同，不能直接拼接数值制造完整总回撤。

### HRS

- 历史 PM 持仓路径缺口只作为容缺事项，不再单独冻结经典模式。
- 当前仓位归属从已认证经典空仓边界重放，要求经典成交覆盖、收入归属、当前独立仓位查询、挂单/保护单、风险预留一致。
- 历史权益段、已知收入/费用、分配变更及触发状态保留。新增运行核验明确区分“观察到的历史回撤”和“完整历史回撤”；不能删除旧段后重启。
- 沿用现有日亏损 3%、滚动回撤 6% 的数值上限；已知触发不得因容缺解除。对于未知历史内部轨迹，仅豁免历史完整性要求；后续经典运行日界、采样缺口、真实超限继续硬拦截。
- 补齐数据后以新版本追加重算与复核，不能自动清除已触发保护。

### AI

- 删除经典模式“无条件 BLOCKED_DATA”作为永久运行路径的设计，改为读取真实经典证据和容缺回执；仅把 PM 未恢复历史降为提醒。
- 经典 USDT 运行预算拟沿用现有 5% 数值上限，单独记录经典资产范围及期初证据。现有批准预算 ID 标记为 PM，不能改标签冒充经典预算已获原批准；需要在新容缺运行政策中明确登记沿用规则。
- 优先恢复分析、参数调优建议和风险观察。恢复不等于更改自动参数应用开关，已有配置 `approval.auto_apply.enabled` 与资金分配控制须分别核对。
- 用户已明确批准恢复自动分配：新经典专用写入路径依据管理员容缺凭据、实时账户风险、当前归属和现行预算上限授权；保留旧分配器全局冻结。缺历史的结算月维持已批准比例，拒绝收益排名，不将研究考核的缺口包装成已通过。

## 当前仍须硬拦截的情况

账户身份不匹配；当前 API 查询失败/超时或数据过期；经典阶段新增采集缺口；收入金额冲突或策略归属冲突；净仓与认领不一致；应有保护单缺失；实测保证金不足；已知亏损/回撤超过现有阈值。不能因历史容缺掩盖这些当前问题。

## 实施范围和验收

1. 固定当前生产账本/权益/风险状态快照；复用已验证资料，生成缺口清单与待激活回执。
2. 实现回执验证和历史/当前双状态契约；如新增 PG 对象，迁移与 `database/postgres/permissions.json` 同步，经 `scripts/database_permissions.py` 审计。
3. HRS 从经典空仓边界建立当前归属与权益核验路径，接入历史容缺规则。不得只把 `_commit` 的 `coverage_complete` 强改为 true。
4. AI 实现经典证据观察和批准预算契约，贯通 `EvidenceJobs.latest_risk/sample_risk`；分析/参数建议与资金自动分配分别处理。
5. 故障测试：错误账号、过宽/未来容缺窗口、过期实时快照、经典新增缺口、归属冲突、真实超限必须拒绝；重复激活无重复基线/收入；回执修订有版本冲突检查；重启不清历史亏损/保护状态。
6. 真实生产只读预演：显示哪些历史项从阻断降为提醒，以及仍有何当前阻断；核对经典余额与账本相等；不能只跑纯函数测试就宣称恢复实盘。
7. 经独立复核后按现有 CI/GHCR 发布路径上线，验证实际镜像/源码身份和 HRS/AI 完整一轮运行。失败回退容缺激活，不回滚或删除原始账本。

本设计不宣称当前已恢复 HRS 或 AI。完成标准是生产当前风险检查通过、历史缺口被准确呈现、策略和任务能按获准范围运行，而不是不再显示报错。

### 月界分配与 HRS 每日亏损锁定

月度分配发布不依赖 HRS 开仓投影就绪，因为 HRS 生成新月投影本身需要新月额度。发布器在同一账户锁内直接校验已保存的 HRS 亏损状态：滚动亏损锁定始终阻止发布；北京时间当日的每日亏损锁定阻止发布；未来日期或损坏的状态拒绝发布。

上一日的每日亏损锁定允许发布不超过既有批准上限的新月额度，但不会清除或修改旧亏损记录、不会把 HRS 开仓投影改为允许，也不会授权新开仓。HRS 获取新月额度后，仍由原有风控根据新日真实权益、零点基准与覆盖证据重新判定每日限制；证据不足或当前亏损超限时继续拒绝开仓。这一处理只解除分配和权益刷新的循环依赖，不代表清除亏损或提高预算。
