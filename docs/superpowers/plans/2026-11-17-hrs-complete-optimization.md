# HRS 完整优化实施计划

**Goal:** 落地经用户批准的市值覆盖、可信权益和门禁、完整决策采集、HRS 回放、SL/TP 离线实验与持续验收。

**Architecture:** 在现有生产 HRS 上增量构建：纯权益/门禁核心与持久状态分离；扫描级决策和市场输入落盘；纯策略决策供实盘与回放共用；仅对通过门槛的新仓使用版本化参数。共享市值独立发布，秘密配置沿用现有服务器文件。

**Tech Stack:** Python 3.11/3.12、Decimal、PostgreSQL、aiohttp、pytest、Docker Compose、现有统一 replay engine。

1. **生产基线与测试**：导出 HRS Python 模块和必要公共政策模块到临时目录，哈希比对后同步隔离分支；用 `/tmp/hrs-test-venv/bin/python -m pytest` 验证现有 HRS、市值、快照和 replay 测试；构建基于当前不可变生产镜像，保留挂载。
2. **资产审计**：对实际扫描范围分类；按 Binance 标的元数据、CMC/CG 唯一 ID 与发行方信息核验，生成分类和源间偏差报告；修改 assets registry 和扫描统计，单元测试身份、同名、过期、比例口径和统计分母。
3. **权益/门禁**：新建 `strategies/hrs/risk_ledger.py`、`loss_gate.py`、持久仓储和 SQL migration；TDD 覆盖资金流调整、未知事实、日界、滚动窗、重启和并发；用真实本地 PostgreSQL验证幂等及锁。
4. **实盘集成与采集**：新建扫描审计/权益采集模块，在每轮扫描保存完整输入和否决；持有风险锁在发单前验证门禁，失败只挡新仓，保留退出与保护维护；保存每仓参数快照。
5. **回放接线**：补齐纯决策编排和 adapter intents/protective_prices，使用实盘共享计算模块；新增实盘/回放契约、未来数据、多个事件、退出与资金占用回归；审计可用历史窗口。
6. **SL/TP 实验**：新增冻结基线、最多 12 个/模式候选、退出路径与完整策略两层实验 CLI；计入费用、资金费、滑点、最小订单和真实部分止盈几何，时间留出验收，不合格保持基线。
7. **审查/构建/发布**：实现者自检后先审规范符合性再审代码；云端断网回归与源码哈希校验，通过后持部署锁仅重建需要的服务，保存回退信息。
8. **技术验收/报告**：记录实际连续扫描周期、覆盖、429、各级否决、信号、订单和生命周期；配置服务器持续检查产物，真实周期和样本不足时保持待验收，不虚报全部完成。

各项执行状态以根目录 task_plan.md 为准。用户已授权实施，无需再为常规选择暂停；只有实际无法自动取得的关键事实才汇报。
