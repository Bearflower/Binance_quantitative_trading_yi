# 目的驱动型 AI Tuner MVP 实施路线图

## 1. 文档说明

- 文档日期：2026-10-17
- 文档状态：设计方案已确认，待决定是否进入开发
- 适用范围：AI Tuner 首期 MVP
- 首期候选策略：MTPCS 激进版；若准备度审计不通过，则评估 HRS
- 关联设计：[目的驱动的全自动 AI Tuner 与策略回测体系设计](../specs/2026-10-16-purpose-driven-ai-tuner-design.md)

> 本文件只用于明确产品目标、系统边界、实施顺序和验收标准，不代表已经开始开发，也不授权系统直接修改实盘参数。

## 2. 核心目标

建设一套目的明确、范围受控、能够验证后自动生效的 AI 调优闭环：

> 在最大回撤硬约束内，最大化扣除手续费、滑点和资金费率后的风险调整收益。

LLM 只负责根据诊断数据提出候选参数，不拥有最终批准权。程序负责验证参数合法性、执行回放和资格考试、比较当前版本与历史版本，并决定保持、切换或暂停新增开仓。

MVP 的重点不是一次性找到收益最高的参数，而是验证以下闭环是否真实、可靠且可重复：

```text
历史数据
→ 策略诊断
→ LLM 提出候选参数
→ 确定性回放与资格考试
→ 当前版本、新候选、历史版本同场比较
→ 自动选择
→ 覆盖层生效
→ 验证策略真实加载
→ 记录成绩卡和决策证据
→ 不合格时保持、切换历史方案或暂停新增开仓
```

## 3. MVP 范围

首期只做以下内容：

- 只选择一个策略进入 MVP。
- 默认优先 MTPCS 激进版；如最近 90 天的数据准备度不合格，再评估 HRS。
- 只开放“入场质量”一个参数组。
- 参数清单只包含 3～5 个真实被实盘代码读取的参数。
- 每轮最多修改 1～2 个参数。
- 单参数变化幅度不超过 10%。
- 每轮只生成一个新的 LLM 候选方案。
- 同场比较当前版本、一个新候选以及最多三个兼容的历史覆盖层。
- 使用六种普通市场状态和一个 `STRESS` 极端状态。
- 自动生效只对最终通过 MVP 的一个策略开放。

首期明确不做：

- 不允许 LLM 修改策略代码或业务逻辑。
- 不允许 LLM 新增指标、交易条件或参数。
- 不调整杠杆、仓位、核心止损红线和候选池结构。
- 不同时调优多个参数组。
- 不同时上线多个策略。
- 不建设 Web 管理界面。
- 不建设账户组合级资金优化。
- 不做大规模 Hyperopt 或黑盒全局寻优。
- 不自动执行网格交易；网格仍然只影响建议系统，并且不纳入本次 MVP。

## 4. 总体实施顺序

整个 MVP 分为三个连续阶段。每个阶段都有独立门禁；前一阶段未通过，后一阶段不得开始。

### 阶段一：参数安全与准备度审计

详细方案：[参数安全与准备度审计计划](2026-10-17-ai-tuner-mvp-safety-readiness.md)

本阶段解决“LLM 到底可以调整什么”和“哪个策略具备验证条件”。

主要交付：

- 建立机器可读的参数清单。
- 确认每个参数的真实运行路径、类型、范围、最大变化率、所属参数组和代码读取位置。
- 修复 MTPCS 激进版等策略中 AI Tuner 参数路径与真实配置路径不一致的问题。
- 校验 LLM 返回的 `from` 是否与当前真实生效值一致。
- 删除“连续多次没有调整后必须强制调参”的规则。
- 把 LLM 输出统一为 `PROPOSE`、`HOLD`、`DATA_ERROR` 三种决定。
- 在新版资格考试完成之前，阻止旧自动生效路径修改 MVP 候选策略。
- 对 MTPCS 激进版和 HRS 执行最近 90 天准备度审计。
- 选出一个首期策略；如果两个策略都不合格，MVP 直接返回 `STOP`。

阶段一通过后，应当能够回答：哪些参数允许调整、是否真的被实盘读取、最大变化幅度是多少、证据不足时能否保持不变，以及哪个策略具备可信回放条件。

### 阶段二：确定性回放与候选资格考试

详细方案：[确定性回放与资格考试计划](2026-10-17-ai-tuner-mvp-replay-qualification.md)

本阶段解决“历史回测能否代表当前实盘逻辑”和“候选参数是否有资格进入版本比赛”。

主要交付：

- 建立只使用已收盘数据的确定性事件回放内核。
- 所有数据读取必须带决策时间，禁止读取未来数据。
- 复用实盘策略的评分、过滤、开仓、止盈、止损、移动止损和时间止损逻辑。
- 模拟手续费、滑点、资金费率、价格精度、数量精度和最小名义价值。
- 建立六种普通市场状态以及 `STRESS` 极端状态。
- 计算扣费后净收益、最大回撤、Sortino、Calmar、单笔期望、样本量和收益集中度。
- 对候选参数执行相邻值稳定性检查。
- 对候选执行 1.5 倍交易成本压力测试；2 倍成本只作为诊断数据。
- 使用真实历史交易区间完成“金样对账”。
- 只有金样对账达到约定容差，才允许开启候选资格考试。

资格考试统一比较当前版本、一个 LLM 新候选以及最多三个兼容历史版本。任何版本只要突破最大回撤、盲测显著恶化、样本不足、相邻参数不稳定、成本压力不合格、收益过度集中、版本身份不兼容或存在数据越界，就直接淘汰，不进入综合评分。

### 阶段三：时间机器验证与生产自动生效

详细方案：[时间机器与生产自动生效计划](2026-10-17-ai-tuner-mvp-automation-rollout.md)

本阶段解决“整套自动调优机制在历史上运行是否合理”和“覆盖层写入后是否真的被实盘策略加载”。

主要交付：

- 保存不可变的覆盖层版本身份。
- 保存每个版本的市场状态、回测结果、资格门禁、综合成绩和实盘成绩卡。
- 缓存 LLM 的原始请求、模型版本、采样参数、原始响应和解析结果。
- 对过去 12～16 周进行逐周“时间机器”演练。
- 每个历史周末只能使用该时点以前的数据做诊断和选择。
- 将自动调优结果与始终使用固定基准覆盖层的结果进行比较。
- 建立保持当前、普通切换、紧急切换、暂停新增开仓和恢复交易的状态机。
- 限制普通情况下同一策略七天内最多切换一次。
- 使用市场状态匹配选择兼容且合格的历史覆盖层。
- 没有任何合格版本时暂停新增开仓，而不是选择“最不差但仍不合格”的版本。
- 覆盖层切换后，核对请求版本、实际加载版本和有效参数哈希。
- 加载确认失败时，自动恢复原来的 `.active` 指针。

## 5. 六道强制门禁

| 门禁 | 必须提供的证据 | 不通过时的处理 |
|---|---|---|
| A：参数安全 | 未知、红线和失效参数被拒绝；`from` 与真实值一致；不存在强制调参 | 停止进入回放阶段 |
| B：策略准备度 | 历史行情、交易身份、覆盖层版本、信号与交易样本均达到要求 | 改评估另一个策略；两个都失败则 `STOP` |
| C：实盘复现 | 回放的信号、入场、退出、费用、盈亏和权益达到金样容差 | `STOP`，先修复数据或回放一致性 |
| D：候选资格 | 盲测、回撤、样本、稳定性和 1.5 倍成本测试全部通过 | 候选保持未生效状态 |
| E：时间机器 | 相比固定基准，风险调整后收益不恶化，最大回撤不增加 | 返回 `REVISE` 或 `STOP` |
| F：生产生效 | 请求版本、实际加载版本和有效参数哈希完全一致 | 恢复原覆盖层指针，不归因给新版本 |

## 6. 数据窗口定义

每次周度调优使用统一的时间分区：

- 诊断区：此前 8 周，用于识别策略问题，并提供给 LLM。
- 盲测区：最近 2 周，候选在该区域的成绩不得提供给 LLM。
- 历史状态库：更早的行情，按市场状态切片，用于稳定性与相似行情验证。
- 后验观察区：时间机器中决策时点之后的一周，仅用于评价当时选择的真实后续表现。

如果当前市场状态的历史样本不足 14 天，可以向前扩展到 16 周寻找相似片段。超过 16 周仍不够，则判定为“证据不足”，不得为了找到一个好结果而无限追溯旧行情。

## 7. 市场状态的作用

市场状态不是直接控制交易的第二套策略，而是用于给覆盖层成绩分组、匹配历史环境、筛选历史版本以及在极端环境下触发安全否决。

普通状态由两个维度组成：

- 方向：上涨趋势、下跌趋势、震荡；
- 波动：正常波动、高波动。

由此形成六种普通状态，并增加一个不参与普通排名的 `STRESS` 状态。

历史版本匹配顺序：

1. 方向和波动都相同；
2. 方向相同、波动相邻；
3. 波动相同、方向相邻；
4. 再按原始特征距离、成绩置信下限和最大回撤排序。

即使市场状态完全匹配，历史版本只要没有重新通过资格门禁，也不得自动恢复。

## 8. 自动决策规则

### 保持当前版本

没有显著更优候选，且当前版本没有突破硬约束时，保持当前版本。系统不为调参而调参。

### 切换到新候选版本

新候选必须通过全部资格门禁，综合成绩超过最小优势门槛，不违反切换冷却期，并能完成生产加载身份验证。

### 切换到历史覆盖层

历史覆盖层必须与当前代码、基础配置和参数 Schema 兼容，并使用当前数据及成本假设重新回放合格。不能仅因为过去成绩好就直接恢复。

### 暂停新增开仓

当当前版本突破硬约束，并且新候选与所有兼容历史版本均不合格时，暂停新增开仓。已有仓位继续由原有止盈、止损和风控逻辑管理。

### 恢复新增开仓

系统每日重新评估。只有出现重新通过全部资格门禁的版本时才能恢复，不因暂停时间已满而自动恢复。

## 9. 时间机器必须回答的问题

12～16 周历史演练结束后，必须能回答：

1. LLM 每周提出了多少次候选、`HOLD` 和 `DATA_ERROR`？
2. 候选通过率是多少，主要淘汰原因是什么？
3. 被选择的覆盖层在下一周未见行情中表现如何？
4. 与固定基准相比，净收益、风险调整后收益和最大回撤如何？
5. 市场状态匹配是否真的改善了版本选择？
6. 系统发生了多少次保持、普通切换、紧急切换和暂停？
7. 是否存在版本反复来回切换？
8. 是否出现任何未来数据访问？
9. 当所有版本都不合格时，系统是否正确暂停？
10. 同一实验重复运行，结果是否完全一致？

## 10. 最终结果定义

### `GO`

完整闭环通过验证，可以只为首期策略开启新版全自动调优。必须同时满足实盘复现通过、无未来数据访问、风险调整后收益不低于固定基准、最大回撤不高于固定基准、未选择不合格版本、切换频率合规，以及覆盖层加载与失败恢复验证通过。

### `REVISE`

回放本身可信，但 LLM 候选质量、评分权重、市场状态匹配或切换规则仍需修改。修订后必须重新执行完整时间机器演练，不能直接进入实盘。

### `STOP`

数据或回放无法可靠复现实盘，存在未来数据访问，关键历史数据缺失，或者自动方案导致系统性风险恶化。此时停止自动生效建设，优先修复数据和回放能力。

## 12. 开发启动前仍需确认的业务阈值

以下阈值不应脱离真实数据直接拍板，必须在准备度审计和基准回放完成后校准：

- 首期策略最大回撤硬上限；
- 最低有效信号数和最低已平仓交易数；
- 盲测允许的最大退化幅度；
- 新版本相对当前版本的最小优势门槛；
- 参数相邻扰动允许的最大成绩下降；
- 单笔收益贡献和单一币种收益集中度上限；
- 实盘金样对账的入场价格、时间、费用、退出原因和权益容差。

这些阈值应先由真实历史数据给出建议值，再由项目负责人确认。阈值未确认之前，系统最多运行到 `shadow` 验证状态，不得进入实盘自动生效。

## 13. 完成标准

只有同时满足以下条件，才可以认为 MVP 设计目标已经实现：

1. LLM 无法修改未批准参数、策略代码、杠杆或仓位红线。
2. 首期策略的新候选在生效前通过可重复的资格考试。
3. 回放与选定历史实盘区间达到约定一致性。
4. 每个覆盖层都有包含市场状态、回测成绩和实盘身份的成绩卡。
5. 当前版本不合格时，只能切换到重新验证合格的历史版本。
6. 没有合格版本时，系统暂停新增开仓，而不是盲目回滚。
7. 覆盖层切换后可以证明目标版本和目标参数已被策略加载。
8. 任意一次自动决定都可以解释当时为何选择该版本，以及其他版本为何被淘汰。
9. 网格交易仍然只自动优化建议参数，不自动执行用户交易。
10. 未取得 `GO` 结论前，生产环境不得启用新版全自动调优。
