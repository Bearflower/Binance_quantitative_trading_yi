# 币安新币精准做空系统 - 技术架构文档

## 1. 系统概述

### 1.1 项目简介

币安新币精准做空系统是一个基于 Python 的自动化交易辅助系统，通过多维度交叉验证（合约数据、项目基本面、K 线/交易量、市场情绪），识别高确定性的做空机会，实现"一击必中"的精准做空策略。

### 1.2 核心理念

- **放弃高频交易，追求高确定性的一次机会**
- 通过四维权重评分体系进行交叉验证
- 自动化监控、评分、信号生成、通知推送
- 支持人工确认后执行交易

### 1.3 系统目标

| 维度 | 权重 | 核心作用 | 技术指标 |
| :--- | :--- | :--- | :--- |
| **合约数据** | **35%** | 排除陷阱 & 寻找对手盘 | OI/市值比 < 1.0 |
| **项目基本面** | **30%** | 评估下跌空间 | 解锁比例 > 10% |
| **K 线/交易量** | **25%** | 确认进场时机 | 技术评分 > 7.0 |
| **市场情绪** | **10%** | 寻找情绪拐点 | 资金费率年化 > 100% |

## 4. 核心业务流程

### 4.1 新币监控流程

```
开始
  ↓
[定时任务触发] (每 60 秒/300 秒)
  ↓
[扫描新上线币种] (72 小时内)
  ↓
[获取合约数据] → [计算 OI/市值比] → [一票否决检查]
  ↓
[获取解锁数据] → [基本面评分]
  ↓
[获取 K 线数据] → [技术面评分]
  ↓
[获取资金费率] → [情绪面评分]
  ↓
[综合评分计算] (四维加权)
  ↓
{评分 >= 7.0 且未被否决？}
  ├─ Yes → [生成交易信号] → [推送飞书通知] → [等待人工确认]
  └─ No  → [记录评分结果] → [结束]
  ↓
[更新评分记录] (用于二次评分追踪)
  ↓
{达到最大评分次数 or 分数过低？}
  ├─ Yes → [发送汇总报告] → [结束]
  └─ No  → [等待下次评分] (30 分钟后)
```

### 4.2 评分决策流程

```python
# 综合评分计算公式
综合评分 = (
    合约数据分 × 0.35 +      # 权重 35%
    基本面分 × 0.30 +        # 权重 30%
    技术面分 × 0.25 +        # 权重 25%
    情绪分 × 0.10            # 权重 10%
)

# 一票否决条件
if OI_市值比 > 1.0:
    return False  # 合约盘远大于现货盘，直接否决

# 开仓条件
if 综合评分 >= 7.0 and not 被否决:
    return True   # 生成交易信号
```

### 4.3 交易执行流程

```
[用户确认信号] (CLI 命令：confirm <SYMBOL>)
  ↓
[获取信号详情] (止损、止盈、仓位)
  ↓
[获取当前价格] (实时行情)
  ↓
[计算开仓数量] (仓位 / 价格)
  ↓
[用户二次确认] (y/n)
  ↓
[执行交易] (SELL 开空)
  ├─ [设置杠杆倍数] (默认 5x)
  ├─ [设置止损单] (STOP_LOSS)
  └─ [设置止盈单] (TAKE_PROFIT)
  ↓
[更新信号状态] (已确认)
  ↓
[发送成交通知] (飞书 webhook)
  ↓
[记录交易日志] (数据库)
```

## 5. 数据设计

### 5.1 数据库表结构

#### 5.1.1 信号表 (trading_signals)

```sql
CREATE TABLE trading_signals (
    id VARCHAR(64) PRIMARY KEY,
    symbol VARCHAR(20) NOT NULL,
    scoring_result JSONB NOT NULL,
    current_price DECIMAL(20, 8) NOT NULL,
    suggested_entry_min DECIMAL(20, 8),
    suggested_entry_max DECIMAL(20, 8),
    stop_loss DECIMAL(20, 8),
    take_profit_1 DECIMAL(20, 8),
    take_profit_2 DECIMAL(20, 8),
    leverage INTEGER DEFAULT 5,
    status VARCHAR(20) DEFAULT 'pending',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    expire_at TIMESTAMP,
    confirmed_at TIMESTAMP,
    rejected_at TIMESTAMP,
    order_id VARCHAR(64),
    notes TEXT
);
```

#### 5.1.2 评分记录表 (scoring_records)

```sql
CREATE TABLE scoring_records (
    id SERIAL PRIMARY KEY,
    symbol VARCHAR(20) NOT NULL,
    total_score DECIMAL(5, 2) NOT NULL,
    contract_score DECIMAL(5, 2),
    fundamental_score DECIMAL(5, 2),
    technical_score DECIMAL(5, 2),
    sentiment_score DECIMAL(5, 2),
    oi_ratio DECIMAL(10, 4),
    listing_hours INTEGER,
    scoring_attempt INTEGER DEFAULT 1,
    veto BOOLEAN DEFAULT FALSE,
    veto_reason TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_symbol_time (symbol, created_at)
);
```

#### 5.1.3 交易记录表 (trade_records)

```sql
CREATE TABLE trade_records (
    id VARCHAR(64) PRIMARY KEY,
    signal_id VARCHAR(64) REFERENCES trading_signals(id),
    symbol VARCHAR(20) NOT NULL,
    side VARCHAR(10) NOT NULL,
    entry_price DECIMAL(20, 8) NOT NULL,
    quantity DECIMAL(20, 8) NOT NULL,
    leverage INTEGER NOT NULL,
    stop_loss DECIMAL(20, 8),
    take_profit_1 DECIMAL(20, 8),
    take_profit_2 DECIMAL(20, 8),
    exit_price DECIMAL(20, 8),
    pnl DECIMAL(20, 8),
    pnl_percent DECIMAL(10, 4),
    status VARCHAR(20) DEFAULT 'OPEN',
    reason TEXT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    closed_at TIMESTAMP
);
```

### 5.2 缓存策略

## 13. 故障处理

### 13.1 常见故障及处理

| 故障 | 原因 | 处理方案 |
|------|------|----------|
| API 限流 | 请求过于频繁 | 实现退避重试、增加缓存 |
| 数据库连接失败 | 服务宕机 | 自动重连、告警通知 |
| 评分任务失败 | 数据异常 | 记录日志、跳过异常币种 |
| 交易失败 | 余额不足 | 告警通知、人工介入 |

### 13.2 应急预案

```python
# 故障自动降级策略
try:
    # 尝试获取真实数据
    data = fetch_from_api()
except APIError:
    # 降级：使用缓存数据
    data = get_from_cache()
    if not data:
        # 再次降级：跳过该币种
        logger.warning("跳过该币种")
        return
```
