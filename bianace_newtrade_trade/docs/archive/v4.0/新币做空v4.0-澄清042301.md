## 🔴 优先级1：核心逻辑澄清

### Q1: OI/市值比评分逻辑反转的确认

- **是否确认反转？**  
  ✅ **确认**。新币做空策略中，OI/市值比越低越安全，得分应越高；比值越高代表主力控盘风险越大，得分应越低。原逻辑（高比值=泡沫大=做空机会好）不适合新币场景。

- **反转后的逻辑依据？**  
  新币上线初期筹码高度集中，主力容易通过拉抬现货引发合约空头爆仓。OI/市值比 > 0.8 时做空风险极高，回测中大量亏损币种具有高OI/市值比特征。因此“低OI/市值比”是安全前提，而非“高OI是机会”。

- **是否需要保留原有逻辑作为备选？**  
  ❌ **不需要**。两种逻辑在新币上互斥，保留备选会造成决策混乱。若未来策略扩展到成熟币种，可另建独立策略。

### Q2: 技术面评分逻辑重构的确认

- **是否确认完全去掉趋势、RSI、波动率指标？**  
  ✅ **确认**。新币极端波动下这些指标频繁失效，回测证明纯形态（三次冲顶、长上影线、放量滞涨）已能达到100%胜率。去掉后简化系统，减少过拟合风险。

- **三次冲顶、长上影线、放量滞涨的评分标准是否明确？**  
  ✅ **明确**，已在V4.0文档第3.2节给出量化标准：
  - 三次冲顶：高点逐次降低（差≥0.2%）或同一水平受阻3次，满分4分。
  - 长上影线：影线长度 ≥ 实体×2，且阴线或十字星，满分3分。
  - 放量滞涨：成交量 ≥ 前5根平均×1.5，且收盘低于前高，满分3分。

- **现有系统已实现形态识别，是否需要调整算法？**  
  🔧 **需要微调**：确保“三次冲顶”跨K线判断（非单根K线内），且避免将开盘第一根异常K线作为基准。建议增加最小K线数量要求（至少5根已收盘K线）再开始形态识别。

### Q3: 基本面评分完全去掉的确认

- **是否确认完全去掉基本面评分？**  
  ✅ **确认**。新币解锁数据难以实时获取且不完整，强行使用默认值会引入大量噪音，去掉后策略更纯粹、可执行性更高。

- **去掉的原因是“数据难以实时获取且不完整”？**  
  ✅ 正是。TokenUnlocks等平台对新币更新不及时，且许多新币无公开解锁计划。策略追求完全量化，必须依赖稳定数据源。

- **是否需要保留基本面数据获取功能（但不参与评分）？**  
  🟡 **可选**：可以作为**人工辅助参考**，在自动评分之外额外展示。但不建议融入自动化决策流程，避免未来不自觉地又引入它。

## 🟡 优先级2：实现细节澄清

### Q4: 技术面硬性要求的实现方式

- **硬性要求（技术总分 ≥6 且 三次冲顶分 ≥2）是在评分前检查还是评分后检查？**  
  **评分后检查**。先计算技术面各项得分，然后判断是否满足硬性要求。不满足时，即使总分≥6.5也**不开仓**，但可以继续等待下一根K线。

### Q5: 长上影线形态识别的具体标准

- **是否需要实现长上影线检测功能？**  
  ✅ **需要**。这是技术面三项核心条件之一。

- **具体的量化标准是否明确？**  
  ✅ 明确：  
  - 上影线长度 = 最高价 - max(开盘价, 收盘价)  
  - 实体长度 = |收盘价 - 开盘价|  
  - 条件：上影线长度 ≥ 实体长度 × 2，且实体为阴线（收盘 < 开盘）或十字星（|收盘-开盘| ≤ 0.1%×价格）。  
  - 若实体长度为0（十字星），则上影线长度 > 0 即可视为满足？

  注意：十字星情况下，实体趋近0，条件自动满足，但为避免噪音，可附加要求上影线长度 ≥ 价格×0.5%。

### Q6: 情绪面评分的简化

- **是否确认简化情绪面评分逻辑？**  
  ✅ 确认保持V4.0中的简化形式：仅根据资金费率年化分四档打分（10/7/3/0），不再引入其他情绪指标（如社交媒体热度、多空比）。简洁、数据易得。

## 🟢 优先级3：风控细节澄清

### Q7: 每日最大交易次数限制

**实现方式**：在策略代码中维护一个全局计数器 `daily_trade_count`，每日0点（UTC+8）重置。每次开仓前检查：若 `daily_trade_count >= 3`，则跳过开仓并记录日志。开仓成功后计数器+1。

### Q8: 连续亏损暂停机制

**实现方式**：维护连续亏损次数（`consecutive_losses`）。每次平仓后若盈亏为负，则 `consecutive_losses++`；若为正，则重置为0。当 `consecutive_losses >= 3` 时，触发暂停标志，当日及次日不再执行任何开仓（恢复时间为触发后的第3日0点）。恢复后 `consecutive_losses` 重置为0。

### Q9: 杠杆调整的实现

**当前规则**：统一杠杆 ≤ 2倍。动态部分（盈利20%后升到2.5%）和亏损降杠杆（单日亏损>5%后次日降至1%）属于进阶特性，**建议初期先固定2倍杠杆运行一个月**，稳定后再加入动态调整。实现时注意：杠杆调整应基于**开仓前的账户净值**计算风险敞口，避免重复累加。

### Q10: 现有数据的兼容性

- **现有回测数据（基于旧逻辑）是否需要重新运行？**

### Q11: 回测数据的验证

- **如何验证回测结果的可靠性？**  
  1. **前向测试**：用最近3个月未参与回测的新币数据验证。  
  2. **模拟盘**：用币安测试网或极小资金（50U）实盘模拟1个月。  
  3. **交叉验证**：对比不同数据源（币安API、CoinGecko）的OI/市值比是否一致。  
  4. **滑点测试**：在回测中增加0.05%~0.1%的滑点成本，观察盈利是否仍为正。
