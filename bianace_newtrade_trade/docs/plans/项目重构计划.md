## 🔧 重构方案

#### 1.1 目录结构调整

**调整前**：
```

│   ├── scripts/ (含多版本脚本)
│   └── ...

```

│   └── main.py                     # 唯一主入口

│   ├── code/                       # 历史代码归档

### 三、版本管理机制

#### 3.1 Git 分支策略

```
main        # 生产分支，仅包含稳定版本
├── develop # 开发分支
└── archive # 归档分支，包含所有历史版本
```

#### 3.2 版本标签

为每个归档版本创建 Git 标签：
- `v1.0.0` - 初始版本
- `v3.1.0` - v3.1 版本
- `v4.0.0` - v4.0 版本
- `v4.1.0` - 当前版本

#### 3.3 未来开发规范

1. **禁止在根目录创建脚本**：所有脚本必须放在 `short_selling_system/scripts/` 下
2. **禁止创建版本后缀文件**：如需新版本，先删除旧版本或归档
3. **文档统一管理**：所有文档必须放在 `docs/` 目录
4. **版本号在文档标题体现**：不在文件名中体现
