## 1. 项目背景与目标

### 1.1 背景

传统币安合约网格在单边行情中容易产生大幅回撤，用户手动干预往往滞后。经过多轮讨论，我们形成了一套"趋势过滤 + 动态参数 + 半自动信号灯"的混合策略，旨在保留网格震荡盈利能力的同时，降低单边风险。

### 1.2 目标

构建一个**半自动信号灯系统**:
- 自动分析市场状态（震荡/趋势/强趋势）
- 自动计算最优网格参数（价格区间、网格数量、止盈止损、移动价格）
- 自动检查仓位可行性（最小合约张数要求）
- 通过飞书推送可执行的操作指令
- 用户根据指令手动在币安网页端创建或修改网格
- 为后续全自动交易打下基础

## 2. 核心策略概述

### 2.1 策略思想

- **震荡市场**: 运行标准双向网格，赚取波动收益。
- **上升趋势**: 切换为偏多非对称网格，配合"上移功能"捕捉趋势，同时避免过度做空。
- **下降趋势**: 切换为偏空非对称网格，配合"下移功能"规避下跌，同时避免过度做多。
- **强趋势（ADX ≥ 40）**: 暂停网格，避免追涨杀跌。
- **多时间框架确认**: 15m（边界突破检测）、1h（主判断）、4h（趋势过滤），减少假信号。

### 2.2 工作流程（半自动）

```
┌─────────────────────────┐
│  定时巡检（每1小时）      │
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│ 获取15m/1h/4h K线数据    │
│ 计算 ADX, EMA, ATR       │
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│ 多时间框架状态判定        │
│ 输出: 最终市场状态+趋势强度│
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│ 计算新网格参数:          │
│ - 价格区间               │
│ - 网格数量               │
│ - 网格模式(等差/等比)     │
│ - 止盈止损价格           │
│ - 停止上移/下移价格       │
│ - 验证每格利润率≥1%       │
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│ 仓位可行性验证:           │
│ 根据当前价格、杠杆、保证金、│
│ 网格数量计算每格合约张数   │
│ 若 <1 张，给出调整建议    │
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│ 与当前运行的网格参数比较   │
│ (若初次运行则直接推送)    │
└────────────┬────────────┘
             ↓ (变化超过阈值)
┌─────────────────────────┐
│ 生成推送消息（含完整参数  │
│ 及操作指令）             │
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│ 推送到飞书               │
└────────────┬────────────┘
             ↓
┌─────────────────────────┐
│ 用户手动在币安网页端      │
│ 终止旧网格，创建新网格    │
└─────────────────────────┘
```

## 3. 市场状态识别

### 3.1 技术指标及参数

| 指标 | 周期 | 用途 | 关键阈值 |
|------|------|------|----------|
| ADX | 14 | 趋势强度 | <20: 震荡；≥25: 趋势；≥40: 强趋势暂停 |
| EMA（快） | 20 | 短期方向 | 用于判断趋势方向 |
| EMA（慢） | 50 | 长期方向 | 用于确认趋势 |
| ATR | 14 | 波动率 | 用于网格宽度、步长计算 |

### 3.2 各时间框架职责

| 时间框架 | 作用 | 巡检/触发频率 |
|----------|------|----------------|
| 15分钟 | 检测价格是否突破网格边界、是否触发上移/下移条件 | 每15分钟（可简化为每小时获取最新值） |
| 1小时 | 主交易周期：计算ADX/EMA/ATR，判断市场状态 | 每小时整点K线收盘后 |
| 4小时 | 趋势过滤器：确认大方向，防止1h假信号 | 每小时获取最新4hK线值（可与1h同步） |

### 3.3 状态判定规则（结合1h + 4h）

| 1h 状态 | 4h 状态 | 最终状态 | 网格模式 | 移动功能 |
|----------|---------|----------|----------|-----------|
| 震荡 | 任意 | 震荡 | 双向中性 | 无 |
| 上升趋势 | 上升趋势 | 上升趋势 | 偏多非对称 | 启用上移 |
| 上升趋势 | 震荡或下降 | 震荡（降级） | 双向中性 | 无 |
| 下降趋势 | 下降趋势 | 下降趋势 | 偏空非对称 | 启用下移 |
| 下降趋势 | 震荡或上升 | 震荡（降级） | 双向中性 | 无 |
| 任意 | 强趋势（ADX≥40） | 强趋势暂停 | 不创建/暂停 | 无 |

### 3.4 趋势强度系数 k

当处于上升或下降趋势时，计算系数 k 用于后续上移/下移步长:

```
k = min(0.5, max(0, (ADX_1h - 25) / 30))
```

**示例**: ADX=28 → k=0.1；ADX=40 → k=0.5。

### 3.5 市场状态判断逻辑（供计算时使用）

```python
ADX = ADX(14)
EMA_fast = EMA(20)
EMA_slow = EMA(50)

if ADX < 20:
    状态 = "震荡"
elif ADX > 25:
    if EMA_fast > EMA_slow:
        状态 = "上升趋势"
    else:
        状态 = "下降趋势"
else:   # 20 ≤ ADX ≤ 25
    # 保持前一状态，或根据ADX变化趋势判断
    状态 = 前一状态   # 简单处理：不切换
```

**多时间框架确认（可选）**: 同时检查4H周期的ADX和EMA，与1H结果一致时才确认状态改变。

## 4. 网格参数计算逻辑

### 4.1 输入数据

- 当前标记价格 \( P \)
- 平滑 ATR: \( ATR_{smooth} = EMA(ATR(14), 14) \)
- 最终市场状态（震荡/上升趋势/下降趋势/强趋势暂停）
- 趋势强度系数 \( k \)（仅趋势时有效）
- 基准 ATR: 过去90天的 ATR 均值（滚动窗口）

### 4.2 价格区间与网格结构

| 参数 | 震荡市场 | 上升趋势 | 下降趋势 |
|------|----------|----------|----------|
| 下边界 | \( P - 2 \times ATR_{smooth} \) | \( P - 1.5 \times ATR_{smooth} \) | \( P - 4 \times ATR_{smooth} \) |
| 上边界 | \( P + 2 \times ATR_{smooth} \) | \( P + 4 \times ATR_{smooth} \) | \( P + 1.5 \times ATR_{smooth} \) |
| 网格数量 N | \( N = \text{round}\left(30 \times \frac{ATR_{基准}}{ATR_{smooth}}\right) \) | 同左 | 同左 |
| N 范围 | [20, 50] | [20, 50] | [20, 50] |
| 网格模式 | 若 (上边界-下边界)/P < 0.3 则等差，否则等比 | 同左 | 同左 |
| 终止最低价 | 下边界 - 2×ATR | 下边界 - 2×ATR | 下边界 - 2×ATR |
| 终止最高价 | 上边界 + 2×ATR | 上边界 + 2×ATR | 上边界 + 2×ATR |
| 停止上移价格 | 不启用 | 上边界 + k × ATR | 不启用 |
| 停止下移价格 | 不启用 | 不启用 | 下边界 - k × ATR |

### 4.3 每格利润率验证

币安要求合约网格每格利润率 > 1%，否则无法创建。

- **等差网格**: 间距 = (上边界 - 下边界) / N，每格利润率 = 间距 / P × 100%
- **等比网格**: 比例 = (上边界 / 下边界)^{1/N}，每格利润率 = (比例 - 1) × 100%

若利润率 < 1%，自动减少网格数量（不低于 20）直到满足，若仍不满足则推送警告。

### 4.4 移动止盈（基础版）

当总盈利 ≥ 15% 时，启动追踪止盈:

```
peak_price = 自网格启动以来的最高价
新终止最高价 = min(当前终止最高价, peak_price × (1 - 0.05))   # 回撤5%止盈
```

此功能需要程序记录历史最高价，在半自动模式下可由用户手动调整。

> **详细移动止盈机制请参见 [第8章 移动止盈机制详解](#8-移动止盈机制详解)**

## 5. 6 个可调参数的详细计算与触发条件

> 本节从原始参数调整文档中提取，详细说明系统可调整的6个核心参数。

### 5.1 网格交易价格范围（上边界 / 下边界）

| 项目 | 说明 |
|------|------|
| **修改逻辑** | 需终止重建：调用币安终止网格API → 等待平仓完成 → 用新参数调用创建网格API |
| **计算逻辑** | 根据市场状态和波动率动态计算新边界 |

**计算公式**:

```python
ATR_smooth = EMA(ATR(14), 14)   # 平滑ATR
基准宽度 = 4 × ATR_smooth
中心价格 = 当前标记价格

if 市场状态 == 震荡:
    下边界 = 中心价格 - 基准宽度 / 2
    上边界 = 中心价格 + 基准宽度 / 2
elif 市场状态 == 上升趋势:
    下边界 = 中心价格 - 1.5 × ATR_smooth   # 浅下界
    上边界 = 中心价格 + 4 × ATR_smooth      # 深上界
elif 市场状态 == 下降趋势:
    下边界 = 中心价格 - 4 × ATR_smooth      # 深下界
    上边界 = 中心价格 + 1.5 × ATR_smooth    # 浅上界
```

**边界保护**:
- 确保 上边界 > 下边界 + 最小宽度（最小宽度建议 2×ATR_smooth）
- 不得超出历史极端价格（可选）

**触发条件**（满足任意一条即可）:
- 平滑ATR变化超过 ±20%（相对于上次调整时的值）
- 市场状态发生变化（震荡↔趋势）
- 价格已运行到当前网格边缘附近（例如价格距上边界 < 0.5×ATR_smooth）

### 5.2 网格数量

| 项目 | 说明 |
|------|------|
| **修改逻辑** | 需终止重建（与价格范围修改同步进行） |
| **计算逻辑** | 根据波动率自适应调整网格密度 |

**计算公式**:

```python
基准网格数 = 30   (可配置)
基准ATR = 过去90天ATR的均值（或指数加权移动平均）
当前ATR_smooth = 同上

网格数量 = 基准网格数 × (基准ATR / 当前ATR_smooth)
网格数量 = max(20, min(50, 网格数量))   # 限制在20~50之间
```

**逻辑解释**:
- 波动率升高（当前ATR变大） → 网格数量减少 → 格子变宽，减少被套仓位
- 波动率降低 → 网格数量增加 → 格子变密，增加获利机会

**触发条件**:
- 平滑ATR变化超过 ±20%（可与价格范围调整同步，避免频繁终止重建）

### 5.3 停止上移价格

| 项目 | 说明 |
|------|------|
| **修改逻辑** | 可直接修改：调用币安修改网格API（更新停止上移价格字段） |
| **计算逻辑** | 在上升趋势中，根据价格突破和趋势强度动态上移 |

**计算公式**:

```python
趋势强度系数 k_trend = min(0.5, max(0, (ADX - 25) / 30))   # ADX越高，系数越大
上移步长 = k_trend × ATR_smooth

新停止上移价格 = max(当前网格上边界 + 上移步长, 上一次的停止上移价格)
```

**触发条件**（满足任意一条即可）:
- 价格连续向上突破网格层数 ≥ 3层（在5分钟内）
- ADX > 25（确认有上升趋势）
- 当前价格已超过当前的停止上移价格

**注意**:
- 每次上移后，应将"上一次的停止上移价格"更新为新值
- 修改后需保存到本地状态

### 5.4 停止下移价格

| 项目 | 说明 |
|------|------|
| **修改逻辑** | 可直接修改：调用币安修改网格API（更新停止下移价格字段） |
| **计算逻辑** | 在下降趋势中，根据价格跌破和趋势强度动态下移 |

**计算公式**:

```python
趋势强度系数 k_trend = min(0.5, max(0, (ADX - 25) / 30))
下移步长 = k_trend × ATR_smooth

新停止下移价格 = min(当前网格下边界 - 下移步长, 上一次的停止下移价格)
```

**触发条件**（满足任意一条即可）:
- 价格连续向下突破网格层数 ≥ 3层（在5分钟内）
- ADX > 25（确认有下降趋势）
- 当前价格已低于当前的停止下移价格

**注意**:
- 下移步长同样基于趋势强度
- 修改后更新本地记录

### 5.5 网格终止最低价格（硬止损线）

| 项目 | 说明 |
|------|------|
| **修改逻辑** | 可直接修改：调用币安修改网格API（更新终止最低价格字段） |
| **计算逻辑** | 根据市场状态和盈利情况动态调整，但保守调整，仅在盈利时考虑上移 |

**计算公式**:

```python
基础终止最低价格 = 初始网格下边界 - 2 × ATR_smooth   # 创建网格时设定
当前盈利状态：total_PnL_percent（总盈亏百分比）

if total_PnL_percent > 0:   # 盈利状态下可考虑上移止损
    新终止最低价格 = max(当前终止最低价格, 当前价格 - 3 × ATR_smooth)
else:   # 亏损或保本状态，维持原值或不变（不建议在亏损时移动止损线）
    新终止最低价格 = 当前终止最低价格   # 或保持不变
```

**触发条件**:
- 盈利状态下，价格持续上涨，且当前价格已远离原止损线（例如价格 > 原终止最低价格 + 2×ATR）
- 为避免频繁修改，可设置最小调整间隔（例如每4小时最多调整一次）

**注意**:
- 终止最低价格是最后的防线，上移时应保守（如用3倍ATR作为缓冲）
- **亏损时绝不向下移动止损线**（避免死扛扩大亏损）

### 5.6 网格终止最高价格（硬止盈线）

| 项目 | 说明 |
|------|------|
| **修改逻辑** | 可直接修改：调用币安修改网格API（更新终止最高价格字段） |
| **计算逻辑** | 结合移动止盈机制动态调整 |

**计算公式**:

```python
基础终止最高价格 = 初始网格上边界 + 2 × ATR_smooth   # 创建网格时设定
移动止盈启动阈值 = 15%   # 总盈利百分比
回撤保护距离 = 0.5 × (最高盈利时的价格 - 当前价格)   # 回撤一半时触发

if total_PnL_percent > 移动止盈启动阈值:
    # 记录本次盈利周期内的最高价 peak_price
    # 当价格从 peak_price 回落时，计算回撤比例
    新终止最高价格 = min(当前终止最高价格, peak_price - 回撤保护距离)
else:
    新终止最高价格 = 当前终止最高价格   # 未启动移动止盈前保持不变
```

**触发条件**:
- 总盈利首次超过15%（启动移动止盈模式）
- 在移动止盈模式下，价格从最高点回落，且回撤幅度达到一定阈值（例如回撤到最高价的95%以下）
- 为简化，可在每次巡检时重新计算，若新值低于旧值则更新

**注意**:
- 终止最高价格通常只下移（降低止盈门槛）来锁定利润
- 如果价格继续创新高，可保留原值，等待回落

### 5.7 实现要点总结

- **参数存储**: 程序需维护当前网格的所有参数（包括可修改的6项），每次巡检时计算新值，并与当前值比较。
- **触发条件**: 设定合理的阈值和最小调整间隔，避免过于频繁的修改（尤其终止重建）。
- **API调用**:
  - 终止重建：`POST /fapi/v1/grid/stop` → 等待订单完成 → `POST /fapi/v1/grid/create`
  - 修改停止/终止价格：`POST /fapi/v1/grid/update`（具体接口名需查阅币安文档，可能为modify）
- **平滑处理**: 使用指数移动平均平滑ATR，避免异常跳动影响。
- **安全边界**: 所有计算出的价格应进行合理性校验，防止出现下边界高于上边界等错误。

## 6. 仓位与资金管理

### 6.1 币安合约最小交易限制

- BTCUSDT 永续合约：最小下单量 **1 张**（1 张 = 1 USDT 面值）
- 创建网格时，每格下单数量必须是整数张数，且 ≥ 1

### 6.2 每格名义价值与张数计算

用户创建网格时需提供:
- 杠杆 \( L \)（建议 10x）
- 总保证金 \( M \)（例如 500 USDT）
- 网格数量 \( N \)

则:
\[
\text{总名义价值} = M \times L
\]
\[
\text{每格名义价值} = \frac{M \times L}{N}
\]
\[
\text{每格下单张数} = \left\lfloor \frac{\text{每格名义价值}}{P} \right\rfloor \quad (\text{向下取整})
\]

**示例（默认参数）**:
- \( M = 500,\ L = 10,\ N = 30,\ P = 69500 \)
- 每格名义价值 = 5000 / 30 ≈ 166.67 USDT
- 每格张数 = floor(166.67 / 69500) = 0 → **不可行**

### 6.3 解决方案（半自动模式下）

由于半自动系统不直接操作资金，我们采用**参数可行性检查 + 友好建议**策略:

1. **自动调整网格数量**: 若每格张数 < 1，尝试减少 N（最小至 5）直到满足或提示用户。
2. **若仍不满足**: 推送中要求用户增加保证金或提高杠杆，并给出最小所需值。

**最小所需保证金公式**（给定 N, L, P）:
\[
M_{min} = \frac{N \times P}{L}
\]
（因为需要每格名义价值 ≥ P，才能买到 1 张）

**示例**:
- 若 N=20, L=10, P=69500，则 \( M_{min} = 20 \times 69500 / 10 = 139000 \) USDT → 不现实。
- 因此必须减小 N 或提高杠杆。

**实用建议**:
- 对于 BTCUSDT 当前价格 6-7 万 USDT，建议使用 **N ≤ 10**，且保证金至少 2000 USDT 以上。
- 信号灯系统在推送中给出"推荐网格数量 = 5 ~ 10"以及所需保证金提示。

### 6.4 推送中的资金建议格式

为了不误导用户，推送内容将包含"可行性提醒"，而非强制固定数值。例如:

```
💰 资金配置提醒
当前价格 69500 USDT，若使用 10x 杠杆，每格 1 张所需保证金 = 6950 USDT。
建议：
- 方案1（保守）：网格数量 5，每格 1 张，总保证金≈34750 USDT（较高）
- 方案2（密度高）：网格数量 20，每格 0.3 张（不可行，需提高杠杆至 50x 以上，风险高）
请根据您的资金情况在币安创建界面调整网格数量和保证金，以确保每格≥1张。
```

由于半自动系统无法强制用户资金，最终决定权在用户。我们的职责是给出清晰的计算公式和提醒。

### 6.5 动态仓位（波动率平价）

- 固定名义本金，根据ATR调整实际开仓保证金  
  `动态仓位 = 固定名义本金 / (ATR * 系数)`  
  确保每单位风险（名义价值×波动率）恒定

## 7. 风险管理器

### 7.1 硬止损（Hard Stop Loss）

- **监控对象**: 策略总盈亏（已实现 + 未实现）
- **触发条件**: 总亏损 ≥ 初始保证金 × 8%
- **动作**: 立即终止网格，市价平仓所有持仓（带滑点保护）

### 7.2 移动止盈（Trailing Take Profit）

- **启动条件**: 总盈利 ≥ 初始保证金 × 15%
- **回撤锁定**: 从峰值盈利回撤 50% 时止盈离场

> **详细机制请参见 [第8章 移动止盈机制详解](#8-移动止盈机制详解)**

### 7.3 紧急暂停协议（Emergency Pause）

**触发条件**（满足任意一条即可）:
- 5分钟内价格连续突破多个网格（如突破3层以上）
- API连续报错或延迟 > 3秒
- 网络断开

**执行动作**:
1. 取消所有挂单（暂停新订单）
2. 保持现有持仓，不平仓（"就地卧倒"）
3. 发送警报（飞书/钉钉/Telegram）
4. 尝试恢复，稳定后重新计算参数重启

### 7.4 滑点保护

- 终止时优先使用限价单（当前买一/卖一价）平仓
- 超时3秒后改用对手方最优价格
- 最后才用市价单

## 8. 移动止盈机制详解

> 本节从补充文档中提取，是针对"不知道何时收割收益"这一痛点专门设计的功能。它的加入，就是为了解决网格盈利后，再V型反转跌回成本价的难题。

### 8.1 工作原理（一句话解释）

当网格总利润达到目标后，系统不再傻等跌回成本线才止损，而是把止盈价"绑定"在价格的峰值上。只要价格从最高点回撤一定幅度，就立刻宣告这轮趋势结束，帮你锁住大部分利润。

### 8.2 触发条件与参数

| 参数 | 设定值 | 说明 |
|------|--------|------|
| 盈利启动线 | +15% | 当网格总盈利（浮动盈亏）达到投入保证金的15%时，移动止盈启动 |
| 追踪回撤比例 | 5% | 从历史最高价回撤5%，即触发止盈 |
| 追踪对象 | 标记价格（Mark Price） | 取币安的标记价格，避免成交价波动过大导致误触发 |

### 8.3 完整运行逻辑（结合信号灯）

为了让逻辑更清晰，建议把网格操作分为"震荡期"和"趋势期"两个阶段来理解，移动止盈主要在趋势期发挥作用:

#### 阶段一：震荡期 — 赚差价，用传统的终止止损保护

- **市场状态**: 震荡市（ADX<20）或降级震荡。
- **收益来源**: 网格震荡套利，赚取波动中的小利润。
- **退出方式**: 系统推送中提供的"终止最低价/最高价"，一旦触发，就代表网格底或顶被有效击穿，手动终止网格。这解决了"正常网格该在哪里止损"的问题。

#### 阶段二：趋势期 — 吃趋势，启动移动止盈

一旦市场状态变为"上升趋势"或"下降趋势":

1. **信号灯会推送新网格参数**: 这时候的网格是偏多或偏空非对称网格，并且启用上移/下移功能。
2. **用户创建新网格**: 根据推送，在币安创建带"上移/下移"功能的网格，并设置好"终止止损"价格。
3. **持续监控盈利**: 在下次巡检或你自行查看时，关注总盈亏。
   - **若盈利从未达到15%**，但价格先触碰了终止止损价，则网格终止。这代表趋势判断错误，止损离场。
   - **若盈利达到15%**，系统会在下次推送中，将"终止最高价"（上升趋势）或"终止最低价"（下降趋势）**更新为一个动态追踪价格**。

4. **手动更新止盈价（关键操作）**:
   **因为目前是半自动，这一步需要你手动完成。**
   当你收到推送，看到终止价格变了，并且提示"移动止盈已启动"，你需要:
   - 打开币安APP，进入当前运行中的网格。
   - 点击"修改"（部分参数可能允许修改，视币安界面当时规则而定）或者直接**终止当前网格，并使用新推送的"终止价格"重新创建一个相同参数的网格**。
   - **这一步是把动态止盈价格写进系统的核心动作。**

**例子（上升趋势）**:
- 你按信号创建了BTC 68000-75000的看多网格，初始"终止最高价"设为78000。
- 行情大涨，价格冲到76500，你的网格总盈利达到15%，系统计算后推送新的"终止最高价": **76500 × (1-5%) = 72675**。
- 你立刻/在下次巡检后收到推送，手动将网格的终止最高价改为72675。
- 之后行情继续涨到77000再回落，一旦价格跌破72675，网格自动终止。你就在价格回落时，保住了大部分利润，而不是跌回68000才止损。

## 10. 直白使用说明书

> 本节为实盘操作时对照使用的快速指南，从收到飞书消息开始，到执行完成结束。

### 10.1 使用前必读（核心风险）

这套系统的核心任务是：**把市场状态分类，并告诉你什么情况下该用什么样的网格配置，尤其是该在什么价格坚决离场（止损或止盈）。**

它不预测行情，只对当前状态做出应对。**你最大的风险，是收到信号后犹豫不决，或因资金不足无法创建网格，错过应对时机。**

### 10.2 快速决策流程图

收到飞书推送消息 → 看标题状态和应用建议:
- **"强趋势暂停"** → 立刻终止当前网格（如有）。目标是空仓规避风险。
- **"震荡/上升/下降"** → 对比推送参数和当前网格。目标是用新参数换掉旧网格。

### 10.3 分步操作指南

#### 第一步：看推送，判断"用新换旧"

推送标题和重点信息解读:

- **`【网格信号灯】震荡市场`**:
  - **做什么**: 运行一个中性双向网格，赚取震荡利润。
  - **不做什么**: 不启用上移/下移，价格突破上下边界2倍ATR就止损。
  - **你该做的**: 如果当前你正持有趋势网格，需换掉。

- **`【网格信号灯】上升趋势`**:
  - **做什么**: 切换到偏多非对称网格（上边界更宽，下边界更窄），并**启用上移功能**。
  - **关键动作**: 设置**停止上移价格**，并密切关注何时**启动移动止盈**。
  - **你该做的**: 立刻终止旧网格，创建一个"看多"配置的新网格。

- **`【网格信号灯】下降趋势`**:
  - **做什么**: 切换到偏空非对称网格（下边界更宽，上边界更窄），并**启用下移功能**。
  - **关键动作**: 设置**停止下移价格**，并密切关注何时**启动移动止盈**。
  - **你该做的**: 立刻终止旧网格，创建一个"看空"配置的新网格。

- **`【网格信号灯】强趋势暂停`**:
  - **做什么**: 不创建任何新网格。
  - **你该做的**: 立刻终止当前所有BTCUSDT合约网格。这是强制休息信号。

#### 第二步：在币安创建网格（对照填入）

打开推送，找到 **`📐 建议网格参数`** 部分，按下面对照填入币安界面:

| 推送中的参数名 | 币安合约网格界面填入位置 |
| :--- | :--- |
| **下边界 - 上边界** | "价格区间"的最低和最高价 |
| **网格数量** | "网格数量" |
| **网格模式（等差/等比）** | "等差"或"等比"选项 |
| *(无，根据资金填写)* | **"保证金"/"总投入"** → 见下方资金提醒操作 |
| *(无，建议10x)* | **"杠杆"** → 选择10倍（或根据推送建议调整） |
| **终止最低价** | "高级设置" → "止损价格" → 最低价 |
| **终止最高价** | "高级设置" → "止损价格" → 最高价 |
| **停止上移价格**（若推送有） | "高级设置" → 打开"上移"开关 → 填入此价格 |
| **停止下移价格**（若推送有） | "高级设置" → 打开"下移"开关 → 填入此价格 |

#### 第三步：处理资金配置（关键）

仔细阅读推送中的 **`💰 资金可行性提醒`** 部分。系统已经帮你计算好了。

- **核心规则**: 创建网格前，看一眼币安界面上的"每格数量"是否 ≥ 1张。如果小于1，订单会被拒。
- **调整方法**:
  - **减少网格数量**: 优先操作。在币安界面直接减小"网格数量"，直到"每格数量"≥1。
  - **增加保证金**: 如果不想减少数量，就增加"总投入金额"，直到"每格数量"≥1。
  - **提高杠杆**: 最后选项，风险高，不推荐超过20倍。

#### 第四步：移动止盈启动后的特殊操作

当你的趋势网格盈利达到15%后，系统会推送一条 **`触发移动止盈更新`** 的消息。

- **你会看到**: 推送中 **`🎯 止盈止损`** 里的"终止最高价"或"终止最低价"变了，不再是初始值，并附有说明。
- **你要做的**:
  1. 立刻打开币安APP，找到正在运行的该网格。
  2. 终止它。
  3. 用**完全相同的网格数量、价格区间、上移/下移价格**，但填入**新的"终止止损价"**，重新创建一个网格。
  4. 这样，你的网格就带上了动态追踪止盈的保护。

**记住**: 这一步是**强制要求手动干预**的，也是你将来最需要养成习惯、转化为肌肉记忆的动作。

### 10.4 币安网页端手动操作指南

#### 终止旧网格

1. 打开币安APP → 交易 → BTCUSDT 永续合约
2. 点击下方"策略交易" → 选择"运行中"
3. 找到当前网格 → 点击"终止" → 确认

#### 创建新网格

1. 点击"创建网格" → 选择"合约网格"
2. 参数设置:
   - **价格区间**: 填写推送中的下边界和上边界
   - **网格数量**: 填写推送中的数量
   - **模式**: 等差或等比
   - **杠杆**: 建议 10x（可调整）
   - **总投入金额**: 根据您的资金能力填写（系统会自动计算每格下单张数，若小于1会提示）
3. 高级设置（可选）:
   - 若启用了上移：打开"上移"开关 → 填入"停止上移价格"
   - 若启用了下移：打开"下移"开关 → 填入"停止下移价格"
   - 终止最高价格 / 终止最低价格
4. 确认每格利润率 > 1%，且每格张数 ≥ 1，然后创建。

#### 注意事项

- 上移/下移功能一旦创建不可修改，如需关闭需终止网格重建。
- 同时启用上移和下移时，止盈止损价格不会自动跟随（币安限制）。
- 若系统提示"每格数量不足1张"，请减少网格数量或增加总投入金额。

- **持续运行**: 调用 `run_loop(interval_minutes=60)` 每小时巡检一次

def validate_position_size(price, grid_count, leverage, margin):
    total_nominal = margin * leverage
    nominal_per_grid = total_nominal / grid_count
    qty = nominal_per_grid / price
    if qty < 1:
        min_margin = (1 * price * grid_count) / leverage
        return False, f"每格仅{qty:.2f}张，不足1张。请将保证金增至{min_margin:.0f} USDT，或减少网格数量至{max(1, int(margin*leverage/price))}格"
    else:
        return True, f"每格{qty:.2f}张（取整后{int(qty)}张）"

## 14. 风险提示与免责

1. **网格交易非保本**，单边行情可能导致亏损。本系统仅提供信号，不保证盈利。
2. **杠杆风险**: 高杠杆会放大亏损，建议不超过 10x，极端行情下甚至可能强平。
3. **上移/下移风险**: 上移可能导致追高，下移可能导致杀跌，请谨慎使用。
4. **手动操作延迟**: 价格可能在推送后快速变化，用户需自行判断是否执行。
5. **参数过拟合**: 历史回测表现不代表未来，建议小资金试运行。
6. **最小张数限制**: 务必在创建网格时确认每格下单张数 ≥ 1，否则订单会被拒绝。
