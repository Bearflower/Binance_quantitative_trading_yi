## 二、分阶段实施步骤

### 阶段 A：MarketState 枚举重构（market_state.py）

**改动内容**：
1. `MarketState` 枚举替换为 V2.1 的 5 个状态值：
   - `OSCILLATION = "震荡市场"`（保留）
   - `WEAK_TREND = "弱趋势"`（新增）
   - `NORMAL_STRONG_TREND = "普通强趋势"`（替代 STRONG_TREND_PAUSE）
   - `EXTREME_STRONG_TREND = "极端强趋势"`（新增）
   - `VOLATILITY_ABNORMAL = "波动率异常"`（新增）
   - ~~`UPTREND = "上升趋势"`~~（删除）
   - ~~`DOWNTREND = "下降趋势"`~~（删除）
   - ~~`STRONG_TREND_PAUSE = "强趋势暂停"`~~（删除）

2. `MarketAnalysis` 数据类新增字段：
   - `ema20_4h: Decimal` — 4h EMA20
   - `ema50_4h: Decimal` — 4h EMA50
   - `atr_2h_ago: Decimal` — 2小时前ATR（波动率异常检测用）
   - `atr_abnormal_count: int` — 连续异常计数
   - `atr_peak: Decimal` — 异常峰值ATR（恢复检测用）
   - `is_volatility_alarm_active: bool` — 波动率警报是否活跃

3. `__init__` 参数调整：
   - `adx_threshold_strong` → 拆分为 `adx_normal_strong`(30) 和 `adx_extreme_strong`(35)
   - 保留 `adx_threshold_trend`(25) 和 `adx_threshold_oscillation`(20)，但实际逻辑不再使用
   - 新增 `weak_trend_lower`(25), `weak_trend_upper`(30)
   - 新增 `volatility_ratio_threshold`(1.5), `volatility_consecutive_count`(2)
   - 新增 `recovery_adx_1h`(25), `recovery_adx_4h`(30)
   - 新增 `recovery_volatility_ratio`(1.3)
   - 新增 `normal_strong_4h_adx`(25)

4. `_calculate_indicators()`：
   - 新增 4h EMA20/EMA50 计算
   - 新增 ATR 历史存储（保留最近 3 次巡检的 ATR）

5. `_determine_state()` 完全重写——按优先级判断：
   ```
   优先级: 极端强趋势 > 波动率异常 > 普通强趋势 > 弱趋势 > 震荡
   
   if 1h ADX >= 35:                     → 极端强趋势
   if ATR连续2次上升>50%:                → 波动率异常
   if 1h >= 30 AND 4h >= 25 AND 方向一致: → 普通强趋势
   if 25 <= 1h < 30 AND 4h < 25:        → 弱趋势
   else:                                 → 震荡
   ```
   - "方向一致" = `(1h EMA20>EMA50 and 4h EMA20>EMA50)` or `(both reversed)`

6. 新增方法：
   - `_check_volatility_abnormal()` — 波动率异常检测
   - `_check_recovery()` — 恢复条件判断
   - `_is_direction_aligned()` — EMA方向一致性判断

**影响文件**：[market_state.py](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/grid/market_state.py)

### 阶段 B：配置文件调整（config.yaml）

**改动内容**：

1. 删除旧配置项：
   - `market.adx_threshold_strong`(40) → 删除
   - `market.atr_multipliers.uptrend_lower/upper` → 删除
   - `market.atr_multipliers.downtrend_lower/upper` → 删除
   - `signal_bot.trigger_thresholds` 中的 `width_change`, `count_change`, `atr_change` → 评估是否删除（V2.1不再需要这些触发条件）

2. 新增/修改配置项：
   ```yaml
   market:
     # ADX阈值（V2.1）
     adx_extreme_strong: 35          # 极端强趋势
     adx_normal_strong: 30           # 普通强趋势（1h）
     adx_normal_strong_4h: 25        # 普通强趋势（4h确认）
     weak_trend_adx_lower: 25        # 弱趋势下限
     weak_trend_adx_upper: 30        # 弱趋势上限
     oscillation_adx: 25             # 震荡上限
     
     # 波动率异常检测
     volatility_ratio_threshold: 1.5  # ATR飙升阈值
     volatility_consecutive_count: 2  # 连续异常次数
     volatility_recovery_ratio: 1.3   # 恢复阈值（ATR/峰值）

     # 恢复条件
     recovery_adx_1h: 25
     recovery_adx_4h: 30
     
     # 价格区间ATR系数（简化，仅保留震荡和弱趋势）
     atr_multipliers:
       oscillation: 2.0             # 震荡：P ± 2*ATR
       weak_trend: 2.4              # 弱趋势：P ± 2.4*ATR
       stop_loss: 2.0               # 止损缓冲
   
   grid:
     base_grid_count: 30            # 基准网格数（从20改为30）
     min_grid_count: 20             # 震荡最小网格数（从8改为20）
     max_grid_count: 50             # 震荡最大网格数（从30改为50）
     weak_trend_count_multiplier: 0.7  # 弱趋势网格数系数
     weak_trend_min_grid_count: 15  # 弱趋势最小网格数
     weak_trend_max_grid_count: 40  # 弱趋势最大网格数
     oscillation_move_buffer_divisor: 2  # 保留
   
   signal_bot:
     push_cooldown_hours: 4         # 推送冷却时间（新增）
     trigger_thresholds:
       profit_rate_low: 0.012       # 保留
   ```

3. 新增推送冷却配置段：
   ```yaml
   push_cooldown:
     enabled: true
     default_hours: 4               # 同状态4小时内不重复
   ```

### 阶段 C：网格计算器适配（grid_calculator.py）

**改动内容**：

1. `calculate_dynamic_grid_params()`：
   - `market_state` 参数改为接受 V2.1 状态值
   - 新增弱趋势分支：使用 Stage B 的弱趋势 ATR 系数
   - 移除上升/下降趋势的独立分支
   - 强趋势/波动率异常/极端趋势：不计算参数（由 signal_bot 决定是否调用）
   - 网格数量公式改为 V2.1：
     - 震荡: N = round(30 * (基准ATR/当前ATR)), [20, 50]
     - 弱趋势: N = round(30 * (基准ATR/当前ATR) * 0.7), [15, 40]

2. `_calculate_price_range()`：
   - 简化为两个分支：震荡（±2*ATR）和弱趋势（±2.4*ATR）
   - 移除 uptrend/downtrend 的不对称区间计算
   - atr_multipliers 配置读取简化为 `oscillation` / `weak_trend` 两个值

3. `_calculate_dynamic_grid_count()`（如有）：
   - 更新公式匹配 V2.1 的网格数量范围

**影响文件**：[grid_calculator.py](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/grid/grid_calculator.py)

### 阶段 D：信号推送重构（signal_bot.py）

**改动内容**：

1. `run_once()` 分发逻辑重写：
   ```
   极端强趋势 → _generate_extreme_strong_message()（不计算网格参数）
   波动率异常 → _generate_volatility_abnormal_message()（不计算网格参数）
   普通强趋势 → _generate_normal_strong_message()（不计算网格参数）
   弱趋势     → _generate_signal_message()（弱趋势公式计算网格参数）
   震荡       → _generate_signal_message()（标准公式计算网格参数）
   ```

2. 新增推送模板方法：
   - `_generate_extreme_strong_message()` — "极端强趋势警报 - 必须立即终止"
   - `_generate_normal_strong_message()` — "普通强趋势警报 - 建议终止网格"
   - `_generate_volatility_abnormal_message()` — "波动率异常警报 - 暂停挂单"
   - `_generate_weak_trend_message()` — "弱趋势谨慎建议"
   - `_generate_recovery_message()` — "趋势减弱/波动率恢复"

3. `_should_notify()` 改造：
   - 删除 V2.0 的复杂触发条件（网格宽度变化、ATR变化等）
   - 改为 V2.1 的简化逻辑：
     - 状态变化 → 立即推送
     - 同状态 + 超过4小时冷却 → 推送
     - 同状态 + 未超4小时 → 不推送
     - 首次运行 → 推送

4. 新增推送冷却机制：
   - 字典 `self.last_push_time: Dict[str, datetime]`，key = 状态值
   - `_check_cooldown(state)` 方法判断是否超4小时

5. `__init__` 调整：
   - 读取推送冷却时间配置
   - 删除不再需要的旧触发阈值（width_change_threshold等，保留profit_rate_low_threshold）

**影响文件**：[signal_bot.py](file:///Users/yl/vscode/Binance_quantitative_trading/strategies/grid/signal_bot.py)

## 三、风险与注意事项

| 风险 | 应对 |
|------|------|
| `MarketState.UPTREND/DOWNTREND` 被外部引用 | 检查 `strategies/` 目录下所有引用，全部替换 |
| 配置变更后旧容器无法启动 | 全量替换 config.yaml，确保无残留旧配置路径 |
| 弱趋势网格计算复杂度 | 使用与震荡相同的公式框架，仅乘以系数，改动最小 |
