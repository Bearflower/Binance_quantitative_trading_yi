# 数据后台独立容器实施计划（调度宿主解耦）

## Context（背景）

dashboard 容器的 [main_docker.py](file:///Users/yl/vscode/Binance_quantitative_trading/dashboard/backend/main_docker.py) lifespan 中挂了 4 个数据维护 APScheduler 任务（净资产快照、指标预计算、持仓对账、佣金回填）。dashboard 一旦被撤/改造，这些任务全部停摆，数据连续性受损（用户已确认此隐患，见交接文档 `docs/handoffs/commissions_backfill_2026-09-21.md` 的 B 项）。

**已拍板方案**：新建独立容器 `services/data_backend` 承载 4 个数据任务，dashboard 退化为纯 API 展示；同时提供共享调度工具箱 `shared/scheduler/`，供其他功能复用定时任务。

**附带处理**（用户已拍板）：
- C 项（条件单平仓佣金无法按 order_id 归集）：**暂缓**，仅更新交接文档记录深化思路。
- D 项（单测断言）：**已完成**——[test_commissions.py L116](file:///Users/yl/vscode/Binance_quantitative_trading/tests/test_shared/test_commissions.py#L116) 改为 `Decimal("-0.8")`，`pytest tests/test_shared/test_commissions.py` 11 passed 已验证。

## 关键现状（已探索确认）

- 4 个任务（均在 dashboard/backend/main_docker.py，各自 new 一个 DataService + 独立 AsyncIOScheduler）：
  - `equity_daily_snapshot` → `run_snapshot`，CronTrigger 23:30 Asia/Shanghai
  - `metric_precompute` → `run_precompute`，IntervalTrigger 默认 60s（env `PRECOMPUTE_INTERVAL_SECONDS`）
  - `position_reconcile` → `data_service.compute_and_store_positions`，IntervalTrigger 默认 300s（env `POSITION_RECONCILE_INTERVAL_SECONDS`）
  - `commission_reconcile` → `run_reconcile`，IntervalTrigger 默认 3600s（env `COMMISSION_RECONCILE_INTERVAL_SECONDS`）
  - 均有启动预热（`STARTUP_READY_DELAY_SECONDS` 默认 30s）+ shutdown；参数全部走环境变量。
- job 函数在 `dashboard/backend/services/`：equity_snapshot_job.py / metric_precompute_job.py / commission_reconcile_job.py；持仓对账是 `data_service_docker.py` 的 `DataService.compute_and_store_positions`（L1519-L1678）。
- `DataService`（data_service_docker.py）：`__init__` 无参，`_ensure_initialized()` 从 env 建 `DatabaseManager`（DATABASE_HOST/DB_PORT/DATABASE_NAME/DATABASE_USER/DATABASE_PASSWORD）+ `BinanceClient`（BINANCE_API_KEY/SECRET/USE_UNIFIED_ACCOUNT）+ `TradeLogger`。import 链含 `from core.config import risk_settings`（dashboard/backend/core/config.py，risk.yaml 缺失时降级默认值），`sys.path.insert(0, APP_ROOT or /app)`。
- **dashboard 独立部署**（不走根 docker-compose）：[dashboard/deploy.sh](file:///Users/yl/vscode/Binance_quantitative_trading/dashboard/deploy.sh) 打包整个项目 → 上传 `/root/dashboard` → build → `docker run --name dashboard-api --network trading-network-v2 --env-file .env -e DATABASE_HOST=trading_system-postgres -e DB_HOST=trading_system-postgres -p 8767:8767`。
- 根 requirements.txt 含 `APScheduler==3.10.4`、structlog、asyncpg、pydantic-settings、PyYAML、python-dotenv。dashboard/backend/requirements.txt 另含 fastapi/uvicorn/httpx。
- 已确认 routes_docker.py 全部走 DB 查询（`get_data_service()`），无进程内调度状态依赖 → 删除调度器安全。

## 变更清单

### 1. 新建 `shared/scheduler/`（共享调度工具箱，禁止 import dashboard 包）
- `__init__.py` 提供：
  - `build_scheduler(timezone="Asia/Shanghai")` → AsyncIOScheduler
  - `add_interval_job(scheduler, func, env_key, default, job_id, args=None, misfire_grace=120)`：env 读间隔、`start_date=now + STARTUP_READY_DELAY_SECONDS`、`max_instances=1, coalesce=True`
  - `add_cron_job(scheduler, func, job_id, args=None, env_hour="SNAPSHOT_HOUR", env_minute="SNAPSHOT_MINUTE", default_hour=23, default_minute=30)`：CronTrigger
  - `schedule_startup_run(loop, coro_factory, delay_env="STARTUP_READY_DELAY_SECONDS")`：封装启动预热
  - `shutdown_scheduler(scheduler)`：`if scheduler.running: shutdown(wait=False)` 幂等
- 仅依赖 APScheduler + os + asyncio；job 函数与 DataService 由宿主传入。

### 2. 新建 `services/data_backend/`（独立数据后台容器）
- `Dockerfile`（build context 项目根，仿 dashboard/backend/Dockerfile 精简）：
  - FROM python:3.11-slim；apt 装 gcc/libpq-dev
  - COPY 根 requirements.txt 安装依赖（含 APScheduler）
  - `COPY shared/ ./shared/`、`COPY dashboard/backend/core/ ./dashboard/backend/core/`、`COPY dashboard/backend/config/ ./dashboard/backend/config/`（risk.yaml）、`COPY dashboard/backend/services/ ./dashboard/backend/services/`、`COPY services/data_backend/src/ ./src/`
  - `ENV APP_ROOT=/app`；healthcheck 用 `python -c "import sys; sys.exit(0)"`；`CMD ["python", "src/main.py"]`
- `src/main.py`：
  - 入口 `sys.path.insert(0, os.path.join(APP_ROOT, "dashboard/backend"))`（最前，防与根 services/ namespace 包冲突）
  - 单 `DataService` 实例（4 job 共用连接池）、单 AsyncIOScheduler 注册 4 个 job（equity_daily_snapshot 用 add_cron_job；其余 3 个用 add_interval_job，env 键沿用现状）
  - `schedule_startup_run` 预热 3 个 interval job；`asyncio.run(main())` + finally shutdown；注册 SIGTERM 优雅退出
- `requirements.txt`：复用 dashboard/backend/requirements.txt 依赖（含 apscheduler）
- `.deploy_config`：`DATA_BACKEND_CONTAINER_NAME="data-backend"`、`DATA_BACKEND_IMAGE_NAME="data-backend:latest"`、SERVER_IP/SERVER_USER/SSH_KEY_PATH/DEPLOY_PACKAGE_NAME
- `deploy.sh`（仿 dashboard/deploy.sh 精简）：
  - rsync 仅 `shared/ dashboard/backend/services/ dashboard/backend/core/ dashboard/backend/config/ services/data_backend/ .env` → tar → scp → 解压到 `/root/data_backend`
  - `docker build -t data-backend:latest -f services/data_backend/Dockerfile .`（context=/root/data_backend）
  - `docker run -d --name data-backend --network trading-network-v2 --env-file /root/data_backend/.env -e DATABASE_HOST=trading_system-postgres -e DB_HOST=trading_system-postgres --restart unless-stopped`（无端口映射）

### 3. 改造 `dashboard/backend/main_docker.py`

- 清理失效 import（APScheduler/CronTrigger/IntervalTrigger、3 个 job 函数、无用的 cache_service 等），保留 MockDataService 需要的 datetime/timedelta/timezone。

## 风险点

1. **import 链**：data_service_docker 依赖 `core.config.risk_settings` → 必须复制 core/ + config/risk.yaml（缺失时 config.py 有默认值降级，但保留）
2. **sys.path 顺序**：容器内 PYTHONPATH 含根目录时 `services` 会命中根 namespace 包 → main.py 手动 insert `/app/dashboard/backend` 到最前
3. **双容器并发**：各自 asyncpg 连接池无冲突；写入均 UPSERT 幂等，切换窗口双写无害；新增 Binance API 限频风险（两容器并发拉 income/trades），部署后监控 429 日志
4. **旧调度残留窗口**：data_backend 先启、dashboard 后重建；如需零窗口可先 `docker stop dashboard-api`
5. **risk.yaml 一致性**：data_backend 复制仓库内 risk.yaml，dashboard/deploy.sh 会实时生成——短时可能不一致，属可接受（后续可抽公共生成步骤）
