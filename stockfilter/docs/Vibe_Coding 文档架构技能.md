# Vibe Coding 文档架构技能

## 技能概述

本技能基于 [vibe-coding-cn](https://github.com/tukuaiai/vibe-coding-cn) 项目的文档架构体系，为 stockfilter 项目提供标准化的文档组织、索引管理和知识沉淀能力。

**核心目标**: 构建一个**自我优化**的文档系统，通过规划驱动和模块化设计，让项目文档成为 AI 结对编程的强力上下文。

---

## 🎯 核心理念

### 道（原则）
- **文档即上下文**：文档不是事后补充，而是开发的第一性要素
- **规划驱动**：先结构后代码，规划好框架避免技术债
- **模块化组织**：按职责分类，保持正交性
- **持续进化**：文档随项目迭代而更新

### 法（方法）
- **分类清晰**：需求、设计、方案、报告、部署五类分离
- **索引先行**：每个目录都有 README.md 作为入口
- **命名规范**：使用中文，版本信息用 `Vx.x` 格式
- **链接可追溯**：文档间使用相对链接

### 术（技巧）
- **元文档驱动**：创建通用模板和原则文档
- **可视化表达**：使用 Mermaid 图表展示架构和流程
- **版本控制**：文档更新标注版本号和日期
- **知识复用**：建立可复用的文档模板库

## 🛠️ 文档创建流程

### 步骤 1: 确定文档类型

根据内容选择合适的目录：
- **需求变更** → `requirements/`
- **技术设计** → `designs/`
- **配置方案** → `schemes/`
- **回测/总结** → `reports/`
- **部署/运维** → `deployment/`

### 步骤 2: 创建文档文件

```bash
# 1. 创建文件
touch docs/requirements/新功能需求.md

# 2. 添加标准头部
cat > docs/requirements/新功能需求.md << EOF
# 标题

## 1. 概述

## 2. 详细需求

## 3. 相关资源
EOF

# 3. 更新索引
# 编辑对应目录的 README.md，添加新文档链接
```

### 步骤 3: 更新索引文件

**必须更新**对应目录的 `README.md`:
```markdown
## 文档列表

| 文档名称 | 说明 |
|---------|------|
| [新文档.md](新文档.md) | 说明文字 |
```

### 步骤 4: 更新总索引

**更新** `docs/README.md`:
- 如有新分类，添加分类说明
- 更新"最后更新"日期

### 步骤 5: 更新项目规则

**更新** `.trae/rules/rule.md`:
- 如有新文档类型，更新分类说明
- 保持规则与文档结构一致

## 🔄 文档更新机制

### 更新触发条件

**必须更新文档**的场景:
1. **功能变更**: 新增/修改/删除功能
2. **配置调整**: 参数变更、架构调整
3. **版本迭代**: V2.1 → V2.2
4. **问题修复**: 重大 Bug 修复
5. **性能优化**: 架构优化、性能提升

### 更新流程

```mermaid
graph LR
  A[触发更新] --> B[修改文档内容]
  B --> C[更新版本号]
  C --> D[更新日期]
  D --> E[更新索引 README]
  E --> F[提交 Git]
  F --> G[通知相关人员]
```

### 版本管理

**版本号规则**: `V{主版本}.{次版本}.{修订号}`
- **主版本**: 重大架构变更
- **次版本**: 功能新增/变更
- **修订号**: 小修小补、文档修正

**历史版本处理**:
- 当前版本：直接覆盖
- 重要历史版本：保留并标注"历史版本"
- 过时版本：移动到 `archive/` 目录
