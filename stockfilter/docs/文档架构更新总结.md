## 🎯 核心特性

### 1. Vibe Coding 核心理念

#### 道（原则）
- **文档即上下文**: 文档不是事后补充，而是开发的第一性要素
- **规划驱动**: 先结构后代码，规划好框架避免技术债
- **模块化组织**: 按职责分类，保持正交性
- **持续进化**: 文档随项目迭代而更新

#### 法（方法）
- **分类清晰**: 需求、设计、方案、报告、部署五类分离
- **索引先行**: 每个目录都有 README.md 作为入口
- **命名规范**: 使用中文，版本信息用 `Vx.x` 格式
- **链接可追溯**: 文档间使用相对链接

#### 术（技巧）
- **元文档驱动**: 创建通用模板和原则文档
- **可视化表达**: 使用 Mermaid 图表展示架构和流程
- **版本控制**: 文档更新标注版本号和日期
- **知识复用**: 建立可复用的文档模板库

### 2. 文档质量保障

#### 内容质量
- ✅ 标题清晰，表达文档主题
- ✅ 有版本号和最后更新日期
- ✅ 有相关资源链接
- ✅ 内容准确，与实际代码一致
- ✅ 使用中文，术语统一

#### 结构质量
- ✅ 放置在正确的目录
- ✅ 对应有索引文件（README.md）
- ✅ 使用相对链接
- ✅ 遵循命名规范
- ✅ 有清晰的层级结构

#### 可维护性
- ✅ 标注版本号
- ✅ 标注最后更新日期
- ✅ 有维护者信息
- ✅ 历史版本已归档或标注
- ✅ 文档间链接可追溯

## 🛠️ 使用指南

### 快速开始

1. **查看文档索引**
   ```bash
   # 打开文档总索引
   cat docs/README.md
   ```

2. **查找需求文档**
   ```bash
   # 打开需求文档索引
   cat docs/requirements/README.md
   # 查看完整需求
   cat docs/requirements/项目需求与迭代.md
   ```

3. **查看技术架构**
   ```bash
   # 打开设计文档索引
   cat docs/designs/README.md
   # 查看技术架构
   cat docs/designs/技术架构文档_V2.1.md
   ```

### 创建新文档

1. **确定文档类型**
   - 需求变更 → `requirements/`
   - 技术设计 → `designs/`
   - 配置方案 → `schemes/`
   - 回测/总结 → `reports/`
   - 部署/运维 → `deployment/`

2. **创建文档文件**
   ```bash
   # 创建文件
   touch docs/requirements/新功能需求.md
   
   # 添加标准头部
   cat > docs/requirements/新功能需求.md << EOF
   # 标题
   
   ## 1. 概述
   
   ## 2. 详细需求
   
   ## 3. 相关资源
   EOF
   ```

3. **更新索引**
   - 更新对应目录的 `README.md`
   - 更新 `docs/README.md`
   - 提交 Git

### 更新现有文档

1. **修改文档内容**
2. **更新版本号**（V1.0 → V1.1）
3. **更新日期**
4. **更新索引文件**
5. **提交 Git**
