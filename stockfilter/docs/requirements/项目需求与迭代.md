# 股票形态筛选系统 - 项目需求与迭代

## 1. 项目概述

### 1.1 项目定位
基于"大跌企稳、缩量见底、放量启动、回踩确认"形态的自动化股票筛选系统，通过技术形态识别 + 量化回测 + 自动化推送，为投资者提供交易决策支持。

### 1.2 核心价值
- **自动化**: 每日收盘后自动扫描全市场股票，无需人工盯盘
- **量化验证**: 基于 7 年历史数据回测，策略有效性经过验证
- **实时推送**: T+1 日开盘前自动推送到飞书，不错过交易机会
- **风险控制**: 内置止损止盈规则，严格执行交易纪律

### 1.3 目标用户
- 个人投资者（希望借助量化策略辅助决策）
- 股票交易者（关注技术形态和量价关系）
- 量化爱好者（希望实现自动化交易策略）

## 2. 核心业务需求

### 2.1 形态检测需求

#### 2.1.1 四步检测流程

**步骤 1: 大跌后支撑**
- **需求**: 识别经历明显下跌的股票
- **规则**: 20-30 交易日内累计跌幅 > 12%
- **目的**: 确保股票经历了一波明显的下跌，存在超跌反弹可能
- **V2.1 优化**: 从 20% 放宽到 12%，增加信号数量

**步骤 2: 缩量见底**
- **需求**: 识别卖压衰竭的底部信号
- **规则**: 成交量低于过去 20 日均量的 50%-60%
- **位置要求**: 缩量必须发生在放量日前 10 天内
- **目的**: 确认卖压衰竭，底部形成

**步骤 3: 放量大涨**
- **需求**: 识别资金入场信号
- **涨幅条件**: 当日涨幅 ≥ 5%（V2.1 放宽，原 7%）
- **放量条件**: 成交量放大至过去 20 日均量的 1.5 倍以上
- **量比要求**: 当日量比介于 1.5~12 倍之间（V2.1 放宽，原 2-8 倍）
- **V2.1 优化**: 取消缩量走平 2 天要求，改为启动后观察

**步骤 4: 回踩确认**
- **需求**: 确认支撑有效，提供买入时机
- **回踩幅度**: 从放量阳线收盘价回落，不超过阳线实体的一半
- **回踩缩量**: 回调时成交量萎缩
- **支撑确认**: 回踩低点不低于支撑位
- **V2.1 新增**: 启动后 5 天内最低价格不低于启动价的 97%

#### 2.1.2 辅助过滤规则

**股票池过滤（V2.1 新增）**
- 剔除 ST 股票（避免风险警示股票）
- 剔除北交所股票（代码 8 开头）
- 剔除退市股票（名称含"退"字）
- 剔除科创板股票（代码 688 开头）
- 剔除创业板股票（代码 300 或 301 开头）
- **过滤效果**: 从 5,505 只过滤到 3,026 只（深市主板 1,375 只 + 沪市主板 1,651 只）

**流动性过滤（V2.1 新增）**
- **要求**: 近 20 日日均成交额 ≥ 3000 万
- **目的**: 确保实盘可买入，避免流动性风险
- **计算方式**: 使用 amount 列（成交额），或 volume × close 估算

**高开过滤（V2.1 优化）**
- 涨停开盘：直接跳过
- 高开>5%：跳过，避免追高
- 高开 3%-5%：允许买入，但买入价加 1% 滑点

**大盘过滤（V2.1 已移除）**
- **原规则**: 指数<20 日均线时禁止买入
- **移除原因**: 验证发现所有信号都出现在指数≥MA20 时
- **结论**: 形态本身具有顺势特性，无需额外大盘过滤

## 3. 功能需求

### 3.1 自动化扫描

**功能描述**: 每日收盘后自动扫描全市场股票

**需求细节**:
- 扫描时间：每个交易日 15:30
- 扫描范围：过滤后的股票池（约 3,026 只）
- 数据来源：本地数据库（PostgreSQL）
- 输出结果：JSON 格式信号文件

**验收标准**:
- 扫描完成时间不超过 5 分钟
- 信号文件格式正确
- 日志记录完整

### 3.2 飞书推送

**功能描述**: T+1 日开盘前自动推送到飞书

**需求细节**:
- 推送时间：每个交易日 08:00
- 推送内容：股票名称、代码、支撑位、止损价、建议买入价
- 推送格式：飞书卡片消息
- 推送目标：飞书群机器人

**验收标准**:
- 推送准时发送
- 消息格式美观
- 信息准确无误

### 3.3 数据同步

**功能描述**: 每日自动同步最新 K 线数据

**需求细节**:
- 数据源：AKShare（主）、AData（备）、Baostock（备）
- 同步频率：每日收盘后
- 数据存储：PostgreSQL + CSV 备份
- 监控机制：sync_monitor.py 监控进度

**验收标准**:
- 数据完整性：无缺失交易日
- 数据准确性：与数据源一致
- 同步及时性：当日数据当日完成

### 3.4 回测验证

**功能描述**: 基于历史数据验证策略有效性

**需求细节**:
- 回测周期：2019-2026 年（7 年历史数据）
- 回测样本：沪深两市主板股票（3,026 只）
- 回测指标：胜率、平均收益、最大收益、信号数量
- 交易成本：扣除佣金、印花税、滑点（总计 0.35%）

**验收标准**:
- 回测结果可复现
- 指标计算准确
- 报告格式清晰

## 4. 版本迭代记录

### V2.1（当前版本）- 2026-04

#### 4.1 迭代背景

**V2.0 存在的问题**:
1. **信号过少**: 严格参数导致年均信号不足，实盘可操作性低
2. **遗漏形态**: 只检测每只股票的第一个形态，遗漏后续相同形态
3. **流动性风险**: 未过滤低成交额股票，实盘可能无法买入
4. **过度过滤**: 大盘过滤规则经验证无效，增加复杂度

#### 4.2 核心优化

**方案 A: 放宽参数**
- 跌幅阈值：20% → 12%
- 放量涨幅：7% → 5%
- 量比范围：2-8 倍 → 1.5-12 倍
- **效果**: 信号数量增加约 520%

**方案 B: 取消缩量走平**
- 原规则：要求缩量走平 2 天
- 新规则：改为启动后观察 5 天，最低不低于启动价 97%
- **效果**: 简化检测流程，提高信号质量

**新增功能**:
- ✅ 流动性过滤：日均成交额≥3000 万
- ✅ 股票池过滤：自动剔除科创板/创业板
- ✅ 高开过滤：涨停/高开>5% 跳过
- ✅ 全形态检测：检测所有形态，不只第一个

**移除功能**:
- ❌ 大盘过滤：验证发现形态本身具有顺势特性

#### 4.3 回测对比（2020-2025 年）

| 指标 | V2.0 | V2.1 | 改进 |
|------|------|------|------|
| 总信号数 | - | 28 个 | 年均 5.6 个 |
| 平均收益 | - | 3.28% | 已扣除交易成本 |
| 胜率 | - | 67.9% | 19 个盈利 / 28 个 |
| 信号间隔控制 | ❌ | ✅ | 至少 60 个交易日 |
| 年度限制 | ❌ | ✅ | 每只股票每年最多 2 个 |

#### 4.4 重要修复

**问题**: 实盘代码只检测每只股票的第一个形态，遗漏后续相同形态

**影响**:
- 回测显示某只股票有 2 个形态（如 000728 在 2 月和 4 月），但实盘只会通知第 1 次
- 遗漏率高达 50%（以 000728 为例）

**修复**:
- 修改 `daily_scan.py` 使用 `check_all_patterns()` 代替 `check_pattern_single()`
- 检测所有形态，不只第一个
- 同一只股票在不同时间出现形态，每次都会发出通知
- 每个股票每天最多发一个信号（避免重复）

**验证结果**:
- 000728 测试：旧逻辑只检测 2019-02-14，新逻辑能检测 2019-02-14 和 2019-04-01
- 实盘系统现在与回测系统一致，不会遗漏任何交易机会
