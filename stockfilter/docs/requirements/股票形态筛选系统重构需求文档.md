## 1. 产品概述

### 1.1 项目背景

股票形态筛选系统是一个基于"大跌企稳、缩量见底、放量启动、回踩确认"形态的自动化股票筛选系统。项目经历了多个版本的迭代(V2.1, V2.2, V2.3, V2.4, V2.5),当前版本为V2.4(最终版)。

随着版本的不断迭代,项目积累了大量的历史代码、配置文件和文档,导致项目结构臃肿、维护困难。为了提高项目的可维护性和开发效率,需要对项目进行系统性重构。

### 1.2 当前问题分析

#### 1.2.1 代码冗余问题

**问题描述**:
- 项目中存在7个回测器类文件,每个版本一个文件
- 存在19个回测脚本文件,功能高度重复
- 不同版本的回测器之间存在大量重复代码(估计重复率>70%)

**具体文件清单**:

**回测器类文件(7个)**:
1. `backtester_v22.py` - V2.2版本回测器
2. `backtester_v23.py` - V2.3版本回测器
3. `backtester_v24.py` - V2.4版本回测器(当前使用)
4. `backtester_v25.py` - V2.5版本回测器(对比测试)
5. `backtester_v25_relaxed.py` - V2.5放宽版回测器
6. `backtester_scheme_ab.py` - 方案AB回测器
7. `backtester_with_rules.py` - 带规则的回测器

**回测脚本文件(19个)**:
1. `backtest_v21.py`
2. `backtest_v21_final.py`
3. `backtest_v21_full.py`
4. `backtest_v21_final_report.py`
5. `backtest_v22.py`
6. `backtest_v22_relaxed.py`
7. `backtest_v23.py`
8. `backtest_v24_full.py`
9. `backtest_v25_full.py`
10. `backtest_603529_v24_vs_v25.py`
11. `backtest_baostock_full.py`
12. `compare_v21_v22.py`
13. `compare_v24_v25.py`
14. `compare_v24_v25_results.py`
15. `comprehensive_analysis_v24_v25.py`
16. `analyze_v22.py`
17. `analyze_v24_results.py`
18. `analyze_main_board_klines.py`
19. `trading/backtest.py`

**影响**:
- 代码维护成本高,修改一处需要同步多个文件
- 新人理解困难,不知道应该使用哪个版本
- 测试覆盖困难,需要为多个版本编写测试
- Git仓库体积大,历史记录混乱

#### 1.2.2 配置文件混乱问题

**问题描述**:
- 项目中存在3个配置文件,不清楚哪个是当前使用的
- 配置文件命名不规范,无法直观识别版本关系

**具体文件清单**:
1. `config_v21_final.yaml` - V2.1最终配置
2. `config_v22_relaxed.yaml` - V2.2放宽配置
3. `config_v24_final.yaml` - V2.4最终配置(当前使用)

**影响**:
- 配置管理混乱,容易使用错误的配置
- 无法快速定位当前使用的配置
- 配置参数分散,难以统一管理

#### 1.2.3 文档混乱问题

**问题描述**:
- docs目录下存在大量报告和方案文档
- 多个版本的文档混杂,存在重复和过时内容
- 文档索引不清晰,难以快速找到需要的信息

**具体问题**:
1. **报告类文档重复**: V2.1和V2.4的报告同时存在
2. **方案类文档重复**: V2.0, V2.1, V2.4的方案文档同时存在
3. **临时文档未清理**: 根目录下存在`V21_回测数据说明.md`等临时文档

**影响**:
- 文档查找困难,效率低下
- 容易参考过时的文档
- 文档维护成本高

#### 1.2.4 分析脚本杂乱问题

**问题描述**:
- 根目录下存在大量临时分析脚本
- 这些脚本可能是调试时创建的,没有及时清理
- 脚本命名不规范,功能不清晰

**具体文件清单**:
1. `check_603529_detailed.py`
2. `check_603529_pattern.py`
3. `check_603529_v22.py`
4. `check_603529_v24_final.py`
5. `check_603529_v24_with_server.py`
6. `check_db_klines.py`
7. `check_db_stats.py`
8. `check_kline_data.py`
9. `check_sync_status.py`
10. `check_today.py`
11. `clear_klines.py`

**影响**:
- 项目结构混乱,难以区分核心代码和临时脚本
- 容易误运行临时脚本
- 影响项目专业性和可维护性

### 1.3 重构目标

#### 1.3.1 核心目标

1. **代码精简**: 将多版本代码统一为单一版本,消除冗余
2. **结构清晰**: 建立清晰的项目结构,职责分明
3. **文档规范**: 整理文档,建立清晰的文档索引和版本管理
4. **配置统一**: 统一配置文件管理,避免配置混乱
5. **可维护性**: 提高项目的长期可维护性

#### 1.3.2 非目标

1. **不改变业务逻辑**: 重构不改变现有的业务功能和检测逻辑
2. **不优化性能**: 本次重构不涉及性能优化
3. **不增加新功能**: 本次重构不增加新的业务功能

## 3. 功能需求

### 3.1 代码重构需求

#### 3.1.1 回测器统一

**需求描述**:
将7个回测器类文件统一为1个核心回测器类,支持通过配置切换不同版本的参数。

**功能规格**:

1. **创建统一回测器类**
   - 文件名: `backtester.py`
   - 支持通过配置文件加载不同版本的参数
   - 保留V2.4的所有功能作为默认配置
   - 支持版本参数配置,可以快速切换到历史版本的参数

2. **参数配置化**
   - 将硬编码的版本参数提取到配置文件
   - 配置文件格式:
     ```yaml
     backtester:
       version: "v24"  # 当前使用的版本
       versions:
         v22:
           drop_threshold: 0.12
           surge_price_ratio: 0.05
           # ... 其他参数
         v24:
           drop_threshold: 0.08
           surge_price_ratio: 0.03
           # ... 其他参数
     ```

3. **历史版本归档**
   - 创建 `archived/` 目录
   - 将历史版本的回测器移动到归档目录
   - 在归档目录中添加 `README.md` 说明文件

**验收标准**:
- [ ] 只保留一个核心回测器类文件 `backtester.py`
- [ ] 历史版本回测器已归档到 `archived/` 目录
- [ ] 支持通过配置切换版本参数
- [ ] 所有现有测试通过
- [ ] 代码覆盖率不低于当前水平

#### 3.1.2 回测脚本整理

**需求描述**:
将19个回测脚本整理为几个核心脚本,删除临时和重复的脚本。

**功能规格**:

1. **保留的核心脚本**:
   - `backtest_full.py` - 全量回测脚本(整合所有全量回测功能)
   - `backtest_single.py` - 单只股票回测脚本
   - `backtest_compare.py` - 版本对比回测脚本

2. **删除的脚本**:
   - 所有临时分析脚本(`check_*.py`, `analyze_*.py`)
   - 所有版本特定的回测脚本(`backtest_v21*.py`, `backtest_v22*.py`等)
   - 所有对比脚本(`compare_*.py`, `comprehensive_analysis_*.py`)

3. **脚本功能说明**:
   - 每个保留的脚本必须有清晰的功能说明和使用文档
   - 脚本支持命令行参数,可以指定回测版本、时间范围等

**验收标准**:
- [ ] 只保留3个核心回测脚本
- [ ] 所有临时脚本已删除
- [ ] 保留的脚本功能完整,文档清晰
- [ ] 可以通过参数指定不同版本的回测

#### 3.1.3 分析脚本清理

**需求描述**:
清理根目录下的临时分析脚本,将有用的分析功能整合到统一的分析模块中。

**功能规格**:

1. **创建分析模块**:
   - 目录: `analysis/`
   - 包含常用的分析工具函数

2. **整合的分析功能**:
   - 数据库检查功能(`check_db_*.py`)
   - K线数据检查功能(`check_kline_*.py`)
   - 同步状态检查功能(`check_sync_status.py`)

3. **删除的脚本**:
   - 所有临时检查脚本(`check_*.py`)
   - 所有临时分析脚本(`analyze_*.py`)

**验收标准**:
- [ ] 创建统一的分析模块
- [ ] 临时分析脚本已删除
- [ ] 分析功能可通过模块导入使用

### 3.2 配置文件统一需求

#### 3.2.1 配置文件整合

**需求描述**:
将3个配置文件整合为1个主配置文件,支持版本切换。

**功能规格**:

1. **主配置文件**:
   - 文件名: `config.yaml`
   - 包含当前版本(V2.4)的所有配置
   - 支持通过配置项切换版本

2. **配置文件结构**:
   ```yaml
   # 当前使用的版本
   current_version: "v24"

   # 版本配置
   versions:
     v21:
       pattern:
         drop_threshold: 0.12
         # ... 其他参数
     v24:
       pattern:
         drop_threshold: 0.08
         # ... 其他参数

   # 当前版本配置(根据current_version自动加载)
   pattern:
     drop_threshold: 0.08
     # ... 其他参数
   ```

3. **历史配置归档**:
   - 创建 `archived/configs/` 目录
   - 将历史配置文件移动到归档目录

**验收标准**:
- [ ] 只保留一个主配置文件 `config.yaml`
- [ ] 历史配置文件已归档
- [ ] 支持通过配置切换版本
- [ ] 所有现有功能正常运行

#### 6.2.1 风险识别

| 风险项 | 风险等级 | 影响范围 | 应对措施 |
|--------|----------|----------|----------|
| 重构破坏现有功能 | 高 | 全局 | 充分测试,保留回滚能力 |
| 配置迁移失败 | 中 | 配置管理 | 保留原配置,逐步迁移 |

| 团队适应困难 | 中 | 团队协作 | 提供培训,编写迁移指南 |

#### 6.2.2 回滚计划

**回滚触发条件**:
- 核心功能无法正常运行
- 测试用例失败率超过20%
- 性能下降超过30%

**回滚步骤**:
1. 停止重构分支的合并
2. 恢复到重构前的代码版本
3. 分析失败原因
4. 修复问题后重新开始重构
