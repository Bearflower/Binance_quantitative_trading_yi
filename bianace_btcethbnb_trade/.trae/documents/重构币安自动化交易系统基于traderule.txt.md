# 重构币安自动化交易系统基于 traderule.txt 的计划

## 1. 项目概述

### 1.1 目标
基于 `config/traderule.txt` 文档中的系统化操作规范，重构现有的币安自动化交易系统，实现更纯粹、更自动化的交易决策和执行。

### 1.2 范围
- **核心功能**：基于技术指标的自动信号检测和交易执行
- **数据源**：币安 API 实时行情数据
- **交易标的**：BTC/USDT、ETH/USDT、BNB/USDT
- **账户类型**：500U 阶段一全仓模式
- **调度频率**：每小时分析一次，实时信号检测

### 1.3 约束
- 保持现有 PostgreSQL 数据库结构，确保数据兼容性
- 保留飞书通知功能
- 兼容现有币安 API 封装
- 支持 DeepSeek AI 作为第二意见参考（可选）

## 2. 现状分析

### 2.1 当前系统架构
- **调度器** (`scheduler.py`)：每 6 小时调用 DeepSeek AI 分析
- **自动交易执行器** (`auto_executor.py`)：解析 AI 报告并执行交易
- **持仓监控器** (`position_monitor.py`)：每 15 分钟监控持仓风险
- **平仓检测器** (`close_detector.py`)：检测平仓并记录盈亏
- **交易统计** (`trade_statistics.py`)：计算胜率、盈亏比等
- **周报生成器** (`weekly_report.py`)：生成周报并推送

### 2.2 traderule.txt 文档分析
1. **第一章（核心交易原则）**：500U 阶段一固定参数（总资金 500U，单笔风险 10U，最大持仓 2 个等）
2. **第二章（交易标的与禁止情形）**：固定标的（BTC/ETH/BNB）和禁止情形检查
3. **第三章（多时间框架入场系统）**：技术信号检测规则（可程序化实现）
4. **第四章（仓位管理）**：仓位计算公式（可程序化实现）
5. **第五章（风险管理强化）**：止盈止损计算规则（可程序化实现）
6. **第六章（自动化交易执行流程）**：订单参数计算模板（可程序化实现）
7. **第七章（特殊情况应急处理）**：应急处理规则
8. **第八章（心理与资金管理）**：指导性内容，不需要程序化
9. **第九章（历史交易回顾与策略优化）**：报告生成和策略优化提醒
10. **第十章（系统优化与绩效评估）**：绩效评估标准

### 2.3 关键发现
1. **第三、四、五章节**包含明确的规则和公式，完全可以程序化实现
2. **第六章**提供了详细的订单参数计算模板
3. **第九、十章节**的报告功能部分已实现，需要优化整合
4. **AI 分析可以保留**，但作为第二意见而非主要决策依据

## 3. 新系统架构设计

### 3.1 模块划分
```
新交易系统/
├── config/
│   ├── settings.py              # 系统配置
│   ├── traderule.txt           # 交易规则文档
│   └── strategy_params.py      # 可调整的策略参数（第三章核心）
├── core/
│   ├── data_fetcher.py         # 行情数据获取（每小时）
│   ├── signal_detector.py      # 信号检测（基于第三、四章）
│   ├── position_calculator.py  # 仓位计算（基于第四章）
│   ├── risk_manager.py         # 风险管理（基于第五章）
│   └── order_generator.py      # 订单生成（基于第六章）
├── execution/
│   ├── trade_executor.py       # 交易执行
│   ├── position_monitor.py     # 持仓监控（优化现有）
│   └── emergency_handler.py    # 应急处理（基于第七章）
├── reporting/
│   ├── trade_recorder.py       # 交易记录（9.1 - 优化现有）
│   ├── performance_reporter.py # 绩效报告（9.2 + 10.2）
│   ├── strategy_reminder.py    # 策略优化提醒（9.3）
│   └── weekly_report.py        # 周报生成（优化现有）
├── ai_advisory/
│   └── deepseek_advisor.py     # DeepSeek 第二意见（可选）
├── backtesting/
│   └── strategy_backtester.py  # 回测工具
└── scheduler.py                # 主调度器（每小时执行）
```

### 3.2 核心模块说明

#### 3.2.1 `strategy_params.py`（可调整参数模块）
- **目的**：将 traderule.txt 第三、四、五章中可能变化的参数集中管理
- **内容**：
  - 信号等级阈值（S/A 级的条件）
  - 仓位计算公式参数
  - 止盈止损倍数
  - 风险控制参数
- **特点**：支持热加载，无需重启系统即可调整

#### 3.2.2 `signal_detector.py`（信号检测模块）
- **实现第三章规则**：
  - 趋势过滤器（日线 EMA21 方向判断）
  - 入场信号等级判定（S/A 级技术形态识别）
  - 禁止入场条件检查
- **输出**：符合 JSON 示例格式的交易信号

#### 3.2.3 `position_calculator.py`（仓位计算模块）
- **实现第四章公式**：
  ```
  名义价值 = 风险金额 / 止损百分比
  合约数量 = 名义价值 / 开仓价格
  保证金 = 名义价值 / 杠杆
  ```

#### 3.2.4 `order_generator.py`（订单生成模块）
- **实现第六章模板**：
  - 止损价计算：`P × (1 ± S/100)`
  - 止盈价计算：`TP1 = P ± 1.5 × R`, `TP2 = P ± 2.5 × R`
  - 订单参数封装

### 3.3 数据流设计
```
每小时调度
    ↓
data_fetcher.py 获取行情数据
    ↓
signal_detector.py 检测交易信号
    ↓
position_calculator.py 计算仓位参数
    ↓
risk_manager.py 风险检查（禁止情形）
    ↓
order_generator.py 生成订单参数
    ↓
trade_executor.py 执行交易
    ↓
trade_recorder.py 记录交易
    ↓
（可选）deepseek_advisor.py 获取第二意见
```

## 5. 关键决策点

### 5.1 第三、四、五章节的灵活性设计
- **问题**：这些章节的策略可能根据交易结果变化
- **方案**：创建 `strategy_params.py` 模块，将所有可调参数集中管理
- **实现**：支持 JSON/YAML 配置文件，支持热加载

### 5.2 AI 分析的集成方式
- **方案 1**：并行执行，系统决策为主，AI 意见为辅
- **方案 2**：条件触发，只在系统不确定时调用 AI
- **方案 3**：定期对比，每小时对比系统决策和 AI 建议
- **推荐**：方案 1 + 方案 3，系统自动执行，AI 提供对比报告

### 5.3 回测工具的设计
- **范围**：支持第三、四、五章节策略的回测
- **指标**：基于 10.2 绩效评估标准（胜率>45%，盈亏比>1.8等）
- **输出**：策略有效性报告，参数优化建议

### 5.4 报告系统的整合
- **9.1 交易记录**：已实现，需要验证完整性
- **9.2 定期复盘**：与 10.2 绩效评估合并
- **9.3 策略优化提醒**：新增功能，提醒用户调整参数
- **输出格式**：统一的飞书消息，包含所有关键指标

## 6. 风险与缓解

### 6.1 技术风险
- **风险**：技术指标计算错误导致错误信号
- **缓解**：使用币安官方 API 数据，实现单元测试，添加数据验证

### 6.2 策略风险
- **风险**：程序化策略在特殊行情下失效
- **缓解**：保留 AI 第二意见，实现应急处理机制，设置最大亏损限制

### 6.3 执行风险
- **风险**：API 调用失败导致订单执行问题
- **缓解**：优化重试机制，添加订单状态验证，实现补偿交易

### 6.4 数据风险
- **风险**：数据库故障导致交易记录丢失
- **缓解**：实现数据备份机制，添加事务回滚，定期数据校验
