**功能**:

- 调用币安 API 获取当前持仓风险
- 检测持仓是否已平仓（当前持仓 < 开仓持仓）
- 如果已平仓，计算盈亏（PNL）
- 调用 `_update_trade_statistics()` 更新胜率统计
- 更新交易记录状态为 `'CLOSED'`

**代码逻辑**:
```python
def _check_closed_positions_and_update_stats(self):
    """检查已平仓订单并更新胜率统计"""
    # 1. 查询未平仓记录
    open_positions = db.query("SELECT * FROM trade_records WHERE status = 'OPEN'")
    
    # 2. 对每个持仓检查是否已平仓
    for position in open_positions:
        current_qty = get_position_risk(position['symbol'])
        
        # 3. 如果当前持仓 < 开仓持仓，说明已平仓
        if current_qty < position['position_qty']:
            # 4. 计算盈亏
            pnl = calculate_pnl(current_qty, entry_price, close_price, direction)
            
            # 5. 更新胜率统计
            _update_trade_statistics(symbol, pnl, trade_date)
            
            # 6. 更新交易记录状态
            db.execute("UPDATE trade_records SET status = 'CLOSED' WHERE id = ?", position['id'])
```

## 四、注意事项

### 4.1 盈亏计算方式

**简化处理**: 使用当前价格估算平仓价格

**原因**: 
- 币安条件单（止损止盈）触发后自动平仓
- 代码不直接接收平仓回调通知
- 使用当前价格作为近似值

**影响**:
- ✅ 对于止损单：价格基本准确（触发价≈平仓价）
- ✅ 对于止盈单：价格基本准确（触发价≈平仓价）
- ⚠️ 对于限期平仓：可能存在小幅偏差

**改进方案**（可选）:
- 查询币安订单历史获取精确平仓价格
- 监听账户余额变化推算盈亏
- 使用币安账户成交记录 API

### 4.2 检查频率

**当前频率**: 每小时一次

**优点**:
- ✅ 资源消耗少
- ✅ 对 API 压力小
- ✅ 满足日常统计需求

**缺点**:
- ⚠️ 平仓后最多延迟 1 小时更新统计
- ⚠️ 交易日报可能不包含最新平仓（如果在 9 点前刚平仓）

**改进方案**（可选）:
- 增加检查频率（如每 15 分钟）
- 在开仓后 N 小时主动检查
- 添加手动触发检查的接口

### 4.3 边界情况

**已处理**:
- ✅ 无未平仓记录：直接返回，不报错
- ✅ 查询持仓失败：记录错误，继续检查其他持仓
- ✅ 盈亏为 0：计入亏损（`is_win = pnl > 0`）

**未处理**（可选）:
- 部分平仓（当前持仓 < 开仓持仓但 > 0）
  - 当前逻辑：按全部平仓处理
  - 改进方案：按平仓比例计算盈亏
