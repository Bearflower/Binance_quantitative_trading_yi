## 🔍 错误详细分析

### 1. Margin is insufficient (保证金不足) ⚠️ 严重

**错误代码**: -2019  
**出现次数**: ~52 次  
**严重程度**: 🔴 高 - 导致交易无法执行

#### 错误表现
```
2026-04-20 06:00:06,929 - scheduler_new - ERROR - ❌ 交易执行失败：BNBUSDT - Binance API Error -2019: Margin is insufficient.
```

#### 错误上下文
- **交易对**: BNBUSDT
- **交易方向**: BUY (做多)
- **订单类型**: MARKET (市价单)
- **数量**: 0.17 BNB
- **杠杆**: 5x

#### 根本原因
1. **账户可用余额不足**: 当前账户余额可能低于开仓所需的保证金
2. **已有持仓占用保证金**: 可能存在未平仓的持仓占用了大量保证金
3. **动态仓位调整未生效**: v6.13 的动态仓位调整机制可能未能正确降低仓位

#### 影响
- 交易信号产生后无法执行
- 错过交易机会
- 策略收益率下降

---

### 2. Too many new orders (订单过多) ⚠️ 中等

**错误代码**: -1015  
**出现次数**: ~4 次  
**严重程度**: 🟡 中 - 止盈止损设置失败

#### 错误表现
```
2026-04-20 08:00:10,298 - scheduler_new - ERROR - ❌ 交易执行失败：BNBUSDT - Binance API Error -1015: Too many new orders.
```

#### 错误上下文
- **交易对**: BNBUSDT
- **操作**: 设置止损/止盈条件单
- **订单类型**: STOP_MARKET / TAKE_PROFIT_MARKET (PM 条件单)
- **触发场景**: 开仓成功后立即设置止损止盈

#### 根本原因
1. **币安订单数量限制**: 币安对 PM 账户的条件单数量有限制（通常最多 10 个未执行订单）
2. **历史订单未清理**: 可能存在大量已触发但未清理的条件单
3. **重复下单**: 代码可能在短时间内重复提交条件单

#### 影响
- 止损止盈设置失败
- 持仓暴露在无保护风险中
- 可能导致更大亏损

## 🔧 需要整改的问题

### 问题 1: 保证金不足 - 需要优化仓位管理 🔴

**整改措施**:

1. **检查当前持仓和余额**
   ```bash
   # 在服务器上执行
   docker exec binance-trade-analyzer python -c "
   from utils.binance_trade_api import BinanceTradeAPI
   api = BinanceTradeAPI()
   account = api.get_account()
   print(f'可用余额：{account[\"availableBalance\"]} USDT')
   print(f'总余额：{account[\"totalWalletBalance\"]} USDT')
   print(f'未实现盈亏：{account[\"crossWalletBalance\"]} USDT')
   for pos in account['positions']:
       if float(pos['positionAmt']) != 0:
           print(f\"持仓：{pos['symbol']} = {pos['positionAmt']} (入场价：{pos['entryPrice']})\")
   "
   ```

2. **检查动态仓位调整器是否正常工作**
   - 查看 `services/position_adjuster.py` 日志
   - 确认调整逻辑是否正确执行
   - 验证 80% 安全垫是否生效

3. **优化建议**:
   - ✅ **降低最小保证金阈值**: 从 5U 降至 3U (如果账户资金紧张)
   - ✅ **调整安全垫比例**: 从 80% 降至 70% (更激进)
   - ✅ **增加账户资金**: 如果账户余额 < 200U，建议充值到 500U+
   - ✅ **清理亏损持仓**: 如果有亏损持仓，考虑手动平仓释放保证金

### 问题 2: 订单过多 - 需要清理条件单 🟡

**整改措施**:

1. **查看当前未执行的条件单**
   ```bash
   # 在服务器上执行
   docker exec binance-trade-analyzer python -c "
   from utils.binance_trade_api import BinanceTradeAPI
   api = BinanceTradeAPI()
   # 获取所有未执行的条件单
   open_orders = api.get_open_conditional_orders()
   print(f'未执行条件单数量：{len(open_orders)}')
   for order in open_orders:
       print(f\"{order['symbol']} - {order['side']} - {order['strategyType']} - 触发价：{order['stopPrice']}\")
   "
   ```

2. **清理已触发但未清理的条件单**
   ```bash
   # 在服务器上执行
   docker exec binance-trade-analyzer python -c "
   from utils.binance_trade_api import BinanceTradeAPI
   api = BinanceTradeAPI()
   # 取消所有未执行的条件单
   open_orders = api.get_open_conditional_orders()
   for order in open_orders:
       api.cancel_conditional_order(order['symbol'], order['orderId'])
       print(f\"已取消：{order['symbol']} - {order['orderId']}\")
   print(f'共取消 {len(open_orders)} 个条件单')
   "
   ```

3. **代码层面优化**:
   - ✅ **添加订单数量检查**: 在设置条件单前检查当前订单数量
   - ✅ **添加重试机制**: 订单过多时等待 5 秒后重试
   - ✅ **优化条件单管理**: 开仓前取消旧的无关条件单
   - ✅ **添加订单数量监控**: 当订单数 > 8 时发出警告

   ```python
       # 取消最早的订单
       self.trade_api.cancel_oldest_conditional_order()
   ```

3. **添加重试机制**:
   ```python
   @retry(stop=stop_after_attempt(3), wait=wait_fixed(5))
   def place_conditional_order_with_retry(params):

       except BinanceAPIError as e:

           raise
   ```
