## 📋 执行摘要

经过详细对比分析,发现**止盈止损的实现代码与业务规则存在多处严重不一致**,主要集中在:

1. **止损倍数错误**: 代码使用 2.0×ATR,业务规则要求 1.5×ATR
2. **止盈倍数混乱**: 不同模块使用不同参数
3. **吊灯止损不完整**: 缺少启动阈值检查
4. **版本管理混乱**: 代码未明确区分 V6.12/V6.13/V6.13.1

**风险等级**: 🔴 **高** - 可能导致实际交易风险控制失效

## 4. 根本原因分析

### 4.1 配置管理混乱

**问题**:
1. `risk_manager.py` 硬编码参数,未从配置文件读取
2. `order_generator.py` 从配置文件读取,但默认值错误
3. 两个模块使用不同的参数来源,导致不一致

**示例**:
```python
# risk_manager.py (硬编码)
tp1_mult = Decimal('2.5')  # 硬编码

# order_generator.py (从配置读取)
tp1_mult = tp_config.get('tp1_multiplier', Decimal('1.5'))  # 默认值错误
```

### 4.2 版本管理缺失

**问题**:
1. 代码未区分 V6.12/V6.13/V6.13.1
2. 无法动态切换策略版本
3. 参数更新后,旧版本参数丢失

**影响**:
- 无法回滚到旧版本策略
- 无法对比不同版本的回测效果
- 部署后难以验证参数是否正确

### 4.3 吊灯止损实现不完整

**问题**:
1. 只实现了回撤阈值检查,未实现启动阈值检查
2. 未维护"吊灯止损已启动"状态
3. 未记录持仓期间最高价/最低价

**业务规则**:
```
吊灯止损是一个两阶段机制:
阶段 1: 价格突破启动阈值 (1.8×ATR) → 启动吊灯止损
阶段 2: 价格回撤触发阈值 (1.2×ATR) → 执行平仓
```

**代码现状**:
```python
# 只实现了阶段 2
if drawdown >= drawdown_threshold:
    return True  # 直接触发,未检查是否已启动
```

### 4.4 参数命名不统一

**问题**:
- `risk_manager.py` 使用 `atr14` 参数
- `order_generator.py` 使用 `r_value` 参数
- 两者含义相同,但命名不同,容易混淆

```python
def check_chandelier_stop_activation(
    self,
    current_price: Decimal,
    entry_price: Decimal,
    atr14: Decimal,
    direction: int
) -> bool:
    """
    检查是否达到吊灯止损启动条件
    
    V6.13.1: 价格突破 1.8×ATR 后启动
    V6.12/V6.13: 价格突破 2.5×ATR 后启动
    
    Args:
        current_price: 当前价格
        entry_price: 开仓价
        atr14: ATR14 值
        direction: 方向 (1=多, -1=空)
    
    Returns:
        True 表示已启动吊灯止损
    """
    # V6.13.1: 1.8×ATR 启动阈值
    activation_threshold = atr14 * Decimal('1.8')
    
    if direction == 1:  # 多头
        profit = current_price - entry_price
        if profit >= activation_threshold:
            logger.info(f"吊灯止损启动: 当前价 {current_price:.2f} - 开仓价 {entry_price:.2f} = {profit:.2f} >= {activation_threshold:.2f}")
            return True
    else:  # 空头
        profit = entry_price - current_price
        if profit >= activation_threshold:
            logger.info(f"吊灯止损启动: 开仓价 {entry_price:.2f} - 当前价 {current_price:.2f} = {profit:.2f} >= {activation_threshold:.2f}")
            return True
    
    return False
```

**修改 `check_trailing_stop_drawdown()` 方法**:
```python
def check_trailing_stop_drawdown(
    self,
    current_price: Decimal,
    highest_price: Decimal,
    lowest_price: Decimal,
    atr14: Decimal,
    direction: int,
    chandelier_activated: bool = False  # 新增参数
) -> bool:
    """
    检查是否触发吊灯止损
    
    V6.13.1: 从最高点回撤 1.2×ATR 触发
    V6.12/V6.13: 从最高点回撤 1.5×ATR 触发
    
    Args:
        current_price: 当前价格
        highest_price: 持仓期间最高价 (多头) 或最低价 (空头)
        atr14: ATR14 值
        direction: 方向
        chandelier_activated: 吊灯止损是否已启动
    
    Returns:
        True 表示触发止损
    """
    # 如果吊灯止损未启动,不检查回撤
    if not chandelier_activated:
        logger.debug("吊灯止损未启动,跳过回撤检查")
        return False
    
    # V6.13.1: 1.2×ATR 回撤阈值
    drawdown_threshold = atr14 * Decimal('1.2')
    
    if direction == 1:  # 多头
        drawdown = highest_price - current_price
        if drawdown >= drawdown_threshold:
            logger.info(f"吊灯止损触发: 从最高价 {highest_price:.2f} 回撤 {drawdown:.2f} >= {drawdown_threshold:.2f}")
            return True
    else:  # 空头
        drawdown = current_price - lowest_price
        if drawdown >= drawdown_threshold:
            logger.info(f"吊灯止损触发: 从最低价 {lowest_price:.2f} 反弹 {drawdown:.2f} >= {drawdown_threshold:.2f}")
            return True
    
    return False
```

**影响**: 吊灯止损逻辑将完整实现,符合业务规则

```python
class RiskManager:
    def __init__(self, params: StrategyParams = None, version: str = 'v6.13.1'):
        self.params = params or get_params()
        self.version = version
        self._load_version_params()
    
    def _load_version_params(self):
        """加载指定版本的参数"""
        config_file = 'config/stop_loss_take_profit_params.yaml'
```
