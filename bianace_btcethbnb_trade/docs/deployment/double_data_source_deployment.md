# 双数据源对比部署说明

## 📋 概述

本次更新实现了双数据源对比功能，可以在相同时间点使用不同数据源进行行情分析，验证数据一致性。

## 🔧 RSI 计算逻辑修复

### 问题

之前 RSI 计算在前 14 个位置会产生 NaN 值，导致信号检测时无法获取有效 RSI 数据。

### 解决方案

统一使用 `ffill() + bfill()` 方式填充 NaN 值：

```python
# 修复 NaN 值处理：使用 ffill + bfill 填充初始 NaN
# RSI 计算会在前 period 个位置产生 NaN，需要填充
if rsi14.isna().sum() > 0:
    logger.info(f"{timeframe} 填充 RSI NaN 值，数量={rsi14.isna().sum()}")
    rsi14 = rsi14.ffill().bfill()
    logger.info(f"{timeframe} 填充后 RSI 是否有 NaN: {rsi14.isna().sum()}")
```

### 影响范围

- `/core/data_fetcher.py` - K 线服务数据获取模块
- `/core/binance_data_fetcher.py` - 币安 API 数据获取模块

两个模块现在使用完全相同的 RSI 计算和 NaN 处理逻辑。

## ⚠️ 注意事项

### 1. 币安 API 网络问题

如果服务器无法直接访问币安 API，币安 API 数据源会失败。此时可以：

- 使用代理服务器
- 仅使用 K 线服务数据源
- 在本地运行对比测试

### 2. 数据同步时间

K 线服务的数据采集时间可能与币安 API 有细微差异：

- K 线服务：整点过后采集已收盘的 K 线
- 币安 API：实时获取最新数据

这可能导致 1-2 根 K 线的时间戳差异，属于正常现象。

### 3. 回滚方案

如果双数据源模式出现问题，可以回滚到单数据源模式：

```yaml
# 恢复为单数据源模式
hourly_analysis:
  minute: 25  # 只使用 K 线服务
```

## 📝 常见问题

### Q1: 为什么价格有微小差异？

A: 可能原因：
- K 线服务数据采集时间略有延迟
- 币安 API 返回的是最新价格，K 线服务是上一根 K 线的收盘价

### Q2: RSI 差异过大怎么办？

A: 如果 RSI 差异 > 2 点：
1. 检查 K 线服务的数据采集是否正常
2. 检查两个数据源的 K 线数量是否一致
3. 查看日志中的 RSI 计算过程

### Q3: 如何禁用币安 API 数据源？

A: 修改配置文件，注释掉币安 API 相关配置：

```yaml
# binance_api_analysis:
#   minute: 20

kline_service_analysis:
  minute: 25
```

然后重启容器即可。
