## 系统概述

### 功能特性

监控告警系统提供以下核心功能：

- **指标收集**：系统、应用、业务三层指标监控
- **告警管理**：灵活的告警规则和通知机制
- **健康检查**：系统和服务依赖的健康状态检查
- **数据持久化**：监控数据和告警历史的数据库存储
- **飞书通知**：集成飞书通知服务，实时推送告警

## 快速开始

### 1. 基础使用

```python
from monitoring import MetricsCollector, AlertManager, HealthChecker

# 初始化组件
metrics_collector = MetricsCollector()
alert_manager = AlertManager()
health_checker = HealthChecker()

# 收集所有指标
metrics = metrics_collector.collect_all_metrics()

# 检查告警
alerts = alert_manager.check_and_alert(metrics)

# 健康检查
health_report = health_checker.check_health()

# 获取指标摘要
summary = metrics_collector.get_metrics_summary()
print(f"系统状态: CPU {summary['system']['cpu_percent']}%, "
      f"内存 {summary['system']['memory_percent']}%")
```

### 2. 集成到现有系统

```python
# 在调度器中集成监控
from monitoring import MetricsCollector, AlertManager

class TradingScheduler:
    def __init__(self):
        self.metrics_collector = MetricsCollector()
        self.alert_manager = AlertManager()
    
    def execute_trade(self, symbol):
        """执行交易并记录指标"""
        start_time = time.time()
        
        try:
            # 执行交易逻辑
            result = self._do_trade(symbol)
            
            # 记录成功的API请求
            self.metrics_collector.record_api_request(
                endpoint='/api/trade',
                success=True,
                response_time=time.time() - start_time
            )
            
            # 记录交易
            self.metrics_collector.record_trade(
                symbol=symbol,
                success=True,
                pnl=result.get('pnl')
            )
            
            return result
            
        except Exception as e:
            # 记录失败的API请求
            self.metrics_collector.record_api_request(
                endpoint='/api/trade',
                success=False,
                response_time=time.time() - start_time,
                error=str(e)
            )
            
            # 发送自定义告警
            self.alert_manager.send_custom_alert(
                title="交易失败",
                message=f"{symbol} 交易失败: {str(e)}",
                level=AlertLevel.ERROR
            )
            
            raise
    
    def run_monitoring(self):
        """定期运行监控"""
        # 收集指标
        metrics = self.metrics_collector.collect_all_metrics(
            account_info=self._get_account_info(),
            positions=self._get_positions()
        )
        
        # 检查告警
        alerts = self.alert_manager.check_and_alert(metrics)
        
        # 健康检查
        if not self.health_checker.is_healthy():
            self.alert_manager.send_custom_alert(
                title="系统不健康",
                message="系统健康检查失败，请立即检查",
                level=AlertLevel.CRITICAL
            )
        
        return metrics, alerts
```

## 核心组件

### 1. 指标收集器（MetricsCollector）

#### 功能

- 收集系统指标：CPU、内存、磁盘、网络
- 收集应用指标：API调用成功率、响应时间、错误率
- 收集业务指标：交易成功率、盈亏、持仓状态
- 提供指标历史记录和摘要

#### 使用示例

```python
from monitoring import MetricsCollector

# 初始化
collector = MetricsCollector(
    collection_interval=60,  # 收集间隔（秒）
    history_size=1000        # 历史记录大小
)

# 收集系统指标
system_metrics = collector.collect_system_metrics()
print(f"CPU: {system_metrics['cpu']['percent']}%")
print(f"内存: {system_metrics['memory']['percent']}%")
print(f"磁盘: {system_metrics['disk']['percent']}%")

# 记录API请求
collector.record_api_request(
    endpoint='/api/klines',
    success=True,
    response_time=0.5
)

# 记录交易
collector.record_trade(
    symbol='BTCUSDT',
    success=True,
    pnl=Decimal('10.5')
)

# 收集所有指标（包含账户和持仓信息）
metrics = collector.collect_all_metrics(
    account_info={
        'totalCapital': '500',
        'availableCapital': '400',
        'usedMargin': '100'
    },
    positions=[
        {
            'symbol': 'BTCUSDT',
            'positionValue': '150',
            'openTime': int(time.time() * 1000) - 3600000  # 1小时前
        }
    ]
)

# 获取指标摘要
summary = collector.get_metrics_summary()
print(f"告警数量: {summary['alert_count']}")

# 获取历史记录
history = collector.get_system_metrics_history(limit=10)
```

### 2. 告警管理器（AlertManager）

#### 功能

- 管理告警规则
- 检查指标并触发告警
- 发送飞书通知
- 告警历史记录和统计
- 告警抑制和冷却

#### 使用示例

```python
from monitoring import AlertManager, AlertLevel, AlertRule

# 初始化
alert_manager = AlertManager(
    notification_url='http://43.156.242.184:8766/api/v1',
    project_name='btc_eth'
)

# 添加自定义告警规则
rule = AlertRule(
    name="cpu_critical",
    metric="cpu_usage",
    threshold=90.0,
    comparison='greater',  # greater, less, equal
    level=AlertLevel.CRITICAL,
    message_template="CPU使用率严重过高: {value:.1f}% > 90%",
    cooldown_minutes=60,  # 冷却时间
    enabled=True
)
alert_manager.add_rule(rule)

# 检查指标并触发告警
metrics = {
    'system': {
        'cpu': {'percent': 92.0},
        'memory': {'percent': 70.0},
        'disk': {'percent': 60.0}
    }
}
alerts = alert_manager.check_and_alert(metrics)

# 发送自定义告警
alert_manager.send_custom_alert(
    title="手动告警",
    message="这是一个手动触发的告警",
    level=AlertLevel.WARNING
)

# 获取告警历史
history = alert_manager.get_alert_history(
    limit=100,
    level='warning',  # 可选：按级别过滤
    rule_name='cpu_high'  # 可选：按规则名过滤
)

# 获取告警统计
stats = alert_manager.get_alert_stats()
print(f"告警统计: {stats}")

# 抑制告警（临时禁用）
alert_manager.suppress_alert("cpu_high", duration_minutes=30)

# 取消抑制
alert_manager.unsuppress_alert("cpu_high")

# 启用/禁用规则
alert_manager.disable_rule("cpu_high")
alert_manager.enable_rule("cpu_high")
```

#### 默认告警规则

系统预置了以下告警规则：

| 规则名称 | 指标 | 阈值 | 级别 |
|---------|------|------|------|
| cpu_high | cpu_usage | > 80% | WARNING |
| memory_high | memory_usage | > 80% | WARNING |
| disk_critical | disk_usage | > 90% | CRITICAL |
| api_success_rate_low | api_success_rate | < 95% | WARNING |
| response_time_high | response_time | > 5s | WARNING |
| error_rate_high | error_rate | > 5% | CRITICAL |
| trade_success_rate_low | trade_success_rate | < 90% | WARNING |
| consecutive_losses | consecutive_losses | > 5 | WARNING |
| capital_usage_high | capital_usage | > 80% | WARNING |

### 3. 健康检查器（HealthChecker）

#### 功能

- 系统健康检查（CPU、内存、磁盘）
- 数据库连接检查
- 服务依赖检查（通知服务、K线服务、币安API）
- 生成健康报告

#### 使用示例

```python
from monitoring import HealthChecker

# 初始化
health_checker = HealthChecker()

# 完整健康检查
report = health_checker.check_health()
print(f"总体状态: {report['overall_status']}")
print(f"检查耗时: {report['check_duration_ms']}ms")

# 快速健康检查（仅关键服务）
quick_report = health_checker.quick_health_check()

# 检查系统是否健康
if health_checker.is_healthy():
    print("系统健康")
else:
    print("系统不健康，请检查")

# 获取健康报告（文本格式）
report_text = health_checker.get_health_report()
print(report_text)

# 单独检查各项
system_health = health_checker.check_system_health()
db_health = health_checker.check_database_health()
notification_health = health_checker.check_notification_service()
kline_health = health_checker.check_kline_service()
binance_health = health_checker.check_binance_api()
```

#### 健康状态

- **healthy**：健康，所有检查通过
- **degraded**：降级，部分检查未通过但不影响核心功能
- **unhealthy**：不健康，关键检查未通过
- **unknown**：未知，检查失败或未配置

## 集成指南

### 1. 与调度器集成

```python
from monitoring import MetricsCollector, AlertManager, HealthChecker
from config.config_manager import get_config

class EnhancedScheduler:
    """增强的调度器，集成监控功能"""
    
    def __init__(self):
        # 初始化监控组件
        self.metrics_collector = MetricsCollector(
            collection_interval=get_config('monitoring.metrics.collection_interval', 60),
            history_size=get_config('monitoring.metrics.history_size', 1000)
        )
        
        self.alert_manager = AlertManager(
            notification_url=get_config('api.services.notification_url'),
            project_name=get_config('api.services.notification_project')
        )
        
        self.health_checker = HealthChecker()
        
        # 监控任务
        self.monitoring_enabled = get_config('monitoring.metrics.enabled', True)
    
    def execute_with_monitoring(self, task_func, *args, **kwargs):
        """带监控的任务执行"""
        start_time = time.time()
        
        try:
            # 执行任务
            result = task_func(*args, **kwargs)
            
            # 记录成功
            self.metrics_collector.record_api_request(
                endpoint=task_func.__name__,
                success=True,
                response_time=time.time() - start_time
            )
            
            return result
            
        except Exception as e:
            # 记录失败
            self.metrics_collector.record_api_request(
                endpoint=task_func.__name__,
                success=False,
                response_time=time.time() - start_time,
                error=str(e)
            )
            
            # 发送告警
            self.alert_manager.send_custom_alert(
                title=f"任务执行失败: {task_func.__name__}",
                message=str(e),
                level=AlertLevel.ERROR
            )
            
            raise
    
    def run_scheduled_monitoring(self):
        """定期运行监控"""
        if not self.monitoring_enabled:
            return
        
        # 收集指标
        metrics = self.metrics_collector.collect_all_metrics(
            account_info=self._get_account_info(),
            positions=self._get_positions()
        )
        
        # 检查告警
        alerts = self.alert_manager.check_and_alert(metrics)
        
        # 健康检查
        health_report = self.health_checker.quick_health_check()
        
        # 如果系统不健康，发送告警
        if health_report['overall_status'] != 'healthy':
            self.alert_manager.send_custom_alert(
                title="系统健康检查异常",
                message=f"系统状态: {health_report['overall_status']}",
                level=AlertLevel.WARNING
            )
        
        return metrics, alerts, health_report
```

### 2. 与交易执行器集成

```python
from monitoring import MetricsCollector, AlertManager, AlertLevel

class MonitoredTradeExecutor:
    """带监控的交易执行器"""
    
    def __init__(self):
        self.metrics_collector = MetricsCollector()
        self.alert_manager = AlertManager()
    
    def execute_trade(self, order_data):
        """执行交易并监控"""
        start_time = time.time()
        
        try:
            # 执行交易
            result = self._submit_order(order_data)
            
            # 记录API请求
            self.metrics_collector.record_api_request(
                endpoint='/api/trade',
                success=True,
                response_time=time.time() - start_time
            )
            
            # 记录交易
            self.metrics_collector.record_trade(
                symbol=order_data['symbol'],
                success=True,
                pnl=None  # 交易刚执行，暂无盈亏
            )
            
            return result
            
        except Exception as e:
            # 记录失败
            self.metrics_collector.record_api_request(
                endpoint='/api/trade',
                success=False,
                response_time=time.time() - start_time,
                error=str(e)
            )
            
            self.metrics_collector.record_trade(
                symbol=order_data['symbol'],
                success=False
            )
            
            # 发送告警
            self.alert_manager.send_custom_alert(
                title="交易执行失败",
                message=f"{order_data['symbol']} 交易失败: {str(e)}",
                level=AlertLevel.ERROR
            )
            
            raise
```

```python
from monitoring import MetricsCollector
from functools import wraps

# 全局指标收集器
metrics_collector = MetricsCollector()

def monitored_api(func):
    """API监控装饰器"""
    @wraps(func)
    def wrapper(*args, **kwargs):
        start_time = time.time()
        
        try:
            result = func(*args, **kwargs)
            
            metrics_collector.record_api_request(
                endpoint=func.__name__,
                success=True,
                response_time=time.time() - start_time
            )
            
            return result
            
        except Exception as e:

                endpoint=func.__name__,
                success=False,
                response_time=time.time() - start_time,
                error=str(e)
            )
            
            raise
    
    return wrapper
```

## 最佳实践

### 1. 监控策略

- **定期收集**：建议每分钟收集一次指标
- **合理阈值**：根据实际业务调整告警阈值
- **告警抑制**：避免重复告警，设置合理的冷却时间
- **分级告警**：区分WARNING、CRITICAL等级别

### 2. 性能优化

- **异步收集**：避免阻塞主业务流程
- **批量存储**：指标数据批量写入数据库
- **定期清理**：定期清理旧的监控数据
- **缓存优化**：使用缓存减少重复计算

### 3. 告警处理

- **及时响应**：收到告警后及时处理
- **根因分析**：分析告警的根本原因
- **持续优化**：根据告警历史优化规则
- **文档记录**：记录告警处理过程

## 故障排查

### 常见问题

#### 1. 指标收集失败

**症状**：无法收集系统指标

**排查步骤**：
1. 检查psutil库是否安装：`pip install psutil`
2. 检查系统权限
3. 查看日志错误信息

#### 2. 告警通知发送失败

**症状**：告警触发但未收到通知

**排查步骤**：
1. 检查通知服务URL是否正确
2. 检查网络连接
3. 查看通知服务日志
4. 验证飞书webhook配置

#### 3. 健康检查超时

**症状**：健康检查耗时过长

**排查步骤**：
1. 增加超时时间配置
2. 检查网络连接
3. 检查服务依赖状态

#### 4. 数据库连接失败

**症状**：无法保存监控数据

**排查步骤**：
1. 检查数据库连接配置
2. 验证数据库表结构
3. 检查数据库权限
