# 上下文交接存档

你是 TRAE 的项目助理。当用户触发"交接存档"时，把**当前这个任务**的关键状态增量追加到交接文件中，供新开对话无缝衔接，避免上下文压缩导致中间内容丢失。

## 触发时机（三种）

1. 用户手动说："执行交接存档" / "生成 handoff" / "记录 handoff" / "记录交接"。
2. 用户问"上下文太长/变卡了"之后。
3. **推荐习惯**：每完成一个重要的子任务（如一次重构、一个需求落地、一次部署验证），主动追问："要我记录到交接文件吗？"

## 文件存放与命名规范

- 存放目录：`docs/handoffs/`（不存在则创建）。
- 文件命名：`<任务名>_<YYYY-MM-DD>.md`，例如 `btc_eth_持仓保护单修复_2026-09-08.md`。
- **同一任务跨多天会生成多个文件**，用于在某一天内做增量追加（当天文件不存在则新建）。

### 命名约定

- `<任务名>` 用简短、可识别的英文或拼音词组，避免空格。
- 日期是当地时区（Asia/Shanghai）今天的日期。
- 若当天文件已存在 → **增量追加**（见下）；若不存在 → 新建。

## 文件结构（每个文件必须包含以下模块）

```markdown
# <任务名> - 交接存档
- 创建时间: <YYYY-MM-DD HH:MM>
- 任务源: <最初由哪条需求/指令发起>
- 取决于上一份: <若有跨天，写上一份文件名；否则写 N/A>

## 🎯 终极目标
用 1-2 句话说明这个任务最终要解决什么。

## ✅ 已完成事项（会固化，不再改动）
- 逐条列出已确定解决、不再改动的成果。
- 每条注明关键文件/提交/部署 ID（若有）。

## 🚧 进行中 / 未完成事项（重要！必须写明卡点）
- 逐条列出做了一半、报过错、搁置的内容。
- **每条必须写明卡住原因**（报错信息、决策待定、依赖缺失等）。
- 格式：`- [块] <事项>: <当前状态> | <卡点原因>`

## 📝 最新可执行代码/配置快照
- 贴出当前最新的、确保能运行的关键代码片段或配置项。
- 只贴关键片段，不贴整文件；标注文件路径与行号。

## 🔗 关键路径与依赖
- 列出涉及的关键文件路径、配置路径、依赖的服务/容器。

## 💡 给新对话的启动指令
用一段话告诉新 AI 助手：第一步读取哪个文件、执行哪条命令、先确认什么。
```

## 执行步骤

1. **定位文件**：判断当前任务名，按当天日期定位 `docs/handoffs/<任务名>_<YYYY-MM-DD>.md`。
2. **增量追加 vs 新建**：
   - 若文件不存在 → 新建，写完整结构。
   - 若文件已存在 → **只更新"进行中/未完成"和"最新快照"两大节**，不动"已完成"和"终极目标"（除非有变化）。在顶部 `创建时间` 下追加一条 `- 更新时间: <HH:MM>`。
3. **保持简洁**：每一条目简洁，代码快照只贴关键片段。
4. **确认 git 忽略**：确保 `docs/handoffs/` 已在 `.gitignore` 中，不被 `/git` 提交和部署范围分析误判为代码变更。若未配置，提醒补充。

## 输出反馈

生成/追加完成后，在对话中回复：
"✅ 交接文件已更新：`docs/handoffs/<文件名>`。请新开对话并引用此文件继续工作。"

## 注意（避免与全局记忆重复）

- 本 skill 只记录**当前任务**的任务级状态，不写 `project_memory.md` / `topics.md`（那是全局/话题级记忆，系统自动维护）。
- 不把 handoff 当作提交进 git 的正式文档；它只是本地交接用的临时快照。
